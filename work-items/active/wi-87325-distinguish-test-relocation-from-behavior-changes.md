# テストの移動と参照の追従だけで、構造変更へ追加の RED を要求しない

## 動機

[振る舞いを保つ変更](../../docs/development/specification-first-workflow.md#振る舞いを保つ変更)は、refactor の差分がテストのパスを含まないことを証拠省略の条件としている。
この条件では、テストの内容が同じ移動や import の追従も、期待結果を変更した場合と同じ証拠を要求される。
これは規則から見える負担の候補であり、削減時間はまだ実測していない。
期待結果と観測する振る舞いを保つ構造変更では、既存テストの成功と配置の検査で確認できる範囲を広げたい。

## 対象範囲

- Git の差分から、テストの変更なし、同じ内容の移動、移動に伴う package と import の追従、振る舞いに関わる変更、不明を区別する。
- 内容と参照の対応を確認できる変更だけを、既存テストの成功と配置検査による証拠の対象にする。
- 開発ワークフロー、作業項目形式、作業項目の証拠検査を同じ判定に揃える。

## 対象外

- 製品コードが振る舞いを保つことの静的な証明。
- テストの期待値、入力、表明、skip、実行対象、fixture の内容を変えた変更の免除。
- 通常テストと race 検査の選択、契約テストの要求、検証結果の再利用、CI の実行範囲の変更。
- 過去の完了記録の書き換え。

## 設計

### 判定する変更

仕様影響がなく `change_kind: refactor` であることは引き続き必要条件とする。
テストの変更をパスの存在だけで判定せず、変更前と変更後の内容と移動先の対応から分類する。
差分の基準は現在の証拠検査と同じ作業範囲を使う。

内容が同じ移動は、新旧のファイルを対応付けて認定する。
package と import の追従は、移動したパッケージの対応が Git の差分から解決でき、変更がその参照と必要な別名の追従に限られる場合だけ認定する。
Go の解析では、テスト名、入力、期待値、呼び出し、表明、ディレクティブ、build tag が保たれることを確認する。
同じ綴りでも別の依存へ向く変更を、参照の追従として認めない。
判定できない言語と構文、曖昧な移動、混在する変更は不明として現行の証拠を要求する。
最初の参照追従の解析は Go に限り、ほかの言語は内容が同じ移動だけを認める。

fixture、testdata、設定の内容が変われば、ファイル移動と同じ扱いにはしない。
期待結果を変える可能性があるためである。
自己申告の免除欄は追加せず、判定結果と認定できない理由を検査の診断として返す。

### 証拠と責務

免除するのは記録のために追加する RED と変更耐性の証拠である。
変更後の既存テストの実行と、公開契約、配置、逆依存など、実際の変更に必要な検査は引き続き求める。
規範を変える変更は本項目の免除対象にしない。

既存の `tools/check` 内に差分分類を集め、[主要ユースケースの証拠検査](../../tools/check/src/primary-use-case-evidence.ts)と作業項目の形式検査が同じ結果を使う。
新しいモジュールと独立した免除台帳は作らない。

### 代替案

- テストパスを含む差分をすべて重く扱う案は、内容が同じ移動を区別できないため変更する。
- refactor の自己申告だけで免除する案は、期待値の変更を隠せるため採らない。
- import 行をすべて比較から落とす案は、別の実装へ切り替えた変更も通すため採らない。

## 計画

1. 証拠検査の現在のすべての判定箇所を確認し、変更分類と認定条件を所有文書へ反映する。
2. 最小 Git fixture で同じ内容の移動と参照追従の RED を確認する。
3. 分類を既存の検査へ接続し、期待結果の変更と不明な変更を拒否する対照を固定する。
4. 実際の構造変更の例に適用し、省略した証拠と維持した検査を記録する。

## 検証

製品要件 ID は N/A（作業項目の証拠選択を行うツール）。
受け入れ RED は記録検査を通る Git fixture、単体 RED は差分分類で観測する。

- 同じ内容の移動と、解決できる Go の参照追従を受理する。
- 期待値の弱体化、表明の削除、テスト名と skip の変更、別の依存への切替、fixture の内容変更を免除しない。
- 不明な移動と解析失敗は従来の証拠を要求し、申告だけで成功にしない。
- 変更分類の接続を外す故障と、表明または依存先の変更を無視する故障をそれぞれ注入し、検出する。
- `mise run test-tools-file -- <変更したテストファイル>`、`typecheck-tools`、`lint-tools`、`check-work-items`、`check-links` を選ぶ。
  文書の変更後に `render-docs` と `check-rendered-docs` を実行する。

## リスク

- 名前だけの追従に見えても、参照先の意味が変わる場合がある。
  対応が解決できる変更だけを認め、不明な場合は従来の証拠を求める。
- 複数の証拠検査で判定がずれると、一方だけを通して免除できる。
  分類結果を共有し、記録検査を通る fixture で両方の条件を確認する。
