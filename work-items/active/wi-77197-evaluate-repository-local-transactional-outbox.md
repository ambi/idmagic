# 専用の保存境界で Transactional Outbox を採る条件を検討する

## 動機

通常の監査は、業務可用性を優先して欠落を許容する。
[wi-46722](../done/wi-46722-reconcile-missing-audit-records.md) は、検知した失敗を指標とログへ記録し、原因の解消と記録の再開を運用手順へつなぐ。
この方式は、失われた過去の監査を正確に復元する保証を持たない。

利用者は、今回の方式を進めつつ、Transactional Outbox を将来の検討可能性として別項目へ残すことを求めた。
現行要件から追加の Outbox が必須となる操作は、まだ特定していない。
この項目は、欠落の許容では足りない要件があるかを確かめ、採用と見送りを判断できる材料を作る。

## 対象範囲

- [REQ-AUDIT-008](../../docs/modules/audit/features/event-search.md) が許容する欠落と、求められる回復の範囲を確認する。
- 操作ごとに、最終状態への収束で足りるか、個々の発生と過去の行為者、時刻、変更内容を残す必要があるかを区別する。
- [Provisioning の差分同期](../../docs/modules/provisioning/decisions.md) と、User とワークフローの実行予定を確定する既存の保存境界を比較する。
- 採用候補がある場合は、状態と発行意図を専用の保存ポートで同時確定する案の、保証、所有者、失敗処理と運用負担を見積もる。
- 採用しない判断も結果として記録し、実装が必要なら合意した保証を持つ別の実装項目を起票する。

## 対象外

- この検討項目での Outbox の実装、スキーマ変更、再配信処理、本番操作。
- 全操作の HTTP ハンドラーへトランザクションを伝播すること。
- Event Sourcing への移行と、業務の正本をイベントストアへ変えること。
- 現在の業務状態から過去の監査の内容を推測して補うこと。
- 特定していない操作を「重要」と分類し、既存の成功条件を先に変更すること。

## 設計

### 比較する保証

| 案 | 正本と確定 | 回復できるもの | 判断条件 |
| --- | --- | --- | --- |
| 失敗の検知と運用対応 | 業務状態を先に確定し、監査を後で記録する | 原因の解消と、以後の記録の再開。過去の復元は独立した証拠が残る範囲に限る | 監査の欠落を許容する場合は現行方式を維持する |
| 差分同期 | 業務状態を正本とし、反映済みの状態との差を処理する | 最終的な状態への収束 | 個々の中間の発生を保持する必要がない場合に適する |
| Transactional Outbox | 業務状態と発行意図を専用の保存ポートで同時確定する | 保存済みの意図からの再配信 | 個々の発生の回復が必要で、発行意図の保存失敗時に業務も未確定となる条件を受け入れられる場合に検討する |
| Event Sourcing | イベントを正本として確定し、業務状態と監査へ反映する | 保存済みのイベントからの再構築 | 履歴と再構築が業務の中心となる別の要件が必要。本項目では採用しない |

Outbox は、監査への書き込み前の停止を回復できる一方、発行し忘れた意図や失われた保存先まで救うものではない。
再配信には重複を許して結果を一度だけ反映する処理、順序、進捗、再試行、保持期間の設計が必要である。
保存先が不調の場合は、監査への書き込みの失敗を業務から切り離せても、発行意図の保存の失敗は業務の失敗になる。

[wi-190](../done/wi-190-transactional-event-log-rollout.md) は、任意の HTTP ハンドラーを囲うトランザクションを撤去し、専用の保存ポートが短いトランザクションを所有する将来の案は残している。
着手時に候補の状態と更新元を調べ、保存の所有者、公開ポート、組み立て地点を変える必要があれば、[境界を選ぶ判断手順](../../docs/design/application/design-guidelines.md#境界を選ぶ判断手順) による比較を記録する。
現在は具体的な境界変更を選ばない。

## 計画

1. 欠落が許されない具体的な結果と操作を、既存要件と利用者の要求から特定する。
2. 既存の専用保存、永続タスク、差分同期で要件を満たせるかを確認する。
3. 不足する場合だけ、Outbox の保存境界と運用を見積もり、業務成功条件の変更を利用者と確定する。
4. 現行方式の維持、限定した採用、追加検討のいずれかを記録する。

## リスク

「回復」という語だけで、記録の再開、状態の収束、過去の監査の復元を混同しやすい。
各案の保証と回復元を明示する。
Outbox を先に共通基盤として広げると、必要性を確認していない操作まで成功条件と依存が変わる。
具体的な要件を満たす最小の保存境界だけを比較する。
