# エージェントのツール選択を見直し、構文に依存しない一斉置換を補う

## 動機

[AGENTS.md のツール表](../../AGENTS.md#ツール)は、同じ構造と同じ文字列の複数箇所の書き換えを、どちらも `ast-grep run -p -r -U` へ割り当てている。
構文パターンで表す変更には適するが、Markdown の文章、URL、設定中の文字列などをファイル形式によらず置き換える手段が明記されていない。

[sd の利用をやめた作業](../done/wi-75753-stop-using-sd-for-repository-edits.md)は、一致がなくても成功する挙動を理由に `sd` を外した。
利用者からは、更新の停滞と挙動への不満も踏まえて代替を調べたいとの要望がある。
その完了記録は代替の道具が一致しなければ失敗すると説明するが、`jq` と `yq` の通常終了は変更の成立を保証しない。
出力値を判定する `-e` を付けても、元のオブジェクトを出力する更新式では、変更がないまま成功し得る（出典 S5、S6）。

また、`mise.toml` の `setup-cli-tools` は `jq yq ripgrep fd gh ast-grep` を Homebrew で導入するが、表で指定する `ax` を含まない。
`jq` は `[tools]` にも固定されており、導入経路が重なる。
ツール名、利用できる条件、失敗を見つける方法、導入手順を合わせて見直す。
候補の評価と採否から始めるため、優先度は p3 とする。

## 対象範囲

- AGENTS.md の「ツール」の各行について、維持、用途の限定、追加の判断を反映する。
- 通常テキストと、コメントなどの範囲に閉じた文字列の一斉置換を構文の組み替えから分け、`srgn` を第一候補として評価する。
  `rg`、`ast-grep`、`srgn` の優先する用途と、機能が重なる場合の選び方を明示する。
- 空振り、変更前の確認、特殊文字の解釈、対象ファイルの選択を、採用する操作の説明へ含める。
- 詳細な操作例と判断理由は、[エージェント向けの指示](../../docs/development/agent-guidance.md)のツール選択の節へ置き、AGENTS.md には短い選択表と参照を残す。
- `mise.toml` の導入宣言と `setup-cli-tools` を、実際に指定する CLI に合わせる。
  取得元、バージョン、対応 OS を同ファイルで管理し、`ax` の導入漏れと `jq` の重複を解消する。
- 操作例の動作と、文書と導入対象の整合を検証する。

## 対象外

- `sd` の再導入、ランタイムと依存関係全体の更新、製品コードのリファクタリング。
- エージェント環境が提供する読み取り、編集、検索、ブラウザーのツールを特定の製品へ統一すること。
- 意味検索のインデックス、外部サービスへのソース同期、対話型 TUI の標準導入。
- 汎用的な置換エンジンや多数の CLI を隠すラッパーの自作。
- 指示の汎用部分の抽出と配置変更。[wi-99632](wi-99632-separate-reusable-practices-from-idmagic-specifics.md)が扱い、この項目は現行の配置でツールの選択を変える。
- 外部の文章からの指示混入と送信権限の規則。[wi-11123](wi-11123-analyze-untrusted-input-flows-in-development-agents.md)が扱う。
- 文書の意味の差分を読むレビュー手順。[wi-18737](wi-18737-review-meaning-changes-in-document-diffs.md)が扱う。

## 設計

### 調査の基準と近年の動向

調査日は 2026-11-28 とし、同日までに公開された一次資料を使う。
検索結果の紹介文は候補を探すためにだけ使い、下表の判断は公式の本文、CLI 定義、ソース、リリース情報へ戻している。
更新間隔だけで保守停止とは判定せず、配布物、変更履歴、実装上の失敗の扱いを別々に評価する。

公開資料では、構文検索をエージェントへ教える skills、意味検索による探索、文脈へ返す出力の削減という方向が確認できる。
ast-grep は公式にエージェント向け skill と構文検索の指示例を提供し、2026-11-16 にもリリースしている（S1、S2）。
`ax` は出力の上限と構造化抽出を提供し、`mgrep` は自然言語検索とバックグラウンド同期を提供する（S8、S10）。
これらを一律に増やさず、このリポジトリの作業で必要な結果、非対話実行、空振りの検出、導入費用で選ぶ。
各製品が示す速度やトークン削減の数値を、このリポジトリでの効果として転用しない。

### ツール表の見直し案

| 作業 | 判断 | 反映する内容と理由 |
| --- | --- | --- |
| ファイルと一部の読み取り | 維持 | 実行環境の専用ツールを先に使い、なければ `cat` と範囲を指定した `sed -n`。単純な読み取りに解析スクリプトを作らない |
| ファイルと部分木の構造把握 | 維持 | `ast-grep outline`。入口の一覧から必要な本体へ進み、単なるファイル名検索とは区別する |
| 局所的なコード編集 | 維持 | 公開されている編集ツール。前後の文脈を指定し、一斉置換の特殊文字を避けたい場合にも使う |
| JSON の照会と変更 | 補足して維持 | `jq`。更新前の対象存在や期待値を検査し、更新後の値も照合する。`-e` を付ければ変更件数を検出できるとは書かない |
| YAML の照会と変更 | 補足して維持 | Mike Farah の `yq` v4 と明示する。同名の別実装と区別し、コメントと空白の完全保存を前提にしない。変更成立の確認は JSON と同じ |
| 内容の検索 | 維持 | `rg`。文字列には `-F`、パス一覧には `-l`、機械への受け渡しには NUL 区切りを使い分ける。構文条件が必要なら ast-grep へ進む |
| 名前によるファイル検索 | 維持 | `fd`。ignore と隠しファイルの扱いを意識し、追跡ファイルに限定する必要がある操作では `git ls-files` も選べるようにする |
| 同じ構造の複数箇所の書き換え | 用途を限定して維持 | `ast-grep`。対象言語とパスを指定し、`-U` で適用する前に変更案を読む。名前の束縛を理解する rename の代替とは扱わない |
| 通常テキストと指定範囲内の文字列の複数箇所の書き換え | 行を分けて追加 | `srgn` を評価し、下記の採用条件を満たす操作に限って使う。コメント内などの単純な範囲指定も含め、構文を照合して組み替える変更は ast-grep が扱う |
| HTML の読み取りと抽出 | 条件を明記して維持 | 静的 HTML は `ax`。`--md --budget`、CSS selector、構造化出力を使う。JavaScript 実行後の DOM やログイン状態が必要なら、利用可能なブラウザーツールへ切り替える |
| GitHub の PR、Issue、API | 補足して維持 | `gh`。`--json` と `--jq`、API のページングを使い、必要なフィールドを取得する。実行環境の専用連携で同じ結果を得られる場合は、先頭の専用ツール優先と矛盾させない |

`rg` と `fd` は ignore を尊重する検索を提供しており、このリポジトリの `.ignore` とも合う（S3、S4）。
一方、複数ファイルの置換では「リポジトリ全体をデフォルトで走査する」こと自体を推奨にしない。
対象パスと除外条件を明示し、既存の編集を含む変更前の差分と、置換が追加した差分を見比べる。

### rg、ast-grep、srgn の分担

三つのツールは検索と変換の機能が重なるが、操作を表す方法で使い分ける。
`srgn` にも Tree-sitter による構文検索と独自の query の指定があり、構文を扱えないから補助にするわけではない。
通常のテキスト検索には `srgn` の README 自身が ripgrep を勧めている（S11 の脚注 1）。

`ast-grep` はコードに似たパターンと構文要素を捕捉するメタ変数を使い、捕捉した式や文を置換先へ組み込める。
`inside`、`has` などの関係条件も組み合わせられる（S16）。
一方、`srgn` は選んだ範囲に対する文字列処理を基本とし、コメントや文字列を選ぶ組み込み指定を提供する。
そのため、構文の照合と組み替えには既存の ast-grep を使い、通常テキストや単純に限定した範囲の中の文字列処理を srgn が補う。

| 判断する内容 | 優先するツール | 例 |
| --- | --- | --- |
| 文字列や正規表現がどこにあるかを調べる | `rg` | シンボルの入口、文書中の旧名称、設定キーの出現箇所を探す |
| コードの形、親子関係、捕捉した構文要素を条件に検索または変換する | `ast-grep` | 呼び出しの引数を入れ替える、特定の関数内の呼び出しを変える |
| ファイル形式によらないテキストを一斉置換する | `srgn` | Markdown の旧名称や URL を置き換える |
| 組み込み指定で選べる範囲内のテキストを検索または置換する | `srgn` | Go のコメント内だけで旧 URL を置換し、コード中の同じ文字列は残す |

最後の用途も ast-grep で表せる場合があるが、範囲の指定と文字列処理だけで済むなら srgn を選べるようにする。
複雑な独自 Tree-sitter query を srgn で書かなければならない操作は、まず ast-grep のパターンと規則で表す。
このリポジトリでは既に `ast-grep outline` と構文変更の手順を使っているため、それを置き換えるだけの便益が確認できない段階で、三つを srgn へ統一しない。
速度の優劣はこの調査では測定しておらず、使い分けの根拠にしない。

### 通常テキストの一斉置換

`srgn` を第一候補にする理由は、非対話での変更、差分を示す `--dry-run`、対象を選ぶ `--glob`、一致なしの `--fail-none`、対象ファイルなしの `--fail-no-files` がそろうことである（S11）。
公式の最新リリースは調査時点で 2026-11-15 の `srgn-v0.14.4` であり、macOS の ARM64 と x86_64、Linux の x86_64 GNU 向け配布を確認した。
Linux ARM64 の配布物は同リリースにないため、対応範囲を無条件に Linux 全体へ広げない。
ただし、これらは期待件数や実変更の検査を代替しない。
`--fail-none` は置換前の一致の有無を調べるもので、同じ文字列への置換や、すべての対象ファイルで一致したことを保証しない。

`--literal-string` は検索の正規表現を無効にするが、検索値と置換値のバックスラッシュの解釈まで無効にはしない。
`\n`、`\t`、`\\` などは別途扱う必要がある。
置換側の `$1` などの展開は正規表現検索の場合に行われ、文字列検索の場合とは異なる（S11）。
文字列検索を、引数のバイト列を一切解釈しない操作として説明しない。

公式の CLI 定義に基づく評価用の操作例を次に示す。
バイナリを実行して確認した例ではなく、T001 で検証してから掲載する。
`--stdin-detection force-unreadable` は、エージェントの標準入力の状態によってファイル処理が変わることを避けるために評価する。

```sh
srgn --stdin-detection force-unreadable --glob 'docs/**/*.md' --literal-string --fail-none --fail-no-files --dry-run '旧名称' -- '新名称'
srgn --stdin-detection force-unreadable --glob 'docs/**/*.md' --literal-string --fail-none --fail-no-files '旧名称' -- '新名称'
```

採用前に、次の条件を実際の CLI で確かめ、通る操作だけを指示へ載せる。

- Markdown の日本語と URL を、複数ファイルで変更できる。
- Go のコメントと文字列リテラルに同じ URL を置き、組み込みのコメント範囲指定でコメントだけを変更できる。
  検索だけの場合も同じ範囲へ限定できる。
- 対象ファイルなしと一致なしを非ゼロで終了できる。
  一致はあるが差分がない場合は、別途変更後の値と差分で判定できる。
- dry-run がファイルを書き換えず、適用後の差分が事前に読んだ変更案と一致する。
- 検索値と置換値それぞれの `$`、バックスラッシュ、文字としての `\n`、実際の改行を区別できる。
  シェルの引用と CLI 自身の解釈を分けた、短く再現できる例を書く。
- 空白を含むファイル名、隠しファイル、`.ignore` と `.gitignore`、明示 glob の対象選択を確認できる。
- CRLF と末尾改行の保存、書き込みエラー、複数ファイルの一部でだけ一致する場合を区別できる。
- 文書で対応を約束する macOS と Linux で同じ操作と導入が成立する。

特殊文字の扱いが複雑になる置換は、既存の編集ツールで文脈を指定して行う。
評価で一般テキストの標準操作として無理があると分かった場合は、導入を見送り、通常テキストは編集ツールに割り当てる。
別の置換エンジンを作って候補を補うことはしない。

### 採らない代替案

| 案 | 判断と理由 |
| --- | --- |
| `sd` を再導入する | 採らない。利用者が外した経緯を維持し、空振りの扱いが改善したという根拠なしに戻さない |
| `fastmod` | 標準には採らない。`--accept-all` で非対話実行できるが、一致なしやエラーの終了状態を十分に区別できない実装がある。最終リリースの古さだけを不採用理由にはしない（S12） |
| `scooter` | 標準には採らない。`--no-tui` による非対話実行もあるが、一致が 0 件でも成功となり、確認した CLI に dry-run と fail-none 相当の指定がない。人が選別する TUI の用途は別途選べる（S13） |
| `ruplacer` | 今回再採用しない。旧 GitHub から Codeberg への移転は確認できるが、移転先の本文と現在の配布を取得できず、前回の不採用判断を覆す根拠を得られなかった。移転を開発停止とは扱わない |
| 一律の `sed -i`、`perl -pi` | 採らない。既存の編集方針と衝突し、対象選択、置換の解釈、空振りの検査を呼び出しごとに組み立てることになる |
| `ast-grep` へすべて集約する | 採らない。構文を持たない文章やファイル形式によらない文字列の変更まで AST パターンに押し込む理由がない |
| `srgn` へ検索と構文変更をすべて集約する | 採らない。通常検索には作者も rg を勧めている。構文要素を捕捉して組み替える変更は ast-grep の表現が適し、既存の outline と規則も維持する。srgn の構文機能は単純な範囲指定に優先して使う |
| `jaq` で `jq` を置き換える | 採らない。公式にも互換性は「多くの場合」とされ、既存の式とタスクを移すだけの問題が確認されていない（S14） |
| `dasel` へ構造化データの操作を統一する | 採らない。複数形式を扱えるが、既存の jq 式を置き換える効果が未実証で、新しい式の体系が増える（S15） |
| `mgrep` で `rg` を置き換える | 採らない。公式にも補完用途として説明され、認証と外部ストアへの同期が必要になる。この項目の正確な文字列検索と置換には追加費用が見合わない（S10） |

## 検証

- 起票は `mise run check-work-items` と `mise run check-links` で、記録の形式と参照を確かめる。
- 実装時は一時ディレクトリの小さなファイル集合で、採用条件にある置換、空振り、dry-run、特殊文字、対象選択を確認する。
  恒常的なラッパーを作らない場合、この調査のためだけのテストスイートを CI へ増やさない。
- `mise run check-agent-guidance`：指示と参照タスクの整合を確認する。
- `mise run check-work-items`、`mise run check-links`、`mise run check-terminology`：記録、追加した参照、説明の表記を確認する。
- `mise run verify-changed`：`mise.toml` の変更が届く検査を選ぶ。
  導入手順の確認は新しい CLI を取得できる環境で行い、取得できない場合は未検証として区別する。

## リスク

置換ツールの名前だけを変えると、バックスラッシュの解釈や一致と実変更の違いを見落とし、`sd` を外した理由を再発させる。
採用条件と操作例を先に確かめ、特殊文字を安全に表せない操作は既存の編集ツールへ戻す。

複数ファイルの更新は途中で失敗して一部だけ変わる可能性がある。
対象を絞り、変更前後の差分を確認し、既存の編集を巻き戻さずに修正できる手順にする。

詳細を AGENTS.md へ増やすと、どの作業でも読む指示が長くなる。
選択表と詳細を分け、既存の読み取りと編集の専用ツール優先を維持する。
