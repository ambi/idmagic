# リポジトリの編集で sd を使わず、ast-grep と編集ツールと jq/yq で書き換える

## 動機

AGENTS.md のツール表は、同じリテラルの一括置換に `sd` を指定している。
`sd` は一致が 0 件でも終了コード 0 で終わり、置換した件数も出さないので、置換が空振りしても失敗に見えない。
エージェントは、改行を含む置換で `-A` を付け忘れる空振りを、表に注意を書いた後も繰り返した。
空振りは後の検査で見つかるまで残り、そのたびにやり直しが生じた。

## 対象範囲

- AGENTS.md のツール表から `sd` の行と言及を外し、コードの書き換えは編集ツールと ast-grep、JSON と YAML の変更は jq と yq で行う形にする。
- `mise run setup-cli-tools` が入れる CLI の一覧から `sd` を外す。

## 対象外

- 開発者の端末に入っている `sd` の削除。各自に任せる。
- コードではないファイル（主に Markdown）にまたがる同じ文字列の一括置換を担う道具の追加。必要な場面が増えたときに、一致が 0 件なら失敗するリポジトリ内のタスクを起票して足す。

## 設計

置き換えの対応は次のとおりである。

| これまでの `sd` の用途 | 代わり | 失敗の見え方 |
| --- | --- | --- |
| 1 か所の書き換え（複数行を含む） | 公開されている専用の編集ツール | 一致しなければエラーで止まる |
| 同じ形のコードの一括書き換え（Go の import パス、呼び出しの置換など） | `ast-grep run -p <pattern> -r <rewrite> -U` | 一致が 0 件なら終了コード 1、書き換えた件数を表示する |
| JSON と YAML の変更 | `jq`、`yq`。整形は既存の整形タスクで戻す | 構文の誤りでエラーになる |

| 案 | 採否と理由 |
| --- | --- |
| `sd` を使い続け、置換のたびに `git diff --stat` で着弾を確かめる | 不採用。確かめる手順を忘れる失敗の型が残る |
| `sd` の代わりに ruplacer を導入する | 不採用。一致が 0 件なら失敗する性質は合うが、現在の開発元の Codeberg のリリースに配布バイナリがなく、旧 GitHub はアーカイブ済みで、保守の見通しに不安がある |
| `sed` を使う | 不採用。一致が 0 件でも終了コード 0 で、固定文字列の指定がなく、GNU 版と BSD 版で書き方が違う |
| `sd` を使わず、上の表の道具で書き換える | 採用。Go と TypeScript の書き換えは ast-grep のほうが確実で、不便になるのはコードではないファイルにまたがる一括置換だけである |

ツール表の「使用しないもの」には `sd` を挙げない。
`sd` は標準で入っている道具ではないので、導入一覧と指示から外せば使う理由がなくなる。

## 要約

`mise run spec-diff` は規範の変更なしと報告した。
AGENTS.md のツール表から `sd` を外し、同じ構造または同じ文字列の複数箇所の書き換えを `ast-grep run -p -r -U` に、JSON と YAML の変更を `jq` と `yq` にまとめた。
`setup-cli-tools` の導入一覧からも `sd` を外した。
`sd` は一致が 0 件でも終了コード 0 で空振りが見えないためで、代わりの道具はいずれも一致しなければ失敗する。
ruplacer は、開発元の Codeberg に配布バイナリがなく保守の見通しに不安があるため採らなかった。
