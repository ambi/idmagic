# 外部の相手に対する前提を、記録した往復の再生と参照実装との比較で確かめる

## 動機

このリポジトリの検証は、自分が提供する契約には厚く、消費する契約には薄い。
`mise run check-api-compat` は提供する OpenAPI をリリース済みのベースラインと比べるが、消費する側に対応する検査はない。
Provisioning は SCIM 2.0 で下流の SaaS へ書き込み、Sourcing は上流の権威から取り込み、SharedSignals は SET を受信者へ送る。
いずれも相手の実装が変われば壊れるが、その壊れ方を検出する仕組みがない。

手で書いた解析器を、独立した実装と突き合わせる検査もない。
SCIM のフィルタの解析器は仕様が複雑で、wi-248 のように継続して手が入るので、同じ入力を参照実装と比べる差分テストが効く。

起票時はこの項目が縮退の順序と無停止の移行の型も扱っていた。
縮退の順序の試験は分散配置の障害試験とあわせて wi-165 へ、移行の型の検証は wi-85300 へ移したので、ここでは外部の相手に対する前提だけを扱う。

## 対象範囲

- Provisioning、Sourcing、SharedSignals について、外部の相手に対して前提にしている振る舞いを書き出し、取り込みと変換の層のどこでその前提を吸収しているかを確かめる。
- 実際の往復を記録して再生する検証を、最も実装の厚い一つの対象に入れ、費用と検出できるものを確かめてから残りへ広げる。
- 相手が実在しない場合と、部分的な失敗、遅延、不正な本文を作る場合は、状態を持つ相手の模倣（behavioral twin）を使う。まず SCIM 2.0 のサービスプロバイダーを一つ作り、作成した User と Group を保持して、フィルタ、PATCH、重複時の `409`、レート制限の `429` を返せるようにする。模倣は記録した往復を再生して同じ応答を返すことを検査し、記録が模倣の忠実さの基準になるようにする。模倣はテストの中だけで使い、製品の経路から呼ばない。
- SCIM のフィルタの解析器に、仕様の文面だけから書いた参照実装との差分テストを入れる。参照実装はテストの中だけで使い、製品の経路から呼ばない。

## 対象外

- OAuth、OIDC、FAPI の適合試験。wi-33 が扱う。
- 縮退の順序の試験。wi-165 が扱う。
- スキーマの移行の段階の検証。wi-85300 が扱う。
- 本番での障害注入。
- 消費者駆動契約テストの枠組み（Pact など）。下流の SaaS も上流の権威も協力を得られず、記録と再生を超えるものが得られない。
- 特定の SaaS（Okta、Entra、Slack など）ごとの模倣。汎用の SCIM の模倣で費用と検出できるものを確かめてから、相手ごとの差分が実際に問題になった対象に限って起票する。

## 設計

外部の相手の代わりに使うものを次の案から比べ、記録と再生を状態を持つ模倣の忠実さの基準として組み合わせる。

| 案 | 採否 | 理由 |
| --- | --- | --- |
| 記録した往復の再生 | 採る | 相手の実際の応答を固定できる。ただし記録した順序の操作しか確かめられず、障害と量の試験には使えない |
| 状態を持つ相手の模倣 | 採る | 記録にない操作の組み合わせ、部分的な失敗、`429` の連続を、レート制限や費用なしに何度でも作れる。記録の再生と一致することを検査すれば、模倣が実物から離れたことに気付ける |
| テストごとの応答の関数（現状） | 残す | `backend/provisioning/e2e_lifecycle_events_test.go` は常に `503` を返す `httptest.NewServer` で隔離を確かめている。一つの応答だけが要るテストには十分であり、置き換えない |
| 実物の SaaS への接続 | 採らない | 協力も試験用の契約も得られず、CI で再現できない |

StrongDM は、依存する外部サービス（Okta、Jira、Slack、Google の各サービス）の模倣（Digital Twin Universe）を、公開の API 文書からコーディングエージェントに作らせた。
模倣を作る費用はエージェントで下がったので、このリポジトリでも記録だけに頼る理由が弱まった。
一方、StrongDM は人がコードをレビューしない開発の一部として模倣を使っているが、この項目はその開発の方法を採らず、テストの資材としての模倣だけを採る。

## 検証

- 相手の応答を仕様に反する形へ変えると、記録と再生の検証が落ちる。
- 模倣の応答を記録と食い違う形へ変えると、模倣の忠実さの検査が落ちる。
- SCIM のフィルタの参照実装と既存の実装の出力が、生成した入力のすべてで一致する。一致しない入力が見つかったら、どちらが正しいかを仕様の文面で決める。
- `mise run verify`

## リスク

外部との契約を記録で固定すると、記録が古くなったときに、相手が変わったのか記録が古いのかを区別できなくなる。
記録には取得日時、相手のバージョン、取得方法を添える。
