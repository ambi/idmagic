# CI の高速化を実測し、6分程度の目標に不足する処理を改善する

## 動機

[wi-31758](../done/wi-31758-reduce-full-ci-feedback-time.md)では、CI の並列化、通常の Go 全体テストへの切り替え、英文検査と重複処理の削除を実装した。
利用者の指示により実装を先に main へ統合するが、Actions 上での時間はまだ測っていない。
[変更前の実行](https://github.com/ambi/idmagic/actions/runs/39308038133)の約12分から6分程度へ短縮できたかを確認し、不足する場合は実測から追加の改善を選びたい。

## 対象範囲

- main への push 後の CI で、ワークフロー全体と各ジョブ、準備、ビルド、検査、後処理の時間を取得する。
- 変更前後の検査内容と runner の条件を照合し、削除、通常テストへの切り替え、並列化、処理改善の効果を分ける。
- 全検査が必要な代表的な変更の結果から、6分程度の目標に不足する処理を特定する。
- 必要な場合に、異なるコミット間の Go 依存、ビルド、lint キャッシュの正味の効果と、他の高速化案を比較して採否を決める。
- 採用する追加改善を実装し、所有文書と CI の説明を同期する。

## 対象外

- CI の race 検査の再導入。wi-47187 が担当する。
- 過去のテスト結果や `.verification/` を現在の成功の証拠へ流用すること。
- 待ち時間だけを理由に DB 必須モード、契約証拠、セキュリティ検査を削ること。
- 計測のためだけに CI の履歴取得や経過日数の判定を常設すること。

## 設計

最初に、キャッシュを増やさない最終構成の実行を測る。
ワークフロー開始から最終ジョブ完了までの時間と、runner の待機、各ジョブ、合計使用時間を区別する。
手元の参考値を Actions の実測値へ置き換えて判断する。
異なる変更量とキャッシュ状態の実行を混ぜて、単一の最適化の効果とは扱わない。

6分程度の目標に届かなければ、最長ジョブの内訳から追加案を選ぶ。
キャッシュを候補にする場合は、同じ head の再実行だけで判断せず、前のコミットから大きく変更した次のコミットでの効果も測る。
復元と保存の時間、同時実行の待機、保守する設定の量を含めて比較する。
作るものを変える採否は、追加実装の前に本項目へ記す。

### 実測を踏まえた採否

[最終構成の実行](https://github.com/ambi/idmagic/actions/runs/39824893483)は Go 1.27.3 の更新コミット `2ce81208a` を対象に全9ジョブが成功し、起動から終了まで4分52秒だった。
最初のジョブ開始まで3秒、最長の CodeQL は4分48秒、Go テストのジョブは3分56秒、仕様とツールは1分47秒である。
各ジョブは並列なので、これらを足した時間を利用者の待ち時間とは扱わない。
変更前の約12分に対して今回の実測が6分の目標を下回ったため、ビルドと lint のジョブ間キャッシュを追加する案や、検査をさらに削る案は採用しない。
これは最終構成全体の評価であり、並列化、race の停止、処理の削減それぞれの寄与や、異なる変更量でのキャッシュ効率を単独に実証したものではない。

通常の Go テスト、DB 必須モード、契約証拠、静的検査、UI と E2E、スキーマ、CodeQL、脆弱性監査、四群の集約と証拠保存を維持した構成を受け入れる。
最初の実測で見つかった Go 標準ライブラリの脆弱性は Go 1.27.3 で解消し、監査を停止せずに全成功を確認した。
race の自動実行は本項目の完了条件に含めず、引き続き [wi-47187](wi-47187-restore-automated-go-race-testing.md) が担当する。

## 計画

1. wi-31758 の統合コミットを含む最初の CI と、変更前の実行の内訳を照合する。
2. 代表的な変更で全体時間と各群の時間を比較し、目標との差を確認する。
3. 不足があれば最長ジョブの追加案を比較し、採用案と検証対象を確定して実装する。
4. 最終構成の実測と検査内容の維持を確認し、結論をまとめる。

## 検証

- Actions の成功した全検査の実行で時間を測り、6分程度の目標への到達を判定する。
- CI の配線を変える場合は `mise run test-tools-file -- check/src/ci-workflow.test.ts`、`lint-repo`、`check-command-map` を使う。
- 文書と記録は `mise run check-work-items` と `mise run check-links` で確認する。
- 追加案の採否と故障から必要な局所検査を選び、実装前に追記する。

## リスク

- runner の性能、待機、依存の更新、変更量で時間が変動する。
  条件と入力を併記し、同じ head の再実行だけで効果を確定しない。
- 目標に達しても検査が抜けていれば改善として受け入れられない。
  wi-31758 が残した各検査と、結果および証拠の配線を照合する。

## 要約

規範仕様の変更はない。
wi-31758 で実装した CI 高速化を、Go 1.27.3 の更新コミット `2ce81208a` の Actions 実行39824893483で確認し、全9ジョブ成功、起動から終了まで4分52秒で6分程度の目標を満たした。
通常の Go テスト、DB 必須モード、契約証拠、UI と E2E、スキーマ、静的検査、CodeQL、脆弱性監査、結果集約と証拠保存を維持した。
現状の実測で目標に届いたため、ジョブ間のビルドと lint のキャッシュ追加や、追加の検査削減は採用しない。
一回の実測を継続的な時間保証や個別最適化の寄与の証明とは扱わず、race の自動実行は wi-47187 に残す。
