# 複数の入口を持つ約束を、すべての経路が守っているかを棚卸しする

## 動機

[wi-98584](../done/wi-98584-reduce-follow-up-refactor-and-bugfix-items-at-first-implementation.md) の観察で最も多く繰り返した原因は、同じ約束を複数の経路が別々に実装し、一部の経路だけが守る形だった（分類 A と L）。

| 項目 | 一部の経路だけが守っていた約束 |
| --- | --- |
| wi-27022 | 隔離した接続へは送らない。イベント同期とインクリメンタル同期だけが止め、ディスパッチャー、ジョブ、再同期、オンデマンドは送り続けた |
| wi-23517 | 同意を撤回したら使用量を減らす。管理者の経路だけが減らし、本人の経路は減らさなかった |
| wi-47878 | Group のエクスポートで `custom:` の列を許す。ワーカーにだけ方言が配線され、管理 API の開始が拒否した |
| wi-54863 | `refresh_token` のグラントを許可したクライアントにだけリフレッシュトークンを渡す。発行はスコープだけを見た |
| wi-85215 | Agent のアクセスを止めたら失効を外部へ伝える。強制終了、無効化、束縛の解除は伝え、削除だけが伝えなかった |
| wi-91126 | 登録できるグラントは公開契約の全種類である。HTTP の入力に四つの独自の許可リストが残っていた |
| wi-10848 | SAML の SP と WS-Fed の RP の不変条件を保つ。管理 API のハンドラーだけが検査し、Catalog の作成と更新は通らなかった |

設計ガイドラインと実装スキルには「既存の呼び出し元と比べる」規則があったが、wi-41012 から wi-85215 への再発を止められなかった。
文章の規則は、変更する人が自分の変更を条件に当たると判断しなければ働かない。
一方、[wi-77372](../done/wi-77372-inventory-standards-acceptance-rules.md) は一つの原因に絞って全入口を照合し、10 件の欠陥を一度に見つけた。
同じやり方で残る欠陥を見つけ、経路を足しても約束を外せない形に直す。

## 対象範囲

- 複数の入口から起きる作用について、約束、入口の経路、約束を担う箇所を表にする。
- 経路ごとに約束を守っているかを照合し、守らない経路を一件ずつ bugfix の作業項目として起票する。
- 約束ごとに、経路を足しても約束を外せない所有の形を、下の設計の候補から選び、起票する項目の設計へ書く。
- 上の表で既に直した約束にも同じ形が入っているかを確かめ、入っていなければ同じく起票する。

## 対象外

- 見つけた欠陥の修正と、所有の形への移行。起票した各項目が行う。
- 単一の経路しか持たない作用。
- 行ロックと確定の単位の検査。`check-sql-concurrency` と D7 が扱う。

## 設計

### 調べる約束

次の種類の作用から約束を抜き出す。
上の表の約束は既知の起点であり、ここに挙げた種類の全件を調べる。

| 種類 | 抜き出す元 | 例 |
| --- | --- | --- |
| 使用量の加算と減算 | Tenancy のクォータのリソース一覧と、加算と減算の呼び出し元 | User、同意、Application、エクスポート |
| 状態が止める処理 | 隔離、無効化、停止、削除予約などの状態と、その状態を読むべき処理 | プロビジョニング接続、Agent、User、クライアント |
| 失効と外部への通知 | 失効エポック、`AgentAccessRevoked`、`SessionEnded` などを出す操作 | Agent、セッション、トークン |
| 許可の判定 | 同じ許可を発行時と使用時、登録時と変更時に判定する箇所 | グラント、スコープ、エクスポートの列 |
| 所有者の不変条件 | 同じ保存型を作るか更新する全入口 | SAML の SP、WS-Fed の RP、Application |
| 障害の公開 | エラーを応答へ変換する全入口 | 管理 API、ポータル、プロトコルのエンドポイント |

### 照合の表

約束ごとに、約束を定める規範、入口の経路、経路ごとに約束を担う箇所、約束を観測するテストを対応付ける。
欠けたものの種類で扱いを分ける。

| 欠けたもの | 扱い |
| --- | --- |
| 経路が約束を守らない | 違反。bugfix を起票する |
| 守るが、約束を担う箇所が経路ごとに別にある | 再発の余地。所有の形へ移す項目を起票する。約束ごとに一件にまとめてよい |
| 守り、担う箇所も一つだが、テストが一部の経路しか観測しない | 証拠の不足。経路の表で観測するテストを足す項目を起票する |
| 規範が約束を定めていない | 規範の取りこぼし。仕様を足す項目を起票する |

経路の列挙は、作用を起こす下位の操作（使用量の加算、タスクの作成、エポックの前進など）の呼び出し元を、コードの参照から求める。
ハンドラーと画面から入口を数える方法は採らない。
ジョブ、反応器、バッチ、組み立ての経路を見落とすためである。

### 所有の形の候補

経路を足しても約束を外せないことを、文章の規則ではなく、コンパイラーか検査で止める。

| 候補 | 経路の追加を止める仕組み | 採否 |
| --- | --- | --- |
| A：約束を担う操作を所有者に一つだけ置き、作用を起こす下位の操作を所有者のパッケージの外から呼べなくする | Go の可視性。新しい経路は所有者の操作を通るしかない | 第一の候補にする。新しい検査が要らない |
| B：経路の閉じた集合を表で定義し、全経路で同じ作用を表駆動のテストで観測する | 表に載せた経路の欠陥はテストが落とすが、表に載せない経路は落とさない | A と組み合わせ、所有者の操作の作用を観測する場合に限る。単独では採らない |
| C：下位の操作の呼び出し元を許可リストと照合する検査を足す | `table-writes` と同じ形の静的検査 | A がモジュールの公開範囲で表せない場合に限る。照合の対象を約束ごとに宣言する費用がかかる |

wi-85215 の場合、A では失効エポックを進める操作を SharedSignals の非公開にし、`AgentAccessRevoked` を出す公開操作だけを残す。
削除の経路を足す人は、その公開操作を呼ばなければエポックを進められない。

### 棚卸しの結果

照合の表は、起票の前にこの節へ残す。

## 計画

1. 失効と外部への通知から始め、照合の表と所有の形の候補が実際の判断に使えるかを確かめる。使いにくければ表の列と候補を直す。
2. 残りの種類を調べる。
3. 違反、再発の余地、証拠の不足、規範の取りこぼしを作業項目として起票する。

## リスク

経路の列挙が漏れると、同じ種類の欠陥が残る。
下位の操作の呼び出し元をコードの参照から求め、ジョブ、反応器、バッチ、組み立ての経路を含める。

候補 A は公開範囲を狭めるため、テストの組み立てが下位の操作を直接呼んでいる箇所を壊す。
起票する項目では、テストの準備も所有者の公開操作を通す形へ直す範囲を見積もる。
