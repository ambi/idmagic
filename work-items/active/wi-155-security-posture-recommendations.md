# テナントの設定を検査し、弱い設定を改善の推奨として管理者に示す

## 動機

IdMagic には MFA、署名鍵、API アクセストークン、サインインポリシー、監査などの個別の設定があるが、どの設定が弱く、何から直すべきかを一覧する画面はない。
Okta HealthInsight のような推奨がないと、機能があっても有効化の漏れや古い設定が残りやすい。

## 対象範囲

- テナントの設定を検査する規則の集まりを持つ。初めの対象は、MFA を求めないアプリ、期限の長いクライアントシークレットと API アクセストークン、ローテーションしていない署名鍵、弱いパスワードポリシーとする。
- 検査の結果を推奨として管理コンソールに示す。管理者は推奨を却下でき、設定を直すと推奨は自動で解決する。
- 却下と解決をドメインイベントとして記録する。

## 対象外

- 自動の修復。
- 外部のコンプライアンスの基準での採点と認定。
- SIEM とチケットシステムとの連携。

## 設計

検査の規則は各モジュールが自分の設定について持ち、推奨の一覧はそれを集めるだけにする。
推奨の側が各モジュールの保存表現を読むと、設定の形を変えるたびに推奨が壊れるので、各モジュールの公開する読み出しを使う。
集める側をどのモジュールに置くかは、着手時に[境界を選ぶ判断手順](../../docs/design/application/design-guidelines.md#境界を選ぶ判断手順)で決める。

## 検証

- 規則ごとに、弱い設定で推奨が出て、直した設定で解決することを固定するテスト。
- `mise run verify`

## リスク

推奨が多すぎると管理者は一覧を読まなくなる。
初めの規則は、誤検知の少ないものに絞る。
