# 完了済みの仕様影響の検査範囲を完了時点で閉じる

## 動機

wi-88544 の検証で、check を9019eae4aから実行すると、wi-55044 の特性化テストの構築引数の変更が、それより前に完了した wi-91505、wi-18088、wi-55774、wi-67577 の違反として報告された。
個々の変更は、それぞれの着手時の main との差分で検証している。
完了記録の宣言を全文から読む際に、状態まで全文の in_progress として扱い、作業範囲の終端も現在の作業ツリーへ伸ばしている。
後の別作業を完了済みの記録に帰属させるため、複数の作業を含む範囲の検査が正しい宣言を拒否する。

## 対象範囲

- 要約済みの記録の現在の状態と、全文から復元する仕様影響の宣言を分けて読む。
- 完了した記録の範囲を、その記録が完了したコミットで閉じる。
- 仕様差分、テストの引用と特性化テストを、同じ範囲と同じ終端の内容から読む。
- 完了前の違反は引き続き拒否し、後の別作業の変更を帰属させないことを受け入れテストで検証する。

## 対象外

- none の宣言で特性化テストや規範仕様を書き換えることの許可。
- 製品の変更と、個々の作業項目の宣言の書き換え。

## 設計

範囲は、状態が初めて着手後になったコミットの親から、完了したコミットまでとする。
着手中と未コミットの完了は現在の作業ツリーまでを扱う。
完了した記録の宣言は従来どおり全文から復元し、状態は現在の要約から取る。
完了済みの全項目を無条件で省く案は、今回の検査範囲で行った違反も隠すため採用しない。
後の項目の宣言を完了済みの none に重ねる案も、違反の所属を曖昧にするため採用しない。
Git の二点間の差分と終端のファイルを読む案を採用する。

## 計画

完了済みの none の後で、別の宣言を持つ項目が特性化テストを変える履歴を再現し、現行の拒否を先に観測する。
完了前に none の範囲で変更した特性化テストは、その後に別作業があっても拒否する例を追加する。
関連する文書へ範囲の終端を記し、tools の局所テストと集約検査で確認する。
