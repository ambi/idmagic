# DB を起動できないとき、DB を使うテストを Skip ではなく失敗にする

## 動機

DB を使うテストの基盤（`backend/shared/storage/testing_postgres/pgtest.go`）の `Require` は、embedded-postgres を起動できない環境（サンドボックスの中など）では DB を使うテストを Skip にする。
`go test` はパッケージを成功として返すので、DB テストを一度も実行していないのに、終了コードは成功になる。
DB を使うテストを持つファイルは 145 ある。

これを失敗に変えるのは、今は CI だけである。
検証の実行器は `VERIFICATION_REQUIRE_DB=1` のときだけ DB の未検証を失敗にし、手元では Skip を「未検証」として報告に記録するにとどめる（wi-85094）。
報告を読まなければ未検証に気付けず、終了コードだけを見る呼び出し（エディターのテスト実行、`go test` の直接の実行、局所検査）では成功に見える。

Go の結果のキャッシュとも食い違う。
サンドボックスの中で Skip した結果がキャッシュされると、DB を使える環境で実行し直しても、入力が変わるまで同じ Skip が返り続ける。
wi-10346（作業中の局所検査で結果のキャッシュを再利用する）は、この食い違いを前提に入れなければならない。

DB を使うテストは、AGENTS.md の規則どおり、もともとサンドボックスの外で実行する。
既定を失敗にして困るのは、サンドボックスの中で実行してしまった場合だけで、それは気付くべき誤りである。

## 対象範囲

- `pgtest` は、DB を起動できないとき、既定で DB を使うテストを失敗にする。
- 明示して許したとき（環境変数）だけ、今までどおり Skip にする。許した実行の Skip は、検証の実行器が報告に「未検証」として記録する。
- CI の `VERIFICATION_REQUIRE_DB=1` と実行器の検査は、基盤の既定と役割が重ならないよう整理する。
- `testing.md` と AGENTS.md の該当箇所に、DB を使うテストの既定と、Skip を許す方法を書く。

## 対象外

- embedded-postgres の起動そのものの改善（wi-76822）。
- DB を使わないテストの扱い。

## 設計

### 候補

- **A. 基盤（`pgtest`）で失敗にする**：`go test` の終了コードが正しくなり、実行器を通らない呼び出しでも気付ける。Skip を許す環境変数は Go の結果のキャッシュの鍵に入るので、許して Skip した結果が、許していない実行に再利用されない。
- **B. 実行器で既定を「DB 必須」に変える**：実行器を通る実行だけが正しくなり、終了コードを見るほかの呼び出しは成功に見えたままになる。キャッシュとの食い違いも残る。

A を採る。

### 決めること

- Skip を許す環境変数の名前と、実行器の報告への記録の仕方。
- `TestMain` で起動に失敗したとき、パッケージ全体を失敗にするか、DB を使うテストだけを失敗にするか。DB を使わないテストの結果も同じパッケージに残すため、後者を基本に比べる。
- CI の `VERIFICATION_REQUIRE_DB=1` を残すか。基盤の既定が失敗になれば、Skip は起こらないので、実行器の検査は二重の守りとして残すか外すかを決める。

## 計画

1. 起動に失敗する環境（サンドボックスの中）で、今は成功を返すことを RED として確かめる。
2. `pgtest` の既定を変え、Skip を許す環境変数を足す。
3. 実行器と CI の役割を整理し、文書を更新する。
