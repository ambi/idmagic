# oauth2 の、相手が省略できる要素の受け入れを宣言と試験に加える

## 動機

[[wi-77372-inventory-standards-acceptance-rules]] の棚卸しで、oauth2 の実装が受け入れているのに、宣言の行も、省いた形を送る試験もない要素が見つかった。
受け入れの行と試験がなければ、後の変更がこれらを必須にしても検出できない。

## 対象範囲

| 要素 | 現在の受け入れ | 足すもの |
| --- | --- | --- |
| `private_key_jwt` の `client_id` の省略（RFC 7521 §4.2） | 共通のクライアント認証が全入口で受け入れる | PAR、イントロスペクション、失効、デバイス認可、CIBA の入口で、省いた要求を送る試験 |
| デバイス認可の `scope` の省略（RFC 8628 §3.1、RFC 6749 §3.3） | `openid` を既定にし、`openid` を持たないクライアントは `invalid_scope` | 既定の範囲と失敗の受け入れの行と試験 |
| `client_credentials` の `scope` の省略（RFC 6749 §4.4.2） | クライアントの登録の範囲を既定にする | 受け入れの行と試験 |
| 失効の `token_type_hint`（RFC 7009 §2.1） | ヒントを読まずにすべての種類を探す | 受け入れの行と、ヒントを外した要求の試験 |
| DPoP の `htu`（RFC 9449 §4.3） | 正規化せずに完全一致で比べる。SHOULD の正規化をしない | 制限を `partial` の行として宣言する |
| 検査の項目だけを並べた行（`RFC7523-CLIENT-ASSERTION`、`RFC9449-PROOF` など） | — | 相手が省略または追加できる要素があれば、受け入れの行へ分ける |

## 対象外

- 実装が拒否する要素。棚卸しが起票した bugfix の各項目が扱う。

## タスク

- [ ] T001 [Spec] `standards.md` に受け入れの行を加える。
- [ ] T002 [Test] 省いた要求を各入口へ送る試験を加え、行を参照する。
- [ ] T003 [Verify] `mise run check-spec` と変更した試験を通す。

## 検証

- `mise run check-spec`：加えた行の形式と参照を確かめるため。
- 加えた HTTP の試験：省いた形を製品の入口が受け入れることを観測するため。

## リスク

試験で受け入れられないと分かった要素は、この項目で直さず bugfix として起票する。
