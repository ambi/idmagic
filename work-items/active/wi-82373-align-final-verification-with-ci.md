# 最終検証で CI との範囲と入力のずれを検出する

## 動機

CI 実行 41310812714 は、用語検査と E2E の8件で失敗した。
同じコミットの手元の全 E2E でも、ページ情報の同期漏れ、削除確認の未操作、古いナビゲーション名の3件が再現した。
残る5件は、macOS 固有の保存先による3件と、画面データの取得完了を待たない2件だった。
今回の故障は wi-30844 で修復し、全 E2E 54件の成功を確認した。

`verify-changed` と `verify` は E2E を含まず、最終検査では対象の E2E を別途選ぶ規則になっている。
CI は別の計画器でブラウザー群を選ぶため、手元の標準コマンドの成功は CI と同じ範囲の成功を意味しない。
また、差分検証レポートは変更パスと結果を保存するが、その結果を現在のファイル内容に結び付ける fingerprint を持たない。
Go の検証には fingerprint と古い結果の診断が既にあり、同じ扱いを最終検証へ広げられる。
元の改修でどの手元検査をいつ実行したかは、今回取得した情報からは確定できない。

## 対象範囲

- 最終検証の一つの入口で、仕様とリポジトリ検査、および変更に応じた製品検査を選ぶ。
- ブラウザー群の選択を CI の計画と共有し、UI とバックエンドの変更で E2E の選択を忘れないようにする。
- 実行前後の入力を特定し、検証中の編集と検証後の追加変更を、現在のツリーの成功と区別する。
- 選択した群、成功、失敗、対象外、未実行を同じレポートへ残す。
- E2E の待機をデータの取得完了に結び付け、遅延応答で今回の待機不足を検出できる検証方法を選ぶ。

## 対象外

- 局所的な RED/GREEN のたびの全 E2E 実行と、CI の無効化。
- タイムアウトの一律延長と、失敗を成功へ変える自動再試行。
- GitHub の設定変更。2026-11-01 の `branches/main` は `protected: false`、必須チェックは未設定だった。PR の CI 成功を取り込み条件にする設定は、リポジトリ管理の変更として別途扱う。
- Linux の常設検証環境の新設。macOS 固有のパスは今回除去したが、OS を揃える費用と追加の検出能力を比較して採否を決める。

## 設計

検査範囲は CI の選択規則を共有し、Go のパッケージ絞り込みは既存の差分検証を使う案を第一候補とする。
CI の計画を別の条件表へ複製する案は、二つの規則が再びずれるため採らない。
最終検証だけで E2E を自動選択し、局所テストの速度は保つ。
現在の `verify-changed` を変更する案と、最終検証専用の入口を追加する案を、呼び出し元と既存テストへの影響から比較する。
証拠は `.verification/` の既存形式と `tools/verification/src/input.ts` の入力特定を調べて再利用し、別の証拠台帳を増やさない。
レポートの必須性と、最終差分を検査するタイミングは実装前に決める。

## 計画

CI の選択器、差分検証器、既存の入力特定、最終検査を呼ぶスキルの境界を調べ、最小の入口変更を選ぶ。
仕様やドキュメントに「実行すること」を追加するだけでは選択漏れが残るため、選択と失敗判定のコードを変える。

## 検証

- 選択器の単体テストで、frontend、局所 backend、共有入口、文書のみ、不明な入力を区別する。
- CLI の統合テストで、選択された E2E の未実行、失敗、検証中の編集、成功後の入力変更を拒否する。
- Go の既存の入力特定と、変更後の最終検証を局所テストと実際の差分で確かめる。

## リスク

E2E は今回の手元の全件で約2分、元の CI では約5分を要した。
局所テストと最終検証を同じ重さにせず、完了直前の検証だけに必要な費用を置く。
