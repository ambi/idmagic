# 完了済み記録の証拠を当時のリビジョンで解決し、現在の仕様への追従を不要にする

## 動機

[作業項目の形式](../../docs/formats/work-item-format.md#着手時の文脈と設計)は、完了済みの affected_spec も現在まで解決するよう要求する。
2026-10-10 の調査では完了または中止済みの記録が 585 件あり、仕様の移動対応表は 61 項目あった。
過去の仕様やテストの移動と削除で、現在の開発が履歴参照の維持に妨げられる。
現在は未リリースであり、当面も未リリースを継続するため、公開後の履歴整備より日常の追従費用の削減を優先する。

## 対象範囲

- 完了済みと中止済みの記録を、当時の仕様、テスト、検証経路へ対応付ける参照方針。
- 未完了項目と現在状態の文書に対する、現在の参照の厳密な検査の維持。
- 通常検査と履歴の照会の分離、移動対応表と旧形式の解決処理の縮小。
- 完了時に記録した証拠と、現在も有効な保証の区別。

## 対象外

- 過去の作業記録や証拠の削除、過去の検証成功を現在の成功へ読み替えること。
- ファイルの完了時の移動は[配置の改善](../done/wi-35829-keep-active-and-completed-work-items-at-the-same-depth.md)が扱う。
- 履歴比較に必要な旧形式の読取処理を、用途の確認なしにすべて削除すること。

## 設計

未完了項目は現在の対象を解決し、履歴は記録が成立した Git revision に対して解決する。
完了した記録を含むコミットから revision を導く案と、作業範囲の証拠へ明示する案を比べる。
自己のコミット ID を事前に書くことや、後のコミットで全記録を更新し続けることは要求しない。

着手時に、未コミットの完了記録、履歴を取得できない環境、古い記録の解決方法を決める。
履歴が不足する場合は未解決として示し、現在の仕様で代用して検証済みにしない。
現在の依存関係の検査と履歴の詳細解決は分離する。
全履歴へのリダイレクト台帳を維持する案は、仕様の移動費用を残すため採らない。

## 計画

1. 現在の参照を要求する検査と、履歴探索の利用箇所を棚卸しする。
2. 当時の revision の解決方法と通常検査の範囲を決める。
3. 解決と表示を更新し、不要になる互換処理を用途ごとに取り除く。

## 検証

- 未完了項目の現在の参照切れは拒否される。
- 現在の仕様やテストの削除だけで、過去に成立した記録が通常検査を妨げない。
- 履歴不足と、当時も解決しなかった証拠を成功へ丸めない。
- 同じ記録を現行と履歴の照会で開き、対象 revision と限界を区別できる。
- mise run test-tools-file、mise run check-work-items、mise run check-links、mise run verify を実行する。

## リスク

履歴の取得が通常検査に増えると、解決の費用を別の形で増やす。
通常の変更では必要な記録だけを読み、全履歴の詳細解決を必須にしない。
