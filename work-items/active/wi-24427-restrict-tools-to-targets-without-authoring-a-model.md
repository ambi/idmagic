# 対象ごとの権限を、モデルの作成なしに操作の割当から設定する

## 動機

デモの「文書ごとの権限」は、通常の管理より多くの概念を要求する。
認可モデルのテンプレートを発行し、「従来の評価規則」に型 `document` と関係 `viewer` を自由入力し、アクセス権の画面で `viewer (document)` と対象 ID を選ぶ。
管理者が決めたいのは「社内文書アシスタントは、就業規則だけを閲覧できる」という一文であり、型と関係の名前は決めたい内容ではない。

REQ-OAUTH2-083 は、対象別の型と関係を持つツールに、操作割当と従来の対象別関係の双方を要求する。
このため、ツール登録の「対象ごとの権限も確認する」を選んでも、モデルと関係の準備が別の作業として残る。
PingGateway は接続先の粗い制御と、追加製品による細かい制御を分けて説明しており（[MCP ゲートウェイの範囲](https://docs.pingidentity.com/pinggateway/2026/mcp/index.html)）、IdMagic が一つの製品の中で同じ制御を少ない概念で示せれば、比較上の利点になる。

## 対象範囲

- ツール登録で「対象ごとの権限」と対象 ID を読む引数を選べば、追加のモデル作成なしに対象を限定した割当を作れるようにする。
- Agent の「利用する接続先」で、操作ごとに「すべての対象」か「指定した対象だけ」を選べるようにする。
- 接続先の対象の画面からも、同じ割当を「この対象を使える Agent と操作」として追加、取消できるようにする。
- 付与の表示は操作の表示名を使い、型と関係の名前を日常の画面に出さない。
- 既存のモデルと関係による対象別の制御は、開発者向けの詳細設定として保つ。
- デモの「文書ごとの権限」を、通常の管理の続きとして一手順で追加できる形にする。

## 対象外

- 外部システムの対象一覧の取得と表示名の検索。対象 ID の入力は残し、既存付与の対象を候補に出す。
- グループ経由の付与、継承、計算された関係を日常の画面で編集すること。
- 既存の従来規則の自動移行。

## 設計

### 対象の制限をどこに持つか

| 案 | 利点 | 制約 |
| --- | --- | --- |
| 操作割当に対象の範囲（すべて、または対象 ID の集合）を持たせる | モデル、型、関係の概念が日常の管理から消える。割当と対象の制限を一か所で取り消せる | グループや継承は表現しない。それが必要なら従来の関係を使う |
| ツール登録時に、接続先専用の型と関係を IdMagic が自動で発行する | 既存の ReBAC の判定と監査をそのまま使える | テナントのモデルへ利用者の知らない型が増え、開発者のモデルの発行と競合する（[wi-26074](wi-26074-reject-stale-authorization-model-publication.md)）。名前の衝突と削除の扱いが要る |
| 現行のまま、テンプレートと説明を改善する | 変更が小さい | 型と関係の概念と、三画面の対応を記憶する負担が残る |

一案目を推薦する。
対象の範囲は割当の属性であり、新しい関係の種類ではないと扱う。
REQ-OAUTH2-083 の「従来の対象別関係」は、ツールが従来の型と関係を宣言した場合に限って要求し、割当に対象の範囲がある場合はその範囲を判定に使う。
割当の所有者、テーブル、評価の呼び出し経路が変わるため、着手時に[境界を選ぶ判断手順](../../docs/design/application/design-guidelines.md#境界を選ぶ判断手順)の比較を記録する。

### 判定と取消

対象 ID は REQ-MCPGATEWAY-010 の `resource_id_argument` で解決した値と完全一致で比べる。
解決できない場合は現行と同じく `operation_not_registered` で拒否する。
対象の範囲の変更と取消は、既発行トークンの次の評価へ反映する。
範囲を「すべての対象」から「指定した対象だけ」へ狭める変更を、保存前の差分で明示する。

## 検証

主要ユースケースは、管理画面で対象を指定した割当から、Gateway 経由の閲覧の許可と未指定対象の拒否までを観測する E2E とする。
範囲の追加、縮小、取消、ツールの削除と再登録（REQ-OAUTH2-085）、従来の関係との併用を含める。
判定は変異テストの対象とし、範囲の比較を外す変異を検出できることを確認する。

## リスク

「すべての対象」を既定にすると、対象の制限を意図した管理者が付け忘れたときに権限が広がる。
「対象ごとの権限」を選んだツールでは範囲の選択を必須にし、既定値で広げない。
従来の関係と範囲の両方があるときの優先を誤ると、意図しない許可が生じる。
双方を満たす論理積を既定とし、例外を作らない。
