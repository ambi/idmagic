# OIDC カタログ管理の重複する契約と変換を除去する

## 動機

[wi-60634](../done/wi-60634-administer-oidc-applications-through-application-ports.md) は Application から OAuth2 の保存知識を除いたが、9操作の要求契約、同じ内容の入力と結果、178行の変換層を追加した。
作成、更新とシークレットの操作の多くは、既存の公開管理操作への項目ごとの委譲である。
Catalog の分離後は OAuth2 への依存を自然に持てるため、この間接化の必要性を再検討する。

## 対象範囲

Catalog の OIDC の作成、設定とクレームの更新、関連付け、削除、シークレットの発行、ローテーションと失効、設定表示。
Catalog の要求型と `backend/shared/http/server_http/applicationdeps/oidc_clients.go` の管理用の変換を対象にする。

## 対象外

Application が使う小さな `ClientNames` の読み取り契約。
OAuth2 のプロトコル、クライアントの不変条件、HTTP 契約と原子性の変更。

## 設計

D1、D2、D3、D4、D6、D7、D8 に従い、[カタログ](../../docs/modules/application/features/catalog.md)と OAuth2 の公開管理操作を照合する。
第一候補は Catalog が OAuth2 の `ClientAdministration` とその入力、結果、エラーを直接利用し、ワイヤ変換を HTTP の近くへ集める案とする。
所有者の検証と更新を Catalog へ戻す案は採らない。
表示はシークレットのハッシュを公開しない専用の射影を維持し、その担当が Catalog か OAuth2 かを実際の利用箇所と変更シナリオで比べる。
同じ値を往復させるだけの型、エラーと変換は除去し、フィールド追加の際に同期する宣言と実装を実例で比較する。
作成と関連付け、通常設定とクレームの別確定、イベントと削除の順序を保つ。

### 着手時に確定した分担

比較基準は `b0a97fc48` とする。
Catalog の管理依存には既存の `clientports.ClientAdministration` を直接渡し、表示の読み取りには既存の `clientports.OAuth2ClientRepository` を渡す。
HTTP の入力を一度だけ所有者の公開入力へ組み立て、Catalog 独自の9操作の契約、14個の管理と表示の型、二つのエラーと管理用の変換アダプターを除去する。
`Create` の結果からは `result.Client.ClientID` と一度だけ返す `ClientSecret` だけを読み、`Update` の戻り値を表示へ使わない。
クォータ、登録と設定の検証、関連付け、クレームとシークレットの更新、失効は同じ OAuth2 の公開操作が担当し続ける。

表示の変換は Catalog の非公開の HTTP ファイルへ集める。
`(Deps).oidcConfiguration(ctx, tenantID, clientID, now) (*oidcConfig, error)` は現在の検索と資格情報の読み取りを行い、`configuration(client, credentials, now) *oidcConfig` と `secretMetadata(credentials, now) []clientSecretMetadata` が表示する項目だけを写す。
この二つの非公開の表示型は既存の JSON 名、空の配列と省略条件を保ち、クライアントの保存型と資格情報をそのまま JSON へ渡さない。
シークレットのハッシュは所有者の結果には含まれるため、発行、ローテーションと失効の応答でも明示的に同じ表示型へ写す。
資格情報の状態は引き続き所有者の `StatusAt` を使い、発行と失効はコマンドへ渡した時刻、ローテーションは完了直後の時刻を使う。
保存先の未配線と未取得では設定の表示を省略し、資格情報の一覧だけの失敗は設定の表示を失敗させない。

現状維持案は、項目追加時に所有者の型、Catalog の要求型と変換を同期する負担が残るため採らない。
所有者の公開管理操作を直接使う案では、HTTP の対応項目と所有者の入力だけを変更すればよい。
表示の変換を OAuth2 の新しい公開操作にする案は、Catalog の JSON と一度だけ使う表示知識を所有者の公開契約へ広げるため採らない。
保存先を直接更新する案は、所有者の検証、クォータとイベントを迂回するため採らない。
Catalog は OAuth2 を一方向に利用し、OAuth2 から Catalog への依存は追加しない。

管理用の Catalog の公開パッケージを除去し、責務表と依存図を同期する。
Application の `ClientNames` と組み立て地点の名前照会は独立した小さな契約として残す。
所有者の実装、SQL とトランザクションは変えず、クライアントの作成、Application の作成と関連付け、関連付けの同期を同じ順で行う。
削除では `DeleteForApplication` を使い、管理画面向けの別の削除操作へ置換しない。
公開済み API とデータの移行はなく、ロールバックはコードの変更を戻すだけでよい。

### 証拠の選択

既存の HTTP の入力、期待値と特性化テストの本文は変えない。
削除する管理アダプターのテストは、同じ値と拒否を直接の所有操作と Catalog の表示で確認する形へ移し、表示のファズ対象も新しい担当へ移す。
名前照会のテストは組み立て地点へ残す。
秘密情報の非公開と、公開鍵の設定項目が所有者へ届く経路を既存の HTTP の fixture で追加検査する。
テストのパスと呼び出しが変わるため、構造変更の免除は使わない。
JSON への資格情報の漏出を故障として実装前の RED を確認し、実装後に同じ HTTP と単体の検査を GREEN にする。
型変換による項目の脱落、クォータの未配線、失効操作の省略、所有者のエラーの対応を独立した故障として選ぶ。
変更した表示と HTTP の変更行には `test-go-mutation` を worker 2、cache off、比較基準 `b0a97fc48` で実行し、ツールで表せないフィールドの脱落と配線の故障だけを手で注入する。
表示のファズ対象は既存の入力と判定基準を維持し、時間を制限して探索する。
最終検査は `test-go-changed -- b0a97fc48`、`lint-go`、`check b0a97fc48`、`render-docs`、`check-published-api-compat` と `spec-diff b0a97fc48` を選ぶ。
HTTP の待受けが必要な Go テストはサンドボックス外で実行する。

## 計画

分離後の Catalog の入口、OAuth2 の管理操作と表示の利用箇所を読み、直接利用案と必要最小限の射影案を比較してから実装する。

## 検証

Catalog の既存 HTTP テストと OAuth2 の管理操作のテストを起点とし、`test-go-changed`、`lint-go`、`check`、`spec-diff` を使う。
型変換の除去による値の脱落、クォータと失効の省略、シークレットの再表示を独立した故障として検査する。
着手時に実際の差分に応じた RED と変更耐性の手順を確定する。

## リスク

委譲を除去する際に所有者の検証を飛ばしたり、表示用の結果へハッシュを混ぜたりすること。
削減する行数だけで採否を決めず、変更の局所性と公開する内部知識を比較する。

## 要約

ApplicationCatalog が OAuth2 の既存の公開管理操作を直接利用するようにし、9操作を複製した要求契約、管理と表示の公開型14個、二つのエラーと変換アダプターを除去した。
必要な二つの表示型は HTTP の近くへ非公開で残し、資格情報の識別子、時刻と状態だけを明示的に写す。
本番の Go コードは差し引き176行減り、管理項目を追加するときに同期する型と変換が減った。
Application の独立した名前照会は対象外として維持した。

登録と設定の検証、クォータ、関連付け、クレームとシークレットの管理は同じ OAuth2 の操作が担当する。
HTTP の入力と応答、シークレットの非公開、拒否後の状態、イベントと部分確定の順序は維持した。
所有者の実装、SQL とトランザクションは変えていない。
管理の直接利用は ApplicationCatalog から OAuth2 への一方向の依存であり、循環負債は17件のままである。
責務表と依存図を現在の構造へ同期し、七つの視点で担当、公開範囲、変更の局所性と結線をレビューした。

Catalog の119テスト、名前照会の1テスト、所有者の管理操作の26テストと、変更箇所と逆依存の race 付き1,767テストが成功した。
失敗、スキップと未実行はいずれも0件だった。
変更行へのミューテーション15件はすべて検出し、表示のファズ検証は10秒間に244,807回成功した。
既存の HTTP の入力と期待値、特性化テストの本文は維持した。

`lint-go`、`check b0a97fc48`、文書生成と公開 API の互換性ゲートが成功し、`spec-diff b0a97fc48` は規範の変更なしだった。
公開前なので互換性ゲートは公開済み契約との比較を行っていない。
既存の HTTP の静的解析には未解析の操作が残るため、全操作を静的に検証済みとは扱わない。
今回の対象に未実施事項はなく、Tenancy の属性定義と相互変換の再検討は別項目 wi-94860 に残す。
