# 実在の MCP クライアントで再現できる執行の手順を公開する

## 動機

IdMagic は実在の MCP クライアントや外部製品との接続を確認していない。
競合は多数の連携例を公開しており、機能があっても第三者が再現できなければ比較の対象にならない。

## 対象範囲

- 実在の MCP クライアントと MCP サーバー、MCP ゲートウェイ、IdMagic を結ぶ手順。
- 委譲、許可、条件の拒否、承認、撤回、停止を順に確かめる再現試験。
- 確認したクライアントの版と、未確認の範囲の明示。
- 権限不足の 403 で実クライアントが権限昇格を試みるかの確認。`insufficient_scope` の応答が必要なら別の項目を起票する。

## 対象外

- クラウド製品ごとの連携例。
- 競合との実機比較の公開。

## 設計

手順は公開契約だけを使い、再現試験は `mise` のタスクで実行できるようにする。
クライアントは 2026-07-28 版の認可を実装し、CI で動かせるものを T001 で選ぶ。

## 計画

1. クライアントを選ぶ。
2. 手順と再現試験を作り、IdMagic を知らない読み手の前提で確かめる。

## タスク

- [ ] T001 [Design] 対象のクライアントとサーバーを選ぶ。
- [ ] T002 [Docs] 手順を書く。
- [ ] T003 [Verify] 再現試験を `mise` のタスクにし、撤回と停止の後の拒否を確かめる。
- [ ] T004 [Verify] 権限不足の応答に対する実クライアントの動作を確かめ、`insufficient_scope` の要否を判断する。

## 検証

- 追加する再現試験のタスクと `mise run check-links`。

## リスク

外部のクライアントの更新で手順が壊れる。
確認した版を固定し、更新の確認を依存更新の作業へ含める。
