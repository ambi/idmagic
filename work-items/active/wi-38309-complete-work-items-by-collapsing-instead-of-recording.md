# 作業項目の完了を、完了記録を書かずに要約へ縮めて移す手順にする

## 動機

[完了記録の縮約](../done/wi-29555-collapse-completed-work-item-records-into-summaries.md)の後は、完了節のうち要約しか残らない。
それでも完了の手順は、受け入れ RED、単体 RED、変更耐性、検証結果を完了節へ書かせ、`check-work-items` がその形を検査する。
2026-10-14〜15 に完了した 6 件（wi-56300、wi-96130、wi-29555、wi-98121、wi-15309、wi-73108）では、完了節が記録の 37〜47%（2.4〜3.5 KB）を占めた。そのすべてが、次の完了で縮められて作業ツリーから消えた。
完了節の「検証結果」を `verify` の後に書き換えるため、記録だけを直すコミットの修正と再検査も生じた。

同じ調査で、完了節のほかにも、書くことは求められるが判断に使われない記入が見つかった。

| 記入 | 現状 | 判断に使われない理由 |
| --- | --- | --- |
| 完了節の証拠（受け入れ RED、単体 RED、変更耐性、検証結果） | 完了時に必須。形を検査する | 自己申告であり検査は実行を確かめられない。縮約で作業ツリーから消える |
| `evidence_policy: risk-based-v4` | 着手時に必須 | 取りうる値が一つしかない |
| `documentation_impact` | 着手時に必須 | 未公開の間は `level: none` と理由を書くだけで、公開状態から決まる |
| `initial_context` | 着手時に必須。参照を解決する | `brief` が同じ一覧を出す。縮約で消え、後から読まれない |
| `move-work-item` と縮約の 2 段階 | 完了の変更は全文を残し、次の完了で縮める | 全文は着手中のコミットにも残っている |

## 対象範囲

- 完了の手順を「`## 要約` を書き、`status` を `completed` にして `mise run move-work-item` を実行する」に改める。
  `move-work-item` は、全文の検査を通した後に、その場で要約へ縮めて `work-items/done/` へ移す。
  `archived_from` は、作業ツリーの記録の全文を最後に含むコミットを指す。
- 完了節の証拠の記入と、その形の検査をなくす。
- `evidence_policy` を廃止する。
- `documentation_impact` は、公開状態が `published` のときだけ求める。
- `initial_context` の記入と解決の検査を廃止する。`brief` の出力は残す。
- 上の変更に合わせて、作業項目の形式、仕様先行のワークフロー、`implement-work-item` と `new-work-item` と `integrate-work-item` のスキルから、該当する記述を削る。
- 置き換えられる進行中の項目を中止として記録する。[wi-82135](wi-82135-record-final-verification-evidence-once.md) は対象がなくなる。

## 対象外

- RED を先に観測する手順そのもの。手順として残し、記録しないだけにする。
- `primary_use_cases` の計画と、宣言したテストが存在し要件を引くことの自動検査。自己申告ではなく実ファイルを確かめるので残し、`move-work-item` の全文の検査で行う。
- 公開後のリリース文書の要求。
- 証拠や反例の記録を増やす進行中の項目（wi-458 など）の扱い。この項目の完了後に、残す価値があるかを別に判断する。

## 設計

記録と検査の役割を分ける。
実行で確かめられる事実（テストの存在、要件の参照、仕様差分と宣言の整合）は検査が確かめる。
自己申告にとどまる事実（RED を観測したこと、検証を実行したこと）は記録させない。
検査で確かめられないうえ、縮約で消えるので、読み手にも検査にも使われないためである。

完了の変更は、要約に縮めた記録だけを含む。
全文は着手中のコミットにあり、`archived_from` から読める。
着手から完了までを一つの変更で行い、全文がまだコミットされていない記録は、`move-work-item` が起票時のコミットを `archived_from` にする。
起票時のコミットもない記録は縮めずに拒否し、先に起票をコミットするよう示す。

採らない案:

- 完了節の証拠をコミットメッセージへ移す案。書く量は同じで、検査もできない。
- 完了節を残し、縮約だけを即時にする案。書いてすぐ消す記入が残る。
- `evidence_policy` を将来の版のために残す案。版を変えるときに足せばよい。

## 計画

1. 現在の完了の検査（完了節の形、`documentation_impact`、`primary_use_cases`、`initial_context`）を棚卸しし、残すものと消すものを確定する。
2. `move-work-item` を、全文の検査、要約への縮約、移動の順に一度で行うよう変える。
3. スキーマと検査から、消す記入の要求を取り除く。
4. 形式とワークフローとスキルの記述を削る。開発文書の合計は純減させる。
5. wi-82135 を中止として記録する。

## 検証

- `mise run test-tools` で、`move-work-item` の検査と縮約、スキーマの変更を確かめる。
- `mise run check` と `mise run verify` を通す。
- 見本の項目で、完了の変更に要約だけの記録が入り、`archived_from` から全文を読めることを確かめる。

## リスク

RED を記録しなくなると、RED を観測せずに完了する作業を記録から見つけられない。
もともと記録は自己申告で、観測の有無を検査できなかった。
`primary_use_cases` が名指すテストの存在と要件の参照は、引き続き検査で確かめる。
