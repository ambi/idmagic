# 直前安定版と新成果物を同時稼働させてリリース互換性を検証する

## Motivation

単一版の E2E が成功しても、ローリング更新中に旧版と新版が同じ PostgreSQL、セッション、署名鍵、ジョブを扱えるとは限らない。現在のリリース手順は先行配備と rollback を定めるが、リリース前に二つの版を同じ入口へ接続してログイン、トークン更新、ジョブ引継ぎを確認する検査を持たない。

本項目は高可用性トポロジや failover を構築するものではない。`wi-165` が所有する配備トポロジと無停止 drill に対し、版間契約だけを検査する再利用可能な受け入れ境界を提供する。

## Scope

- 直前安定版の不変なリリース成果物と現在コミットの成果物を同じ PostgreSQL と外部入口へ接続する混在版ハーネスを作る。
- 検査する主要経路を、ログインと認可コード交換、旧版発行の refresh token を新版で更新、新版発行を旧版で更新、セッション継続、ジョブ lease の引継ぎ、起動と準備状態に限定する。
- 入口から旧版と新版の両方へ到達したことを、版スタンプ、ログ、メトリクスなど利用者の応答を変えない観測で証明する。
- 直前安定版の解決規則と成果物 digest を記録し、浮動タグやローカルの古いビルドを使わない。
- `rolling` を宣言する変更のリリース gate とし、失敗を再試行で成功扱いにしない。

## Out of Scope

- マルチ AZ、データベース昇格、ロードシェディング、障害注入。`wi-165` が所有する。
- すべての過去版との組合せ。
- 非互換を検出した製品コードの修正。本項目では最小再現と個別 work item を作る。
- 更新方式を決定すること。`wi-449` の判定器が所有する。

## Design

組合せは `previous=latest supported release` と `next=current artifact` の一組を既定とし、明示した追加組合せだけを matrix に加える。両版は同じ外部入口、データベース、鍵の集合へ接続するが、個別の作業領域とログを持つ。各要求は一方の版で状態を作り、もう一方で継続する交差操作を必ず含む。

テストは版を選ぶ内部ポートへ直接接続せず、本番相当の入口を通す。ハーネスが片方へしか配送しなかった場合でも成功しないよう、各版が処理した相関 ID と版スタンプを検査する。版スタンプを利用者向けプロトコル応答へ追加する必要がある場合は、本項目で行わず別の仕様変更を起票する。

## Plan

1. 現行成果物の組立方法、直前安定版の取得、共有依存、隔離方法を固定する。
2. 片方の版へしか到達しない誤ったハーネスで Acceptance RED を確認する。
3. ログイン、refresh token、セッション、ジョブの順に交差操作を追加する。
4. `wi-449` の `rolling` 候補だけを対象にリリース gate へ接続する。
5. `wi-165` が同じハーネスを無停止 drill から利用できる境界を文書化する。

## Tasks

- [ ] T001 [Inventory] 直前安定版と現行成果物の取得、版固定、共有依存、観測方法を確定する。
- [ ] T002 [Acceptance RED] 両版を起動しても一方へしか配送しないハーネスが失敗することを固定する。
- [ ] T003 [Harness] 同じ PostgreSQL と入口へ二版を接続し、各版への到達を観測できるようにする。
- [ ] T004 [Scenarios] ログイン、認可コード、双方向 refresh、セッション、ジョブ引継ぎ、準備状態を検査する。
- [ ] T005 [Release] `rolling` 候補のリリース gate として実行し、成果物 digest と結果を保存する。
- [ ] T006 [Verify] 片方停止、片方未到達、互換性のない fixture を与えて検査が失敗することを確認する。

## Verification

- 新設する混在版受け入れテストの `mise` タスク
- `mise run check-links`
- `mise run verify`
- 旧版と新版の片方だけへ配送すると失敗し、両方向の交差操作が成功した場合だけ通る。
- 取得した旧版と新成果物の digest、実行した組合せ、失敗した経路が結果から追跡できる。

## Risk Notes

リスクは medium。ハーネスが実際には片方の版しか通らないと、最もありそうな誤実装のまま GREEN になる。両版で作った状態を相手側が継続する操作と版ごとの到達証拠を必須にし、単なる二プロセス起動を合格にしない。
