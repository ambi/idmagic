# Bounded Context と Module を比較し、IdMagic のモジュールとその関係の扱いを見直す

`mise run spec-diff -- main` は規範仕様に差分がないことを示した。
設計と実装の単位は Module に統一する。ドメインモデルを業務上の概念、その関係、操作と守る規則と定義し、各モジュールの設計で扱う。Bounded Context の分類や Module との対応表は作らない。
相手のモデルの利用、自分のモデルへの変換、一部の共同管理を区別し、Shared Kernel は共有範囲、変更時の合意、双方の統合検証、解消条件を定める場合の選択肢とした。専用の共有モデルは追加しない。
共通設計と用語集を更新し、重複する定義を参照へ縮めた。
25 モジュールの README を照合し、9 モジュールの「責務と境界」にモデルの利用、変換と更新の担当を反映した。属性定義とサインイン条件の旧担当の記載も直し、説明が足りる残りは維持した。
既存の全体図にモデルの関係を示すラベルと、HTTP やポート越しの呼び出しを加えた。生成器はコードの参照を実線で更新し、人が記した関係ラベルを保持し、コード上の参照がない関係を破線で描く。
新しい台帳や分類欄は作らず、製品コードと契約も変更していない。
用語検査は Bounded Context、Context Map、Published Language を認め、単独の Context の指摘を維持した。追加の実装や検査の移行は残していない。
