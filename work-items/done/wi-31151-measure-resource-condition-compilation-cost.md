# リソースアクセス条件のコンパイル費用を測り、追加対策の要否を決める

規範と製品の振る舞いは変えず、十種類の上限ちょうどの式について、初回のコンパイル、反復コンパイル、評価だけ、二つの式の通常判定を分けて測るベンチマークを加えた。
初回は入力ごとに新しいプロセスで三回、反復は 100 ms の区間で五回測定し、時間と累積割り当て量を性能設計へ記録した。
日本語と BMP 外の文字を含む式を二つ毎回コンパイルする判定は約 4.9 ms と約 9.3 MiB を要し、正式な HTTP 測定でも処理量の目標未達を再現した。p99 と応答の正しさは目標内だった。
条件の登録と評価の配線を拒否の対照で確かめ、拒否条件を登録しない故障を検出する検査も残した。
1024 コードポイントの受理範囲は維持し、コンパイル済みの式の再利用を第一候補とする性能修正は wi-85881 に引き継いだ。本番の混合負荷と長時間のメモリ使用量は今回の測定の対象外である。
