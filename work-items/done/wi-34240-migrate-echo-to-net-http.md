# HTTP の配線を Echo から標準 net/http へ移す

中止した。
HTTP の配線は Echo のまま維持し、移行の代わりに wi-16357（クライアント IP の抽出の一本化）と wi-35482（`Bind` と `BodyLimit` を標準の処理へ置き換える）を行う。
判断は直接依存のライブラリの選定の基準に沿う。
信頼する公開元は labstack の一つだけ減るが、golang.org/x/net と x/time は grpc-gateway、OTel、go-ldap、MCP SDK などからも入るので、`go.mod` から消えるのは Echo 本体だけである。
利用者の入力が届くコードのうち、Echo 固有の入力処理は `Bind` の 1 か所と `BodyLimit` の 1 か所に限られ、どちらも Echo を残したまま外せる。
一方、入場制御、管理 API のスコープの判定、メトリクスのラベル、非推奨ヘッダーはルートパターンで判定し、優先度の参照は経路の一覧をルーターから得る。
ServeMux はグループのミドルウェアと経路の列挙を持たず、パスの正規化、405、HEAD の扱いも異なる。
移行後は、これらを補う経路の組み立てを自前で保守することになり、置き換えたライブラリに近い規模の補助コードを持つという見直し条件に移行の時点で当たる。
着手時の主張だった差は小さく、必要な機能と移行後に所有する保守責任では Echo の維持が勝ると判断した。
Echo の保守が止まる、脆弱性が繰り返される、または互換性のない次のメジャーバージョンへの移行を迫られた場合は、その更新の代わりに標準 net/http への移行を改めて検討する。
