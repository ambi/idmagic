# テナント属性定義の管理と表現の重複を整理する

規範仕様の差分はない。
User と Group の属性スキーマの管理 HTTP と更新処理を IdManagement へ集約し、Tenancy の重複型、保存ポート、組み立て地点の双方向変換と参照照会を除去した。
属性の型、検証、組み込み属性、参照保護と保存を同じ所有者に置き、管理用の型と変換の同期を不要にした。
URL、TypeSpec、規範 ID と既存のイベント型は維持し、通知先の照会は別の意味の射影として残した。
責務表、両モジュールの README とデータ、属性スキーマの実現方式を現在の分担へ合わせた。

既存の HTTP とユースケースのテストの入力と期待結果を保ち、全項目の保存と読み戻し、拒否後の状態とイベント、テナント分離の検査を補った。
逆依存の race テスト、Go lint、仕様と境界、HTTP 契約とブラウザーの属性追加と削除を検査した。
変更耐性は利用者の指示で重要な故障に絞り、参照保護と検証の省略、一意性エラーの誤変換、PII フラグの脱落、Group の更新経路の欠落を検出した。
広範囲の統合モードの変異計測は中止したため、全変異の検出能力は主張しない。
対象を実行しない DB テストまで個別に計測する費用は wi-89214 に記録した。
属性の意味、API の本文、PII とクレームの規則、テーブル所有者、データ移行と更新の原子性の変更は対象外である。
