# マネージド型 MCP Gateway を加え、個別の配置なしに接続先を保護できるようにする

Gateway の別途配置を不要にするマネージド型 MCP Gateway を既存の API プロセスへ加え、セルフホスト型との選択を管理画面へ設けた。
テナントの正規 issuer と資源登録 ID から公開 URL とメタデータを返し、毎回のトークン検証、操作割当、条件、上限、承認の使用を既存の評価へ通す。
上流には単回使用の交換許可と登録専用の DPoP 鍵、または本人の TokenVault 接続を使い、資格情報を返さずに JSON と SSE を制限内で逐次転送する。
設定は既存の資源登録が所有する nullable な列に保存し、MCP の構文検査と発行前ガードを共用した。既存のセルフホスト型の入力と配置は保つ。
同居は初期構成として選び、接続予算と認証を優先する受付制御を設けたが、CPU、メモリとプロセス停止の隔離はない。本番規模の混合負荷による SLO は未実測であり、独立した増設、再起動、障害隔離が必要になれば分離を見直す。
閉域への中継、API キー型の資格情報、ツールの自動発見と競合製品の実テナントでの計測は加えていない。比較表には上流の登録と本人の OAuth 連携の前提も明記した。
