# 変更入力に影響する CI の検査群を選び、文書変更で製品テストを起動しない

変更入力から Go、UI、ブラウザー、スキーマの群と理由を選ぶ `plan-ci` を追加し、CI の各ジョブへ接続した。
作業項目と開発文書の Markdown だけを対象外にし、共有入力、未知のパス、空差分、比較不能では全群を選ぶ。
削除と移動は新旧のパスを比較し、最終必須チェックは計画、常時実行の仕様検査、選択した全群の成功を要求する。
選択済みの skip、失敗、取消、結果欠落を拒否し、対象外と理由を summary に表示する。
着手時の基準 `52d1963b` に対する `spec-diff` には規範仕様の変更がなく、製品の振る舞いと検査群内のタスク、DB 必須条件、同じ実行の契約証拠は維持した。
計画上の製品ジョブ数は従来の一律 5 件に対し、文書 0 件、UI 2 件、backend の局所変更 3 件、スキーマと契約 5 件とする。
ローカルの計画 CLI の計測をテストログへ出すが、GitHub 上の実ジョブ起動、準備時間、検査時間と短縮量は未収集である。
パッケージ単位への分割、race の自動実行、CodeQL、依存監査と保護設定の変更は対象外とした。
