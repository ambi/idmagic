# 変更した規範要素ごとに反例を記録し、仕様の未決定を明示する

中止した。
2026-11-14 の棚卸しで、前提が二つとも変わっていた。
一つ目に、作業項目の形式は `evidence_policy` と `risk-based-v3` を廃し、RED の観測や検証の実行を「記録は自己申告であり、検査は書いたかどうかしか確かめられない」という理由で記録に書かない形になった。
反例を前付けに記録して検査する案は、この原則と食い違う。
二つ目に、仕様を書くときと既存のコードを読むときに未決定の振る舞いを探す問いは、仕様の漏れを探す観点として開発ワークフローに入った。
状態と操作の組、同じ種類の操作の経路の一致、境界、並行性、再試行、拒否の後の作用を、操作ごとに問う。
残る価値（いま書いた仕様を満たしたまま誤った実装が書けるかという問い）を観点の表へ足すかは、必要になったときに開発ワークフローの変更として扱う。
