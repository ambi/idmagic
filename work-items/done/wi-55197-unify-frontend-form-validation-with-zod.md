# Zod でフォームの変換、検証、エラー表示を共通化する

規範仕様の差分はない。WCAG22-LABELS-ERRORS と REQ-SYSTEM-028 の要件は変えず、フロントエンドの実装をそれに合わせた。
Zod 4.6.7 を runtime の依存に加え、共通の欄の規則が唯一の利用箇所として読み込み時に `jitless` を設定する。画面からの直接の import は Biome で拒否する。
入力だけで判定する検証を持つ画面を共通の部品へ移し、不備のある欄に `aria-invalid` と修正方法を示すエラー文を付け、送信ボタンを無効にした。空白だけの必須、`maxLength` による UTF-16 の数え方（コードポイントへ変更）、検証しなかった CIDR を直した。
URL、scope-token、PEM、JSON、整数の範囲、RFC 3339 の日時、件数、属性キー、realm、SPIFFE のトラストドメインの形式検証を、欄ごとにサーバーの検証と同じ受理範囲で加えた。画面がサーバーより狭かった欄と広かった欄（realm の末尾のハイフン）は契約に合わせた。
アプリケーション編集とシステムのテナント編集は、複数の API へ順に保存する途中の検査の失敗で一部だけが保存されていたので、送信の最初にすべてを検査するようにした。
上限 500 以上の欄に文字数を示す。桁数が固定の数字の確認コード、セルフサービスのプロフィール、認可モデルの下書きは移していない（対象外に理由を記す）。
UI 設計、API ガイドライン、フロントエンド設計の文書を現在の検証の分担に合わせ、設計フォーマットに「実装の名前に依存しない記述」、コーディングスタイルに「マークアップの `id` と `name` を観測される値として扱う」を加えた。既存の設計文書の違反は wi-85394 で直す。
E2E 全体で見つかった、User の失効と同じ秒の再発行の拒否は wi-94301 で直した。
