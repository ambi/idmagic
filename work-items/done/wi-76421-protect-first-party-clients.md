# 組み込みクライアントの削除を拒否し、内部エラーの公開を防ぐ

REQ-OAUTH2-080 と REQ-APPLICATION-017 を追加し、組み込みの管理コンソールとポータルの削除を、トークンの有無や表示名によらず拒否する。
クライアント単体と Application 経由の双方で 409 と `first_party_client_protected` を返し、一覧と詳細に `deletion_protected` を公開して削除操作を隠す。
REQ-SYSTEM-023 を未分類の内部障害という条件へ明確化し、SQL、言語とライブラリの生のエラー、スタックトレースを本文とヘッダーへ含めず、相関 ID とサーバー側に原因を残す。
原因は、管理 API が未知の DB 障害を一括で入力エラーへ変換し、共通の非公開処理を迂回していたことである。
クライアント、Application とカテゴリの管理では既知の拒否だけを公開し、共通処理も 5xx の HTTPError の内部文面を公開しない。
API ガイドラインとテスト方針に分類と障害注入の規則を追加し、実 DB、HTTP とブラウザーの検査を用意した。
個別ハンドラー全体の監査、削除済みポータルの復元と実環境への反映は含まない。
別機能で見つけた未分類エラーの公開候補は、横断監査に具体的な入口とともに残した。
