# モジュール間の依存を生成図で示し、実行単位と通信の図をランタイムアーキテクチャへ移す

`mise run spec-diff` は main に対して規範仕様の差分なしを報告した。
モジュールの責務、依存規則、実行単位、通信、配置、REQ と TypeSpec の契約は維持した。
起票後に追加されたモジュール索引の依存図を重複させず、関係ラベル 37 件を表へ移し、境界検査と同じ責務表、import、負債台帳から論理アーキテクチャへ生成する表示に統合した。
26 モジュールと 88 本の関係を結ぶ flowchart は線を追いにくいため、代替案の生成行列を採用した。
行列は import、HTTP とポート越しの関係、境界の負債を区別し、スクロール中も行と列の見出しを保つ。
Markdown の図の写しと手動再生成コマンドを廃止し、関係の表の未知のモジュールと重複を検査する。
サーバー側の実行単位と通信の図をランタイムアーキテクチャへ C4 の Container 図として移し、利用者配置の Directory Connector と MCP Gateway、その通信相手と TLS 終端も同じ図に加えた。
CLI からの公開 HTTP の呼び出し、LDAP の読み取り、MCP の評価と許可後の転送を示し、IdMagic の PostgreSQL へは直接接続しない構成を表した。
デプロイメントアーキテクチャには公開入口、起動の対応、配置の表とプロファイルを残した。
設計フォーマットにモジュール間の依存と実行単位の通信の図種を加えた。
デプロイプロファイルは、通信、基盤からの制御、未作成要素の区別を維持するため flowchart を採用し、C4 Deployment 図への置き換えは行わない。
