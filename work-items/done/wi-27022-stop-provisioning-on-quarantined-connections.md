# 隔離した接続では、作成済みのプロビジョニングタスクを下流へ送らず、フル同期も始めない

隔離中の接続では未投入タスクのジョブ投入と、投入済みタスクの下流への送信を止めるようにした（REQ-PROVISIONING-017、追加した REQ-PROVISIONING-020）。
実行時に隔離を観測したタスクは、前の job_id を保った pending に戻し、解除後に同じタスクを新しいジョブで回収する。
保留を成功や配信不能にせず、連続失敗数とフル同期の完了判定も変えない。

再投入の重複排除キーは前のジョブを区別し、関連付けは走査時の job_id の一致を条件にする。
解除と古いジョブの完了、遅れて関連付ける worker が競合しても、古い実行へ戻してタスクを失わない。
隔離タスクを読み飛ばしても正常な接続を走査し、投入上限を守る。
pending の索引と、メモリと PostgreSQL の走査をこの回収へ合わせた。

隔離中のオンデマンドとフル同期は、409 と provisioning_conflict で拒否し、タスクとフル同期を作らない（REQ-PROVISIONING-012、013）。
TypeSpec に拒否と job_id の意味を反映し、タスクの状態遷移へ隔離による保留を加えた。

実行中のタスクの取り消しと、既存の削除予約の実体化の停止は対象外である。
データ移行は不要だが、隔離を無視する旧版の worker を残さないよう、worker を停止して新版へ更新する。
