# リソースアクセスの規則を専用の入力欄で編集する

仕様に REQ-OAUTH2-090 を追加した。
MCP リソースサーバーの作成と編集の画面で、ツールの行に人の承認の要否、認可詳細の種類、実行回数の上限、交換先の `resource`、条件の式と承認に求める明細の種類の入力欄を加えた。
サーバーが拒否する組み合わせ（承認と明細の種類、承認と承認の条件の併用、条件の対、承認と交換先の併用、上限の範囲と重複、https でない交換先）は、送信前に該当する欄へ示して保存を止める。
入力欄で表せない型の制約は行で読み取り専用の JSON として示し、行の編集でも保つ。条件の欄をすべて空にすると `condition` を除く。

判断は次のとおりである。
条件の式は CEL の文字列のまま入力させ、コンパイルは保存時のサーバーに任せた。
式の長さは送信前に検査しない。TypeSpec の `@maxLength(1024)` はコードポイント、サーバーはバイトで数え、受理範囲が一致しないためである。
認可詳細の種類は自由入力のままとし、登録済みの種類からの選択は採らなかった。

検証は `resource-access-rule-form.spec.ts` が、JSON で入れた上限と条件を持つ行で承認を求め、明細の種類の不足で保存できないこと、入力後の保存と再読込で値が残ることを確かめる。
承認と明細の入力は実キーで操作し、不足の説明が入力欄の `aria-describedby` に結び付くことも確かめる。
