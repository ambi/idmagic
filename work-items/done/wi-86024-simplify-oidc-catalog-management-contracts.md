# OIDC カタログ管理の重複する契約と変換を除去する

ApplicationCatalog が OAuth2 の既存の公開管理操作を直接利用するようにし、9操作を複製した要求契約、管理と表示の公開型14個、二つのエラーと変換アダプターを除去した。
必要な二つの表示型は HTTP の近くへ非公開で残し、資格情報の識別子、時刻と状態だけを明示的に写す。
本番の Go コードは差し引き176行減り、管理項目を追加するときに同期する型と変換が減った。
Application の独立した名前照会は対象外として維持した。

登録と設定の検証、クォータ、関連付け、クレームとシークレットの管理は同じ OAuth2 の操作が担当する。
HTTP の入力と応答、シークレットの非公開、拒否後の状態、イベントと部分確定の順序は維持した。
所有者の実装、SQL とトランザクションは変えていない。
管理の直接利用は ApplicationCatalog から OAuth2 への一方向の依存であり、循環負債は17件のままである。
責務表と依存図を現在の構造へ同期し、七つの視点で担当、公開範囲、変更の局所性と結線をレビューした。

Catalog の119テスト、名前照会の1テスト、所有者の管理操作の26テストと、変更箇所と逆依存の race 付き1,767テストが成功した。
失敗、スキップと未実行はいずれも0件だった。
変更行へのミューテーション15件はすべて検出し、表示のファズ検証は10秒間に244,807回成功した。
既存の HTTP の入力と期待値、特性化テストの本文は維持した。

`lint-go`、`check b0a97fc48`、文書生成と公開 API の互換性ゲートが成功し、`spec-diff b0a97fc48` は規範の変更なしだった。
公開前なので互換性ゲートは公開済み契約との比較を行っていない。
既存の HTTP の静的解析には未解析の操作が残るため、全操作を静的に検証済みとは扱わない。
今回の対象に未実施事項はなく、Tenancy の属性定義と相互変換の再検討は別項目 wi-94860 に残す。
