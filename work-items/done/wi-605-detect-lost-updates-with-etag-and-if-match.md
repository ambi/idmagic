# 管理 API の更新で ETag と If-Match による競合を検出する

REQ-SYSTEM-037 を追加し、対象の 11 リソースの GET と PATCH に強い ETag、更新と削除に任意の If-Match と不一致の 412 を宣言して実装した。
REQ-TENANCY-034 のタグの導出を更新日時から返送する JSON の SHA-256 ハッシュへ変えた。
バージョン列、シーケンス、トリガーを追加せず、PostgreSQL のロックとメモリの mutex で照合から保存までを保護し、拒否時には関連状態、イベント、使用量、派生するワークフローを変えない。

ブランド設定の部分更新を PATCH に変更し、属性スキーマ、サインインポリシー、通知テンプレートの全体置換は PUT を残した。
変換する PUT の成功応答には RFC 9110 §9.3.4 に従って ETag を付けず、管理画面が保存後の GET の本文とタグを一緒に採用する。
編集元の本文へタグを結び付け、412 は入力を保持して再読み込みを促し、自動で上書きしない。

標準検証、スキーマの収束、11 リソースのメモリと PostgreSQL での並行更新と拒否の無作用、race 検査、二画面での競合表示、ヘッダーの fuzz 探索を検証した。
SCIM、If-Match の必須化、対象外のリソースと独立したサブリソースへの展開は行わず、ドメインの expected_revision は維持した。
