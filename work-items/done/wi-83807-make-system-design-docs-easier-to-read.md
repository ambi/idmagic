# システム全体の設計文書を、読み手が構造と判断を追える形に直す

規範の差分はない（`mise run spec-diff`）。システム全体の設計文書の構成と表現、文書サイトの表示を変えた。

- 論理アーキテクチャの依存の行列を、区分の全体図と区分ごとの図の二段の Context Map（Mermaid）に置き換えた。モジュールの間の依存の表に「関係の種類」（使う、変換、共同管理、公開契約）の列を加え、未知の種類と import を持つ公開契約を検査が拒否する。表に宣言のない import は「使う」として描く。
- アーキテクチャ上の判断を、モジュールと同じ判断の記録の節（背景、決定、検討した代替案、結果と再検討の条件、関連する要件）に揃え、`check-spec` がシステムの `decisions.md` にも節を求めるようにした。ADR の連番、状態、判断ごとのファイルは採らない。直接依存の選定の方針はコーディングスタイルへ移した。
- 設計ガイドラインを推敲し、「エラーと拒否」を「失敗の表し方」（入力の不正、規則による拒否、作用の失敗）に改め、「確立した実装への委譲」を削ってセキュリティ設計の入口へ一節で移した。
- バックエンド設計と設計ガイドラインから、モジュールの組ごとの配線、実装状況、トランザクションの保証の一覧を外し、役割の名前の例に置き換えた。現在の組ごとの結び方は OAuth2 と IdManagement の「責務と境界」へ移した。
- ユーザーインターフェース設計にはどの画面にも適用する規則だけを残し、管理コンソールに固有の構成を Frontend の管理コンソールの機能仕様の実現方式へ移した。
- 文書サイトの表の 1 列目を行の見出しにし、太字にして 2 列目との間に縦線を引き、20 文字以下なら折り返さない。1 列だけに背景色を付ける案はページの配色の中で浮き、1 列目のインラインコードの枠を外す案はかえって目立たなくなったので、どちらも採らなかった。インラインコードだけのセルはラベルとして表示する。データベース設計のテーブル一覧は、長い「役割」の列を最後へ移した。
- 脅威モデルの `Controls` の文書の参照を題名つきのリンクにし、存在しない `contexts/` と古いパスを現在の節へ直した。
- 検証設計の設計領域をなくした。要件の群ごとの証拠と受入れはテスト方針、宣言的なファイルの検証は継続的インテグレーション、障害試験と復元試験は可用性設計、脅威の状態ごとの証拠と制御の種類ごとの検証手段は脅威モデル、モジュールのファジングの確かめ方は各モジュールの `security.md` へ移した。
- プロトコルの攻撃の被覆の調査は wi-78912 に分けた。Context Map の図の見た目はブラウザーで確かめておらず、Mermaid の構文の検査だけを通した。
