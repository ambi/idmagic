# 接続削除後に古いプロビジョニング状態を残さず、既存ジョブを安全に終了させる

REQ-PROVISIONING-002 の削除契約を REQ-PROVISIONING-021 へ分け、接続と資格情報、全状態のタスク、リンク、削除予約、フル同期と関連付けを一括削除し、失敗時には全状態を保持することを定めた。
TypeSpec の履歴保持という説明を一括削除へ合わせ、メモリの削除を PostgreSQL の連鎖削除と揃えた。
REQ-PROVISIONING-022 により、削除済みタスクの旧ジョブは資格情報の取得、下流への送信、成功失敗の記録をせず正常終了し、再登録した接続へ旧状態を引き継がない。
共有契約で削除の両側、全状態のタスクと再登録を検査し、正式なメモリ構築、旧ジョブ、実 PostgreSQL の削除途中の故障注入と並行読み取りの race 検査を加えた。
タスク履歴とリンクは復元しない。下流のアカウントとグループの削除、送信を開始した外部リクエストの取り消し、削除時の Jobs の取り消しは対象外とする。
