# Entra 側の切り戻しを確認してからドメイン単位でフェデレーションを解除する

REQ-WSFEDERATION-001 に、Entra の切り戻しを確かめてから一つのドメインだけを解除する操作を加えた。
管理 API の専用の DELETE と、残るドメイン、RP の削除の有無、確認の根拠を返す応答、解除のイベントを TypeSpec に定めた。
Entra の RP を汎用の DELETE で消す要求は 409 で拒否する。

解除時は Microsoft のレルム探索を優先し、まだ IdMagic を指せば拒否する。
探索の失敗、未知の答え、送り先として読めない URL は、現在の設定に対応する切り戻しの観測記録があるときだけ解除する。
行を固定して読み直した RP から対象だけを外し、残るドメインの IssuerUri、sourceAnchor、エンドポイント、署名鍵を保つ。
最後のドメインでは RP と観測記録を消し、署名鍵は残す。
画面に切り戻しのコマンド、以前の構成の復元の説明、対象と影響範囲の確認、拒否後の再実行を加えた。

外部の切り戻しとローカルの解除は原子的ではない。
保存に失敗すればドメインを残して再実行できるが、先に消した観測記録は失われ得るため、探索か観測の取り込み直しで再確認する。
レルム探索は非公式の外部サービスに依存し、手動で取り込む観測記録は管理者の申告として扱う。
実テナントでの伝播中の応答、切り戻し先と残るドメインのサインインは未実施で、WI-79 が担う。
Graph による自動変更と読み取り、Managed 認証の構築は対象外とし、Graph の自動化は WI-33604 に残した。
