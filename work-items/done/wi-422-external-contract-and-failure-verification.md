# 外部の相手に対する前提を、記録した往復の再生と参照実装との比較で確かめる

消費する側の SCIM の契約を、RFC 7644 と RFC 7643 の例を転記した記録の再生と、記録を忠実さの基準にした状態を持つ模倣で確かめるようにし、Sourcing のフィルターの解析器を RFC の文面だけから書いた参照実装と差分テストで比べるようにした。
記録は実物に接続できないので一次資料の例から作った（利用者の判断）。保証するのは一次資料の示す応答を解釈できることまでで、特定の製品の応答の癖は保証しない。

検査が見つけた誤りを直し、標準の宣言を三つ変えた（`spec-diff` の結果）。

- RFC7644-OUT-PATCH：下流が PATCH に返す 204 No Content を成功として扱う。これまでは更新と Group のメンバーの追加が、再試行しない失敗になっていた。
- RFC7644-OUT-FILTERING：衝突の解決で送るフィルターの値を JSON の文字列として符号化する。これまでは Go の引用符付けで、制御文字を含む値が下流に拒否された。
- RFC7644-FILTERING（Sourcing）：制御文字をそのまま含む文字列と符号付きの `\u` を拒否し、サロゲートペアを一つの文字として比べ、`id` を caseExact で比べる。字句の間の空白の量と `true`、`false` の大文字は、既存のクライアントを壊さないよう寛容に受理を続け、逸脱として宣言した。

外部の相手に対する前提を Provisioning、Sourcing、SharedSignals について棚卸しし、記録と模倣は最も実装が厚い Provisioning の SCIM のクライアントだけに入れた。
記録の作成と再生、模倣と照合の費用は、往復 7 件の転記と模倣一つで足り、二つの誤りを見つけた。
残るリスクは次である。Provisioning の OAuth 2.0 のトークン取得と SharedSignals の SET の送信には記録も模倣もない。模倣のフィルターは `eq` だけを解釈する。差分テストは大文字小文字の畳み込み、属性が無いときの比較、xsd:dateTime のタイムゾーンなしの値を、文面が決めないので製品と同じにしており、そこは検証していない。
