# seed の適用を記録の正を持つ Context のユースケースへ通し、プロセスをまたいで排他する

seed の書き込みを記録の所有モジュールの公開操作へ通し、通常作成の検証、使用量管理、イベントと監査を共有した。
`performance` も上限と監査を維持し、部分失敗後の再実行では未完了分だけを作成する。

PostgreSQL では専用接続のアドバイザリーロックで同じ要求の再計画から適用後の確認までを排他し、デモのドリフトは資格情報、履歴、所属、割り当てと連携先も項目ごとに比較する。
規範上の差分は REQ-SEEDING-006 のプロセス間排他と所有者の公開操作の保証で、REQ-SEEDING-009 と REQ-SEEDING-010 は既存の要件に実装を合わせた。
該当する三件のリスクを一覧から除いた。

変更した 112 パッケージと逆依存の 5,071 テスト、静的検査、仕様サイトの生成と PostgreSQL 排他の race 検査を通した。
マニフェストの文法と環境ポリシーの変更は対象外とし、今回の範囲に未実施事項は残していない。
