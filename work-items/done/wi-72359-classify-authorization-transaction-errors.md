# 認可トランザクションの不在と読取障害を区別する

仕様差分は REQ-AUTHENTICATION-007 の変更であり、不在、別テナント、期限切れと処理済みの認可要求だけを401または正当な直接ログインへ写し、読取障害はreturn_toの有無によらず安全な500と相関ID付きの診断へ渡すことを明記した。
TypeSpecの操作、モデルと認証方式は変更していない。
既存の `PendingAuthorizations` に型付きの `AuthorizationUnavailableError` を追加し、Cookie、テナント、期限と状態の検査はOAuth2に残した。
Authenticationのパスワード、TOTP、WebAuthn、復旧コードとMFA登録は共通の分類を使い、トランザクション取得、同意、再開と明示的なNegotiateの認可継続も未分類障害を通常の拒否へ変換しない。

SQLとラップした内部障害を正式なHTTPの組み立てへ注入するテストで、最終応答、サーバー側の診断、セッションの認証状態、認証器、復旧コード、認可要求、認可コードとイベントを観測する。
既知の利用不能での通常の直接ログインと、有効な認可要求での同意への継続は維持する。
認証の解決が記録する既存の `last_seen_at` は利用の記録として維持し、無作用の規範はセッションの発行、認証の完了と認可を確定する操作を対象とする。
認可の状態機械、明示的なreturn_toだけで始めるNegotiateの直接ログイン、画面とブラウザーの入力方式は変更していない。
