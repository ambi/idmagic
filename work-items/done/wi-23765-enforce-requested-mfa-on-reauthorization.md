# 再認可が求めた MFA の水準を、記憶済みの端末で省略せず満たすまで発行しない

REQ-OAUTH2-005 と REQ-AUTHENTICATION-027 を変更し、標準の OIDC-UNMET-AUTHENTICATION-REQUIREMENTS を加えた。
`acr_values` で求めた MFA の水準は、実効のサインインポリシーによらず、満たすまで認可コードを発行しない。
`max_age` か `prompt=login` で再認証も求めた要求では、記憶済みの端末を照合も充足もしない。
新しさを満たし水準だけが足りないセッションには、TOTP に限らず登録済みのいずれかの第二要素を求め、新しさを満たさないセッションはログインからやり直させる。
第二要素を一つも登録していなければ `unmet_authentication_requirements` を返す。

着手前に、受け入れ境界で四つの欠陥を観測した。記憶済みの端末が再認証の MFA を満たす、ポリシーが MFA を求めないアプリで MFA の要求が無視される、TOTP 以外の第二要素の利用者がログインへ戻される、第二要素のない利用者が同意へ進むかログインへ戻される、である。
以前は `max_age` を過ぎたセッションでも TOTP だけで済ませる経路があり、認証の時刻が古いトークンを発行していた。この経路はログインからのやり直しに変わる。
エラーコードの仕様は必須のクレームの `acr` に SHALL、それ以外に「適切なら MAY」を定めており、`acr_values` での利用は MAY の範囲である。
WebAuthn の資格情報は fixture で作れないので、TOTP 以外の第二要素の利用者は復旧コードで代用して確かめた。
認可設計の「認証の保証」の記述を実装に合わせ、リスクの行を外した。
