# 複数の入口を持つ約束を、すべての経路が守っているかを棚卸しする

複数の入口を持つ作用の約束を、下位の操作の呼び出し元から経路を求めて照合し、違反と再発の余地を 11 件の項目として起票した。
`mise run spec-diff` は `main` との規範の差分を示さない。この項目は規範を変えず、規範の変更は起票した項目が行う。

- 違反（規範の取りこぼしを含む）：wi-23764（削除の予約が記憶済みの端末を失効させない）、wi-83844（サインイン中の TOTP の登録が端末を失効させない）、wi-32983（多くのセッションの終了が `active_sessions` を減らさず、SLO などが `SessionEnded` を出さない）、wi-83761（Job の取り消しが `active_jobs` を減らさない）、wi-28886（作成の失敗が Hard Quota の使用量を戻さない）、wi-67391（単独のクライアントの削除が同意とトークンを扱わない）、wi-56472（デバイス認可が割り当ての関門を通らない）、wi-27520（止めた Agent が client_credentials 以外のグラントで発行を受ける）、wi-47962（無効の接続へ積んだタスクを送る）、wi-85253（SAML の SP の管理 API が証明書の要件を確かめない）。
- 再発の余地：wi-19265（User と Agent の停止の失効が、呼び出し元の選ぶ `Emit` に依存する）。
- 起票しなかったもの：隔離（wi-27022）と SSF ストリームの無効は送信点の一箇所が担う。リフレッシュトークンの許可（wi-54863）は共通の判定関数が担う。スコープの範囲、型の不変条件、障害の公開は、それぞれ wi-11707、wi-15826、wi-33421 が扱う。User の削除の同意の使用量は wi-51164 が扱う。
- 所有の形は、ほぼすべての約束で候補 A を選んだ。入口がモジュールをまたぐデバイス認可の関門だけは B を組み合わせ、加算と保存を同じ確定の単位にできない使用量は再集計と比べる。C を要する約束はなかった。
- 照合の表の「約束を観測するテスト」の列は、全経路では埋めなかった。違反が見つかった経路は起票した項目が RED のテストを計画し、守る経路の証拠の不足は今回の照合の対象から外した。
