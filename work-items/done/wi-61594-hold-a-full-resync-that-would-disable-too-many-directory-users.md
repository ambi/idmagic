# 完全な再同期が多すぎる User を無効にするとき、無効化を保留して管理者の承認を待つ

REQ-SOURCING-015、018、019 と IngestionRunLifecycle を変更し、完全再同期の無効化が多すぎる実行を保留して候補を保存する。
REQ-SOURCING-020〜022 と管理 API を追加し、Connector ごとのしきい値（既定 500 件と 20%）、候補の照会、承認、破棄を提供する。
設定の項目名と超過の判定は下流とそろえ、既存の下流ガード、SCIM、明示的なバッチの無効化と削除へは対象を広げない。
新しい実行は古い保留を失効させ、承認中は同じ Connector の競合を拒否し、失敗後は保存した候補から再開する。
正式なルーターの代替組み立てもライフサイクルと失効の反応器へ接続する。

通知は監査イベントと照会で提供し、メールは今回見送るが、メール通知全般の追加、拡充時には対応対象に含める。
全 User と実行の進捗は不可分でなく、途中の失敗で部分適用と件数のずれが残る制限を Sourcing のリスクへ記録する。

変更耐性は費用対効果からしきい値と重要な保留、排他の故障へ絞り、広い逆依存の変異調査は中断した。
候補 0 件の判定の `>` を `>=` にする変異は、有効なしきい値では他の超過条件も成立しないので等価と判断した。
PostgreSQL の広い調査で時間超過になった 2 件と、中断した広域の変異は判定未収集とし、網羅を主張しない。
