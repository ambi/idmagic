# 着手時に毎回読む開発文書の量を、ガードレールの効果を保ったまま減らす

`mise run spec-diff` は main に対する規範仕様の変更がないと報告した。
着手時に `brief` が返す節の本体を、行動の規則を残したまま縮めた。代表の 4 作業の本体の合計は 26→21、27→22、27→22、17→16 KB になった。
`#仕様影響の宣言` は、宣言を書く時点の規則を本体に残し、検査の範囲と判定を子節「検査の範囲と条件」へ移して 6.3 KB から 2.7 KB にした。
`testing.md#テストダブル` は例を文にまとめ、E2E と共有する画面操作を同じ名前の子節へ移した。`work-item-format.md` の `affected_spec` の解決は、一次情報の節である `#仕様影響` へ移した。
実装の skill は、コーディングスタイルの全文ではなく `#使い方` を読むよう改めた。
本体を縮めるときの文の扱い（検査で止まらない行動の規則は本体に残し、子節へ移すのは名前で場面がわかる規則と検査の説明だけにする）を `agent-guidance.md` に、4 作業での量の測り方を `task-context.md` に書いた。
AGENTS.md の表以外の節と `spec-change` は対象外とした。再発事例の再演は利用者の判断で省き、規則の対応表だけで確かめた。
