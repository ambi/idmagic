# MCP ゲートウェイを IdMagic がホストする構成と自前設置の構成を、どちらも選べるようにするか判断して対応する

Gateway の運用場所を段階的に増やすと決め、McpGateway の設計判断に記録した。
MCP サーバーの近くに置く構成と専用ホストの構成を現行の Gateway で支え、IdMagic がホストする構成は wi-61303 で設計と実装を行う。
規範の差分は REQ-MCPGATEWAY-004 の判断だけである。上流は、ゲートウェイからだけ到達できるように置くか、`downstream` の鍵に束縛したトークンだけを受け付ける。
`downstream.resource` は登録済みの宛先なので、Agent は同じ宛先のトークンを自分で得られる。このため専用ホストでは、トークン交換だけでは迂回を防げない。上流が `cnf.jkt` を Gateway の下流の鍵に限る条件を、セキュリティ上の考慮に加えた。
自前設置の構成で設定を配信する仕組みは採らなかった。操作の対応はすでに `mapping.catalog` で IdMagic 側にあり、残る設定は配置先でだけ決まるためである。
確認した範囲は文書と形式の検査に限る。`cnf.jkt` を検査する上流の手引きと実例はなく、条件を満たさない配置を Gateway から検出できない。
