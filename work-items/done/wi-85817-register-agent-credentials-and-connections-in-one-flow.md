# Agent の登録、認証の準備、利用する接続先を一つの作成手順にまとめる

REQ-IDMANAGEMENT-105 を追加した。
Agent の登録画面で、名前、責任者、区分に加えて、認証（公開鍵、JWKS の URL、後で）と利用する接続先の操作を選べる。一回の送信で Agent の登録、認証用クライアントの作成と紐付け、操作の割当を行う。
画面が既存の API を段階ごとに呼び、完了した段階を保って未完了の段階だけを再試行する。三つのモジュールにまたがる複合の API は作らなかった。
JWKS の URL は既存のクライアント作成 API の `jwks_uri` と、その宛先の検証を使う。
登録後は client_id、トークンエンドポイント、接続先のリソースと設定の例を示し、Agent ID を転記させない。
デモの通常の例は 4 手順になった。登録画面を使う既存の E2E を「後で設定する」の選択に合わせ、`ui-scenario-actions` に残っていた古い期待値も直した。
