# リフレッシュで発行するアクセストークンに元の認証時刻と方式を引き継ぐ

REQ-OAUTH2-006 を変更した。
リフレッシュトークンのローテーションは、元の付与を得た認証の `auth_time`、`amr`、`acr` をアクセストークンと次のリフレッシュトークンへ引き継ぎ、リフレッシュの時刻を `auth_time` にしない（RFC 9068 §2.2.1）。
認可コードの交換とデバイスフローが初回の記録へ認証の値を保存し、`refresh_tokens` に NULL を許す `auth_time`、`amr`、`acr` の列を加えた。
列の追加前の記録からローテーションしたアクセストークンには、時刻を補わず `auth_time`、`amr`、`acr` を載せない。署名は `auth_time` が 0 のときクレームを省くが、現在の発行経路はどれも 0 を渡さない。

受け入れテストは `/token` の HTTP 境界で、認証から 1 時間経った付与を 2 回ローテーションしても元の値が残ること、値のない記録から載せないことを観測した。
メモリーと PostgreSQL の共有契約は、保存と読み戻し、値のない記録の読み戻しを確かめた。
ステップアップの判定は引き続きトークンの `iat` を使うので、利用者の操作はまだ変わらない。判定の修正は [[wi-52890-step-up-bearer-requests-with-rfc-9470]] が扱う。
