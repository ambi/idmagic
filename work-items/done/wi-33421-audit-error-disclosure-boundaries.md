# 個別のエラー写像を監査し、内部障害の詳細を公開しない

仕様差分は REQ-SYSTEM-034 の追加であり、プロトコルでも内部障害の詳細を説明欄へ写さず、原因を要求の相関IDとともに記録することを明記した。
TypeSpecの操作とモデルは変更していない。
Provisioningは入力検証を型で区別し、フェデレーション設定はSave前の検証と保存障害を分け、UserInfoはクレーム生成の原因を保持してOAuthの出力で非公開にする。
追加で見つけたSCIMの読取・更新・削除・認証の障害も安全なSCIM応答と診断へ渡し、不在と保存障害を区別する。
Provisioningの接続テストは到達不能の結果を保ち、ライブラリエラーを固定の説明へ置き換える。

構造検索の本番コード164件を起点に、外向きのエラー写像、入力検証、既知の拒否、保存する診断とログを分類した。
入力検証と型または値で識別できる拒否の説明は維持し、文字列化を一律に禁止する検査は採用していない。
SQL、実行時エラー、ライブラリエラー、スタックトレースとラップした障害を注入するHTTPテストで、応答本文とヘッダー、相関ID付きの診断、失敗後の保存状態を観測する。
網羅的なデータフロー解析、全依存先への故障注入、保存済み診断の閲覧範囲の全面監査は行っていない。
認可トランザクションの読取障害を401へ変換する経路は、直接ログインへのフォールバックとポートの契約を一緒に直す必要があり、wi-72359 へ分離した。
