# システムコンソールとシステム API に MFA の認証と直近の MFA 再認証を求める

REQ-SYSTEM-033 を追加し、制御面の読み出しには MFA で成立した認証を、変更には直近 5 分の MFA の認証を求めるようにした。
MFA とみなす方式は `otp`、WebAuthn 系、`rc` で、`tdev` は含めない。
新しさはセッションの `step_up_at` ではなく `auth_time` で判定する。`step_up_at` は方式を記録しないためである。
テナント、鍵と DEK のヘルス、DEK の操作、システムのジョブ、システムの監査とエクスポートの 23 操作に、RFC 9470 の 401 を宣言した。Cookie の経路の 403 `step_up_required` も宣言した。
システムの監査エクスポートには、テナントの経路と共有しない 403 のモデルを追加した。
ステップアップの写像は、制御面専用の `WriteControlPlaneAccessError` に置いた。共有の `WriteAdminAccessError` に置くと、制御面でない操作の契約にも拒否が現れるからである。
管理発行の API アクセストークンはこの判定を受けず、スコープの宣言に従う。テナントの無効化、再開、エンドポイント形式の変更は `interactive_session` に限った（REQ-TENANCY-011、REQ-TENANCY-027）。
システムコンソールは画面の読み込みで MFA を確かめ、変更の前に再認可する。第二要素を登録していない運用者には登録を案内する。
操作理由と監査は wi-47234 に、実行時の復旧手段は wi-31080 に残した。
