# サプライチェーンリスクを踏まえてライブラリ選定を見直す

規範仕様の差分はない。
直接依存の選定の基準をアーキテクチャ上の判断に記録し、個々の採否は強い決定ではなく理由が変われば見直すとした。
調査時の候補から、pgx は lib/pq へ寄せず維持し、etree は利用を限らず維持し、go-webauthn は自前化せず維持すると改めた。
pgx は推移依存が同じ公開元のものだけで、etree は署名の API が要求し、WebAuthn は実際の認証器への対応を確かめる手段がないためである。
フロントエンドのフォーム検証は、Valibot との差が小さいなかで、新しい公開元を増やさない Zod を選んだ。
実施する変更は wi-17165（標準 uuid）、wi-34240（net/http）、wi-38782（Zog の置き換え）、wi-39599（golang-jwt の統合）、wi-47102 と wi-48351（WebAuthn）、wi-54600（Inter、tw-animate-css、clsx）、wi-55197（Zod）、wi-56243（API 応答）へ分けた。
成果物の署名と SBOM は既存の wi-100 が扱う。
