# 管理 API の POST で Idempotency-Key を受け付ける

REQ-SYSTEM-036 と TypeSpec の共通ヘッダー、400、409、422 の応答を追加し、管理 API の 15 操作で任意の `Idempotency-Key` を受け付けるようにした。
再送でも現在の認証、認可と CSRF の検査を通し、テナントと主体に束縛した受付記録から、5xx を含む保存済み応答を再生する。

受付記録をメモリと PostgreSQL に実装し、応答全体をテナントの DEK で暗号化した。
24 時間の保持、期限切れ行の削除、鍵の移行と古い実行による上書きの拒否を共通処理へ閉じ込めた。
HTTP の正式な入口、保存先の共有契約、PostgreSQL 構成の再生成、保存失敗、panic、同時要求と Structured Field の解析を検査する。
状態コード検査は、コールバック内の定数で外側の共通処理の追跡を打ち切らないようにした。

業務の作用と応答保存は原子的には確定しない。
結果が不明な要求は保持期間中 409 で拒否し、自動回復の要否と方式は wi-28557 で扱う。
保持期間を過ぎたキーの再利用には重複排除を保証しない。
PostgreSQL 構成の検査では外部のマスター鍵保管を HTTP のフェイクで置き換えており、実際の OpenBao の稼働は未検証である。
