# クライアント IP を Echo の IPExtractor で解決し、デフォルトでは接続相手を使う

REQ-SYSTEM-032 を追加し、デフォルトでは直接の接続相手を使い、明示した代理の範囲だけを信頼して送信元を解決する規則を定めた。
REQ-AUTHENTICATION-043 の自動 Negotiate も同じ規則を参照する。
旧ホップ数設定を `TRUSTED_PROXY_CIDRS` に替え、不正な CIDR は REQ-SYSTEM-016 に従って起動前に拒否する。
Echo の IP 解決器を経路の組み立てで設定し、ログインの抑制、レートリミット、CIDR 条件、Negotiate、監査は `RealIP()` を使う。
Application と Authentication の独自の解決の配線、重複した処理と別名を除き、設定リファレンス、設計と脅威モデルを同期した。
検査は直接の接続と代理の背後の HTTP 経路、解決の規則、起動設定と既存の利用側を対象とし、実環境の代理の構成は対象にしない。
信頼範囲を広げると送信元を偽装でき、代理の背後で未設定なら IP 単位の制限を全利用者が共有するため、運用者が実際の代理だけを含む範囲を設定する。
`Forwarded` と `X-Real-IP`、旧設定を使った起動の拒否、セキュリティヘッダーの置き換えは対象外とした。
