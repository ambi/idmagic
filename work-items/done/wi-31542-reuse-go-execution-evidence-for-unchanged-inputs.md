# 作業項目とコミットだけの更新では、入力が同じ Go テストの成功結果を再利用する

中止した。
試作では、実行入力と環境の識別、実行記録と判定の分離、再利用タスクを実装し、39 件のテストと 13 種類の手動の故障注入で拒否条件を確認した。
それでも、得られる効果に対して保守の費用と誤った受理の危険が大きいと判断した。
- 削減できるのは完了処理の後の `test-go-race` 一回であり、実測で約 121 秒だった。
- Go が読む無視対象の入力を `spec/generated/` と決め打ちで識別する必要があった。テストが別の生成物を読み始めても対照では検出できず、検証ツールが古い実行を黙って受理する。
- 環境の識別は、何も変えていない二回の `go env -json` の間でも `GOGCCFLAGS` の一時パスにより揺れた。同種の調整が続くと見込まれる。
- 実行と判定の二層のレポート、再利用タスク、識別の除外規則という新しい概念が、約 250 行の本番コードと約 330 行のテストとともに残る。
代わりに、検証済みの revision からの差分が作業記録だけである場合の判断を、wi-37681 で文書の手順として扱う。
