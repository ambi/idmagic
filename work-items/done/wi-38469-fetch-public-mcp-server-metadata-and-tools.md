# 公開された MCP サーバーから、IdMagic がメタデータとツールの一覧を取得して候補に示す

管理者の操作で、セルフホスト型の公開された MCP サーバーから PRM と `tools/list` を取得し、最新のカタログとして保存する管理 API と編集画面の操作を加えた（REQ-OAUTH2-095）。
PRM の `resource` が登録と一致し、`authorization_servers` がテナントの issuer を含む宛先へだけ、IdMagic 内部の主体 `urn:idmagic:mcp-tool-discovery` のトークンを送る。トークンは宛先を登録の資源だけとし、スコープは空、寿命は 60 秒で、PRM が ES256 を宣言すれば取得ごとの鍵へ DPoP で束縛する（REQ-OAUTH2-096）。
このトークンは `token_use` の印により、introspection、トークン交換、評価、管理 API と account API のすべてで無効になる。宛先は safehttp で公開アドレスに限り、リダイレクトを追わず、本文、期限、ページ、登録ごとの流量に上限を置いた。
REQ-OAUTH2-086 と 094 の判断を、閉域は Gateway の報告、公開は直接の取得に改め、PRM のスコープは出所付きの候補として選ぶまで登録を変えない。
方式は AWS AgentCore の 2LO と同じ構造で、認可サーバー自身がクライアントなので秘密を保管しない。資格情報の保管と管理者本人のトークンは採らなかった。
確認した範囲は代役の MCP サーバーによる受け入れテスト、ループバックへの実接続による宛先の制限、手動の故障注入（信頼の検査と印の検査）である。実在の MCP サーバーとの相互運用は確かめていない。
残るリスクは THREAT-117（`aud` だけを検査するサーバーで他の操作が通る）として受容した。定期取得、取得結果の保存と接続確認の認証の項目、introspection への対応は wi-19974 に分けた。
