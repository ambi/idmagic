# 仕様影響の照合を、仕様の申告漏れと本番コードの宣言漏れに絞る

`mise run spec-diff` は main に対して規範の差分なしを示す。
仕様影響の照合を三つの判定に絞った。範囲の仕様差分が変えた規範要素を、範囲で変わったどの作業項目も `affected_spec` に挙げていなければ拒否する。作業範囲にも完了した作業の区間にも入らず、本番コードを変えるコミットにトレーラーがなければ拒否する。`spec_impact: none` の作業範囲と `Spec-Impact: none` のコミットが規範仕様か既存の `TestCharacterize*` の本文を変えていれば拒否する。
`impact: modifies` と `impact: conforms` の区別、理由の言い回しの判定、`checkpoint(<id>)` の件名による名指しは廃止した。着手した作業項目の作業範囲のコミットは、件名を問わずその宣言を使う。スキーマから `impact` を外し、未完了の 5 件から取り除いた。
仕様差分と特性化テストは、範囲から完了した作業の区間を除いた部分ごとに両端で比べ、コミットごとには比べない。範囲の途中で変えて戻した仕様は検出しない。
完了した作業の区間は、最も古い起点からの一回の `git log` と、記録の内容をまとめて読む一回の `git cat-file --batch` で求める。長く続く `none` の記録が数百件の完了記録を範囲に含むとき、記録ごとに履歴を読む作りでは `check-spec-impact -- main~20` が約 170 秒かかり、新しい作りでは約 3 秒になった。受け入れテストは約 15 秒から約 11 秒になった。
