# ライフサイクルバッチが XmlFederationSigning 鍵も周期で準備し、アーカイブする

`idmagic-batch signing-key-lifecycle` が、`Signing` に加えて `XmlFederationSigning` の鍵を持つすべてのスコープ（共有の `default` と SAML 専用プロファイル）を扱うようにした（REQ-SIGNINGKEYS-002、003）。
有効な XML 鍵が作成から `-cadence-days` を過ぎ、準備済みの鍵がない集合にだけ次の鍵を `Prepared` として準備して `SigningKeyPrepared` を発行し、有効化はしない。連携先の登録をバッチは確かめられないため、専用プロファイルも管理者の確認付きの切り替えに委ねた。猶予期間を過ぎた XML 鍵はスコープごとに `SigningKeyArchived` を残してアーカイブする。

回す集合は鍵ストアの `KeyScopes` で列挙し、鍵を作らない。SAML のプロファイルを組み立て地点で読む案は、ほかのスコープの取りこぼしとモジュール間の依存の追加を避けて採らなかった。`Signing` の鍵のないテナントに鍵を作る既存のバッチの振る舞いは変えていない。

変更耐性は、domain と提供元の変更行の機械的変異をすべて検出し、生存した 1 件（失敗した初回作成が残す空の集合）は共有契約に観測を足して検出した。ユースケースはバッチの入口で観測するため、スコープの省略、デフォルトのみの処理、確認なしの有効化、周期の無視、遅延生成の 5 件を手で注入し、すべて検出した。残るリスク（準備した鍵の通知がない）は SigningKeys のリスク台帳に記した。
