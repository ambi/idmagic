# 作成に失敗したリソースが Hard Quota の使用量を占め続けないようにする

`spec-diff` の差分は REQ-TENANCY-050 の追加である。
`users`、`groups`、`agents`、`applications`、`oauth2_clients`、`consents` の作成は、上限の確認の後の検証や保存の失敗で加算を戻す。`ssf_streams` は既に戻していた。
利用者の確認を経て、同じトランザクションと再集計ではなく補償を採った。加算の前へ検証を移し、`tenantports.ReserveQuota` の予約を作成の直後に `defer Release` し、保存の成功で `Keep` する形に揃えた。保存の後の失敗ではリソースとともに加算を残す。
動的登録の不正なメタデータは加算の前に拒否するので、繰り返しても上限を占めない。
認可の同意の加算は HTTP ハンドラーから `consentusecases.GrantConsent` へ移した。
加算と保存の間のプロセスの停止と減算そのものの失敗によるずれは、`users` 以外では回収しない。観測されたら再集計の拡張として起票する。
受信側の SSF ストリームで、ストリームの保存の後に受信の設定の保存が失敗すると、ストリームが残ったまま枠を戻す。作成の部分的な確定の欠陥であり、対象外とした。
