# 設計文書から実装のパスと名前を取り除く

設計とモジュールの 61 文書で、処理の説明に含まれるソースのパス、関数、補助型、UI 部品の名前を、担当する役割と規則へ書き換えた。
仕様差分に規範変更はなく、製品の振る舞い、TypeSpec、設計判断は変えていない。
利用者の指示に従い、明示的なディレクトリ構造の設計と定義は残した。
配置表、構成ファイル、外部技術、公開ポートと契約の識別子、検証コマンドも例外として維持した。
パスの形に合う候補は 177 行から 126 行になり、残る候補は配置、構成と検査対象の定義、および MCP の契約だった。
パスだけの機械検査はこれらも違反と誤判定し、関数名は検出できないため追加せず、既存のレビュー方針を維持した。
製品コードの変更と新しい検査の追加は対象外とし、未実施の作業は残していない。
