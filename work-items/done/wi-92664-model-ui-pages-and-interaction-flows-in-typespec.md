# TypeSpec を基に UI のページ一覧と操作の詳細設計を整備する

UI 専用の名前空間 `IdMagicUi` に、ページ、状態、操作と遷移を表すモデルと共有の状態・到達先を追加し、19 モジュールの `pages.tsp` で 130 ページ、描画しない 15 経路、主要な利用手順を宣言した。
宣言は既存の API 操作を型で参照し、入力項目は持たない。
入力項目は実装の画面、受理範囲は API プロパティと共通 UI 設計が担当し、wi-80172 は中止、wi-24528 は `formSchema` と API 制約の直接照合へ書き直した。

ページの詳細とモジュール別の索引を `docs/modules/<module>/pages/`、領域と作業カテゴリの索引を `docs/design/application/pages/` へ生成し、各モジュールの設計領域の表から参照する。
`check-ui-pages` は TanStack Router の生成済み経路ツリーと静的な `PageMarker` から実装の経路を読み、全経路の双方向の対応、参照、遷移、生成文書の一致を通常ゲートで検査する。
棚卸し中だけ使ったプレビューは取り除き、ast-grep への依存も外した。

経路集合の一致は操作の完全性を保証しないため、実装が呼ぶ API とリンク先を宣言と両方向に突き合わせ、参照専用の詳細や一覧に載っていた編集操作を編集ページへ移すなど、宣言を実装に合わせた。
公開 OpenAPI はベースとバイト単位で一致し、製品の振る舞いと公開 HTTP 契約は変えていない。
管理メニューなどの共有表示を経由する移動は各ページに宣言せず、React やクライアント SDK の生成、IFML の全面導入は対象外とした。
