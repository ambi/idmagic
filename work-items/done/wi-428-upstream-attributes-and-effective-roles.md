# 上流の権威が書き込む属性が、実効ロールへ波及する経路を制限する

REQ-IDMANAGEMENT-092 と REQ-IDMANAGEMENT-093 を追加し、動的 Group と上流管理 Group から管理ロールを付与せず、現在のロール一覧と式への明示承認がある業務ロールだけを実効ロールへ加える。
REQ-IDMANAGEMENT-014、015、020 と REQ-SOURCING-005 のロール解決も、この制限に合わせた。
属性の取り込みと所属の評価は継続し、ローカルの手動 Group と User への直接付与は従来どおり扱う。

TypeSpec に対話セッション限定の SetGroupRoleDelegation と委任のモデルを追加し、管理画面から承認と取消しを行えるようにした。
Group が承認と上流管理の印を所有し、通常の保存による承認の復活と、印の解除を防ぐ。
両保存先は現在の設定と承認を同じ参照で照合し、GroupUpdated は委任したロールと式の SHA-256 を監査へ残す。

既存環境ではスキーマ適用後、新しい API と worker の起動前に SCIM 対応表のバックフィルを行い、業務ロールを個別に承認する。
既存の所属を自動承認せず、旧コードへ戻す場合は先に対象 Group のロールを外す。
取り込み元ごとの個別委任、アプリケーション割り当ての制限と発行済みトークンの一斉失効は対象外とし、承認済み業務ロールへ上流が影響できるリスクと見直す条件を設計判断に残した。
