# 監査イベントのエクスポートを有界な非同期ジョブにする

REQ-AUDIT-009 から 012 と ExportLifecycle を追加し、テナント管理とシステム管理のそれぞれに作成、一覧、状態、取消し、ダウンロードの TypeSpec 契約を定めた。
検索とエクスポートの責務を分け、REQ-TENANCY-048 の保存バイト数へ監査成果物を含めた。
Audit が専用の成果物ストアを所有し、Jobs の bulk レーンで 500 件ずつ読み、一時ファイルと 64 KiB 以下の PostgreSQL チャンクへ書く。
成功したジョブと一致する期限内の成果物だけを、現在の権限、要求者と範囲を照合して公開し、生成、保存、取消しの失敗は内部の例外本文と部分成果物を公開しない。
両管理画面、ライフサイクルの監査、期限削除、Soft Quota の照合と監視を配線した。
同期 API は 1,000 件への切詰めを修正し、10,000 件、16 MiB、同時 2 枠の互換経路とした。
非推奨日は 2026-10-25、Sunset は 2027-10-25 とし、削除には初回公開からも最低 12 か月を置く。
Apple M3、Go 1.27.3 のローカル測定では、旧 HTTP 経路は 10,000 件中 1,000 件を返し、新しい作成ユースケースは対象 1,000 件と 10,000 件の両方で約 3.2 KB、27 回の割当てだった。
同時点スナップショット、実環境の長時間負荷、全変異の調査、継続ストリーミングと監査チェーンの検証は対象外とした。
固定済み API 基準との既存 133 件の差分は main と同数であり、今回の変更では修正しない。
