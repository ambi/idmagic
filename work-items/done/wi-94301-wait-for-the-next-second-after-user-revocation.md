# User の失効と同じ秒には、次の秒まで待ってからトークンを発行する

REQ-SHAREDSIGNALS-012 に、User の失効エポックと同じ秒にその User へアクセストークンを発行するときは、エポックの次の秒に入るまで発行を待たせることと、その判断を加えた。
アクセストークンの `iat` は秒しか持たず、同じ秒の発行は失効の前か後かを見分けられないので、失効の後の発行を次の秒へずらし、失効の前のトークンを止めたまま、資格情報の変更や認証器のリセットの直後の再認証を通す。
判定を秒に丸める案は、失効の直前に発行したトークンを有効期限まで残し、「発行済みのトークンを即時に無効にする」保証に反するので採らなかった。秒より細かい発行時刻の claim と、セッションへの結び付けは、トークンの形式や失効の設計を変えるので対象外とした。
OAuth2 のハンドラーへ渡す発行器を装飾で包み、トークンエンドポイントのすべてのグラントに適用した。失効の判定の規則、Agent のエポック（REQ-OAUTH2-012）、管理用の API トークンの発行は変えていない。
wi-55197 のブランチへ重ねた E2E 全体（60 件）が通り、認証器のリセットの直後にログインし直すテストの失敗が消えた。
