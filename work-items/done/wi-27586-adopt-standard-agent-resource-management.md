# 接続先と操作の割当から Agent の利用を管理する

通常の Agent 管理を、接続先と登録済み操作を選ぶ利用割当へ変更し、認可モデル、関係タプル、対象 ID の手入力を不要にした。
Agent と接続先の両方の入口で同じ割当を参照し、追加と取消を一括で確定する。
組み込みの操作割当も現在の主体、行為者、スコープを同じ判定器で検査し、対象別の権限、条件、承認を必要とする操作ではそれらを併せて要求する。
カタログだけの接続先への client_credentials 発行は、割当と既存の認証上限の共通部分に絞り、取消は既発行トークンの次の評価にも反映する。
操作の識別子と不透明な割当参照をサーバーが発行し、削除後の同名再登録で古い割当を復活させず、接続先の同時更新は409で拒否する。
Gateway のカタログ参照と通常のデモ手順を追加し、従来の文書別権限の例を残した。
対象カタログ、自動ツール発見、Gateway への一回の操作承認の鍵の受け渡しは対象外であり、承認デモはトークン発行までを示す。
Okta と Ping の例は公式資料に基づく構成比較であり、実製品での計測や優位性の実証は含まない。
