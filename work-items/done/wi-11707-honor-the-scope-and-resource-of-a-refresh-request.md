# リフレッシュの要求の `scope` と `resource` を読み、範囲を狭める

リフレッシュ要求の `scope` を読み、元の付与の部分集合だけをアクセストークンへ発行し、範囲外を `invalid_scope` で拒否する。
`resource` の明示指定は元の束縛先との一致と登録状態を確かめ、未束縛の付与への後付け、別の対象、未登録、無効、複数指定を `invalid_target` で拒否する。
指定を拒否した要求は親トークンを消費せず、パラメーター省略時と新しいリフレッシュトークンには元の付与を保持する。
REQ-OAUTH2-006 にこの扱いと代表例を加え、RFC6749-REFRESH-SCOPE を追加し、RFC8707-MCP-RESOURCE-BINDING と TokenRequest の説明を同期した。
発行前のガード、署名、応答、発行イベントは同じ絞ったスコープを使う。
複数リソースへの対応と、ローテーションや再利用検知の規則の変更は対象外とした。
