# 接続先の変更通知でツールの一覧を報告し直し、前回からの差分を管理者に示す

REQ-MCPGATEWAY-012 を追加した。カタログを参照する Gateway は上流へ `subscriptions/listen` を開き、受信確認の後と自分の購読の `notifications/tools/list_changed` のたびに一覧を報告し直す。報告の開始は10秒以上空け、切断は1秒から5分までの倍の間隔で開き直す。通知に対応しない上流では起動時の報告だけを行う。REQ-MCPGATEWAY-011 の失敗時の扱いを「その回の報告をやめる」に改めた。
REQ-OAUTH2-086 と 087 を変えた。IdMagic は内容の変わった報告で直前の一覧を残し、管理 API の任意の `changes`（TypeSpec の `ReportedToolChanges`）と管理画面で追加、削除、定義変更を示す。完全でない側からは追加と削除を推測しない。差分は表示だけで、公開設定、評価、割当を変えない。
内容は並びを無視した指紋で比べ、PostgreSQL は一つの `ON CONFLICT` の更新で比較と置き換えを行う。指紋のない既存の行からは変更前を作らない。
起票時の候補のうち、公開された MCP サーバーからの PRM と一覧の直接取得は wi-38469、接続確認は wi-85145 へ分けた。閉域のサーバーは IdMagic から届かないため、直接取得の対象外とした。
確認の限界：Gateway の待ち受けと PostgreSQL の更新文は実装を先に書いたため、RED の代わりに故障の注入で検出を確かめた。E2E は race 検出器なしで実行した。差分の基準は直前の報告であり、管理者の確認状態は持たない。受信確認の後に上流が黙ったまま接続を保つ場合、切断を検出する期限は設けていない。
