# DEK の無効化とローテーションを、すべてのプロセスの DEK の保持へ伝える

`DataKeyCache` は有効なバージョンと状態を保持せず、暗号化と復号のたびに保存先から読むようにし、保持するのはバージョンごとの鍵素材だけにした。
ローテーション、無効化、破棄は確定の直後から全プロセスに効き、手順書の再起動は要らなくなった。
`spec-diff` の差分は REQ-DATAKEYS-002 と REQ-DATAKEYS-003 で、確定の後に始まる暗号化と復号のどのプロセスでの結果、確定より前に始まった復号を中断しないこと、状態を読めない間は保持した DEK を使わないことを要件にした。

期限付きの保持は無効化の「即時」を満たさず、プロセス間の通知は取りこぼすとフェイルオープンになるので採らなかった（DataKeys の設計判断）。
当初の案は復号だけを対象にしていたが、定期のローテーションが `batch` で動くので暗号化にも広げた。
費用は暗号化と復号ごとに索引で 1 行の読み取りで、アンラップは増えない。

残るリスクは `docs/modules/data-keys/risks.md` に載せた。
再び読まれないバージョンの鍵素材は再起動までメモリに残り、状態を読んだ直後にローテーションが確定した暗号化は旧バージョンで保存する。
`secrets.md` の DEK の生成の記述も、初回の暗号化での生成へ直した。
