# エージェントと MCP リソースサーバーの管理画面をほかの管理画面にそろえ、ツールの一覧を「カタログ」と呼ぶ

REQ-OAUTH2-086、REQ-OAUTH2-087、REQ-MCPGATEWAY-011、REQ-MCPGATEWAY-012 のツール一覧を「カタログ」へ統一した。
管理 API を `tool-catalog`、受信時刻を `received_at` とし、TypeSpec の操作とモデル、Go と TypeScript の型、Gateway と保存先の名前をそろえた。
送信の `POST /resource-access/tools`、入力上限、認証、差分の規則、公開設定と評価の独立性は維持する。

REQ-OAUTH2-088 に登録結果のクライアント ID、シークレット、YAML のコピーと設定方法の説明を加え、REQ-IDMANAGEMENT-105 の用語をエージェントと MCP リソースサーバーへそろえた。
管理画面から値の出所の印を除き、対象を限定する効果の補足、日英の状態表示、一覧の表と詳細カード、戻る操作を整えた。
配置方法の説明は結果画面の本文へまとめ、コピーする YAML は設定値だけを示す。
デモ画面自身の値の出所の印、状態の保存値、ページングと旧 API の互換期間は対象外とした。

未リリースのためデータ移行は設けず、宣言スキーマを新しい表名と列名へ更新した。

最終差分を `verify-changed -- main`、`check-schema`、関連 E2E 4 本、公式 MCP SDK を使う実行例の 13 項目で検証した。
日英の一覧、作成、登録結果、編集、エージェントの作成と割当画面をブラウザーで確認した。
本項目に残した未実施事項はない。
