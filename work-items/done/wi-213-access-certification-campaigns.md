# Group の所属、Application の割り当て、Agent を定期的に見直す

REQ-IDGOVERNANCE-020〜026、見直しの状態遷移、管理と本人の HTTP 契約を追加した。
Group の手動所属、Application の User・Group への割り当て、Agent を対象に、一回または日数の周期で見直す計画、回答、期限後の処置、通知と結果の画面を実装した。
日本語は「アクセスの見直し」「見直し計画」「確認担当者」に統一した。

Entra ID と Okta の方式を参考に、対象と担当者は各回の開始時点で固定し、所有者不在時には明示した代替担当者を使う。
維持は再付与せず、失効は状態の所有者の公開操作を使う。
Application は対象の割り当て行だけを解除し、別の Group を介するアクセスは残す。

開始と次回時刻を同じ確定境界で保存し、周期変更との競合を拒否する。
通知と失効は短い占有の取得後に保存のロック外で行い、項目ごとの結果を保存して再試行する。
本人とテナントの境界、期限、並行更新、正式な HTTP・worker の組み立て、Agent の保存後の失効失敗からの回復を独立に確認するテストを残した。

動的・上流管理の所属、多段階の確認、再割り当て、履歴の自動削除は対象外とした。
通知は停止と再試行により重複し得るため、厳密な一回配送は保証しない。
外部環境への適用は行っていない。
