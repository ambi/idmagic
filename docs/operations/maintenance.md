# 保守

## 定期作業

証明書と鍵の期限、依存ソフトウェア、データベース保守、バックアップ、保持期限、保存容量、アラートとrunbookを定期的に確認する。
実行頻度と担当は採用する運用環境で定め、実作業は対象ごとのrunbookへ置く。

## キャパシティ見直し

[キャパシティ設計](../design/performance/capacity.md)の Planning assumption と実測を比較し、テナント数、データ量、リクエスト率、待ち時間、データベース接続、保存容量のいずれかが前提へ近づいた時点で見直す。
目標未達を Planning assumption や SLO の引下げで解消しない。

## 更新と廃止

スキーマ変更は拡張と縮小へ分け、アプリケーションの新旧版が混在する期間を通す。
外部契約の非推奨と削除は[API ガイドライン](../design/application/api-guidelines.md)とリリース告知に従う。
機能、データ、鍵、外部連携を廃止するときは、保持、失効、エクスポート、監査、シークレットの廃棄、運用責任の終了を同じ計画で扱う。
