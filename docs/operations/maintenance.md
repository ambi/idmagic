# 保守

## 定期作業

頻度の値は採用する運用環境で決まるが、何をもとに決めるかはここで定める。
実作業は対象ごとの[runbook](../runbooks/)へ置き、この表へ手順を書かない。

| 作業 | 頻度を決める条件 | 担当の分界 | 対応する runbook |
| --- | --- | --- | --- |
| 証明書の更新 | 発行者が定める有効期間。[可用性設計](../design/reliability/availability.md#障害単位ごとの検知と対処)が定める残り日数のアラートが更新の遅れを検知する | 運用基盤側。証明書と DNS はクラスターの外で管理する | 無い |
| 署名鍵の世代交代 | テナントごとの鍵の有効期間。世代交代は `idmagic-batch` が実行する | プロダクト側 | 無い |
| 依存ソフトウェアの更新 | 脆弱性の通知と、定期の更新。どちらか早い方が契機になる | プロダクト側 | 無い |
| バックアップの取得と復元試験 | [リカバリ設計](../design/reliability/recovery.md#データの種類ごとの復旧)の復元試験の頻度 | 取得は運用基盤側、復元試験の内容はプロダクト側 | [バックアップ、復元、災害復旧](../runbooks/backup-restore-dr.md) |
| 可用性と復旧の試験 | 可用性の構成、実行単位の構成、健全性の確認のいずれかの変更。変更が無い期間も定期に実施する。内容は[システム受入れ設計](../verification/system-acceptance.md#可用性と復旧の試験)が定める | 試験の内容はプロダクト側、実施環境の用意は運用基盤側 | [バックアップ、復元、災害復旧](../runbooks/backup-restore-dr.md)（復元試験のみ） |
| データベースの保守 | 統計の陳腐化と肥大の兆候。指標が示す実データの増え方で決める | 運用基盤側。マネージドサービスの自動保守に任せる範囲もここで決める | 無い |
| 保持期限を過ぎたデータの削除 | [データライフサイクル設計](../design/data/lifecycle.md)の保持期間。削除は `idmagic-batch` が実行する | プロダクト側 | 無い |
| 保存容量の確認 | [キャパシティ設計](../design/performance/capacity.md)の前提に対する実測の接近 | 運用基盤側 | 無い |
| アラートと runbook の点検 | アラートの追加、削除、発報の多さ。対応する runbook がないアラートが残っていないかを確かめる | プロダクト側 | 無い |

「無い」と書いた作業に runbook が要るかは、事象の最中に読む手順があるかで決まる。
計画した作業で、失敗しても再実行できるものは runbook を要しない。

## 依存の更新

更新の範囲は、バックエンドとフロントエンドの依存、リポジトリが使う開発ツール、固定した第三者イメージである。
更新は最新の安定バージョンへまとめて上げ、上げられないものだけを個別に残す。

検証は `mise run verify` と、イメージを変えたときの[宣言的なファイルの検証](../verification/README.md#宣言的なファイルの検証)で行う。
既知脆弱性の扱いは[セキュリティ検証設計](../verification/security.md)が定め、抑制には理由と期限を付ける。

後退は、更新をまとめた変更ごと戻す。
一つの依存だけを戻すと、ロックファイルと宣言が食い違ったまま次の更新へ進むことになる。

## キャパシティ見直し

[キャパシティ設計](../design/performance/capacity.md)の仮定値と実測値を比較し、テナント数、データ量、リクエスト率、待ち時間、データベース接続、保存容量のいずれかが前提へ近づいた時点で見直す。
目標未達を、仮定値や SLO の引き下げで解消しない。

## スキーマと外部契約の更新

スキーマ変更は[スキーマ管理](../design/data/schema-management.md#拡張と縮小)の段階に分けて適用し、縮小の段階は人が承認した適用として行う。
外部契約の非推奨と削除は[API ガイドライン](../design/application/api-guidelines.md)とリリース告知に従う。

## 廃止と引渡し

機能、データ、鍵、外部連携の廃止は、一つの計画として次の段階で進める。
段階を分けるのは、失効と廃棄が済んだ後では、利用者が移行できたかを確かめられないためである。

| 段階 | 内容 | 完了の条件 |
| --- | --- | --- |
| 告知 | 廃止の対象、期限、代替手段をリリース告知で知らせる | 対象を使っている利用者が期限と代替手段を得ている |
| 停止 | 新規の利用を止め、既存の利用だけを残す | 新しい利用が発生しない |
| 退避 | 利用者が必要とするデータをエクスポートできる状態を保つ | 保持期間の内に取り出す手段がある |
| 失効 | 発行済みの資格情報、トークン、外部連携の接続先を失効させる | 失効後の呼び出しが通らない |
| 廃棄 | データ、鍵、シークレットを保持期間の規則に従って廃棄する | 復元できる複製が残っていない |
| 引渡し | 監査記録の保管先と、運用責任の終了時点を決める | 記録の保管先と責任の終了が記録されている |

鍵の廃棄は取り消せない。
廃棄した鍵で暗号化したデータは、バックアップから戻しても復号できない。
廃棄の段階へ進む前に、その鍵で暗号化したデータの退避が済んでいることを確かめる。
