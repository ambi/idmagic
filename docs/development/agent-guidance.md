# エージェント向けの指示

この文書は、コーディングエージェントが読む指示（AGENTS.md と `.agents/skills/`）の置き場所、書く内容、skill の書き方を定める。
指示が定める作業の規則そのものは、それぞれの開発文書と設計文書が持つ。

## 置き場所

指示は、毎回読むものと必要なときだけ読むものに分けて置く。
毎回読む文章が長いと、どの作業でも読む量が増え、作業に関係する規則が埋もれるためである。

| 置き場所 | 書くもの | 読まれ方 |
| --- | --- | --- |
| AGENTS.md | 作業ごとの参照先の表と、どの作業にも効く短い規則（`mise` の使い方、ツールの選び方） | どの作業でも最初に読まれる |
| `.agents/skills/<name>/SKILL.md` | 一つの作業を完了する手順と、各段階で読む節 | description が依頼に合うときに読まれる |
| 開発文書と設計文書 | 規則、判断の基準、その理由 | 参照先の表、`brief`、skill から節単位で読まれる |

AGENTS.md の表は `brief` が読む一次情報でもある。
表の行の条件コメントは[作業文脈の導出](task-context.md)に従う。

AGENTS.md に製品の概要やリポジトリの構成の説明を足さない。
エージェントはそれらを README と `docs/` から読めるうえ、文脈ファイルの評価（Gloaguen ほか、arXiv:2602.11988）では、リポジトリの概要を書いても作業の成功率は上がらなかった。

## 書くものと書かないもの

指示に書くのは、このリポジトリに固有で、どのエージェントの実行環境でも成り立つ規約である。
次のものは書かない。

- 特定のエージェントのサンドボックスや権限の制限で起きる失敗とその回避。環境が変われば起きなくなり、別のエージェントには誤った指示になる。ただし、操作が必要とするもの（localhost の待受け、ブラウザーの起動）は環境によらない事実なので、AGENTS.md の `mise` の節のように、その事実を理由として書いてよい。
- どのリポジトリにも当てはまる一般的な注意。エージェントは既に知っており、書いても行動を変えない。
- 一度だけ起きた失敗。

同じ指摘を繰り返し受けたら、上の基準に当たるかを判断してから、その規則を所有する文書か skill へ書く。
機械で確実に判定できる規則だけを検査にし、誤検出しうる規則は文章に留める。
理由は[リポジトリ検査](../../tools/check/README.md#検査の判定基準)の判定基準と同じである。

## skill の書き方

skill の一般的な書き方は Anthropic の「Skill authoring best practices」に従う。
このリポジトリでは、それに加えて次のように書く。

- `name` は一度決めたら変えない。起動の名前であり、ほかの文書と skill が名前で参照するためである。
- `description` は、[文章の言語](writing-language.md)に従って日本語で、「〜する。〜のときに使う。」の二文にする。エージェントは description だけを読んで skill を選ぶので、使う場面を書かないと起動されない。
- skill は手順と、各段階で読む開発文書と設計文書の節へのリンクだけを持つ。規則とその理由は開発文書と設計文書に置き、skill へ写さない。写すと、規則を変えたときに skill が古くなる。
- `mise run` で呼ぶタスクは `mise.toml` に宣言されていなければならない。`check-agent-guidance` が検査する。
