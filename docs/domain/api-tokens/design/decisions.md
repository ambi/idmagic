# ApiTokens の重要な設計判断

この文書は、ApiTokens の設計判断のうち、代替案を比べたものと、見直す条件が要るものを扱う。
一つの要件やモデルだけを正当化する判断は、機能仕様のその要件またはモデルの判断の欄に置く。

## この Context を Generic に分類する

### 背景

ドメイン文書の索引は、各 Context を `Core`、`Supporting`、`Generic` のいずれかに分類する。

### 決定

ApiTokens を `Generic` に分類する。

### 検討した代替案

| 案 | 利点 | 欠点 | 採らない理由 |
| --- | --- | --- | --- |
| `Supporting` | 製品に合わせたトークンの形を設計できる | テナント単位のアクセストークンを発行し、失効させ、スコープで絞る形は、解決済みの問題でほかの製品と変わらない | ここに設計を投資する理由がない |

### 結果と再検討の条件

トークンの形式と失効の経路は、`OAuth2` の部品と標準に従う。
API アクセストークンの扱いを、製品の差別化の主張にする場合に見直す。

### 関連する要件

この判断は分類であり、特定の要件を正当化しない。

## トークンの発行と失効を対話のセッションに限る

### 背景

API アクセストークンは、付与したスコープの集合の範囲で管理 API を呼べる。

### 決定

API アクセストークンの発行、一覧、失効は、API アクセストークンからは呼び出せない、対話のセッションに限る操作とする。

### 検討した代替案

| 案 | 利点 | 欠点 | 採らない理由 |
| --- | --- | --- | --- |
| トークンの管理のスコープを設け、トークンからトークンを発行できるようにする | トークンの入れ替えを自動化できる | トークンでトークンを発行できると、任意のスコープの集合への昇格の経路になる | 漏れたトークンが、より広いトークンを作れてしまう |

### 結果と再検討の条件

トークンが、自分より広いトークンを作ることはない。
その代わり、トークンの入れ替えには、管理者が対話のセッションで操作する必要がある。
発行できるスコープを、提示したトークンのスコープの部分集合に限る仕組みを入れる場合に見直す。

### 関連する要件

| 要件 | 機能仕様 |

| REQ-APITOKENS-004 | [API アクセストークンの認証と認可](../authentication/README.md) |

## 認可に発行者の現在のロールとトークンのスコープの両方を求める

### 背景

トークンは長寿命であり、発行した後に発行者のロールが変わることがある。

### 決定

トークンを提示した呼び出しは、発行者本人として認証する。
認可には、発行者が対象の操作に必要なロールを今も持つことと、トークンのスコープの集合が対象の API を許可することの両方を求める。

### 検討した代替案

| 案 | 利点 | 欠点 | 採らない理由 |
| --- | --- | --- | --- |
| トークンのスコープだけで認可する | 発行者の状態を読まずに判定できる | 発行者がロールを失っても、トークンで管理の操作を続けられる | 退職や降格の後も、権限が残る |

### 結果と再検討の条件

発行者が後からロールを失えば、トークン自体が有効でも管理の操作は通らない。
その代わり、要求のたびに発行者のロールを解決する。
発行者に依らないサービスアカウントのトークンを提供する場合に見直す。

### 関連する要件

| 要件 | 機能仕様 |
| --- | --- |
| REQ-APITOKENS-004 | [API アクセストークンの認証と認可](../authentication/README.md) |

## 署名と管理のレコードの二段でトークンを検証する

### 背景

API アクセストークンは、自己完結した JWT として発行する。
管理者が失効させたトークンは、すぐに使えなくならなければならない。

### 決定

提示された JWT は、署名、発行者、audience、有効期限を満たしたうえで、さらに `jti` に対応する管理のレコードを毎回照合する。

### 検討した代替案

| 案 | 利点 | 欠点 | 採らない理由 |
| --- | --- | --- | --- |
| 署名だけで受け入れる | レコードを読まずに検証できる | 失効は、署名の鍵をローテーションするまで効かない | 失効を即時に効かせられない |
| レコードだけを見る | 署名を検証せずに済む | 偽造された `jti` を拒否できない | 推測した `jti` で成りすませる |

### 結果と再検討の条件

失効は即時に効き、偽造したトークンも拒否できる。
その代わり、要求のたびにレコードを読む。
レコードの照合が、要求の遅延の目標を満たせない規模になった場合に見直す。
