# Tenancy のリスク

この文書は、Tenancy の既知の欠陥、技術的負債、受容したリスクを扱う。
脅威は[脅威モデル](../../../design/security/threat-model.md)に置く。

| リスク | 現状 | 影響 |
| --- | --- | --- |
| Soft の上限が働かない | `audit_events_retained` と `export_artifacts_bytes` の上限は保存できるが、使用量を加算する呼び出しも、警告を発行する処理もない。PostgreSQL の実装はこの二つの加算を受け付け、メモリの実装は未知のリソースとして拒否する | Soft の上限を設定しても、蓄積を検知できない。二つの実装の契約が食い違う |
| 使用量のカウンターを照合する仕組みがない | 使用量は作成と削除の加算と減算だけで保ち、実際のレコード数と突き合わせるジョブはない | 加算や減算が漏れると、カウンターが実際の数からずれたまま残り、上限の判定を誤る。既存のテナントへ初めて上限を適用するときは、現在の使用量を下回らないよう、余裕のある値（現在の使用量の 2 倍、またはデフォルトの 10 倍）から始める必要がある |
