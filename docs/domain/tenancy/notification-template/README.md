# 通知テンプレート

## 概要

この文書は、通知メールの文面のテナントによる上書き、プレビュー、試し送り、通知の言語の解決の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 通知テンプレートの一覧、上書きの保存とリセット、プレビュー、試し送り、通知 1 通の文面と言語の解決 |
| 行為者 | テナント管理者（上書き、プレビュー、試し送り）、通知メールを受け取る利用者（`EndUser`） |
| 扱わないもの | 文面の描画と送信は `backend/shared/notification` が扱う。通知を送る契機は、それぞれの Context が扱う |

## モデル

通知メールの文面（`NotificationTemplate`）は、`template_key` と `locale` の組で一つに定まり、次の 2 段で解決する。

| 段 | 内容 |
| --- | --- |
| テナントによる上書き | `(tenant_id, template_key, locale)` ごとに一つ。版の履歴は持たない |
| 組み込みのデフォルト | システムが同梱する日本語と英語のカタログ。テナントは編集できない |

- `template_key` は仕様で定める固定の列挙であり、テナントは追加できない。各キーは一つの送信経路に対応し、送信元のないテンプレートは作れない。
- 上書きできるのは、件名、HTML 本文の断片、平文本文、差出人の表示名だけである。HTML 文書の外枠と差出人のアドレスはシステムが保持する。
- 上書きは、件名、平文本文、HTML 本文の 3 つを同時に置き換える。メールは `multipart/alternative` として送るので、平文と HTML の内容が意図せず食い違わない。

本文に書ける差し込み変数（`{{name}}`）は、テンプレートキーごとに許可した集合に限る。

| キー | 差し込み変数 |
| --- | --- |
| すべてのキー | `product_name`、`tenant_display_name`、`user_display_name` |
| `PasswordReset`、`EmailVerification`、`EmailChangeConfirmation` | 1 つの `*_url` の導線、`expires_in_minutes` |
| `EmailChangeConfirmation`（追加） | `new_email` |
| `LifecycleWorkflowNotification`（追加） | `notification_key` |
| `AccountSecurityAlert`（追加） | `event_description`、`occurred_at`、`device_summary`、`security_review_url` |
| `ProvisioningConnectionQuarantined`（追加） | `application_id`、`quarantine_reason`、`quarantined_at` |

- **判断**：宣言していない差し込み変数を参照する上書きは、空の値で描画せず、保存時に拒否する。アカウント復旧などの導線が実行時に欠けることを防ぐためである。

通知 1 通の言語は、受信者の `User.locale`、テナントの `default_locale`、システム設定の `DEFAULT_LOCALE`（デフォルト値は `en`）の順に、カタログに翻訳がある最初の言語とする。
`ProvisioningConnectionQuarantined` の宛先は User ではなく接続の `notification_email` なので、受信者の言語はなく、テナントのデフォルト言語から解決し、`user_display_name` は空文字列で描画する。

- **判断**：テナントのデフォルト言語は、明示した設定として持つ。ある言語のテンプレートを上書きしただけで、他の通知までその言語へ変わることを防ぐためである。

## 操作

### 通知メールの文面の解決

#### REQ-TENANCY-015 日本語ロケールのユーザーには日本語のパスワードリセットメールが届く

- 通知メールを送るとき、受信者の `User.locale`、テナントの `default_locale`、システム設定の `DEFAULT_LOCALE` の順に、カタログに翻訳がある最初の言語で文面を描画する。
- 設定されていない段と、カタログに翻訳のない言語の段は飛ばす。どの段でも空の本文のメールを送らない。
- 通知メールは、平文の本文と HTML の本文の両方を含む。
- パスワードのリセットのメールに載せるリンクは、要求を解決したテナントの正規ロケーションから組み立てる。
- **例**：EX-TENANCY-015-01、EX-TENANCY-015-02、EX-TENANCY-015-03、EX-TENANCY-015-04

#### REQ-TENANCY-016 テナントの通知テンプレート上書きは組込みデフォルトより優先される

- 通知メールを送るとき、テナントがそのテンプレートキーと言語の組を上書きしていれば上書きの文面を、上書きしていなければ組み込みの文面を使う。
- ある言語の上書きは、ほかの言語の文面を変えない。
- テナント管理者がテンプレートの一覧を取得したとき、すべてのテンプレートキーと同梱翻訳のあるすべての言語の組を、上書きの有無（`customized`）とともに返す。
- **例**：EX-TENANCY-016-01、EX-TENANCY-016-02、EX-TENANCY-016-03

### テナント管理者による上書きの保存

#### REQ-TENANCY-017 許可されていない差し込み変数を含むテンプレート上書きは保存時に拒否される

- テナント管理者が上書きを保存したとき、件名、平文の本文、HTML の本文、差出人の表示名を保存し、200 と保存後の文面を返し、テンプレートキーと言語を載せた `NotificationTemplateUpdated` を発行する。
- 件名と差出人の表示名は、前後の空白を除いて保存する。
- 差出人のアドレスは上書きできない。
- テンプレートキーに許可した集合にない差し込み変数を含む上書き、件名と平文の本文と HTML の本文のどれかが空の上書きを指定された場合は、400 と `invalid_notification_template` で拒否する。
- カタログにないテンプレートキーまたは言語を指定された場合は、400 と `invalid_request` で拒否する。
- 保存を拒否した場合は、上書きを作らず、保存済みの上書きを変えず、イベントを発行しない。
- **例**：EX-TENANCY-017-01、EX-TENANCY-017-02、EX-TENANCY-017-03、EX-TENANCY-017-04

### テナント管理者による上書きのリセット

#### REQ-TENANCY-039 リセットは、上書きの有無にかかわらず NotificationTemplateReset を発行する

- テナント管理者が上書きをリセットしたとき、上書きを削除し、200 と組み込みの文面を返し、テンプレートキーと言語を載せた `NotificationTemplateReset` を発行する。
- 上書きがないテンプレートのリセットも成功し、`NotificationTemplateReset` を発行する。
- カタログにないテンプレートキーまたは言語を指定された場合は、400 と `invalid_request` で拒否する。
- **例**：EX-TENANCY-039-01

### テナント管理者によるプレビュー

#### REQ-TENANCY-038 プレビューは、空の項目を現在有効な文面で補う

- テナント管理者が文面をプレビューしたとき、差し込み値を展開した件名、平文の本文、HTML の本文を 200 で返し、メールを送らず、上書きを保存しない。
- 空白だけの項目は、現在有効な文面で補う。上書きがあれば上書き、なければ組み込みの文面が現在有効な文面である。
- 差し込み値には固定のサンプル値を使う。`product_name` と `tenant_display_name` だけは、テナントの値を使う。
- HTML の本文に差し込む値はエスケープし、タグとして解釈させない。
- 補った後の文面が許可した集合にない差し込み変数を含む場合は、400 と `invalid_notification_template` で拒否する。
- **例**：EX-TENANCY-038-01、EX-TENANCY-038-02

### テナント管理者による試し送り

#### REQ-TENANCY-018 プレビューは実送信せずテスト送信は操作者本人にしか届かない

- テナント管理者が試し送りを要求したとき、現在有効な文面のメールを、操作者本人の確認済みのメールアドレスへ送る。
- 試し送りの要求は宛先を指定する項目を持たず、操作者本人以外へ送らない。
- 確認済みのメールアドレスを持たない操作者が試し送りを要求した場合は、400 と `invalid_request` で拒否し、メールを送らない。
- **例**：EX-TENANCY-018-01、EX-TENANCY-018-02、EX-TENANCY-018-03、EX-TENANCY-018-04

#### REQ-TENANCY-040 試し送りは編集中の言語の文面を送り、配送の成否を応答で返す

- 文面の言語は、要求が指定した言語とする。操作者の言語とテナントのデフォルト言語へは変えない。
- `user_display_name` には操作者の表示名を使い、表示名がなければメールアドレスを使う。
- 試し送りの応答は、200 と宛先（`to`）と配送の成否（`delivered`）を返す。
- 送信に失敗した場合も 200 を返し、`delivered` を `false` にする。
- **例**：EX-TENANCY-040-01、EX-TENANCY-040-02

## セキュリティ上の考慮

- 資格情報、ダイジェスト値、TOTP のシークレット、API トークン、生の IP アドレスは、差し込み変数にしない。メールは受信者によって転送され、引用され、無期限に保持されるため、後に受信箱が侵害されたときに露出する。
- 試し送りは、操作中の管理者自身の確認済みのアドレスにだけ送り、エンドポイントは宛先を受け取らない。任意の宛先を許すと、テナントのブランド表示を使ったメールを第三者へ送る手段になるためである。
- 下書きのプレビューは、実際の利用者のデータではなく固定のサンプル値で描画する。
- プレビューは描画結果を返すだけなので、API アクセストークンでは参照のスコープで呼べる。試し送りは実際にメールを送るので、変更のスコープを要する。
