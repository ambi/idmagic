# リソース上限

## 概要

この文書は、テナントごとのリソース上限のデフォルト値、上書き、使用量の計数、超過時の拒否の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 上限のデフォルト値と上書き、使用量の加算と減算、超過する作成の拒否 |
| 行為者 | System 管理者（上限の変更）、テナント管理者（自身の上限と使用量の参照）、リソースを作成する各 Context（上限の確認） |
| 扱わないもの | 上限を確認する契機。各リソースを作成する Context が、作成のトランザクションの中で確認を呼び出す |

## モデル

リソースの作成には、テナントごとの上限を設ける。
共有基盤の上で、負荷の高い、または暴走した一つのテナントが及ぼす影響の範囲を抑えるためである。
上限は、強制の方法によって二つに分かれる。

| 種類 | リソース | 超過したとき |
| --- | --- | --- |
| Hard | `users`、`groups`、`agents`、`applications`、`oauth2_clients`、`active_sessions`、`consents`、`active_jobs`、`ssf_streams` | 作成のトランザクションの中で同期的に確認し、操作を拒否する |
| Soft | `audit_events_retained`、`export_artifacts_bytes` | 操作を成功させ、非同期の警告と監査イベントを発行する |

- **判断**：二つに分ける理由は、[リソース上限を Hard と Soft に分ける](../design/decisions.md#リソース上限を-hard-と-soft-に分ける)。
- **判断**：SSF ストリームの上限は、送信側と受信側で分けず、`SsfStream` のレコード数として一つの上限で数える。向きは同じ集合の属性でしかなく、上限を分けても、抑えたい資源（ストリーム 1 本ごとに増える配送先、鍵の取得先、保持する配送記録）は変わらないためである。

## 操作

### System 管理者による上限の更新

#### REQ-TENANCY-012 System管理者はテナントのクォータ上限を調整できる

#### REQ-TENANCY-037 クォータの更新は上書きの全体を置き換える

- 要求に含めたリソースの上書きを保存し、含めなかったリソースの上書きを消してデフォルト値へ戻す。
- 現在の使用量を下回る上限も保存する。既存のリソースは残し、新しい作成だけを拒否する。
- **担保手段**：`QuotaRepository.SetQuota`
- **要判断**：負の上限を検証せずに保存する。負の上限はすべての作成を拒否する。負の値を拒否するかを決める。

### リソースの作成時の上限の確認

#### REQ-TENANCY-036 Hard Quota の実効値は、上書きがあればその値、なければデフォルト値である

| リソース | デフォルト値 |
| --- | --- |
| `users` | 10,000 |
| `groups` | 1,000 |
| `agents` | 100 |
| `applications` | 50 |
| `oauth2_clients` | 100 |
| `active_sessions` | 50,000 |
| `consents` | 10,000 |
| `active_jobs` | 10 |
| `ssf_streams` | 20 |

- 使用量に加算分を足した値が実効値を超える作成を拒否し、使用量を変えない。実効値と等しくなる作成は受け付ける。
- 上書きが 0 のリソースは、すべての作成を拒否する。
- 表にないリソース名の確認は失敗させ、使用量を変えない。
- 使用量の減算は 0 を下回らない。
- **判断**：Hard の上限はデータベースの枯渇を防ぐために同期的に止める。詳細は[リソース上限を Hard と Soft に分ける](../design/decisions.md#リソース上限を-hard-と-soft-に分ける)。
- **担保手段**：`TenantQuota.EffectiveLimit`、`QuotaRepository.CheckAndIncrement`、`QuotaRepository.Decrement`

#### REQ-TENANCY-013 Hard Quota を超過したリソース作成は拒否される

## セキュリティ上の考慮

上限を変更できるのは System 管理者だけである。
テナント管理者は、テナント設定の取得で自身の上限と使用量を参照できるが、変更はできない。
理由は、[管理の認可を所属テナント内の admin とテナントを越える system_admin の 2 段にする](../design/decisions.md#管理の認可を所属テナント内の-admin-とテナントを越える-system_admin-の-2-段にする)。
