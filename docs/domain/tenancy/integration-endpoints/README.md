# 連携エンドポイント

## 概要

この文書は、テナント管理者へ示す、正規ロケーションから導出した各プロトコルと API の URL の一覧の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 解決したテナントの正規の発行者から、OAuth/OIDC、SAML、WS-Federation、SCIM、管理 API、本人用 API の URL と署名証明書の情報を導出して返す |
| 行為者 | テナント管理者 |
| 扱わないもの | 一覧に載る各エンドポイントの振る舞いは、それぞれのプロトコルの Context が扱う |

## 操作

### テナント管理者による連携エンドポイントの取得

#### REQ-TENANCY-001 管理者は正規ロケーションの連携情報を取得する

- テナント管理者が連携エンドポイントを取得したとき、要求を解決したテナントの発行者から OAuth/OIDC、SAML、WS-Federation、管理 API、SCIM、本人用 API の URL を導出し、200 と発行者とともに返す。
- SAML のエンティティ ID と WS-Federation の realm は、そのテナントの発行者とする。
- SAML の署名証明書は、取得 URL、フィンガープリント、有効期間を返す。
- 応答には、クライアントシークレット、API トークン、秘密鍵を含めない。
- 連携エンドポイントの取得は対象のテナントを指定する入力を持たず、要求を解決したテナント以外の情報を返さない。
- 正規の発行者と同じオリジンで配信するゲートウェイは、一覧に載る公開のプロトコルの URL への要求を、対応するサーバーのエンドポイントへ転送する。
- **例**：EX-TENANCY-001-01、EX-TENANCY-001-02

#### REQ-TENANCY-041 署名証明書のフィンガープリントは、SHA-256 をコロンで区切った大文字の 16 進で返す

- 署名証明書のフィンガープリントは、証明書の DER の SHA-256 を、大文字の 16 進 2 桁ごとにコロンで区切って返す。
- 証明書の有効期間は UTC で返す。
- **例**：EX-TENANCY-041-01

#### REQ-TENANCY-042 署名用の資格情報を解決できないときは、連携情報を返さない

- 署名用の資格情報または証明書を解決できない場合は、503 と `federation_credentials_unavailable` を返し、証明書を除いた一部だけの連携情報も返さない。
- **例**：EX-TENANCY-042-01
