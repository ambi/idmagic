# ブランド設定

## 概要

この文書は、ホステッド UI に表示するプロダクト名、ロゴ、ファビコン、配色、フッターの設定と、その公開配信の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | ブランド設定の保存、ロゴとファビコンのアップロードと削除、ブランド設定とブランドアセットの公開配信 |
| 行為者 | テナント管理者（設定の変更）、未認証の利用者（公開配信の取得） |
| 扱わないもの | 画面の描画はフロントエンドが、画像の形式の検証は `backend/shared/mediavalidation` が扱う |

## モデル

`TenantBranding` は、テナントごとに一つのブランド設定であり、`Tenant` とは別に保存する。
項目は、プロダクト名、ロゴ、ファビコン、2 つのブランドカラー（`primary_color`、`accent_color`）、2 つのフッターリンク（`footer_link_1`、`footer_link_2`）、フッター文言（`footer_text`）に限る。
任意の CSS、HTML、スクリプト、背景画像は受け付けない。

- **判断**：外装として受け取る項目を限るのは、信頼できないテナントの入力を、共有のログインシェルへマークアップとして渡さないためである。
- **判断**：`Tenant` に埋め込まない理由は、[外装と属性スキーマを Tenant から独立した Aggregate にする](../design/decisions.md#外装と属性スキーマを-tenant-から独立した-aggregate-にする)。

## 操作

### テナント管理者によるブランド設定の更新

#### REQ-TENANCY-004 管理者はテナントのロゴと配色をカスタマイズでき利用者のログイン画面に反映される

- テナント管理者がブランド設定を更新したとき、Tenancy は、要求に含まれた項目を保存し、200 と保存後のブランド設定を返し、要求に含まれた項目の名前を `changed_fields` に載せた `TenantBrandingUpdated` を発行する。
- 利用者がログイン、同意、アカウントポータルの画面を開いたとき、Tenancy は、そのテナントのロゴを表示する。
- 利用者がログイン画面を開いたとき、Tenancy は、そのテナントのブランドカラー、フッターリンク、フッター文言を表示し、未設定の項目にはシステムデフォルトを表示する。
- **例**：EX-TENANCY-004-01、EX-TENANCY-004-02、EX-TENANCY-004-03

#### REQ-TENANCY-032 ブランド設定の文字列は空白を除いて保存し、空文字列は未設定に戻す

- テナント管理者がブランド設定を更新したとき、Tenancy は、文字列の項目を前後の空白を除いて保存する。
- テナント管理者がブランド設定を更新したとき、Tenancy は、省略した項目の保存済みの値を変えず、空文字列を指定した項目を未設定に戻す。
- テナント管理者がブランド設定を更新したとき、Tenancy は、色の 16 進の大文字と小文字を区別せずに受け付ける。
- 81 文字以上の `product_name` またはフッターリンクのラベル、281 文字以上の `footer_text`、2,049 文字以上のフッターリンクの URL を指定された場合、Tenancy は、400 と `invalid_branding` で拒否し、どの項目も保存せず、イベントを発行しない。
- `#` と 16 進 6 桁の形でない色を指定された場合、Tenancy は、400 と `invalid_branding` で拒否し、どの項目も保存せず、イベントを発行しない。
- 小文字の `https://` で始まらないフッターリンクの URL を指定された場合、Tenancy は、400 と `invalid_branding` で拒否し、どの項目も保存せず、イベントを発行しない。
- フッターリンクのラベルと URL の一方だけを指定された場合、Tenancy は、400 と `invalid_branding` で拒否し、どの項目も保存せず、イベントを発行しない。
- **判断**：色は形式だけを検証し、WCAG のコントラストを保存時の制約にしない。管理 UI で結果を確認できるようにし、最終的な可読性はテナントが負う。
- **例**：EX-TENANCY-032-01、EX-TENANCY-032-02、EX-TENANCY-032-03

#### REQ-TENANCY-005 不正な branding 入力は拒否されシステムデフォルトにフォールバックする

- ブランド設定を一度も保存していないテナントでは、利用者がログイン画面を開いたとき、Tenancy は、システムデフォルト（IdMagic）の外装を表示する。
- ブランド設定の更新またはアセットのアップロードを拒否した場合、Tenancy は、保存済みのブランド設定を変えず、ログイン画面に拒否の前と同じ設定と、未設定の項目のシステムデフォルトを表示し続ける。
- テナント管理者がコントラストの低い色を形式どおりに指定したとき、Tenancy は、その色を保存し、ログイン画面に反映する。
- **例**：EX-TENANCY-005-01、EX-TENANCY-005-02

### テナント管理者によるロゴとファビコンのアップロードと削除

#### REQ-TENANCY-033 ロゴとファビコンは 256 KiB 以下の PNG、JPEG、WebP、GIF だけを受け付ける

- テナント管理者がロゴまたはファビコンをアップロードしたとき、Tenancy は、画像を新しい ID で保存し、`logo_url` または `favicon_url` をその ID の配信 URL に置き換え、200 と保存後のブランド設定を返す。
- テナント管理者がロゴまたはファビコンを削除したとき、Tenancy は、保存済みの画像と URL を消し、200 と保存後のブランド設定を返す。
- ブランド設定が未設定のテナントでは、テナント管理者がロゴまたはファビコンを削除したとき、Tenancy は、200 と未設定のブランド設定を返す。
- テナント管理者がロゴまたはファビコンのアップロードまたは削除に成功したとき、Tenancy は、種別を `changed_fields` に載せた `TenantBrandingUpdated` を発行する。
- 種別に `logo` と `favicon` 以外を指定された場合、Tenancy は、400 と `invalid_request` で拒否する。
- 先頭のバイト列が PNG、JPEG、WebP、GIF のどれでもない画像を指定された場合、Tenancy は、400 と `invalid_request` で拒否する。
- 262,144 バイトを超える画像を指定されたか、画像のない要求を受け取った場合、Tenancy は、400 と `invalid_request` で拒否する。
- アップロードを拒否した場合、Tenancy は、ブランド設定を変えず、イベントを発行しない。
- **例**：EX-TENANCY-033-01、EX-TENANCY-033-02、EX-TENANCY-033-03

### ブランド設定の公開の取得

#### REQ-TENANCY-034 公開のブランド設定は、版を表す ETag とともに返す

- ブランド設定を取得したとき、Tenancy は、認証を求めず、200 と未設定の項目を省いたブランド設定を返す。
- ブランド設定が未設定のテナントでは、ブランド設定を取得したとき、Tenancy は、ETag に `"branding-default"` を返す。
- ブランド設定を保存済みのテナントでは、ブランド設定を取得したとき、Tenancy は、最終更新時刻から導出した ETag を返す。
- ブランド設定を更新したとき、Tenancy は、以後の取得で返す ETag を変える。
- `If-None-Match` が ETag と完全に一致する要求でブランド設定を取得したとき、Tenancy は、本文のない 304 を返す。
- ブランド設定を取得したとき、Tenancy は、応答に `Cache-Control: public, max-age=60` を付ける。
- **例**：EX-TENANCY-034-01、EX-TENANCY-034-02、EX-TENANCY-034-03

### ブランドアセットの配信

#### REQ-TENANCY-035 ブランドアセットは、検証済みの形式と nosniff を付けて配信する

- ブランドアセットを取得したとき、Tenancy は、認証を求めず、保存した画像のバイト列を、保存時に先頭のバイト列から判定した形式の `Content-Type` で返す。
- ブランドアセットを取得したとき、Tenancy は、応答に `X-Content-Type-Options: nosniff` と `Cache-Control: private, max-age=3600` を付ける。
- 種別が `logo` でも `favicon` でもないか、ID が存在しないか、ID が別のテナントのものである場合、Tenancy は、404 と `not_found` を返し、画像を返さない。
- **例**：EX-TENANCY-035-01、EX-TENANCY-035-02

## セキュリティ上の考慮

ブランド設定は、信頼できないテナントの入力を、すべてのテナントが共有するログインシェルへ渡す経路である。

| 入力 | 共有のログインシェルへの渡し方 |
| --- | --- |
| ブランドカラー | `#rrggbb` として検証し、固定した 2 つの CSS カスタムプロパティ（`--tenant-brand-primary`、`--tenant-brand-accent`）にだけ注入する |
| テキストの項目 | デフォルトのエスケープ処理で描画し、`dangerouslySetInnerHTML` を使わない |
| フッターリンクの URL | `https://` のスキームだけを許し、`javascript:`、`data:`、平文の `http://` を書き込み時に拒否する |
| ロゴとファビコン | 先頭のバイト列、大きさ、形式を検証し、`nosniff` を付けて配信する |
