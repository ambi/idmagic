# 属性スキーマ

## 概要

この文書は、テナントごとのユーザー属性とグループ属性のカスタム定義の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | ユーザー属性スキーマとグループ属性スキーマの保存と取得 |
| 行為者 | テナント管理者 |
| 扱わないもの | 属性定義そのものの形式と、属性値の検証は `IdManagement` が扱う |

## モデル

ユーザー属性スキーマ（`TenantUserAttributeSchema`）とグループ属性スキーマ（`TenantGroupAttributeSchema`）は、テナントごとに一つずつあり、`Tenant` とは別に保存する。

- **判断**：グループ属性スキーマをユーザー属性スキーマと統合せず、別の Aggregate とする。テナント単位の属性スキーマはどのプリンシパルのものであれ `Tenancy` に置くが、`Group` には照合先となる組み込みのカタログが存在しないためである。
- **判断**：`Tenant` に埋め込まない理由は、[外装と属性スキーマを Tenant から独立した Aggregate にする](../design/decisions.md#外装と属性スキーマを-tenant-から独立した-aggregate-にする)。

## 操作

### テナント管理者によるユーザー属性スキーマの更新

#### REQ-TENANCY-002 管理者はテナント固有のユーザー属性スキーマを定義できる

#### REQ-TENANCY-043 動的グループの規則が参照するユーザー属性は、削除も型の変更もできない

- ユーザー属性スキーマの更新は定義の全体を置き換え、要求にない属性を削除する。
- 動的グループの規則が参照する属性を削除する更新と、その属性の型を変える更新は、`attribute_referenced_by_dynamic_group` の 409 で拒否する。
- 拒否した場合は、スキーマを変えず、イベントを発行しない。
- 定義が不正な更新は `invalid_attribute_schema` の 422 で拒否する。
- **担保手段**：`Deps.handleUpdateUserAttributeSchema`
