# テナント設定

## 概要

この文書は、テナント管理者が自身のテナントに設定する表示名、セキュリティポリシーの上書き、通知のデフォルト言語の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 表示名、パスワードポリシーと委譲の深さと信頼済みデバイスの有効期間の上書き、通知のデフォルト言語の保存と取得 |
| 行為者 | テナント管理者 |
| 扱わないもの | 上書きされた値を使う判定そのもの。パスワードの検証と信頼済みデバイスは `Authentication` が、委譲の深さの判定は `OAuth2` が扱う |

## モデル

テナントのセキュリティポリシーの上書きは、デプロイ全体のプロダクトデフォルトを緩めず、厳しい方向にだけ働く。

| 上書き | 厳しい方向 | 上書きの解除 |
| --- | --- | --- |
| パスワードポリシー | 最小長と履歴件数を下げず、最大長を上げない | 省略または 0 以下の項目は、プロダクトのデフォルト値を継承する |
| Token Exchange の `max_delegation_depth` | システムデフォルトの 3 を超えて上げない。未設定なら 3 を継承する | `0` は委譲を全面禁止する値ではなく、上書きを解除する |
| `trusted_device_max_age_seconds` | デフォルトが「機能なし」の側にあるので、方向が逆になる。正の値は、テナントが第二要素の省略を明示的に有効にしたことを表す | 未設定と `0` は、どちらも信頼済みデバイスを無効にする値であり、上書きの解除ではない |

設定の取得は、現在の上書きとシステムデフォルトを別々に返す。
管理 UI が、継承している状態と実効値を区別できるようにするためである。

- **判断**：上書きを厳しい方向にだけ許し、上書きを解決できないときもデフォルトへ退避せずに拒否する。退避すると、テナントが意図して狭めた認可境界を黙って広げてしまうからである。

## 操作

### テナント管理者による設定の更新

#### REQ-TENANCY-019 管理者はパスワードポリシー設定を参照・更新できる

- テナント管理者が設定を取得したとき、Tenancy は、パスワードポリシーの上書き（`password_policy_override`）と、プロダクトのデフォルト値（`password_policy_defaults`）を別々に返す。
- パスワードポリシーの上書きのないテナントでは、テナント管理者が設定を取得したとき、Tenancy は、`password_policy_override` を省く。
- 上書きのないパスワードポリシーの項目では、Tenancy は、プロダクトのデフォルト値（最小長 12、最大長 128、履歴件数 5、有効期限の日数 0（有効期限なし））を使う。
- テナント管理者がパスワードポリシーの上書きを保存したとき、Tenancy は、上書きを保存し、200 と更新後の設定を返し、以後のパスワードの検証と有効期限の判定に上書きを使う。
- 最小長が 12 未満、最大長が 128 を超える、または履歴件数が 5 未満の上書きを指定された場合、Tenancy は、422 と `policy_override_weaker` で拒否し、保存済みの値を変えない。
- 有効期限の日数（`max_age_days`）が 30 未満または 3,650 を超える上書きを指定された場合、Tenancy は、422 と `policy_override_weaker` で拒否し、保存済みの値を変えない。
- **判断**：有効期限の日数は、短いほど安全とはいえない。極端に短い周期は予測しやすいパスワードを招き、極端に長い周期は設定の意味を失わせるので、デフォルト値からの方向ではなく固定の範囲で検証する。
- **例**：EX-TENANCY-019-01、EX-TENANCY-019-02、EX-TENANCY-019-03

#### REQ-TENANCY-021 委譲深さの上書きは厳しい方向にのみ働く

- テナント管理者が `max_delegation_depth` に 1 以上 3 以下の値を保存したとき、Tenancy は、その値を Token Exchange の委譲の深さの上限として保存する。
- テナント管理者が `max_delegation_depth` に `0` を指定したとき、Tenancy は、上書きを消し、システムデフォルトの 3 を継承する状態に戻す。
- 負の値と 3 を超える値を指定された場合、Tenancy は、422 と `policy_override_weaker` で拒否し、保存済みの値を変えない。
- テナント管理者が `max_delegation_depth` を省略して設定を更新したとき、Tenancy は、保存済みの値を変えない。
- テナント管理者が設定を取得したとき、Tenancy は、現在の上書き（`max_delegation_depth`）とシステムデフォルト（`max_delegation_depth_default`）を別々に返す。
- 委譲の深さの上書きのないテナントでは、テナント管理者が設定を取得したとき、Tenancy は、`max_delegation_depth` を省く。
- **例**：EX-TENANCY-021-01、EX-TENANCY-021-02、EX-TENANCY-021-03、EX-TENANCY-021-04、EX-TENANCY-021-05

#### REQ-TENANCY-028 信頼済みデバイスの有効期間は 0 で無効にし、90 日を超える値を拒否する

- テナント管理者が `trusted_device_max_age_seconds` を省略して設定を更新したとき、Tenancy は、保存済みの値を変えない。
- テナント管理者が `trusted_device_max_age_seconds` に `0` を指定したとき、Tenancy は、信頼済みデバイスを無効にし、以後の設定の取得でこの項目を省く。
- テナント管理者が `trusted_device_max_age_seconds` に 1 以上 7,776,000（90 日）以下の値を指定したとき、Tenancy は、その値を保存する。
- 負の値と 7,776,000 を超える値を指定された場合、Tenancy は、422 と `policy_override_weaker` で拒否し、保存済みの値を変えない。
- テナント管理者が設定を取得したとき、Tenancy は、上限の 7,776,000 を `trusted_device_max_age_seconds_ceiling` として返す。
- 保存済みの値が範囲の外にあるテナントでは、Tenancy は、信頼済みデバイスを無効として扱う。
- **判断**：ほかの上書きと違い、緩める方向の値を保存できる。この設定のデフォルトが、最も厳しい状態そのものだからである。システムの上限を超える値だけを拒否する。
- **例**：EX-TENANCY-028-01、EX-TENANCY-028-02、EX-TENANCY-028-03、EX-TENANCY-028-04

#### REQ-TENANCY-029 通知のデフォルト言語は、同梱翻訳のある言語だけを受け付ける

- テナント管理者が `default_locale` を指定したとき、Tenancy は、前後の空白を除いてから検証し、保存する。
- テナント管理者が `default_locale` に空文字列を指定したとき、Tenancy は、設定を消し、システムのデフォルト言語を使う状態に戻し、以後の設定の取得でこの項目を省く。
- 同梱翻訳のない言語を指定された場合、Tenancy は、400 と `invalid_request` で拒否し、保存済みの値を変えない。
- テナント管理者が設定を取得したとき、Tenancy は、同梱翻訳のある言語の一覧を `supported_locales` として返す。
- **例**：EX-TENANCY-029-01、EX-TENANCY-029-02、EX-TENANCY-029-03

#### REQ-TENANCY-030 パスワードポリシーの上書きは 0 以下の項目を継承として読み、上書きを含む更新だけが基準時刻を進める

- テナント管理者がパスワードポリシーの上書きを保存したとき、Tenancy は、省略または 0 以下の値の項目を、プロダクトのデフォルト値の継承として保存する。
- すべての項目が継承である上書きを保存したとき、Tenancy は、上書きそのものを消す。
- 要求が `password_policy_override` を含む場合、Tenancy は、値が保存済みと同じでも `password_policy_updated_at` を要求の時刻に進める。
- 要求が `password_policy_override` を含まない場合、Tenancy は、`password_policy_updated_at` を変えない。
- **判断**：パスワードの有効期限は `password_policy_updated_at` から測る。表示名だけの更新で進めると、有効期限の猶予が際限なく延びる。
- **例**：EX-TENANCY-030-01、EX-TENANCY-030-02、EX-TENANCY-030-03

#### REQ-TENANCY-031 設定の更新は、要求に含まれた項目を TenantUpdated に記録する

- テナント管理者が設定を更新したとき、Tenancy は、200 と更新後の設定を返し、`TenantUpdated` を発行する。
- テナント管理者が設定を更新したとき、Tenancy は、値が変わったかにかかわらず、要求に含まれた項目の名前を `TenantUpdated` の `changed_fields` に載せる。
- テナント管理者が表示名を更新したとき、Tenancy は、前後の空白を除いて保存する。
- 前後の空白を除くと空になる表示名を指定された場合、Tenancy は、400 と `invalid_request` で拒否する。
- 要求のどれか一つの項目を拒否した場合、Tenancy は、どの項目も保存せず、イベントを発行しない。
- **例**：EX-TENANCY-031-01、EX-TENANCY-031-02

### System 管理者によるテナントの設定の更新

#### REQ-TENANCY-044 System 管理者によるテナントの設定の更新は、テナント管理者の更新と同じ規則で検証する

- System 管理者が realm を指定してテナントの設定を更新したとき、Tenancy は、そのテナントの表示名、パスワードポリシーの上書き、`max_delegation_depth`、`trusted_device_max_age_seconds` を保存し、200 と更新後のテナントを返し、要求に含まれた項目の名前を `changed_fields` に載せた `TenantUpdated` を発行する。
- System 管理者がテナントの設定を更新したとき、Tenancy は、各項目をテナント管理者による更新と同じ規則で検証し、拒否する。
- System 管理者による設定の更新を拒否した場合、Tenancy は、どの項目も保存せず、イベントを発行しない。
- 存在しない realm を指定された場合、Tenancy は、404 と `tenant_not_found` で拒否する。
