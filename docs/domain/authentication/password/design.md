# パスワードの設計

この文書は、[パスワード](README.md)の要件を保証する仕組みを扱う。

## アーキテクチャ

パスワードを忘れた場合の処理は、単回限りの 32 バイトの乱数のトークンを発行し、`password_reset_tokens` には SHA-256 のハッシュとしてだけ保存する（`ttl=1800s`）。
トークンは共通のアクショントークンの核が発行し検証する（[設計ガイドライン](../../../design/application/design-guidelines.md)）。
この Context ではパスワードという用途に固有の作用だけを実装し、目的の束縛、有効期限、ダイジェストだけの保存を自前で書かない。
引き換えでは、パスワードの変更と同じ検証、履歴、漏洩の一連の処理を通す。

`BreachedPasswordChecker` は、同梱の辞書に加えて HIBP の Range API を使える。
k-匿名性を保つため、外部へ送るのは SHA-1 の接頭辞だけである。
デフォルトは何もしないアダプターで、`breached_password_check_enabled=false` とするので、外部への依存を持ち込まない。

メールは `EmailSender` のポートを通じて配送する。
本番のアダプターは送信サービスごとの HTTP の SDK ではなく SMTP を使い、デフォルトで STARTTLS を求め、PLAIN の認証は TLS の上でだけ許す。
送信の前に CRLF と NUL を除き、HTML の本文へ差し込む値を無害化し、件名を RFC 2047 で符号化して、SMTP のヘッダーや HTML への注入を防ぐ。

## データ

履歴は、`password_hash` と同じ Argon2id の PHC の文字列として `password_histories` に保存する。
別の符号化にしても攻撃の費用は上がらず、二重の保守が増えるだけだからである。
履歴は登録時とパスワードの変更時の両方で書き込む（初回と同じ値への変更も検出できるようにするため）。

パスワードのハッシュの復号は、コスト、salt、digest の長さをすべて範囲に収めてから argon2 へ渡す。
`argon2.IDKey` は繰り返しの回数と並列度が 1 未満だとパニックし、鍵の長さが 0 だと内部で nil の blake2b の digest をつかんで落ちる。
保存済みのハッシュの 1 レコードが壊れているだけで、検証の経路が止まってはならない。

## 信頼性

トークンの使用済み化と、パスワードおよび履歴の保存は、一つのトランザクションで確定する。
分けると、同じリンクで二度パスワードが変わる状態か、パスワードの規則や履歴の照合で拒否された利用者がリンクだけを失う状態のどちらかが起きる。
後者は、正当な利用者から回復の手段を奪うという点で、拒否そのものより重い。
したがって、作用の前にトークンを消費せず、作用が失敗したときはトークンを未使用のまま残す。

漏洩の照合はフェイルオープンとし、タイムアウトや障害では資格情報の変更を止めず `breached=false` を返すが、障害自体は監査用に記録する。
