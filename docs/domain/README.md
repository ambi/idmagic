# モジュール設計

この文書は、モジュールごとの責務、公開契約、振る舞い、内部設計を収める文書の入口である。
システム全体の構成と共有する設計は[設計文書](../design/README.md)、製品の目的と要求は[要求文書](../requirements/README.md)で定める。

モジュールは、保存表現、正規化、外部プロトコルの変換など、変わりうる設計判断を内部へ隠す単位として設計する。
境界の追加や変更は、要求と不変条件、状態の更新元、公開範囲、変更の波及を[境界を選ぶ判断手順](../design/application/design-guidelines.md#境界を選ぶ判断手順)で比較して決める。
`docs/domain/` は既存の文書パスであり、文書の区分名は「モジュール設計」とする。

## システム全体

モジュールを跨いで固定されるもの。
どのモジュールを読む前でも成り立つ。

| 文書 | 内容 |
| --- | --- |
| [用語集](glossary.md) | モジュールを跨いで意味が固定される語 |
| [全体の標準仕様](standards.md) | システム全体として準拠する外部規範 |
| [コード構成](structure.md) | モジュールの内部構造、依存規則、公開範囲、モジュール間イベント、リポジトリの配置 |
| [システム横断シナリオ](scenarios.feature.md) | 一つのモジュールでは起こせない振る舞いの規範シナリオ |

## モジュール

モジュールの一覧は[論理アーキテクチャ](../design/architecture/logical.md#モジュールの責務)の責務表に記録する。
ここに一覧を複製すると、モジュールを足したときに片方が古くなる。

各モジュールには責務と境界を宣言する `README.md` と、設計の話題を索引する `design/README.md` を置く。
その他の文書は、書くべき仕様や設計があるときに置く。

| 文書 | 内容 |
| --- | --- |
| `README.md` | 責務と境界、モデル、公開契約、機能の索引 |
| `glossary.md` | モジュール固有の語義と、全体の語を狭めた定義 |
| `standards.md` | 採用する外部規範と逸脱 |
| `quality.md` | システムから割り当てられた品質要件と固有の値 |
| `design/README.md` | 設計の話題の索引。該当しない話題には理由を書く |
| `design/<topic>.md` | アーキテクチャ、データ、セキュリティなど、話題ごとの内部設計 |
| `design/decisions.md` | 代替案を比べた、現在有効な判断と見直し条件 |
| `<group>/README.md` | 関係の深い機能の境界と索引。機能群を置かない構成も許す |
| `<group>/<feature>/README.md` と章 | 一つの機能の要件、操作、状態遷移 |
| `<group>/<feature>/acceptance.feature.md` | 要件に付ける任意の受け入れ例 |
| `<group>/<feature>/design.md` | その機能に閉じた、コードから読み取れない仕組み |

モデル、API、認証機構の契約は `spec/contexts/<context>/` の TypeSpec が定める。
散文の側に同じ契約を書かない。
配置と記述規則は[仕様フォーマット](../formats/specification-format.md)が定める。
