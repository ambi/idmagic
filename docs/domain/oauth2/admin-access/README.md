# 管理 API の認可

## 概要

この文書は、OAuth2 の管理 API の認可と、ロールポリシーの確認の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 管理 API のクライアントのリソースごとのスコープによる認可、管理者が見えるロールポリシーの一覧 |
| 行為者 | 管理 API のクライアント、テナント管理者 |
| 扱わないもの | システム全体の認可は[認可設計](../../../design/security/authorization.md)が扱う |

## モデル

すべての認可の判定は AuthZEN の形式の `authorize()` ポートを通り、規則表が要件の論理積を評価する。
判定を返せない場合、事実が欠けている場合、ストアへ到達できない場合のいずれも、許可へ退避しない。

- **判断**：AuthZEN 型のポートを使う理由は、[ポリシーの境界をまたぐ認可の判断を AuthZEN 型のポートに通す](../design/decisions.md#ポリシーの境界をまたぐ認可の判断を-authzen-型のポートに通す)。

## 操作

### 管理 API のクライアントによる操作

#### REQ-OAUTH2-003 管理 API クライアントは OAuth リソースのスコープで許可された操作だけを実行できる

### 管理者によるロールポリシーの確認

#### REQ-OAUTH2-004 管理者は自身に可視なロールポリシーを確認できる

## セキュリティ上の考慮

管理 API では、API アクセストークンにロールに加えて、リソースごとのスコープを求める。
リソースをまたぐ流用はできず、あるリソースのスコープで別のリソースを操作することはない。
