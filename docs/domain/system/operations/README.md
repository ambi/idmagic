# 運用

## 概要

この文書は、運用者が SLO を検証し、プロセスの状態を観測するための仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 運用のマニフェストによる SLO の評価、生存、受付可否、起動完了のプローブ、永続化のクエリの期限 |
| 行為者 | Operator |
| 扱わないもの | SLO の値は[品質要求](../../../requirements/quality.md)が、監視の設計は[オブザーバビリティ設計](../../../design/observability/README.md)が扱う |

## 操作

### 運用者による運用の資産の適用

#### REQ-SYSTEM-001 Operator は分離された運用資産で SLO を検証する

### 運用者によるプローブの呼び出し

#### REQ-SYSTEM-002 オーケストレーション用プローブはプロセスのライフサイクルと依存先の状態を区別する

### System による永続化のクエリ

#### REQ-SYSTEM-012 PostgreSQL クエリの期限は結果の読み取り完了まで維持される

## セキュリティ上の考慮

生存確認、受付可否、起動完了の各プローブは認証を要さないが、返すのは状態だけで、設定値や依存先の詳細は含めない。
`/metrics` も認証しないので、公開先は折り返しのアドレス、管理用のネットワーク、認証付きのプロキシの背後に限る。
