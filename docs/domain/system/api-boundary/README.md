# API の境界

## 概要

この文書は、API の経路の分け方と、経路が表す認可の範囲の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 経路の種類ごとの認可の分離、非推奨のインターフェースのヘッダー、テナント横断の操作の入口の限定、フロントエンドのゲートウェイの許可リストと経路表の照合 |
| 行為者 | APIConsumer、System 管理者、Operator |
| 扱わないもの | 各操作の権限は、記録の正を持つ各 Context と[認可設計](../../../design/security/authorization.md)が扱う |

## モデル

入口は四つに分かれ、それぞれ別の認可を通る。

| 入口 | 経路 | 認可 |
| --- | --- | --- |
| ブラウザー向けの認証 API | `/api/auth/*` | 認可トランザクションの Cookie |
| 管理 API | `/api/admin/*` | ポータルの境界のスコープ `idmagic.admin` と、各 Context のロールとスコープ |
| セルフサービス API | `/api/account/*` | ポータルの境界のスコープ `idmagic.account` と、本人の範囲 |
| OAuth と OIDC のプロトコルのエンドポイント | 各標準が定めるパス | 各標準と `OAuth2` |

ログインの途中であることは、管理の操作の権限に影響しない。
アカウントポータルのトークンで管理 API を呼ぶ経路は、フェイルクローズで塞ぐ。

テナントの境界を越える操作は、システムコンソール（`/system`）と、制御面主体の専用のシステム API だけに置く。
どの操作が横断かは散文に一覧せず、TypeSpec がテナントの側とシステムの側を別の操作の記号として定義する。

- **判断**：入口を一つにする理由は、[テナント横断の操作の入口を一つにする](../design/decisions.md#テナント横断の操作の入口を一つにする)。

## 操作

### API の利用者による非推奨のインターフェースの呼び出し

#### REQ-SYSTEM-014 非推奨のインターフェースを呼ぶと Deprecation / Sunset ヘッダーが返る

- `deprecated_since` を設定したインターフェースを呼び出されたとき、System は、応答に `Deprecation` ヘッダーを付ける。
- `sunset_at` も設定したインターフェースを呼び出されたとき、System は、応答に `Sunset` ヘッダーも付ける。
- `deprecated_since` を設定していないインターフェースを呼び出されたとき、System は、`Deprecation` ヘッダーを付けない。
- **例**：EX-SYSTEM-014-01、EX-SYSTEM-014-02、EX-SYSTEM-014-03

### 制御面主体によるテナント横断の操作

#### REQ-SYSTEM-020 テナント横断の操作はシステム経路とシステムコンソールだけに置く

- 操作者がテナント管理コンソールを開いたとき、System は、テナント横断への切り替えの UI を置かず、要求先のテナントの記録だけを表示する。
- 制御面主体がシステムコンソールを開いたとき、System は、全テナントに固定したシステムの経路だけを呼び、対象のテナントを列として表示し、取り消しの確認に対象の `tenant_id`、ジョブの種類、ジョブの ID を示す。
- テナント管理コンソールの URL に横断を求める状態が残っている場合、System は、その状態を検証済みの検索の条件から落とし、要求先のテナントの表示に戻す。
- 制御面主体の資格を持たない操作者がシステムコンソールを開いた場合、System は、テナント管理コンソールへ送り返し、システムの経路も拒否する。
- **例**：EX-SYSTEM-020-01、EX-SYSTEM-020-02、EX-SYSTEM-020-03

### 運用者によるゲートウェイの許可リストの照合

#### REQ-SYSTEM-021 フロントエンドゲートウェイの経路許可リストは組み立て済みの経路表と照合され乖離を検出できる

- 運用者がゲートウェイの許可リストを照合したとき、System は、通すべきと分類した経路がホストの形式と `/realms/{tenant_id}` の配下のパスの形式の両方で許可リストに一致し、通してはならない経路がどの許可リストにも一致しないことを確かめる。
- 通すべき経路がどれかの許可リストに一致しない場合、System は、照合を失敗させ、到達できない経路と、それを欠く許可リストを報告する。
- `/metrics` のように通してはならない経路がどれかの許可リストに一致する場合、System は、照合を失敗させ、公開してはならない経路と、それを通す許可リストを報告する。
- 許可リストを読み取れない場合、System は、照合を失敗させ、照合が空振りしたことを報告する。
- **例**：EX-SYSTEM-021-01、EX-SYSTEM-021-02、EX-SYSTEM-021-03、EX-SYSTEM-021-04

## セキュリティ上の考慮

テナント管理コンソール（`/admin`）とテナント管理 API は、操作者が `system_admin` であっても、要求先のテナントへ閉じる。
範囲は操作者のロールからも画面の切り替えからも決めず、どの経路を呼んだかだけで決まる。
制御面の操作へ到達できる資格情報の種類は、[認可設計](../../../design/security/authorization.md)が定める。
