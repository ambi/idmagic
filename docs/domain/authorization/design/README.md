# Authorization の設計

この文書は、Authorization の設計を話題ごとに索引する。
このモジュールが外へ約束することは、仕様の [Authorization](../README.md) と各機能仕様が定める。
一つの機能だけの仕組みは、その機能の `design.md` に置く。

| 話題 | 記述した場所 |
| --- | --- |
| アーキテクチャ | [Authorization のアーキテクチャ](architecture.md) |
| 設計判断 | [Authorization の重要な設計判断](decisions.md) |
| アプリケーション | 該当なし：管理 API はシステムの[アプリケーション設計](../../../design/application/README.md)に従い、このモジュールに固有の方式はない |
| データ | 該当なし：書き込みの版と永続化は[関係の判定の設計](../check/design.md)が、テーブルの定義はスキーマファイルが扱う |
| セキュリティ | 該当なし：システム全体の認可は[認可設計](../../../design/security/authorization.md)が、テナントの境界は各機能仕様のセキュリティ上の考慮の節が扱う |
| 信頼性 | 該当なし：ストアの障害は判定不能として不許可にし、[関係の判定の設計](../check/design.md)が扱う |
| 性能 | 該当なし：システムの[性能設計](../../../design/performance/README.md)に従い、このモジュールに割り当てた品質要件はない。列挙の規模の限界は[判断](decisions.md#リソースの列挙を上限付きの走査と-1-件ずつの判定で行う)に置く |
| オブザーバビリティ | 該当なし：判定と列挙は監査のイベントに残り、それ以外はシステムの[オブザーバビリティ設計](../../../design/observability/README.md)に従う |
| 検証 | [Authorization の検証](verification.md) |
| インフラストラクチャ | 該当なし：実行基盤に固有の要求はない |
| リスク | 該当なし：このモジュールに固有の既知の欠陥は見つかっていない |
