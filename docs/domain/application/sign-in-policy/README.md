# サインインポリシー

## 概要

この文書は、アプリケーションごとのサインインポリシーと、テナントのデフォルトのサインインポリシーの仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | ポリシーの設定、実効のポリシーの選択、フェデレーションの開始のときの評価、デフォルトより弱いポリシーの警告 |
| 行為者 | テナント管理者（設定）、System（フェデレーションの開始のときの評価） |
| 扱わないもの | ステップアップ認証そのものは `Authentication` と `OAuth2` が扱う |

## モデル

ポリシーには、評価器が実際に確かめられる値だけを設定できる。

| 規則の項目 | 内容 |
| --- | --- |
| 必須の認証強度 | 自由な入力ではなく、`Password` または `Mfa` に制約した `RequiredAuthnStrength`。内部の ACR の URN と AMR の値へ一対一で対応付ける |
| `allow_trusted_device` | `Mfa` を要求する規則で、Authentication の信頼済みデバイス（AMR の `tdev`）で満たしてよいか。デフォルトは `true`。`false` は毎回の MFA を意味する |
| `reauth_max_age_seconds` | Authentication のステップアップ認証の直近性に対して評価する |
| `network_allow_cidrs` | 保存の時点で検証した CIDR に対して、要求元のクライアントの IP を検査する |

評価器が確かめられない端末の条件は受け付けない。
自由な入力の認証強度や端末の条件を許すと、保存はできるのに評価で必ず落ちる設定が作れてしまうからである。

テナントのデフォルトとアプリケーションごとのポリシーは合成せず、後者で上書きする。
アプリケーションが有効な規則を一つでも定義していれば、その規則がテナントのデフォルトを完全に置き換え、定義がなければデフォルトをそのまま適用する。
新しいテナントは、規則が空の、すべてを許すデフォルトから始める。

- **判断**：上書きにする理由は、[テナントのデフォルトとアプリケーションごとのポリシーを合成せず上書きにする](../design/decisions.md#テナントのデフォルトとアプリケーションごとのポリシーを合成せず上書きにする)。
- **判断**：信頼済みデバイスを属性で表す理由は、[信頼済みデバイスでの充足を Mfa の規則の属性として表す](../design/decisions.md#信頼済みデバイスでの充足を-mfa-の規則の属性として表す)。
- **判断**：弱いポリシーを禁じない理由は、[デフォルトより弱いポリシーを禁じず警告にする](../design/decisions.md#デフォルトより弱いポリシーを禁じず警告にする)。

## 操作

### 管理者によるアプリケーションごとのポリシーの設定

#### REQ-APPLICATION-009 管理者はアプリケーション別サインインポリシーを設定できる

### 管理者によるテナントのデフォルトのポリシーの設定

#### REQ-APPLICATION-010 管理者はテナントデフォルトサインインポリシーを設定し全アプリに適用できる

## セキュリティ上の考慮

ポリシーは、割り当てと同じ関門で評価するので、別のプロトコルを入口に選んでも評価を迂回できない。
評価はすべてフェイルクローズで行う。
空でない CIDR の許可リストにクライアントの IP が一致しない場合と、要求元のクライアントの IP を特定できない場合は、ステップアップ認証の機会とせず、無条件に拒否する。

テナントのデフォルトのサインインポリシーは Application 単位ではなくテナントの設定なので、API アクセストークンでは `settings:read` と `settings:write` に対応させる。
