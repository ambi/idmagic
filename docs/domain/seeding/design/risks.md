# Seeding のリスク

この文書は、Seeding の既知の欠陥、技術的負債、受容したリスクを扱う。
脅威は[脅威モデル](../../../design/security/threat-model.md)に置く。

| リスク | 現状 | 影響 |
| --- | --- | --- |
| 適用が各 Context のユースケースを通らない | `Contributor` は、記録の正を持つ Context のユースケースではなく、Repository の保存を直接呼ぶ | ユースケースが行う検証、リソース上限の確認、ドメインイベントと監査の記録を、seed の書き込みは通らない。seed で作ったデータに、通常の作成の経路と同じ不変条件が成り立つとは限らない |
| プロセスをまたぐ排他がない | 適用の排他は、同じプロセスの中のミューテックスだけである | 二つのプロセスが同じ要求を同時に適用すると、両方が同じ論理キーを `create` と計画し、保存が競合しうる。失敗した側は再実行で収束する |
| デモのデータのドリフトを存在でしか判定しない | `development` のプロファイルでは、デモのクライアント、User、Group、Application が存在するかだけで完了を判定する | 存在するデモのデータを手動で変えても、`conflict` にならない |
