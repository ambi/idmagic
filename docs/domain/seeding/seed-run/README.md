# seed の計画と適用

## 概要

この文書は、`SeedOperator` が環境とプロファイルを指定して、初期データを計画し適用する仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | マニフェストの選択と厳密な読み込み、環境ポリシーによる拒否、シークレットを伏せた計画、冪等な適用、手動の変更の検出 |
| 行為者 | `SeedOperator`（プロセスを起動できる運用者または自動化主体） |
| 扱わないもの | 投入したデータの以後の変更は、記録の正を持つ各 Context の管理 API が扱う |

## モデル

プレビュー（`dry_run`）と適用（`apply`）は、同じ決定的な計画器を通る。
`dry_run` は永続状態を変えずに、適用したときに何が起きるかを返す。
マニフェストとプロファイルの検証と環境ポリシーは、どちらのモードでも、シークレットの解決と書き込みより前に行う。

| プロファイル | 内容 | 本番 |
| --- | --- | --- |
| `bootstrap` | ファーストパーティーのクライアントなど、稼働に必要な最小のデータ | 受け付ける |
| `development`、`test` | 既知のサンプル | 拒否する |
| `performance` | 機密情報を含まない合成データ | 拒否する |

| シークレットの提供元 | 開発とテスト | ステージングと本番 |
| --- | --- | --- |
| `env` | 受け付ける | 拒否する |
| `file` | 受け付ける | 受け付ける |

- **判断**：権限の代わりに環境ポリシーで書き込みを制限する理由は、[seed の計画と適用に HTTP のエンドポイントを設けない](../design/decisions.md#seed-の計画と適用に-http-のエンドポイントを設けない)。

## 操作

### 運用者による seed のプレビュー

#### REQ-SEEDING-001 環境別の明示プロファイルが選択される

#### REQ-SEEDING-002 明示したマニフェストまたはプロファイルのデフォルトマニフェストを選択する

#### REQ-SEEDING-003 マニフェストと指定プロファイルの不一致を拒否する

#### REQ-SEEDING-004 不正なマニフェストは書き込み前に拒否する

#### REQ-SEEDING-005 本番では env シークレットプロバイダーを拒否する

#### REQ-SEEDING-007 本番では development または performance プロファイルを拒否する

### 運用者による seed の適用

#### REQ-SEEDING-006 同じ seed を再適用しても何も変更しない

#### REQ-SEEDING-010 部分失敗後に同じリクエストを再実行すると目的の状態へ収束する

#### REQ-SEEDING-009 手動変更によるドリフトは上書きせず競合とする

#### REQ-SEEDING-008 本番の bootstrap には明示的なリダイレクト URI が必要である

## セキュリティ上の考慮

seed は、テナントをまたぐ書き込みができる唯一の経路である。
実行できるのはプロセスを起動できる運用者と自動化主体だけで、テナント管理者やアプリケーションのトークンからは到達できない。

本番が `bootstrap` だけを受け付けるのは、宛先を誤った要求からデモ用の資格情報が本番へ投入されることを防ぐためである。
本番の `bootstrap` では、ファーストパーティーのリダイレクト URI が本番として安全な形（localhost でない HTTPS）であることも同時に求める。

プレビューはシークレットの参照を解決できることを確かめるが、取得した値は計画、診断、ログ、エラーのどこにも現れない。
