## アーキテクチャ

| 構成要素 | 責務 | 依存先 |
| --- | --- | --- |
| 管理者のユースケース | 登録、更新、束縛と解除、無効化と再有効化、停止、削除。所有者の検証と、テナントの Agent の使用量の増減 | `AgentRepository`、`UserRepository`（所有者の検証）、`OAuth2` の `OAuth2Client` の読み取り、テナントのリソース上限 |
| 所有者の停止に伴う無効化 | 止めた User が所有する `Active` の Agent を `Disabled` にし、`AgentDisabled` を発行する | `AgentRepository` |
| 管理 API のハンドラー | 管理者の認可、入力の変換、応答の型への変換 | 管理者のユースケース |

Agent のトークンの発行の可否は、この機能ではなく `OAuth2` が、束縛した `OAuth2Client` のトークンの発行の境界で Agent の状態を読んで判定する。

所有者の停止に伴う無効化は、User のユースケース（無効化、削除の予約、完全削除）が User を確定した後に呼ぶ。
User を止める経路は、管理 API、ライフサイクルワークフロー、SCIM の取り込みのどれも User のユースケースを通るので、無効化はどの経路でも同じように起きる。
経路と組み立ては、Context の[アーキテクチャ](../../design/architecture.md#ほかの-context-からの-user-の停止)が扱う。

## 信頼性

所有者の停止に伴う無効化は、User の保存と同じトランザクションにしない。

| 失敗の状況 | 結果 | 回収の方法 |
| --- | --- | --- |
| User を保存した後、Agent の無効化の途中で失敗する | User は止まり、一部の Agent が `Active` のまま残る。操作はエラーを返す | 同じ操作を再実行する。止まっている User への無効化と削除の予約は、User を変えずに残った `Active` の Agent だけを無効化する |
| 完全削除で、Agent の無効化の途中で失敗する | 完全削除は Agent の無効化を User の Tombstone より先に行うので、User は残り、一部の Agent が `Active` のまま残る。操作はエラーを返す | 完全削除を再実行する |
