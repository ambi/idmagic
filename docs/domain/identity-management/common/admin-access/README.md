# 管理 API の認可

## 概要

この文書は、IdManagement の管理 API（User、Group、Agent の管理）の呼び出しを認める条件の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 管理者のセッションによる呼び出しと、API アクセストークンによる呼び出しの認可 |
| 行為者 | 管理者（`Administrator`）、管理 API クライアント（API アクセストークンの提示者） |
| 扱わないもの | システム全体の主体の種類、スコープの名前空間、テナント境界は[認可設計](../../../../design/security/authorization.md)が、API アクセストークンの発行と失効は `ApiTokens` が扱う。操作ごとに要るスコープの割り当ては、TypeSpec の各操作の `x-api-token-scopes` が定める |

## 操作

### 管理者のセッションによる呼び出し

| 項目 | 内容 |
| --- | --- |
| 行為者 | ブラウザーのセッションで認証した User |
| 入力 | 管理 API の要求 |
| 成功時の作用 | 要求した管理操作を実行する |
| 拒否 | 実効ロールに `admin` を含まない User（AccessDeniedError）。拒否した要求は対象を変えない |

#### REQ-IDMANAGEMENT-014 管理 API は、要求先のテナントで実効ロールに `admin` を持つ User の要求だけを受け付ける

- 管理 API は、要求先のテナントに属する有効な認証済みの User で、実効ロールに `admin` を含むものからの要求だけを受け付ける。
- 実効ロールは、User に直接付与したロールと、所属する Group のロールの和集合である。
- 実効ロールに `admin` を含まない User の要求は、AccessDeniedError で拒否する。
- **担保手段**：`Authenticator.RequireAdmin`
- **例**：EX-IDMANAGEMENT-014-01、EX-IDMANAGEMENT-014-02

### API アクセストークンによる呼び出し

| 項目 | 内容 |
| --- | --- |
| 行為者 | 管理 API クライアント |
| 入力 | 対象テナントの有効な API アクセストークンと、管理 API の要求 |
| 成功時の作用 | トークンのスコープが操作の要求するスコープを満たせば、要求した管理操作を実行する |
| 拒否 | 操作が要求するスコープをトークンが持たない要求（AccessDeniedError）。拒否した要求は対象を作成、更新、削除しない |

#### REQ-IDMANAGEMENT-025 管理 API のスコープは、プリンシパルの種類と読み書きの別ごとに操作を許可する

- `users:*`、`groups:*`、`agents:*` のスコープは、それぞれ User、Group、Agent の操作だけを許可する。種類をまたいで使えない。
- `read` のスコープは対象を変更しない操作を、`write` のスコープは対象を変更する操作を許可する。
- `users:read` は、User の参照と、User の CSV エクスポートの開始、参照、ダウンロード、取り消しを許可する。
- `groups:read` は、Group の参照、動的グループの規則のプレビュー、Group の CSV エクスポートを許可する。
- `groups:write` は、Group の変更と、Group の CSV インポートのプレビューと適用を許可する。
- `agents:write` は、Agent のキルと削除の両方を許可する。
- 操作が要求するスコープを持たないトークンの要求は AccessDeniedError で拒否し、対象を作成、更新、削除しない。
- **判断**：読み書きの境目は HTTP メソッドではなく、操作が対象を変更するかで決める。CSV エクスポートの開始、参照、ダウンロード、取り消しと、動的グループの規則のプレビューは、対象のデータを読むだけなので参照のスコープに置く。データを読むだけのために変更の権限を渡さずに済むからである。
- **判断**：Agent のキルを `agents:write` に含める。同じスコープにある Agent の削除はキルより破壊的なので、キルだけを外しても防御にならない。
- **担保手段**：`support_http.requireAdminApiTokenScope`
- **例**：EX-IDMANAGEMENT-025-01、EX-IDMANAGEMENT-025-05

## セキュリティ上の考慮

| 観点 | 内容 |
| --- | --- |
| 判定の向き | API アクセストークンの判定はフェイルクローズである。要求のルートに対応する操作が契約にない場合と、操作がスコープを宣言していない場合も拒否する |
| テナント境界 | 管理者のセッションでは、User の所属テナントと要求先のテナントが一致しなければ拒否する |
| 対話セッション限定の操作 | 対話セッションに限ると宣言した操作には、どのスコープの API アクセストークンでも到達できない |
