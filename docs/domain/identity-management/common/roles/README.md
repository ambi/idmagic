# ロール

## 概要

この文書は、User、Group、Agent にロールを書き込むときに共通してかかる規則の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | ロールの字句の正規化と、予約ロール `system_admin` を割り当てられる対象の制限 |
| 行為者 | 管理者（管理 API と CSV のインポート） |
| 扱わないもの | ロールに基づく認可は[管理 API の認可](../admin-access/README.md)と[認可設計](../../../../design/security/authorization.md)が、Group 由来のロールの合成は[グループ](../../groups/group/README.md)が扱う |

## モデル

ロールは文字列であり、テナントが自由に名前を決める。
製品が意味を定めて割り当てられる対象を限るロール（予約ロール）は `system_admin` だけである。
`admin` とテナント固有のロールは予約せず、ロールの語彙全体を閉じた列挙にもしない。

- **判断**：`system_admin` を予約するのは、同じ名前を通常のテナントの任意の文字列としても使える状態を残すと、管理 UI、監査、将来の認可の処理が、それを製品のロールとして扱うのかテナント固有のロールとして扱うのかを判別できないからである。

## 操作

### ロールの書き込み

| 項目 | 内容 |
| --- | --- |
| 行為者 | 管理者。User、Group、Agent の作成と更新、User と Group の CSV の適用で書き込む |
| 入力 | ロールの集合 |
| 成功時の作用 | 前後の空白と重複を除き、昇順に並べたロールを保存する |
| 拒否 | 空のロールを含む書き込み（`invalid_role`）。予約ロールを割り当てられない対象への `system_admin` の新しい割り当て（管理 API では `invalid_role`、CSV では行の `invalid_roles`）。拒否した書き込みは、同じ要求のほかの項目を含めて対象を変えない |

#### REQ-IDMANAGEMENT-033 ロールは前後の空白を除き、重複を除いて昇順に保存する

- User、Group、Agent のロールは、管理 API と CSV のどちらから書いても同じ正規化を通す。
- 各ロールの前後の空白を除く。
- 空白を除いて空になるロールを一つでも含む書き込みは、`invalid_role` で拒否し、対象を変更しない。
- 同じロールを二度以上含む書き込みは、一つにまとめて保存する。
- 保存するロールの並びは、文字列の昇順とする。
- ロールの照合は大文字と小文字を区別する。`Admin` と `admin` は別のロールである。
- **担保手段**：`usecases.NormalizeRoles`

#### REQ-IDMANAGEMENT-032 `system_admin` を新しく割り当てられるのは、制御面テナントの User と Group だけである

- `system_admin` を新しく割り当てられるのは、制御面テナントの User と Group だけである。直接の付与と Group 経由のどちらでもよく、Group 経由で割り当てた `system_admin` は User の実効ロールに現れる。
- 制御面テナント以外の User と Group、およびどのテナントの Agent へも、`system_admin` を新しく割り当てる管理 API の書き込みは、InvalidRequestError と `invalid_role` で拒否する。同じ要求のほかの項目も変えず、`updated_at` を進めず、イベントを発行しない。
- 同じ対象への CSV の行は、`roles` 列を指す `invalid_roles` で `rejected` にし、対象を変えない。
- 判定は、その書き込みが新しく加えるロールだけを見る。すでに `system_admin` を持つ対象に同じ値を書き込む行は拒否しない。
- **判断**：Agent にはどのテナントでも割り当てない。[認可設計](../../../../design/security/authorization.md)は Agent をシステム運用者とは別の主体として定義しており、制御面の管理 API が受け入れるのは User と ApiToken だけだからである。
- **判断**：新しく加える分だけを見る理由は、[予約ロールを書き込みが新しく加える分だけで判定する](../../design/decisions.md#予約ロールを書き込みが新しく加える分だけで判定する)。
- **判断**：制御面テナントの外にすでに保存した `system_admin` は、移行で自動的に消さない。テナント固有の文字列として使っている環境から値を無断で失わせないためである。テナントをまたぐ能力は、所属テナントを要求する制御面の判定で先に無効になっている。
- **担保手段**：`usecases.ValidateRoleAssignment`
- **例**：EX-IDMANAGEMENT-032-01、EX-IDMANAGEMENT-032-08
