# アカウントのセルフサービスの設計判断

- セルフサービス API (`/api/account/*`) は認証済み本人の記録だけに閉じる。本人が書き込めるのは `editable_by_user == true` の属性に限り、更新は対応表全体の置き換えではなくキーごとの併合とする。本人へ開示するのも `self_readable` と `claim_exposed` の属性だけで、`admin_readable` と `private` は読み出せない。
- メールアドレス変更の確認トークンは共通のアクショントークン核が発行し検証する ([設計ガイドライン](../../../design/application/design-guidelines.md))。この Context では、新しいアドレスという用途別のペイロードと、`User` の primary email を確定する作用だけを扱う。トークンの使用済み化とその確定は 1 つのトランザクションで行う。分けると、同じリンクで二度アドレスが変わる状態と、起票から確定までの間に別の利用者が同じアドレスを取ったために拒否された利用者がリンクだけを失う状態のどちらかが起きる。相手がアドレスを手放せば同じリンクがまだ使えるべきなので、作用が失敗したときはトークンを未使用のまま残す。
