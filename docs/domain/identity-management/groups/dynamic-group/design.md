## アーキテクチャ

| 構成要素 | 責務 |
| --- | --- |
| 規則のコンパイル（`CompileDynamicGroupRule`） | 式を、実効的な User の属性の定義に対して検査し、許した関数と参照だけからなる評価器にする |
| 規則の保存と有効化のユースケース | 版を進め、有効な規則なら再評価のジョブを予約する。無効化ではその場で所属を外す |
| 再評価のジョブ（`DynamicGroupReconcileHandler`） | 予約した版と現在の規則を比べ、一致するときだけ全件を評価する |
| User の変更に伴う再評価（`SyncDynamicGroupsForUser`） | User の作成と変更の後に、その User だけを有効な規則で評価し直す |

### 実行時の流れ：全件の再評価

1. 規則の保存または有効化が、規則の版を載せたジョブを予約する。
2. ジョブは規則を読み直し、規則がない、無効である、版が違うときは何もせずに成功する。
3. テナントの User を評価し、一致する User には現在の版を記録した所属を作り、一致しない User の所属を外す。
4. 追加、除外、変化なし、誤りの件数を載せた `DynamicMembershipEvaluated` を一つ発行する。

## データ

| データ | 内容 |
| --- | --- |
| 動的な所属 | 由来（規則）と、所属を作ったときの規則の版を記録する。版の記録のない動的な所属は作らない |
| 有効な所属 | 記録した版が現在の規則の版と一致する所属だけを有効とする。版が進んだ時点で、古い版の所属は再評価を待たずに数えなくなる |

## 信頼性

| 症状 | 原因 | 直し方 |
| --- | --- | --- |
| 規則を有効にしたのに所属が増えない | 再評価のジョブが動いていないか、より新しい版が保存されて古いジョブが何もせずに終わった | `worker` が動いていることを確かめる。最新の版のジョブが予約されていなければ、規則を保存し直す |
| `DynamicMembershipEvaluated` の誤りの件数が 0 でない | 一部の User の評価に失敗した。その User は所属しない | 式と、失敗した User の属性の値を確かめる |
