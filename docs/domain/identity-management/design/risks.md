# IdManagement のリスク

この文書は、IdManagement の既知の欠陥、技術的負債、受容したリスクを扱う。
脅威と統制は[脅威モデル](../../../design/security/threat-model.md)が扱う。
規則の現在の挙動を維持するか是正するかが決まっていない点は、各規則の要判断の欄に置き、生成する未決事項の一覧に集まる。

| リスク | 影響 | 現在の扱い |
| --- | --- | --- |
| User の完全削除の途中で失敗すると、再実行しても関連する記録が残り、User の使用量も減らない | 削除した User のセッションや資格情報の記録が残り得る。使用量が実際の件数より多くなる | 残った記録をストアごとに手で消す。[ユーザーの設計](../principals/user/design.md#信頼性)を参照 |
| データエクスポートの期限切れが状態表と食い違う。状態表は完了時刻から 30 日で `expired` とし、ファイル本体を消すと定めるが、実装は作成時刻から 30 日で `expired` を導き、成果物を消さない | 期限を過ぎた CSV が成果物ストアに残り続ける。生成に時間がかかったエクスポートは状態表より早く期限切れになる | [データエクスポートの設計](../bulk-transfer/data-export/design.md#リスク)を参照。状態表と実装のどちらに合わせるかは決まっていない |
| 所有者の User を無効化または削除しても、その User が所有する Agent は変わらない。用語集は所有者を User または Group とするが、実装は `Active` の User だけを受け付ける | 所有者が組織を去った後も Agent が動き続ける。用語集を読んだ管理者が Group を所有者にできると誤解する | [エージェントの設計](../principals/agent/design.md#リスク)を参照 |
| 管理 API の操作の監査の記録は、Aggregate の保存の後に別に追記する | 追記の失敗と、保存と追記の間のプロセスの停止で、変更が残り監査の記録だけが欠ける | 配信点が失敗を「照合が必要」としてログに残す。[イベントと監査の記録](audit-events.md)を参照 |
| User、Group、Agent の更新は後勝ちである | 同じ対象を同時に更新すると、先の更新の項目が黙って失われる | [データ](data.md#排他と一意性)を参照 |
| 猶予期間を過ぎた削除予約の User は、管理者がユーザー一覧を取得するまで完全削除されない | 一覧を取得しないテナントでは、期限を過ぎた User の個人情報が残り続ける | 規則 REQ-IDMANAGEMENT-044 の要判断の欄に置く |
