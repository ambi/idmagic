# IdManagement の信頼性

この文書は、IdManagement の仕組みが壊れたときの症状と直し方を扱う。
一つの機能だけの障害は、その機能の `design.md` に置く。

| 症状 | 原因 | 直し方 |
| --- | --- | --- |
| CSV の適用のジョブが、ペイロードの照合で失敗する | プレビューの後に、成果物ストアのペイロードが置き換わったか壊れた | 同じ CSV でプレビューからやり直す。適用は別の CSV を受け付けないので、迂回する手段はない |
| CSV の適用の一部の行だけが失敗する | 適用の時点の状態で、行の検証が失敗した（プレビューの後の同時の変更など） | 行のエラーを読み、失敗した行だけの CSV でプレビューからやり直す。成功した行は確定済みであり、巻き戻らない |
| ジョブが `queued` のまま進まない | `worker` が動いていない | `worker` を起動する。ジョブの再実行は `Jobs` の手順に従う |
| User の完全削除の後に、関連する記録が残る | [ユーザーの設計](../user/design.md#信頼性)を参照 | 同左 |
