# SigningKeys

## 責務と境界

テナント単位の署名鍵の素材について、ライフサイクル、ローテーション、公開の重複期間、監査をプロトコル横断で扱う。
OAuth2 と OIDC は JWK、JWKS、JWT の署名器を、SAML と WS-* は X.509 証明書と XML 署名のアダプターを使うが、鍵の用途、ローテーション、テナントの間の分離に関する規則はここに集約する。
鍵の提供元の選択と保管もここに含む。

| 扱わないもの | 担当 |
| --- | --- |
| JWKS とトークンの形式への直列化 | `OAuth2` のアダプター |
| SAML と WS-Fed のメタデータと XML 署名の形式への直列化 | `SAML`、`WS-Federation` のアダプター |
| 提供元に到達できないときのトークンの発行の停止 | `OAuth2` のトークンの発行 |
| 可逆なシークレットのエンベロープ暗号化 | `DataKeys` |

鍵素材は、署名のポートと公開鍵のポートを通じてだけ提供する。

## モデル

| Aggregate | 境界の内側にあるもの | 他の Aggregate との関係 |
| --- | --- | --- |
| `SigningKey` | `kid`、テナント、用途（`KeyUsage`）、スコープ、提供元、公開鍵と秘密鍵の JWK、XML 用の証明書、有効か、退役、期限、アーカイブの時刻 | `Tenant` を `tenant_id` で参照する |

鍵は、テナント、用途、外部には意味を公開しないスコープ ID の組で分離する。
組ごとに、有効な鍵は 1 本だけである。

| 用途 | 使う側 | スコープ |
| --- | --- | --- |
| `Signing` | OAuth2 と OIDC の JWT。用途とスコープを明示しない呼び出し元にはこれとデフォルトのスコープを適用する | デフォルトのスコープ |
| `XmlFederationSigning` | SAML と WS-Federation の XML 署名 | SAML では IdP のプロファイルの ID |

| 提供元（`KeyProvider`） | 秘密鍵の置き場所 | 署名する主体 |
| --- | --- | --- |
| `Local` | プロセスのメモリ | アプリケーション |
| `Database` | `signing_keys.private_jwk` に平文で置く。PostgreSQL のバックアップにも平文で入る | アプリケーション |
| `VaultTransit` | Vault の中から出さない。データベースには公開鍵の写しだけが残る | Vault |

- **判断**：署名鍵の秘密鍵は、[データベース設計](../../design/data/database.md#可逆な秘密情報のエンベロープ暗号)のエンベロープ暗号化の対象ではない。署名鍵は読み出して復号するものではなく、提供元の内側で署名に使うものであり、保護は暗号化ではなく提供元の選択で決まるからである。

## 公開する契約

HTTP の操作とモデルの形は TypeSpec の `Signing Keys` のタグが定める。
次の表は、それ以外にほかの Context と結ぶ契約である。

| 契約 | 相手 | 向き | 内容 |
| --- | --- | --- | --- |
| `KeyStore` の署名と公開鍵の一覧 | `OAuth2`（JWT の署名と JWKS）、`SAML` と `WS-Federation`（XML 署名とメタデータ） | この Context が提供する | 要求のテナント、用途、スコープの有効な鍵で署名し、有効な鍵と期限内の検証用の鍵を返す |
| 提供元の健全性 | `OAuth2` のトークンの発行 | この Context が提供する | `provider_healthy` を観測できるシグナルとして返す |
| `idmagic-batch signing-key-lifecycle` | 外部のスケジューラー | この Context が提供する | 期限の来た鍵のローテーションと、期限切れの検証用の鍵のアーカイブ |
| ドメインイベント | 監査と下流が購読する | この Context が発行する | `SigningKeyRotated`、`SigningKeyArchived` |
