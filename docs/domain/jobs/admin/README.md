# ジョブの管理

## 概要

この文書は、運用者がジョブの状態を確かめ、終端に達していないジョブを取り消す仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | テナント管理の経路での一覧、参照、取り消しと、システムの経路でのテナントを横断した一覧、参照、取り消し |
| 行為者 | テナント管理者、System 管理者（制御面主体） |
| 扱わないもの | 再試行、再実行、強制の完了は提供しない |

## モデル

管理 API は、状態、試行の回数、`error` を返し、`params`、`result`、`dedup_key` を返さない。
どれも投入した Context が意味を決める不透明な値であり、Jobs はその中身を検証しない。
中身を保証できない値を管理画面へ流すと、個人情報が混ざっていないことを Jobs が主張できないまま公開することになる。
`error` は返す。失敗の理由が分からなければ、失敗の一覧に意味がないためである。

- **判断**：参照と取り消しに限る理由は、[管理 API を参照と取り消しに限る](../design/decisions.md#管理-api-を参照と取り消しに限る)。

## 操作

### 管理者によるジョブの一覧と参照

#### REQ-JOBS-012 管理者は自テナントのジョブだけを一覧・参照できる

#### REQ-JOBS-014 管理 API はハンドラーの入出力を返さない

### 管理者によるジョブの取り消し

#### REQ-JOBS-013 管理者は終端に達していないジョブを取り消せる

### 制御面主体によるシステム経路の操作

#### REQ-JOBS-015 制御面主体はシステム経路で全テナントのジョブを一覧・参照・取り消せる

## セキュリティ上の考慮

テナント管理の経路の参照と取り消しは、要求先のテナントに閉じる。
テナントを横断した一覧、参照、取り消しは、テナント管理の経路のパラメーターではなく、制御面主体の専用のシステムの経路に置く。
テナント管理の経路に横断を求める入力を残さないのは、その入力が一つ書き漏らされるだけで、テナントの境界の穴になるからである。
運用者は失敗したジョブを一覧で見つけた直後に止めたいので、横断の一覧と取り消しを同じシステムの経路にそろえる。
