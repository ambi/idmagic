# IdP プロファイルとメタデータ

## 概要

この文書は、SAML の IdP プロファイルの管理と、プロファイルごとのメタデータと署名証明書の公開の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | IdP プロファイルの作成、変更、削除。プロファイルごとのメタデータと署名証明書の公開 |
| 行為者 | テナント管理者（プロファイルの管理）、SP（メタデータと証明書の取得） |
| 扱わないもの | プロファイルの署名の鍵のローテーションは `SigningKeys` が扱う |

## モデル

各 SP は、テナントの中の IdP プロファイル一つだけに関連付ける。
`default` のプロファイルは短い `/saml/*` の経路を、追加のプロファイルは `/saml/idp/{profile_id}/*` の経路とプロファイルに固有の entityID を使う。
`shared` のプロファイルは複数の SP で共有でき、`dedicated` のプロファイルを割り当てられる SP は一つまでである。

プロファイルの管理 API は、サーバーが生成した正式な entityID、メタデータ、SSO、SLO、証明書の取得の各 URL、証明書のフィンガープリント、関連付けた SP の数を返す。
デフォルトのプロファイルの変更、`dedicated` のプロファイルへの複数の SP の割り当て、使用中のプロファイルの削除は、Repository が最終的に拒否する。

各プロファイルのメタデータは、有効な証明書に加え、同じ鍵のスコープの有効期限内の検証用の証明書をすべて公開する。
SP は、ローテーションの直前に発行されたメッセージも検証できる。

## 操作

### SP による署名証明書の取得

#### REQ-SAML-001 SP は署名証明書を取得できる

### SP によるメタデータの取得

#### REQ-SAML-003 専用プロファイルは固有のメタデータを公開する

### 管理者による IdP プロファイルの管理

#### REQ-SAML-004 管理者は SAML IdP プロファイルを共有用または専用として管理できる

## セキュリティ上の考慮

IdP プロファイルの登録、参照、削除は、`AdminFederationTrustsManage` の権限（AuthZEN の action `admin:federation_trusts_manage`）を要し、`admin` ロールを持つ、有効かつ認証済みのユーザーが、所属テナントに対して行える。

IdP のメタデータと証明書の取得は、認証を要さない公開の Discovery である。
公開するのは、entityID、エンドポイント、署名証明書に限る。
