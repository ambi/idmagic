# DEK の健全性の一覧

## 概要

この文書は、制御面主体がテナントを横断して DEK の状態を一覧する仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | DEK を持つテナントごとの `active_version`、`status`、プロバイダーへの到達性の一覧 |
| 行為者 | System 管理者（制御面主体） |
| 扱わないもの | DEK の状態の変更は[DEK のライフサイクル](../lifecycle/README.md)が扱う |

## 操作

### System 管理者による DEK の健全性の一覧

#### REQ-DATAKEYS-006 制御面主体はテナント横断で DEK の健全性を一覧できる

- 制御面主体が制御面テナントの経路で DEK の健全性を一覧したとき、DataKeys は、DEK を持つテナントごとに `tenant_id`、`active_version`、`status`、プロバイダーの名前、プロバイダーへの到達性、最後のローテーションの時刻を 200 で返す。
- DEK の健全性を一覧するとき、DataKeys は、DEK をまだ持たないテナントを一覧から省く。
- DEK の健全性を一覧するとき、DataKeys は、`wrapped_dek`、平文の DEK、`MasterKey` の識別子を応答に含めない。
- `system_admin` を持たないか、制御面テナントに所属しないか、要求先が制御面テナントでない利用者が一覧を要求した場合、DataKeys は、403 と `access_denied` で拒否し、ほかのテナントの識別子も DEK の状態も返さず、テナント横断の収集を実行しない。
- API アクセストークンで一覧を要求された場合、DataKeys は、トークンのスコープによらず 403 と `insufficient_scope` で拒否する。
- **例**：EX-DATAKEYS-006-01、EX-DATAKEYS-006-02、EX-DATAKEYS-006-03

## セキュリティ上の考慮

この操作はテナントを横断した運用情報を返すため、制御面主体だけが呼べる。
制御面主体は、認証済みで有効な User のうち、制御面テナントに所属し、要求先も制御面テナントであり、Group 由来を含む有効ロールに `system_admin` を持つものである。

レスポンスには鍵素材を含めず、`active_version`、`status`、プロバイダーへの到達性に限る。
この操作は対話セッションに限り、API アクセストークンからは、どのスコープを持っていても到達できない。
`ApiTokenScope` は DEK に対応する語彙を持たないためである。
