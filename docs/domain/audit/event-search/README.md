# 監査イベントの検索

## 概要

この文書は、管理者が監査イベントを検索、取得、エクスポートする仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 期間、種類、検索属性による絞り込み、ページ単位の閲覧、1 件の取得、エクスポート、検索の選択肢の提示 |
| 行為者 | テナント管理者（テナント管理の経路）、System 管理者（システムの経路） |
| 扱わないもの | 監査イベントの発行は各 Context が、記録の保持期間はデータのライフサイクルが扱う |

## モデル

検索の文法は、検索属性の登録簿（`AuditEventSearchRegistry`）が宣言する属性、演算子、変換の閉じた集合に限る。
任意の SQL や JSONPath は受け付けない。

| 演算子 | 意味 |
| --- | --- |
| `eq` | 完全一致。値は 1 個 |
| `in` | 値の集合のいずれかに一致 |
| `contains` | 生の文字列の部分一致。値は 1 個 |
| `time_range` | 発生時刻の期間。値は開始と終了の 2 個 |

フィルターの各式は論理積で結ぶ。
多値の属性は、いずれかの値が一致すればそのイベントが返る。
検索軸を持たないイベントは、その軸のどの値にも一致しない。

- **判断**：閉じた文法にする理由は、[検索の文法を登録簿の閉じた集合に限る](../design/decisions.md#検索の文法を登録簿の閉じた集合に限る)。

## 操作

### テナント管理者による監査イベントの検索

#### REQ-AUDIT-001 管理者は監査ログを期間で絞り込み参照・エクスポートできる

#### REQ-AUDIT-002 worker プロセスが発行した業務イベントも管理者は監査ログで参照できる

#### REQ-AUDIT-003 管理者は workflow_id と run_id で LifecycleWorkflow の監査イベントを検索できる

#### REQ-AUDIT-004 管理者は監査ログをページ単位で閲覧でき、絞り込みを変えるとカーソルが無効になる

#### REQ-AUDIT-005 管理者はエージェントが代行した操作を本人の操作と区別して検索できる

#### REQ-AUDIT-006 管理者は委譲チェーンの参加者から代行の連なりを横断検索できる

### 制御面主体によるシステム経路の検索

#### REQ-AUDIT-007 制御面主体はシステム経路で全テナントの監査ログを検索・エクスポートできる

## セキュリティ上の考慮

監査イベントの参照とエクスポートは、`AdminAuditEventsRead` の権限（AuthZEN の action `admin:audit_events_read`）を要し、`admin` または `system_admin` のロールを持つ、有効かつ認証済みのユーザーだけが行える。
API アクセストークンでは、ロールに加えて `audit:read` を要求する。
対になる変更のスコープは存在しない。書き込みの経路そのものを公開しないためである。

問い合わせの範囲は、入力ではなく経路が決める。
テナント管理の経路は呼び出し元のテナントへ固定し、全テナントを横断する参照とエクスポートは、制御面主体だけが到達できる専用のシステムの経路に置く。
範囲を切り替えるクエリを持たせないのは、テナント管理の経路に横断の能力が残っていると、経路を見ただけでは認可の範囲が分からなくなるからである。

検索の選択肢を返す経路は、システムの経路に双子を作らず、1 本で共有する。
返すのは検索軸の語彙だけで、どのテナントの記録も含まないため、経路が範囲を表すという規則の対象にならない。

カーソルは、絞り込みの指紋に範囲の識別子を混ぜる。
制御面主体はテナント管理の経路でも所属テナントが制御面テナントであり、範囲を混ぜなければ両経路の指紋が一致して、テナントの中で発行したカーソルが横断の検索の続きとして読めてしまう。
