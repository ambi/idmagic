# ApiTokens Internals

## The token body exists exactly once

発行時に一度だけ返す JWT は、どこにも保存しない。永続化するのは `jti` とライフサイクルのメタデータ (発行者、スコープ集合、有効期限、失効時刻) だけである。したがって発行済みトークンの一覧から本文を取り出す経路は存在せず、紛失に対する手段は再発行しかない。

## Signature validity is not sufficient

提示された RFC 9068 JWT は、署名、発行者、audience、有効期限を満たしたうえで、さらに `jti` に対応する管理レコードを毎回照合する。レコードが失効している、期限切れである、そもそも存在しない、スコープ集合が空である場合は、署名が有効でも認証を通さない。

この二段構えが、失効を即時に効かせている実体である。署名だけで受け入れる設計にすると、失効は署名鍵をローテーションするまで効かない。逆にレコードだけを見る設計では、偽造された `jti` を弾けない。

## Fuzzed parse boundaries

`ParseScopes` は Go native fuzzing の対象である。返すスコープは必ず宣言済み集合の要素で、重複を持たず、宣言済みの入力を取りこぼさない。宣言外の文字列がそのまま `Scope` として通ると、API 認可の判定が知らない権限名を持ち回ることになる。
