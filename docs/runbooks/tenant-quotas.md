# テナントクォータのランブック

## 概要

IdMagic では、テナントごとのリソース消費量（ユーザー、グループ、エージェント、アプリケーションなど）に対して制限（クォータ）を設け、意図しない大量作成や悪意のある使用による影響を抑え、システムの可用性を保ちます。

ハードクォータに達した場合、対象の作成操作は `QuotaExceededError` で直ちに失敗します。

## クォータ超過への対応

テナント管理者からクォータ超過の連絡を受けた場合は、以下の手順で対応します。

1. **状況を確認する**
   - システム管理者としてシステム管理画面のテナント一覧を開き、該当テナントのリソース使用量とクォータを確認します。
   - エラーレスポンスの `resource` から、`users`、`groups` など超過したリソースを特定します。

2. **原因を特定する**
   - 正当な利用の増加によるものか、ループスクリプトのバグや不正アクセスによる急増かを、関係者への確認と監査イベントから判断します。

3. **クォータを引き上げる**
   - 正当な理由がある場合は、システム管理画面のテナント一覧から対象テナントの設定を開き、該当リソースのクォータ上限を必要な数だけ引き上げます。
   - 更新は即座に反映され、再度作成操作が可能になります。

4. **未使用のリソースを削除する**
   - クォータ上限の引き上げが適切でない場合、テナント管理者に不要なリソース (休眠ユーザー、未使用のアプリなど) の整理を促します。
   - 削除操作によって使用量カウンターが低下し、再び作成が可能になります。

## 確認事項

クォータ変更後は、テナント一覧に表示される上限値を再取得して保存結果を確認し、拒否されていた操作を再試行します。上限を引き上げた場合は、その理由と変更前後の値を監査記録で確認できるよう、操作を行ったシステム管理者と対象テナントを記録します。
