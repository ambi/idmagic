# WI-551: 外部 IdP 接続の削除拒否と、API アクセストークン管理の CSRF 検証

作業項目は `wi-551-back-api-tokens-examples-with-tests` である。

外部 IdP 接続は、利用者との連携が残っている間は削除できなくなった。
削除要求は 409 と `urn:idmagic:error:connection_in_use` で拒否され、接続と連携はどちらも残る。
これまで PostgreSQL では外部キーが削除を止めて 500 を返し、メモリの保存先では連携を残したまま接続を削除していた。
管理画面は拒否の理由を表示言語で示す。
規範上の条件は [REQ-AUTHENTICATION-037](../../domain/authentication/scenarios.feature.md) が定める。

API アクセストークンの発行と失効は、ほかの管理 API の状態変更と同じく、ログインセッションで届いた要求に Origin と CSRF トークンの二重送信を要求する。
揃わない要求は 403 の `invalid_origin` または `csrf_failed` で拒否される。
管理画面はすでに CSRF トークンを送っているため、画面からの操作は変わらない。
規範上の条件は [REQ-PLATFORM-004](../../domain/scenarios.feature.md#rule-req-platform-004-周囲資格情報による状態変更は同一オリジンと-csrf-トークンを必要とする) が定める。

API アクセストークンの発行、一覧、失効は、`admin` に加えて `system_admin` ロールを持つ利用者にも開いた。
[ApiTokens の設計判断](../../domain/api-tokens/decisions.md)が定めていたとおりの振る舞いである。

あわせて、外部 IdP 接続と API アクセストークンの管理 operation の契約へ、実装が返していた 401 と 403 の問題コードを宣言し、どの経路も返さない 400 の宣言を外した。
