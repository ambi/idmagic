# WI-508: 復旧コードによる第二要素が MFA の要求を満たす

作業項目は `wi-508-amr-vocabulary-declaration-and-implementation-disagree` である。

WI-508 は、復旧コードで成立した第二要素を MFA の要求の充足として扱う。これまで `acr` は `urn:idmagic:acr:pwd` のままだったため、実効サインインポリシーが `Mfa` のアプリケーションでは、正しい復旧コードを使っても認可のたびに第二要素の画面へ戻されていた。認証要素を失った利用者にとって復旧コードが唯一の経路であることを踏まえると、この経路がその場面で通らなかったことになる。

正しい復旧コードを消費すると `amr` に `rc` が加わり、`acr` は `urn:idmagic:acr:mfa` へ上がる。以後の認可要求は第二要素を再び求めない。発行される ID トークンとアクセストークンの `acr` も、実際に成立した強度を申告する。復旧コードを `User.mfa_enrolled` に数えない規則は変わらないため、復旧コードだけを唯一の MFA 手段として登録することは引き続きできない。記憶済みデバイスの起点として復旧コードを認めないことも変わらない。

`LoginSession.amr` の語彙は、`pwd`、`otp`、`webauthn`、`hwk`、`swk`、`rc`、`tdev` に `federated` を加えた 8 語となり、この語彙の外の値を持つセッションは保存されなくなった。`federated` は外部 IdP による連合ログインが以前から発行していた値であり、標準の宣言だけが取り残されていた。この 8 語は ID トークンとアクセストークンの `amr` クレームとしてリライングパーティーへ届く値の全体である。

管理者の設定変更は要らない。`allow_trusted_device=false` のルールも、復旧コードは充足として認める。記憶済みデバイス (`tdev`) の扱いはこれまでどおり、そのルールでは充足として認めない。

規範上の条件は [REQ-AUTHENTICATION-036](../../contexts/authentication/scenarios.feature.md#rule-req-authentication-036-復旧コードで成立した第二要素は-mfa-の要求を満たす) と `docs/contexts/authentication/standards.md` の `RFC8176-AMR-VOCABULARY` が定める。
