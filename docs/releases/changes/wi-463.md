# WI-463: Reserve the system_admin role for control-plane users

作業項目は `wi-463-reserve-system-admin-role-to-control-plane` である。

WI-463 は `system_admin` を予約ロールとし、新しく割り当てられる対象を制御面テナントの `User` と `Group` に限定する。

`Agent` にはどのテナントでも割り当てられない。

判定の条件は対象の種類と所属テナントであり、操作者が持つロールではない。

対象になる書き込みは、`User` と `Group` の作成と更新、`Agent` の登録と更新、そして `User` CSV と `Group` CSV のプレビューと適用である。適用はプレビュー結果を信頼せず、再計画で同じ検査を行う。

JSON API の拒否は HTTP 422 と `invalid_role` で、`detail` が予約ロールであることを述べる。CSV の拒否は `roles` 列を指す行ごとの `invalid_roles` である。エラーコードの語彙は増えない。

拒否された書き込みは何も保存しない。同じ要求に含めた名前、メールアドレス、カスタム属性も残らず、`Agent` の登録では割当て枠も消費しない。

判定は保存後のロール集合ではなく、その書き込みが新しく加える予約ロールだけを見る。対象が既に `system_admin` を持つ場合、同じ値を再送する書き込みは通り、無編集の CSV エクスポートの再適用は従来どおり全行 `unchanged` になる。`roles` を明示して `system_admin` を外す除去経路も残る。

制御面テナントの `Group` へ `system_admin` を付与すると、従来どおり所属する制御面 `User` の有効ロールに現れる。

規範上の許可と拒否の条件は [REQ-IDMANAGEMENT-032](../../domain/identity-management/scenarios.feature.md#rule-req-idmanagement-032-system_admin-は制御面テナントの-user-と-group-にだけ割り当てられる) が定める。
