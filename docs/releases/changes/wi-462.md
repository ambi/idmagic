# WI-462: テナント横断の監査とジョブをシステムコンソールへ集約する

作業項目は `wi-462-control-plane-console-single-entry` である。

WI-462 は、テナント境界を越える監査ログの検索とジョブの運用を、システムコンソール (`/system`) と制御面主体専用のシステム API だけに置く。これまでは、テナント管理コンソール (`/admin`) の監査画面とジョブ画面が操作者のロールと realm を見て、テナント内表示とテナント横断表示をチェックボックスで切り替えていた。同じ画面が 2 つの権限文脈を行き来するため、利用者はいまどちらの範囲を操作しているかを画面の中の切替から読み取るしかなく、システムコンソールを分けた意図が成立していなかった。

範囲は操作者のロールでも画面の切替でもなく、どの経路を呼んだかだけで決まるようになった。テナント管理 API は要求先テナントに閉じ、`all_tenants` を受け付けない。テナント横断は新しいシステム API が担う。監査は `/api/admin/v1/system/audit_events` とその詳細およびエクスポート、ジョブは `/api/admin/v1/system/jobs` とその詳細および取消しである。いずれも、制御面テナントに所属し `system_admin` を有効ロールに持つ利用者が制御面テナントの経路で呼んだときにだけ通り、この 3 条件のいずれかを欠く呼出しは AccessDeniedError で拒否される。`admin` ロールの併せ持ちは要らない。

システムコンソールに監査ログ画面 (`/system/audit-events`) とジョブ画面 (`/system/jobs`) が加わった。どちらも範囲が全テナントに固定された専用 API だけを呼び、切り替える UI を持たない。ジョブ画面は一覧に対象テナントの列を常時表示し、取り消しの確認では対象の `tenant_id`、ジョブ種別、ジョブ ID を再掲する。取り消しは他テナントの実行に影響するため、どのテナントのどのジョブを止めようとしているかを操作の直前にもう一度示す。

テナント管理コンソールの監査画面とジョブ画面からは、横断の切替が消えた。古い画面のブックマークに横断を求める URL 状態が残っていても、検証済みの検索条件から落ちてテナント内表示へ戻る。

ページングのカーソルは範囲に束縛される。テナント管理経路で発行したカーソルをシステム経路へ持ち込んでも続きとしては読まれず、`InvalidRequestError` を返す。制御面主体はテナント管理経路でも所属テナントが制御面テナントなので、範囲を束縛に含めなければ 2 つの経路のカーソルが取り違えられていた。

規範上の条件は [REQ-AUDIT-007](../../contexts/audit/scenarios.feature.md)、[REQ-JOBS-015](../../contexts/jobs/scenarios.feature.md)、[REQ-SYSTEM-020](../../contexts/system/scenarios.feature.md) が定める。既存の `system_admin` 向け自動化の移行は [アップグレードノート](../upgrades/wi-462.md) が扱う。
