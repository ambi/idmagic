# WI-465: 参照ゲートウェイが中継していなかった経路を通す

作業項目は `wi-465-gateway-route-allowlist-drift-detection` である。

リポジトリが同梱するフロントエンドゲートウェイの参照設定（`frontend/Caddyfile` と `frontend/vite.config.ts`）が、実行時に登録されている次の経路を中継していなかった。

| 経路 | 届いていなかった機能 |
| --- | --- |
| `/ssf/streams/{stream_id}/events` | 顧客側の IdP が送るセキュリティイベントの受信 |
| `/session/check` | OIDC Session Management の `check_session_iframe` |
| `/application-icons/{application_id}/{id}` | 管理コンソールが組み立てるアプリケーションアイコンの URL |
| `/authorize/resume` | 中断した認可要求の再開（`Caddyfile` だけで欠けていた） |

ゲートウェイは中継しないパスを静的アセットの配信へ落とすため、これらの要求は 404 ではなく SPA の `index.html` を 200 で受け取っていた。
`Content-Type` も `text/html` になるので、受信も iframe も画像も、エラーではなく意味のない成功として観測されていた。
これらの経路をホスト形式と `/realms/{tenant_id}` 配下のパス形式の両方で中継するようにした。

**参照設定を自分のデプロイへ写している場合は、同じ 4 つの経路を許可リストへ足す必要がある。**
この参照設定は必須のランタイムではないため、別のゲートウェイを使っているデプロイは自分の許可リストを確かめること。

再発を防ぐため、`mise run check-gateway-routes` が参照設定の許可リストと組み立て済みの経路表を突き合わせるようになった。
経路ごとの公開可否は経路の登録と同じ場所で分類し、分類の無い運用経路はデフォルトで「通してはならない」に倒れる。
`MetricsExposition` の経路は認証を持たないため、このデフォルトによりゲートウェイを通らない。

観測できる振る舞いは `docs/domain/system/scenarios.feature.md` の `REQ-SYSTEM-021` が定める。
セキュリティイベントの受信の契約は、TypeSpec の `IdMagic.SharedSignals.Operations.ReceiveSecurityEvent` が定める。
