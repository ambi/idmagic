# WI-536: グループの表示名の取得元が実際に効くようになる

作業項目は `wi-536-group-display-name-source-selects-nothing` である。

WI-536 は、プロビジョニング接続の `group_push.display_name_source` を、下流へ送るグループの `displayName` に実際に反映する。
これまでこの設定は保存されるだけで、読む経路がどこにも無かった。
管理画面で何を入力しても、下流が受け取る `displayName` は常にグループ名だった。
設定は保存され、画面は入力を受け付け、配信は成功し、観測できる差だけが無い状態だった。

取得元に選べるのは、グループ名 (`name`)、説明 (`description`)、メールアドレス (`email`) の 3 つである。
既定はグループ名で、これは従来の実際の振る舞いと同じなので、取得元を変えていない接続の送出内容は変わらない。

**選べる値は列挙になった。** これまで `display_name_source` は任意の文字列を受け付け、管理画面も自由入力の欄だった。
今後は 3 つの値以外を送る要求は拒否される。
自由入力のままにすると、打ち間違いが「保存され、配信も成功し、下流だけが変わらない」という結果になり、効いている設定と区別が付かない。
管理画面の欄も選択に変わる。

**選んだ属性を持たないグループは、グループ名で送られる。**
説明とメールアドレスは設定されていないことがあるので、空の値をそのまま送ることも、配信を失敗させることもしない。
表示名は失敗して止めるべき判断ではなく、設定の打ち間違い 1 つでそのグループの送出全体が止まる方が害が大きい。

規範上の条件は `docs/contexts/provisioning/standards.md` の `RFC7643-OUT-GROUP-RESOURCES` が定める。
値の集合は TypeSpec の `IdMagic.Contract.ProvisioningGroupDisplayNameSource` にある。
