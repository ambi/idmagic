# WI-351: グループのメンバーシップを CSV で往復する

作業項目は `wi-351-per-group-membership-csv-round-trip-ui` である。

WI-351 は、1 つのグループのメンバーシップを CSV でエクスポートし、編集し、事前検証してから戻す経路を追加する。`IdMagic.Contract.ImportAdminGroupMembers` がアップロードを副作用のないプレビューへ流し、`IdMagic.Contract.ApplyAdminGroupMemberImport` が成功済みプレビューを現在のメンバーシップに対して再計画して適用し、`IdMagic.Contract.GetAdminGroupMemberImport` が操作別の件数と行エラーを返す。管理画面ではグループ詳細のメンバー一覧から、エクスポートと同じ場所でインポートを開始できる。

意図を運ぶ列は `membership_state` ただ 1 つで、値は `present` と `absent` だけである。`present` は未所属の `User` を追加し、`absent` は手動の所属を解除する。どちらも現在の状態と一致していれば何もしない。**CSV に現れない `User` は変更しない。** ファイルに無い行を削除と解釈する完全同期は採らないので、転送ポリシーに合わせてエクスポートを分割しても、一方のファイルの適用がもう一方のメンバーシップを消すことはない。空のセルと未知の値は既知の値へ丸めず行ごと拒否し、`membership_state` 列を欠いたファイルはファイルごと拒否する。

対象のグループを決めるのは URL の `group_id` だけである。CSV の `group_id` と `group_name` は読み取り専用の照合列で、別のグループを指す行は拒否され、その別のグループへは書き込まれない。適用は同一テナントかつ同一グループのプレビューにしか結び付かない。動的グループ、動的規則が作ったメンバーシップ、外部の取り込み元が所有するグループまたは `User` は、いずれも判定不能の場合を含めて拒否する。

`IdMagic.Contract.StartGroupMemberCsvExport` は、ほかの CSV と同じ機械可読ヘッダー、同じ `CsvTransferPolicy`、同じ不変成果物ストアへ移った。ヘッダーは表示ラベルではなく機械キーになり、`membership_state` は全行 `present` として出力される。したがって無編集のエクスポートをそのままプレビューすれば全行が `unchanged` になる。表示ラベルの CSV を機械処理していた場合は、機械キーのヘッダーを読むよう変更する必要がある。

規範上の条件は [REQ-IDMANAGEMENT-029](../../contexts/identity-management/scenarios.feature.md#rule-req-idmanagement-029-管理者は-1-つのグループのメンバーシップ-csv-を検証し行ごとに宣言した所属状態だけを適用できる)、[REQ-IDMANAGEMENT-030](../../contexts/identity-management/scenarios.feature.md#rule-req-idmanagement-030-管理者はエクスポートしたメンバーシップ-csv-を分割しても大量解除にならない形で再適用できる)、[REQ-IDMANAGEMENT-031](../../contexts/identity-management/scenarios.feature.md#rule-req-idmanagement-031-メンバーシップ-csv-は動的規則と外部の取り込み元が所有する所属を上書きしない) と `docs/contexts/identity-management/internals.md` の「Group Membership CSV and Explicit Desired State」が定める。
