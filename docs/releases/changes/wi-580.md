# WI-580: 別テナント向け API トークンの Application API 応答を訂正する

作業項目は `wi-580-align-cross-tenant-application-api-token-refusals` である。

発行元テナントでは有効な API アクセストークンを別テナントの Application account API または admin API へ提示すると、401 の `invalid_token` を返す。
以前の Application シナリオは、この拒否を 403 の `access_denied` と宣言していた。

この変更により、クライアントは要求先で利用できないトークンを破棄し、対象テナント向けの資格情報を取得し直せる。
応答は、audience 不一致、期限切れ、失効、改ざんを区別しない。

同一テナントで有効なトークンのスコープが不足する場合は、引き続き 403 になる。
要求先テナントを解決できない場合と、認証および認可を終えた主体が別テナントまたは存在しない資源 ID を指定した場合は、404 として扱う。

観測できる振る舞いは、`docs/domain/application/scenarios.feature.md` の `REQ-APPLICATION-003` と `REQ-APPLICATION-004` が定める。
401 の本文候補は、TypeSpec の `IdMagic.Contract.AuthenticationRequiredResponse` が定める。
