# WI-513: 消去要求が WebAuthn 資格情報とリカバリコードまで届く

作業項目は `wi-513-purge-leaves-webauthn-credentials-and-recovery-codes` である。

WI-513 は、利用者の消去 (Purge) が破棄する認証資格情報に、WebAuthn / パスキーの登録済み資格情報と、バックアップ用のリカバリコードを加える。これまでの消去は、同意、リフレッシュトークン、セッション、パスワード履歴、MFA 要素、信頼済みデバイス、デバイスコード、承認リクエストの 8 種を破棄していた。WebAuthn 資格情報とリカバリコードはその一覧に入っておらず、消去を終えた利用者の識別子に紐付いたまま残っていた。

残っていたのは、WebAuthn 資格情報の credential ID、COSE 公開鍵、AAGUID、表示名、最終利用時刻と、リカバリコードのハッシュである。消去後は、これらがどの読み出し経路からも返らない。credential ID を知っていても引けず、リカバリコードの残数は 0 になる。消去した利用者では WebAuthn による認証も、リカバリコードによる認証も成立しなくなる。

管理者の設定変更は要らない。消去そのものの入口 (`DELETE /api/admin/v1/users/{sub}?purge=true` と、猶予期間の経過による自動消去) も、猶予期間も変わらない。消去していない利用者の資格情報には影響しない。

`recovery_codes` テーブルには `users` への `ON DELETE CASCADE` があるが、消去は `users` の行を削除せず Tombstone 化する更新なので、この制約は発火しない。したがってこの変更は制約ではなく、消去のカスケードそのものを直している。データベースのスキーマは変わらない。

規範上の条件は [`docs/standards.md`](../../standards.md) の `GDPR-ERASURE` が定める。同行は「消去は IdManagement の UserLifecycle Purge 遷移と Authentication の資格情報破棄が個別に担う」と宣言しており、この変更は後者の担い分を実装に一致させるものである。
