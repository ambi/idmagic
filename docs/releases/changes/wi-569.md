# WI-569: OAuth2 クライアントの拒否契約を実際の応答へそろえる

作業項目は `wi-569-declared-refusals-that-live-at-a-different-boundary` である。

管理 API の `GetAdminOAuth2Client`、`UpdateAdminOAuth2Client`、`DeleteAdminOAuth2Client` は、404 の `OAuth2ClientNotFoundError`（`urn:idmagic:error:client_not_found`）を契約に宣言した。
製品はこれまでも、存在しない `client_id` と別テナントの `client_id` を同じ 404 で拒否していたが、TypeSpec はこの応答を宣言していなかった。
以前の OAuth2 シナリオは、別テナントの `client_id` の指定を `InvalidRequestError` で拒否すると宣言していた。

この変更により、クライアントは 404 を契約どおりの応答として扱える。
応答は、対象が別テナントにあるか存在しないかを区別しないため、`client_id` だけから別テナントのクライアントの存在を確かめられない。

`client_credentials` を宣言した public クライアントは、登録では拒否されず、`/token` が 400 の `unauthorized_client` で拒否してトークンを発行しない。
以前の OAuth2 シナリオは、この登録を `InvalidRequestError` で拒否すると宣言していた。
製品の応答は変わらない。

観測できる振る舞いは、`docs/domain/oauth2/scenarios.feature.md` の `REQ-OAUTH2-026` と `REQ-OAUTH2-035` が定める。
404 の本文は、TypeSpec の `IdMagic.Contract.OAuth2ClientNotFoundError` が定める。
