# WI-467: Verify Origin and the CSRF token on tenant quota updates

作業項目は `wi-467-enforce-csrf-on-tenant-quota-update` である。

WI-467 は、テナントのクォータ上限を変更する `IdMagic.Tenancy.Operations.UpdateTenantQuota` に、ほかの制御面変更操作と同じ `Origin` と CSRF トークンの検証を適用する。

Cookie セッションからの要求は、`Origin` が発行者と一致し、テナントに対応する CSRF Cookie と `X-Csrf-Token` が一致する場合だけ受け付ける。いずれかを欠く要求には HTTP 403 を返し、クォータも利用量も変更しない。

`Authorization` ヘッダーで渡す Bearer および DPoP の資格情報は周囲資格情報ではないため、これまでどおり Cookie の CSRF 検査を通らずに `tenants:write` で呼び出せる。認証、スコープ、制御面主体の判定は変わらない。

システムコンソールは既に `X-Csrf-Token` を送っているため、画面の操作に変更はない。セッション Cookie だけでこの操作を呼ぶ独自の自動化がある場合は、CSRF Cookie と同じ値のヘッダーを付けるか、API アクセストークンへ切り替える必要がある。

規範上の条件は [REQ-TENANCY-012](../../contexts/tenancy/scenarios.md#req-tenancy-012-system管理者はテナントのクォータ上限を調整できる) と `docs/contexts/tenancy/decisions.md` の管理認可の決定が定める。
