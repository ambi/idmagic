# WI-447: Share one typed action-token core between password reset and email change

作業項目は `wi-447-typed-action-token-core` である。

WI-447 は、パスワード再設定とメールアドレス変更が別々に持っていたトークンの発行と検証を、`backend/shared/security/actiontoken` の共通核へ移す。共通核は用途を閉じた集合として識別し、生のトークンではなくそのダイジェストだけを保存し、発行と検証という 2 つの決定的な計算だけを公開する。用途別のペイロードと業務作用は所有 Context に残る。

利用者から見える差は、確定が失敗したときのトークンの扱いである。これまでは作用の前にトークンを消費していたため、新しいパスワードがパスワード規則に反した場合や、起票から確定までの間に別の利用者が同じメールアドレスを確定していた場合に、拒否と同時にリンクも失われた。今後はトークンの使用済み化と対象の変更を同じトランザクションで確定するため、拒否されたときトークンは未使用のまま残り、同じリンクをもう一度使える。

同じ変更により、並行する 2 つの確定要求のうち作用が成立するのは一方だけであることが保存層で保証される。ブラウザーやメールスキャナーがリンクを `GET` または `HEAD` で先読みしてもトークンは消費されない。確定はこれまでどおり `POST` だけが行う。

HTTP の経路、リクエストの本文、ステータスコード、エラーコードは変わらない。画面の操作にも変更はない。

`password_reset_tokens` と `email_change_tokens` に `id`、`purpose`、`used_at` を追加した。消費は行の削除ではなく `used_at` の設定になる。`purpose` を行に持たせるのは、用途の束縛をどの表を引いたかではなく保存された値で決めるためである。

規範上の条件は [REQ-AUTHENTICATION-016](../../contexts/authentication/scenarios.feature.md#rule-req-authentication-016-ユーザーはメールのリセットリンクでパスワードを再設定する) と [REQ-IDMANAGEMENT-017](../../contexts/identity-management/scenarios.feature.md#rule-req-idmanagement-017-ユーザーはメールアドレス変更を起票し確認リンクで確定できる) が定める。
