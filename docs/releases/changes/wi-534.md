# WI-534: SCIM で削除した User が SCIM の表面から消える

作業項目は `wi-534-deleted-scim-users-stay-visible-to-the-scim-client` である。

WI-534 は、SCIM の `DELETE /scim/v2/Users/{id}` で削除した User を、以後の SCIM の応答から消す。
これまで削除は内部 User を soft delete して `lifecycle.status` を `pending_deletion` にするだけで、SCIM の側では何も消えていなかった。
削除した id への `GET` は 200 と本文を返し、`GET /scim/v2/Users` の一覧にも現れ、`PUT` と `PATCH` も通った。
Group の member として参照されていれば `members` にも残り、他の User の `manager` にも残った。

外部 IdP から見ると、この状態は退職者の扱いを壊す。
削除を送った SCIM クライアントは、次の同期で同じ User を現役の利用者として読み戻す。
`active` が false になっているだけなので無効化と区別できず、クライアント側の照合表に削除済みの id が残り続ける。

削除した id に対して、`GetScimUser`、`UpdateScimUser`、`PatchScimUser`、`DeleteScimUser` は 404 の `ScimProtocolError` を返す。
一度も存在しなかった id との区別は付かない。
`ListScimUsers` は削除済みの User を `Resources` と `totalResults` の双方から除く。
Group の `members` にも、Enterprise 拡張の `manager` にも現れない。
削除済みの id を member や `manager` として送ると `invalidValue` で拒否され、対象のリソースは変わらない。

**無効化した User の扱いは変わらない。** `active: false` は削除ではないので、参照も一覧も member 射影もそのまま通る。
削除と無効化を SCIM の応答で区別できる状態は、この変更で保たれる。

内部の User レコードは従来どおり残る。
削除は依然として soft delete であり、管理側からは読める。
このため、削除した `userName` はそのまま占有され続け、同じ `userName` で作り直そうとすると 409 の `uniqueness` になる。
RFC 7644 §3.6 は削除済みリソースを一意性判定から外すことを SHOULD として求めているが、本製品はこれを採っていない。
再利用が必要な場合は、管理側で User を復元するか purge する。

規範上の条件は `docs/contexts/sourcing/standards.md` の `RFC7644-DELETE-SEMANTICS` が定める。
観測できる振る舞いは `docs/contexts/sourcing/scenarios.feature.md` の `REQ-SOURCING-002` にある。
