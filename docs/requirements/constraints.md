# システム制約

## 外部標準仕様

プロダクト全体と各プロトコルが採用する外部標準仕様は[全体の標準仕様](../standards.md)と各 Context の `standards.md` が持つ。
この文書は規範本文を再掲せず、設計の選択範囲を狭める条件を記録する。

## 実行時制約

- 永続状態とレプリカ間で共有すべき短命状態の正本は PostgreSQL である。
- 複数レプリカの配備では `PERSISTENCE=postgres` を使用し、`memory` は単一プロセスの開発と試験に限る。
- ブラウザー向け UI と API は、Cookie と `Origin` の検証が依存する同一オリジン境界をゲートウェイで構成する。
- API、ワーカー、バッチは同じコードベースを共有するが、負荷とライフサイクルが異なる実行単位として配備する。
- 秘密値、リリースイメージのダイジェスト、クラウド固有のデータベース接続先をリポジトリへ保存しない。

## 提供上の制約

ツールの版、環境、標準タスクは `mise.toml` が持つ。
モデル、API、HTTP バインディング、認証機構は TypeSpec を正本とし、OpenAPI と仕様サイトは未追跡の派生成果物とする。
データベース構造は宣言的な PostgreSQL スキーマを正本とし、起動時に破壊的なスキーマ変更を適用しない。
