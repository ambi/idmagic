# プロダクト概要

## 課題

組織では、利用者、業務用エージェント、連携アプリケーションの認証方式とアイデンティティ情報が分散しやすい。
その結果、退職や権限変更の反映、アクセス制御、操作の追跡がシステムごとに分断される。
IdMagic は、認証、アイデンティティ同期、資格情報、委譲、監査をテナント単位でまとめて管理する。

プロダクトの現在の範囲は [Context Map](../design/architecture/logical.md#context-map) の索引に示す。

## 利用者

- **テナント管理者**：利用者、グループ、アプリケーション、認証ポリシー、プロビジョニング、委譲を管理する。
- **アプリケーションと連携の実装者**：OAuth 2.0、OpenID Connect、SAML 2.0、WS-Federation、SCIM 2.0 のプロトコルと標準仕様を使って IdMagic と接続する。
- **運用担当者**：デプロイ、可用性、キャパシティ、鍵、バックアップ、監視を管理し、障害時には運用手順書に従う。
- **利用者**：組織のアプリケーションへ認証し、自身のプロフィール、セッション、資格情報を管理する。

## 対象としない責務

次の責務は IdMagic が担わず、境界を接する外部の仕組みが引き受ける。

| 対象としない責務 | 担当 |
| --- | --- |
| 人事情報の正本 | 人事システムなどの上流の権威。IdMagic は `Sourcing` として取り込む側であり、在籍情報の発生源にはならない。 |
| メールと SMS の配信経路の運用 | 外部の SMTP サーバーと配信事業者。IdMagic は送信を依頼するが、到達性、送信者評価、通信事業者との接続は管理しない。 |
| 汎用の API ゲートウェイと WAF | 前段のゲートウェイまたはリバースプロキシ。TLS 終端、同一オリジン境界、低速接続への防御はそちらが担う（[ネットワーク設計](../design/infrastructure/network.md)）。 |
| 人事判断やアクセス承認の決定 | 組織の責任者と承認者。IdMagic は決定済みのポリシーを執行し、判断と結果を記録する。 |
