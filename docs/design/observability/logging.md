# ログ設計

アプリケーションは `timestamp`、`level`、`service`、`message` と、利用可能な `trace_id`、`span_id`、`request_id` を持つ JSON Lines を標準出力へ書く。
プロセス自身はログファイルの回転、転送、保存を行わない。

予期された業務上の拒否を `ERROR` にせず、運用者が対処すべき異常と分ける。
件数と比率は指標で測り、ログ集計を SLO の正本にしない。

ローカルの Docker Compose では Promtail が Docker のログを Loki へ送り、Kubernetes では DaemonSet が Pod ログを収集する。
`service` と `level` は有限集合のラベル、相関 ID は高カーディナリティの構造化メタデータとして扱う。

パスワード、トークン、Cookie、認可コード、クライアントシークレット、秘密鍵、TOTP シード、個人情報をログへ出さない。
監査証跡は診断ログへ書かず、[Audit](../../contexts/audit/) の保持と検索を使う。

保持期間、外部オブジェクトストレージ、閲覧権限、削除、容量超過時の挙動は配備環境に依存し、現在の本番設計としては未確定である。
開発用 Loki の単一レプリカとローカルファイル保存を本番の可用性または保持保証として扱わない。
