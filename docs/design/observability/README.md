# オブザーバビリティ設計

## 目的

この文書は、動いているシステムの状態を外から知るために、システムが何を出力し、別々の出力に残った記録をどう結び付けるかを定める。

メトリクス、ログ、トレースの三つをまとめて**シグナル**と呼ぶ。
OpenTelemetry がテレメトリーの種類を指してこの語を使うので、同じ語を使う。
プロセスへ送る OS のシグナルとは別のものであり、この文書でシグナルと書くときは常にテレメトリーの種類を指す。

個別のメトリクス、ログ、トレースの設計は子文書が持つ。
サービス目標の値と運用手順は、この文書へ複製しない。

## シグナルモデル

| シグナル | 所有者 | 主な用途 |
| --- | --- | --- |
| Metrics | [監視設計](monitoring.md) | サービス目標、資源、依存先、キューの継続的な状態判定とアラート |
| Logs | [ログ設計](logging.md) | 個別リクエストとジョブの事実、障害理由、監査対象外の診断情報 |
| Traces | [トレース設計](tracing.md) | 実行単位と外部依存をまたぐ因果関係と所要時間 |

監査イベントは診断ログではなく、改ざん耐性と保持要件を持つ業務上の記録である。監査の意味と保持期間は [Audit](../../contexts/audit/README.md) が所有し、監査イベントがほかのデータとどう違う消え方をするかは[データライフサイクル設計](../data/lifecycle.md)が持つ。

## シグナル間の相関

一つの処理の記録は、メトリクス、ログ、トレースに分かれて残る。
これらを同じ処理のものとして結び付けることを**相関**と呼び、そのために**相関 ID** を使う。

API は入口で `traceparent` を検証し、有効ならトレースを継続し、無効または欠落なら新しいトレースを開始する。すべてのレスポンスへ `X-Request-ID` を返し、構造化ログには `request_id`、`trace_id`、登録済みのルートパターン、メソッド、状態コード、所要時間を含める。Worker と Batch はジョブまたは実行の識別子を持ち、HTTP リクエストから派生した処理では元の相関 ID を引き継ぐ。

テナント ID、ユーザー ID、クライアント ID などの高カーディナリティ値をメトリクスのラベルにしない。必要な調査軸はログまたはトレースに置き、資格情報、トークン、Cookie、認可コード、秘密鍵、復号済みの秘密情報をいずれのシグナルにも記録しない。

## 所有と流れ

アプリケーションは OpenTelemetry と構造化ログを生成し、Prometheus はメトリクスを収集する。現行のローカル監視構成では Grafana Alloy がコンテナログを Loki へ送り、Grafana が Prometheus と Loki を表示する。プロダクトコードは特定の可視化プロダクトへ依存せず、シグナルの意味と属性名を安定させる。

サービス目標の測定境界と値は [品質要求](../../requirements/quality.md) が、アラートからの対応手順は [Runbooks](../../runbooks/) が所有する。観測設計は、目標を計算できるシグナルと手順へ到達できる通知を提供する。

## 子文書の担当

| 子文書 | 定めるもの |
| --- | --- |
| [監視設計](monitoring.md) | 検知したいことと、それを判定するシグナル、通知の種類、対応する runbook の対応。検知できていないものの記録 |
| [ログ設計](logging.md) | 共通フィールド、`event_name` の命名規約、ログレベル、サンプリング規則、保持と閲覧権限、容量超過と収集停止時の動作 |
| [トレース設計](tracing.md) | 伝播、標本化、属性と span 名、保持とコスト。実装の現状と目標設計の区別 |

## 未確定事項

デプロイ先が決まるまで確定しない項目がある。
値が決まるまで、これらを暗黙の保証として扱わない。

| 未確定な項目 | 記録する子文書 |
| --- | --- |
| 通知の宛先とエスカレーション | [監視設計](monitoring.md) |
| ログの保持期間、外部オブジェクトストレージ、閲覧権限の分離 | [ログ設計](logging.md) |
| トレースの保存先、本番の標本化率、保持期間 | [トレース設計](tracing.md) |

いずれのシグナルについても、**欠落を正常と読まない**。
アラートが鳴らないこと、ダッシュボードが空であること、トレースが見つからないことは、収集が止まっている場合にも同じ見え方をする。
収集そのものの状態は、[監視設計](monitoring.md)が別の判定として持つ。
