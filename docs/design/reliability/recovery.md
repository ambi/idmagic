# 復旧設計

## 保護層

論理削除、過去の時点へ戻すバックアップと復元、破損を保持期限内に見つける監視を別の防御として使う。
レプリカは物理障害への可用性を高めるが、誤操作やアプリケーションによる論理破損も複製するため、復元を代替しない。

## 現在の復旧経路

`infra/backup/` は PostgreSQL の論理バックアップ、チェックサム、空のデータベースへの復元、整合性検査を実装する。
`mise run restore-drill` は使い捨てのローカル環境で損失、復元、検査を通す。
具体的な作業順序と障害シナリオは[バックアップと復旧のrunbook](../../runbooks/backup-restore-dr.md)が持つ。

復元では、スキーマを適用し、データを戻し、再生成可能な短命テーブルを空にし、テナント分離と参照整合性を確認する。
署名鍵、データ暗号のマスター鍵、構成、DNS、証明書も復旧対象として扱う。

## 未検証の目標

ローカル訓練の時間は本番のデータ量、外部鍵、ネットワーク、承認手順を含まない。
本番のデータ種別ごとの RPO と RTO、バックアップ頻度、保管先、暗号化、リージョン喪失時の切替は未確定である。
これらは [wi-165](../../../work-items/wi-165-high-availability-and-failover-resilience-topology.md) と既存の復旧作業の後続で確定し、[品質要求](../../requirements/quality.md)へ目標を追加する。
