# セキュリティ設計

この文書は、資産、信頼境界、認証と認可、シークレットのライフサイクルを扱うセキュリティ設計の入口である。
プロトコル固有の制御は各モジュールの標準仕様とシナリオで定める。

| 文書 | 内容 |
| --- | --- |
| [脅威モデル](threat-model.md) | 資産、信頼境界、脅威、応える制御 |
| [認可設計](authorization.md) | 主体、スコープ、テナント境界、フェイルクローズ規則、認証の保証（水準と新しさ） |
| [シークレット設計](secrets.md) | シークレットの種類ごとの管理主体とライフサイクル |

## 暗号とプロトコルの処理を自作しない

暗号、署名、プロトコルのメッセージの解析のように、広く使われ検証されたライブラリがある処理は自作せず、ライブラリに委ねる。
IdMagic が書くのは、ライブラリの使い方（鍵の選択、検証する項目、拒否の条件）だけである。
暗号とプロトコルの誤りは正常系のテストでは見つからず、悪用されるまで気付かないことが多いためである。
どこまで検証するかは、作業項目の `risk` と[脅威モデル](threat-model.md)が決める。
