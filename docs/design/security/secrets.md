# シークレットと鍵の設計

## 区分と所有

| 種類 | 正本と所有者 | 主な保護 |
| --- | --- | --- |
| 起動時の秘密 | 配備基盤の Secret 管理 | Git へ保存せず、必要な実行単位だけへ注入する |
| クライアント資格情報 | 所有する Context の Repository | 平文の再表示を避け、比較可能な表現または封筒暗号で保存する |
| データ暗号鍵 | [Data Keys](../../contexts/data-keys/) | テナント単位の DEK と外部または起動時のマスター鍵を分離する |
| 署名鍵と証明書 | [Signing Keys](../../contexts/signing-keys/) | 用途とテナントを分け、公開鍵の配布と秘密鍵の利用を分離する |
| TLS 証明書 | 配備基盤 | DNS 名と更新を基盤が所有し、アプリケーションへ秘密鍵を渡さない構成を優先する |

## ライフサイクル

秘密は生成、保存、配布、利用、ローテーション、失効、廃棄、復旧の各段階で所有者と監査対象を定める。
新旧の鍵を同時に受理する期間を設け、署名または暗号化済みデータの寿命より短い切替で既存データを読めなくしない。

マスター鍵を失うと暗号化されたデータは復旧できない。
データベースのバックアップだけを復旧可能性の証拠にせず、鍵素材または外部鍵サービスへの到達性を復元訓練に含める。
