# データライフサイクル設計

データの意味と所有者は各 Context が持ち、データベース設計はそのライフサイクルを横断して支える。

| 段階 | 設計規則 |
| --- | --- |
| 作成と更新 | Context のユースケースが検証し、Repository ポートを通じて一つのトランザクション境界で確定する |
| 短命状態 | `expires_at` を持ち、読み取り時に期限を判定する。掃除の遅延で有効期間を延ばさない |
| 失効 | 監査や再送安全性が必要な記録は理由と時刻を残し、単純な削除に置き換えない |
| 保持 | 外部規範と Context の判断を正本とし、容量設計はその値を参照する |
| 削除と匿名化 | テナント境界と参照整合性を保ち、監査対象の事実を通常ログへ退避しない |
| スキーマ移行 | 拡張、書き込み移行、読み取り移行、縮小の順に分け、新旧の版が混在できる期間を作る |
| 復元 | 空の対象へ復元し、スキーマ、テナント分離、参照整合性、鍵への到達性を確認する |

保持期間の変更は容量、プライバシー、復旧へ同時に影響するため、対象 Context の標準仕様と[品質要求](../../requirements/quality.md)を先に変更する。
