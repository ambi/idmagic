# リスクと技術的負債

この文書は、システム全体にかかわる既知のリスクと技術的負債を扱う。
脅威と統制は[脅威モデル](../security/threat-model.md)が、一つの Context に閉じたリスクはその Context の `design/risks.md` が扱う。
是正を担う作業項目はこの文書に書かず、作業項目の側からこの文書を参照する。

| リスク | 影響 | 現在の扱い | 詳細 |
| --- | --- | --- | --- |
| キャパシティの数値がすべて仮定値である | サイジングと品質要求の達成見込みが、測定で裏付けられていない | 測った値は、条件とともに実測値として記録する | [キャパシティ設計](../performance/capacity.md#仮定値と実測値) |
| デプロイプロファイルの稼働実績がない | 汎用 Kubernetes は検査を通るが、適用した環境での稼働はリポジトリから確かめられない。Google Cloud のプロファイルは構成ファイルがない | 各プロファイルを構成例として扱い、本番への適用や検証の完了を示すものとしない | [デプロイメントアーキテクチャ](deployment.md#デプロイプロファイル) |
| 可用性の設計の一部が実装されていない | 障害の単位ごとの検知と対処のうち、構成ファイルも実装もない行がある | 行ごとに実装状況の区分を示す | [可用性設計](../reliability/availability.md#実装状況の区分) |
| 分散トレースが入口での文脈の受信にとどまる | 要求をまたぐ調査を、ログの相関に頼る | 目標設計と現状を分けて示す | [トレース設計](../observability/tracing.md#実装の現状) |
