# リスクと技術的負債

この文書は、システム全体にかかわる既知のリスクと技術的負債を扱う。
脅威と統制は[脅威モデル](../security/threat-model.md)が、一つのモジュールに閉じたリスクはそのモジュールの `design/risks.md` が扱う。
是正を担う作業項目はこの文書に書かず、作業項目の側からこの文書を参照する。
是正を担う作業項目を起票しただけでは行を消さず、実装、構成、測定のいずれかで解消を確かめてから消す。

各行の現状は次の区分で示す。

| 区分 | 意味 |
| --- | --- |
| 未実装 | 設計は決まっているが、構成ファイルにも実装にもまだ反映していない |
| 未実測 | 値が仮定のままで、測定で裏付けていない |
| 実環境で未検証 | リポジトリの構成と検査はあるが、適用した環境での稼働は確かめていない |
| 残存 | 設計の規則に反するコードが残っている |

| リスク | 現状 | 影響 | 現在の扱い | 詳細 |
| --- | --- | --- | --- | --- |
| キャパシティの数値がすべて仮定値である | 未実測 | サイジングと品質要件の達成見込みが、測定で裏付けられていない | 測った値は、条件とともに実測値として記録する | [キャパシティ設計](../performance/capacity.md#仮定値と実測値) |
| デプロイプロファイルの稼働実績がない | 汎用 Kubernetes は実環境で未検証。Google Cloud は未実装 | 汎用 Kubernetes は検査を通るが、適用した環境での稼働はリポジトリから確かめられない。Google Cloud のプロファイルは GKE 向けの構成ファイルがない。`infra/deploy/gcp/` にある Cloud Run 案のひな型は、GKE の構成に数えない | 各プロファイルを構成例として扱い、本番への適用や検証の完了を示すものとしない | [デプロイメントアーキテクチャ](deployment.md#デプロイプロファイル) |
| 可用性の設計の一部が実装されていない | 未実装 | 障害の単位ごとの検知と対処のうち、構成ファイルも実装もない行がある | 行ごとに実装状況の区分を示す | [可用性設計](../reliability/availability.md#実装状況の区分) |
| HTTP アダプターの一部がドメイン型をレスポンス型のフィールドへ直接使う | 残存 | 外部形式の変更が、ドメイン型と呼び出し側へ波及しうる | 配置だけから変換の分離を仮定しない | [設計ガイドライン](../application/design-guidelines.md#アダプターと表現) |
| System の組み立て地点の宣言にフロントエンド全体が含まれる | 残存 | 画面、認可トランザクションの表示とポータルの OIDC RP の判断を結線として扱い、実装の責務と宣言が一致しない | 画面の責務とサーバーの結線を分けて設計する。別イメージであることだけから独立したリリース系列を仮定しない | [責務表](../../modules/README.md#基盤)、[フロントエンド設計](../application/frontend.md#全体構成) |
| Seeding のリソース生成と差分判定が組み立て地点に残る | 残存 | seed の規則の変更が起動処理へ波及し、Seeding が隠す判断を実装の境界から読めない | 生成と計画は Seeding、状態更新の保証は各所有者、結線は組み立て地点に分ける。公開操作を通らない現状はモジュールのリスクで扱う | [Seeding](../../modules/seeding/README.md#責務と境界)、[Seeding のリスク](../../modules/seeding/risks.md) |
| OAuth2 が汎用認可のポートと複数モジュールの管理ロールの表示を担当する | 残存 | トークンの発行と無関係な管理権限の追加が OAuth2 へ波及し、Authorization も OAuth2 の認可ポートへ依存する | トークンと委譲の判断は OAuth2 に残し、汎用認可の契約、管理表示と規範から生成する表現の担当を分ける | [OAuth2](../../modules/oauth2/README.md#責務と境界)、[Authorization](../../modules/authorization/README.md#責務と境界) |
| ApplicationCatalog が SAML の SP と WS-Fed の RP の保存型を直接変更する | 残存 | 所有者の不変条件と保存表現の変更が Catalog へも波及し、管理経路ごとに検証と作用がずれうる | Saml と WsFederation の管理操作へ更新を集め、Catalog は HTTP の変換と編成を担当する。OIDC は公開管理操作を利用済み | [ApplicationCatalog](../../modules/application-catalog/README.md#設計の要点)、[依存の向き](../application/backend.md#依存の向きを選ぶ基準) |
| WsFederation が WS-Trust の再送防止に OAuth2 のクライアント認証ポートを使う | 残存 | WS-Trust の MessageID の記録が、業務上必要のない OAuth のクライアント認証の語彙へ依存する | 要求側の最小のポートと技術的な再送ストアを比べ、キー、有効期間と同じ保存先を維持して結ぶ | [WsFederation](../../modules/ws-federation/README.md#責務と境界)、[境界の判断手順](../application/design-guidelines.md#境界を選ぶ判断手順) |
| ドメインの構造体の一部が構築後の検証を必要とする | 残存 | 不正な状態を型だけでは構築できないとは言えない | 「不正な状態を型だけでは構築できない」をリポジトリ全体の性質とはしない | [設計ガイドライン](../application/design-guidelines.md#型の所有と不変条件) |
| 分散トレースが API の一部の経路の受信スパンにとどまる | 未実装 | `idmagic-worker` と `idmagic-batch` は Provider を組み立てず、データベース、外部 HTTP、ジョブの子スパンもない。要求をまたぐ調査を、ログの相関に頼る | 目標設計と現状を分けて示す | [トレース設計](../observability/tracing.md#実装の現状) |
