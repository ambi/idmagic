# Product Overview

## Problem

組織内の人間、業務用エージェント、接続先アプリケーションが別々の認証方式とアイデンティティ情報を持つと、退職や権限変更を一貫して反映できず、誰が何を行ったかを追跡する経路も分断される。IdMagic は、複数の認証プロトコル、アイデンティティの取り込みと配布、資格情報、委譲、監査をテナント境界の内側で結び付ける。

製品の現在の範囲は [Context Map](README.md#context-map) の索引が宣言する。機能の一覧をここに複製しないため、実装済み機能の詳細は各 Bounded Context の入口から辿る。

## Users

- **テナント管理者**：利用者、グループ、アプリケーション、認証ポリシー、プロビジョニング、委譲を管理する。
- **アプリケーションと連携の実装者**：OAuth 2.0、OpenID Connect、SAML 2.0、WS-Federation、SCIM 2.0 の契約を使って IdMagic と接続する。
- **運用担当者**：配備、可用性、容量、鍵、バックアップ、監視を管理し、障害時には runbook に従う。
- **利用者**：組織のアプリケーションへ認証し、自身のプロフィール、セッション、資格情報を管理する。

## Non-goals

次の責務は IdMagic が担わず、境界を接する外部の仕組みが引き受ける。

| Non-goal | Owner |
| --- | --- |
| 人事情報の正本 | 人事システムなどの上流の権威。IdMagic は `Sourcing` として取り込む側であり、在籍情報の発生源にはならない。 |
| メールと SMS の配信経路の運用 | 外部の SMTP サーバーと配信事業者。IdMagic は送信を依頼するが、到達性、送信者評価、通信事業者との接続は持たない。 |
| 汎用の API ゲートウェイと WAF | 前段のゲートウェイまたはリバースプロキシ。TLS 終端、同一オリジン境界、低速接続への防御はそちらが担う（[Deployment](deployment.md)）。 |
| 人事判断やアクセス承認の決定 | 組織の責任者と承認者。IdMagic は決定済みのポリシーを執行し、判断と結果を記録する。 |
