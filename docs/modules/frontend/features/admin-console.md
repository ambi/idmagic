# 管理コンソールのリソース操作

## 概要

管理コンソールの一覧から作成、編集、更新へ進む操作と、入力欄の意味を揃える。
システムコンソールのテナント画面の、詳細から変更へ進む操作と確認も扱う。
業務上の認可と保存は、各 API の所有モジュールが判断する。

## 操作

### 管理者によるリソースの一覧と更新

#### REQ-FRONTEND-001 一覧は対象の件数と再取得の操作を共通の形式で示す

- 管理者がリソース一覧を開いたとき、System は、一覧上部に件数と更新操作を表示する。
- 総件数を取得した一覧では、System は、総件数と表示中の件数を区別する。
- 総件数を取得していない一覧では、System は、取得した件数を表示件数と明記する。
- 管理者が一覧を更新したとき、System は、現在のページと検索条件を保ってデータを再取得する。
- 再取得に失敗した場合、System は、直前の一覧を維持し、失敗を表示する。
- 管理者がロール一覧を開いたとき、System は、ロールの総数とロールごとの付与人数を区別する。
- 管理者がロールの付与人数を確認したとき、System は、ユーザーの先頭ページだけに切り詰めずに集計する。

### 管理者によるリソースの作成

#### REQ-FRONTEND-002 リソースの作成は専用画面へ遷移し、資格情報の用途を区別する

- 管理者が外部サービス連携の追加を選んだとき、System は、専用の作成画面へ遷移する。
- 管理者が未作成の認可モデルの作成を選んだとき、System は、専用の作成画面へ遷移する。
- 管理者が外部サービス連携の作成画面を開いたとき、System は、必須と任意の項目を区別し、機械用シークレットにログインパスワードと異なる自動補完の用途を指定する。
- 作成に失敗した場合、System は、作成画面と入力を維持し、失敗を表示する。
- 作成に成功したとき、System は、戻り先で保存結果を再取得し、成功を通知する。

### System 管理者によるテナントの確認と変更

#### REQ-FRONTEND-003 システムコンソールのテナントの変更は、読み取り専用の詳細から専用の変更画面へ遷移して行う

- System 管理者がテナントの詳細を開いたとき、System は、現在の値を読み取り専用で表示し、表示名とパスワードポリシー、上限、正規ロケーションのそれぞれの変更画面への入口を置く。
- System 管理者がテナントの作成を選んだとき、System は、専用の作成画面へ遷移する。
- テナントの作成に成功したとき、System は、作成したテナントの詳細へ遷移し、成功を通知する。
- System 管理者が変更画面で保存したとき、System は、その変更画面が扱う一つの API だけを要求する。
- 保存に成功したとき、System は、テナントの詳細へ戻って現在の値を再取得し、成功を通知する。
- 作成または保存に失敗した場合、System は、その画面と入力を維持し、失敗を表示する。
- **判断**：表示名とパスワードポリシーの更新と、上限の更新は別の API である。一つの保存で両方を送ると、片方だけが保存された状態を利用者に示す必要が生じるため、変更画面を API ごとに分ける。

#### REQ-FRONTEND-004 システムコンソールのテナントの無効化、再開、正規ロケーションの切替は、確認を経てから要求する

- System 管理者が一覧の行または詳細から無効化または再開を選んだとき、System は、対象の realm、操作の結果、取り消せるかを示す確認を表示し、要求をまだ送らない。
- System 管理者が正規ロケーションの切替を保存したとき、System は、発行者、WebAuthn の RP ID、Cookie の適用範囲が変わることを示す確認を表示し、要求をまだ送らない。
- System 管理者が確認を承認したとき、System は、要求を送り、一覧または詳細の状態を再取得する。
- System 管理者が確認を取り消した場合、System は、要求を送らず、テナントの表示を変えない。
