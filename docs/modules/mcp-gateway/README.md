# McpGateway

## 責務と境界

利用者の環境で既存の MCP サーバーの手前に置く実行単位 `idmagic-mcp-gateway` として、MCP の要求を解釈し、IdMagic の評価が許可した要求だけを上流へ転送する。
役割は Policy Enforcement Point であり、判断は IdMagic が行う。
IdMagic のサーバーとは別に配布され、別々に版が進む。
このモジュールとサーバーの間の契約は、TypeSpec の `POST /resource-access/evaluate` だけである。

| 扱わないもの | 担当 |
| --- | --- |
| トークンの検証、主体の導出、送信者制約の確認、関係の判定 | `OAuth2`、`AccessControl` |
| 主体と Agent を含む判断の監査記録 | `OAuth2` の `ResourceAccessEvaluated`、`Audit` |
| 汎用 API ゲートウェイ、WAF、プロンプトの検査、TLS の終端 | 前段のゲートウェイまたはリバースプロキシ |

## 主な流れ

| 流れ | 契機 | 実行する場所 | 詳細 |
| --- | --- | --- | --- |
| 要求の執行 | MCP クライアントの `POST`、または Envoy の `ext_authz` の呼び出し | 利用者の環境のプロセス | [要求の執行](features/runtime.md#要求の執行) |

## 設計の要点

| 方針 | 理由 |
| --- | --- |
| サーバーのモジュールを import せず、評価のワイヤの型を TypeSpec に合わせて自分で持つ | 配布済みのゲートウェイとサーバーは版がずれる |
| トークンを解析せず、提示されたトークンと DPoP の証明をそのまま評価へ渡す | 未検証の値を主体として扱わず、トークンの解釈を IdMagic の一か所に保つ |
| 要求の解釈と評価の選択を、作用のない計算に閉じる | 解釈の誤りは許可の取り違えに直結するので、入力の全域を単体で確かめる |
| 解釈できない要求と宣言のない方法をデフォルトで拒否する | 未知の入力を通さない |
| 下流のトークンを呼び出しごとに交換し、保持しない | 状態を持たず、一回限りの許可と短い有効期間で再束縛の影響を抑える |
