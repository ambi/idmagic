# モジュール設計文書

この文書は、モジュールごとの責務、公開契約、振る舞い、内部設計を収めるモジュール設計文書の入口である。
システム全体の構造と、モジュールへの割り当ては[全体設計文書](../design/README.md)、製品の目的と要件は[要件文書](../requirements/README.md)で定める。
モジュール設計文書は、全体設計文書からの割り当てと例外だけを書き、同じ内容を書き写さない。

モジュールは、保存表現、正規化、外部プロトコルの変換など、変わりうる設計判断を内部へ隠す単位として設計する。
境界の追加や変更は、要件と不変条件、状態の更新元、公開範囲、変更の波及を[境界を選ぶ判断手順](../design/application/design-guidelines.md#境界を選ぶ判断手順)で比較して決める。

## モジュール

モジュールの一覧は[論理アーキテクチャ](../design/architecture/logical.md#モジュールの責務)の責務表に記録する。
責務表の一行、`docs/modules/<module>/` のモジュール設計文書、`backend/` の実装のモジュールは一対一に対応する。
ここに一覧を複製すると、モジュールを足したときに片方が古くなる。

## モジュールの文書

各モジュールには責務と境界を宣言する `README.md` と、設計を設計領域ごとに索引する `design/README.md` を置く。
その他の文書は、書くべき仕様や設計があるときに置く。

| 文書 | 内容 |
| --- | --- |
| `README.md` | 仕様：責務と境界、モデル、公開契約、機能の索引 |
| `glossary.md` | 仕様：モジュール固有の語義と、全体の語を狭めた定義 |
| `standards.md` | 仕様：採用する外部規範と逸脱 |
| `quality.md` | 仕様：システムから割り当てられた品質要件と固有の値 |
| `design/README.md` | 設計：設計領域の索引と、設計の記録へのリンク。該当しない設計領域には理由を書く |
| `design/<area>.md` | 設計：アーキテクチャ、データ、セキュリティなど、設計領域ごとの内部設計 |
| `design/decisions.md` | 設計の記録：代替案を比べた、現在有効な判断と見直し条件 |
| `design/risks.md` | 設計の記録：既知の欠陥、技術的負債、受容したリスク（任意） |
| `<group>/README.md` | 仕様：関係の深い機能の境界と索引。機能群を置かない構成も許す |
| `<group>/<feature>/README.md` と章 | 仕様：一つの機能の要件、操作、状態遷移 |
| `<group>/<feature>/acceptance.feature.md` | 仕様：要件に付ける任意の受け入れ例 |
| `<group>/<feature>/design.md` | 設計：その機能に閉じた、コードから読み取れない仕組み |

モデル、API、認証機構の契約は `spec/contexts/<context>/` の TypeSpec が定める。
散文の側に同じ契約を書かない。
仕様の記述規則は[仕様フォーマット](../formats/specification-format.md)、設計の記述規則は[設計フォーマット](../formats/design-format.md)、配置は[文書ガイド](../formats/documentation-guide.md#配置)が定める。
