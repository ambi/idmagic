# ポータルのアプリケーション

## 概要

この文書は、エンドユーザーがポータルで自分のアプリケーションを一覧し、並べ替える仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 割り当て済みのアプリケーションの一覧、手動の並び順の保存と適用 |
| 行為者 | EndUser、API トークンの発行者 |
| 扱わないもの | 割り当ての作成と解除は[割り当て](../assignment/README.md)が扱う |

## モデル

`ListMyApplications` は、割り当て済みで、表示され、有効なアプリケーションを解決してから、保存済みの並び順を適用する。
割り当てが外れた項目は除き、保存済みの並びにない割り当て済みのアプリケーションは、名前の順で末尾に加える。
並び順を保存していない場合は、すべてを名前の昇順に並べる。
そのため、割り当てが並行して変わっても、一覧は壊れない。

`ReorderMyApplications` は並び順を作成または更新するだけであり、個人の表示の設定なので、ドメインイベントを発行しない。

## 操作

### 利用者によるポータルのアプリケーションの操作

#### REQ-APPLICATION-003 API トークン発行者は account スコープで自分のポータルアプリケーションだけを操作できる

- 利用者が自分のアプリケーションを一覧したとき、Application は、本人またはその Group に割り当てられ、`visible` で、有効なアプリケーションだけを、保存した並び順で返す。
- 並び順を保存している間、利用者が自分のアプリケーションを一覧したとき、Application は、割り当てが外れた項目を除き、並び順にない割り当て済みのアプリケーションを名前の順で末尾に加える。
- 並び順を保存していない間、利用者が自分のアプリケーションを一覧したとき、Application は、名前の昇順で返す。
- 利用者が並び順を保存したとき、Application は、本人の並び順を作成または更新し、ドメインイベントを発行しない。
- `account:read` のスコープの API アクセストークンで呼び出されたとき、Application は、発行者本人のアプリケーションと並び順の参照だけを許可し、ほかの利用者の一覧と並び順を返さない。
- `account:write` を持たないトークンで並び順の保存を要求された場合、Application は、403 と `insufficient_scope` で拒否し、並び順を変えない。
- 別のテナントで発行したトークンを提示された場合、Application は、401 と `invalid_token` で拒否し、並び順を変えない。
- **例**：EX-APPLICATION-003-01、EX-APPLICATION-003-02、EX-APPLICATION-003-03

## セキュリティ上の考慮

エンドユーザーが触れるのは自分自身の範囲だけである。
`ListMyApplications` と `ReorderMyApplications` は認証済みの本人の割り当てと表示の設定に閉じ（`account:applications_read`）、ほかのユーザーの一覧や並び順へは到達できない。
