# SigningKeys のデータ

この文書は、SigningKeys が鍵の状態をどう保存するかを扱う。
テーブルの定義はスキーマファイルが定める。

## 状態の表し方

鍵の状態は、状態の列ではなく、有効かどうかと三つの時刻の組で表す。

| 状態 | 保存した値 |
| --- | --- |
| `Active` | 有効である |
| `Verifying` | 有効でなく、退役の時刻と期限があり、期限が来ていない |
| `Retired` | 有効でなく、期限が過ぎ、アーカイブの時刻がない。保存した値を変える処理はなく、時刻の経過だけで `Verifying` からこの状態になる |
| `Archived` | アーカイブの時刻がある |

公開鍵の一覧は、アーカイブの時刻がなく、有効であるか期限の来ていない鍵を返す。
検証用の鍵の無効化は、有効でないことを確かめてからアーカイブの時刻を立てる。

## 排他

テナント、用途、スコープの組ごとに、有効な鍵は 1 本だけである。
PostgreSQL では部分一意索引でこれを保証し、ローテーションは組ごとのアドバイザリーロックの中で、古い鍵の降格と新しい鍵の作成を一つのトランザクションで行う。
Vault では、鍵の集合の識別情報にスコープを含める。
