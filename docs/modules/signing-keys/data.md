# SigningKeys のデータ

この文書は、SigningKeys が鍵の状態をどう保存するかを扱う。
テーブルの定義はスキーマファイルが定める。

## 集約

| Aggregate | 境界の内側にあるもの | 他の Aggregate との関係 |
| --- | --- | --- |
| `SigningKey` | `kid`、テナント、用途（`KeyUsage`）、スコープ、提供元、公開鍵と秘密鍵の JWK、XML 用の証明書、有効か、退役、期限、アーカイブの時刻 | `Tenant` を `tenant_id` で参照する |

鍵は、テナント、用途、外部には意味を公開しないスコープ ID の組で分離する。
組ごとに、有効な鍵は 1 本だけである。

| 用途 | 使う側 | スコープ |
| --- | --- | --- |
| `Signing` | OAuth2 と OIDC の JWT。用途とスコープを明示しない呼び出し元にはこれとデフォルトのスコープを適用する | デフォルトのスコープ |
| `XmlFederationSigning` | SAML と WS-Federation の XML 署名 | SAML では IdP のプロファイルの ID |
| `IdJagSigning` | ID-JAG の RS256 の署名。JWKS に `Signing` の鍵と並べて公開する | スコープは使わない |

| 提供元（`KeyProvider`） | 秘密鍵の置き場所 | 署名する主体 |
| --- | --- | --- |
| `Local` | プロセスのメモリ | アプリケーション |
| `Database` | `signing_keys.private_jwk` に平文で置く。PostgreSQL のバックアップにも平文で入る | アプリケーション |
| `VaultTransit` | Vault の中から出さない。データベースには公開鍵の写しだけが残る | Vault |

- **判断**：署名鍵の秘密鍵は、[データベース設計](../../design/data/database.md#可逆な秘密情報のエンベロープ暗号)のエンベロープ暗号化の対象ではない。署名鍵は読み出して復号するものではなく、提供元の内側で署名に使うものであり、保護は暗号化ではなく提供元の選択で決まるからである。

## 状態の表し方

鍵の状態は、状態の列ではなく、有効かどうかと三つの時刻の組で表す。

| 状態 | 保存した値 |
| --- | --- |
| `Active` | 有効である |
| `Prepared` | 有効でなく、`prepared` が真であり、退役と期限とアーカイブの時刻がない |
| `Verifying` | 有効でなく、退役の時刻と期限があり、期限が来ていない |
| `Retired` | 有効でなく、期限が過ぎ、アーカイブの時刻がない。保存した値を変える処理はなく、時刻の経過だけで `Verifying` からこの状態になる |
| `Archived` | アーカイブの時刻がある |

公開鍵の一覧は、アーカイブの時刻がなく、有効であるか、準備済みであるか、期限の来ていない検証用の鍵を返す。
検証用の鍵の無効化は、有効でないことを確かめてからアーカイブの時刻を立てる。

## 排他

テナント、用途、スコープの組ごとに、有効な鍵は 1 本だけである。
PostgreSQL では部分一意索引でこれを保証し、ローテーションは組ごとのアドバイザリーロックの中で、古い鍵の降格と新しい鍵の作成を一つのトランザクションで行う。
Vault では、鍵の集合の識別情報にスコープを含める。

XML の候補を先に公開するため、集合ごとに準備済みの鍵も一つだけにする。
Local は mutex、Database は同じ advisory lock と部分一意索引でこれを保つ。
切り替えと無効化も同じ直列化の内側で状態を読み直すので、無効化の途中で候補を有効にする競合を避ける。

PostgreSQL の構成で Vault を選んだとき、XML 鍵の世代と公開部分と状態は `vault_signing_key_sets` に保存する。
保存するのは証明書、公開 JWK、Vault のバージョン、用途とスコープ、有効か準備済みか、ライフサイクルの時刻であり、秘密鍵は含めない。
要求ごとに保存した選択を読み、署名には指定した Vault のバージョンを使う。
Vault のバージョンを生成した後に DB の確定が失敗しても、そのバージョンを署名へ使わない。
memory の構成では、公開部分の状態と RP の構成はどちらもプロセス内だけで持つ。
