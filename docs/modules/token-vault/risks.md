# TokenVault のリスク

この文書は、TokenVault の既知の欠陥、技術的負債、受容したリスクを扱う。
脅威は[脅威モデル](../../design/security/threat-model.md)に置く。

| リスク | 現状 | 影響 |
| --- | --- | --- |
| 上流の応答がトークンを反射する | Vault は応答の本文を検査しない | 規則が許した上流の API がリクエストのヘッダーを本文へ返すと、Agent がトークンを読める。規則の範囲を管理者が決める |
| User の物理削除で上流のトークンを失効できない | 行は外部キーで消えるが、上流の失効を試さない | 上流の有効期限まで上流側でトークンが有効のまま残る。IdMagic は保持しないので使えない |
| 更新の応答を保存する前にプロセスが落ちる | 回転した更新トークンを失う | 次の更新が `invalid_grant` になり、本人の再連携が必要になる。安全側の失敗である |
| 上流のレート制限へ適応しない | 上流の 429 をそのまま返す | Agent の呼び出しが同じ接続の上限を使い切ることがある |
