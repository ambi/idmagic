# アカウントのセルフサービスの設計

この文書は、[アカウントのセルフサービス](README.md)の規則を保証する仕組みを扱う。

## アーキテクチャ

| 構成要素 | 責務 |
| --- | --- |
| アカウントのハンドラー | 本人の `sub` を認証から解決し、ほかの入力から対象を決めない |
| プロフィールのユースケース | 本人が書ける属性だけをキーごとに併合し、本人が読める属性だけを返す |
| メールアドレスの変更のユースケース | 起票で確認のトークンを発行して送り、確定でトークンを使用済みにしてアドレスを確定する |

### 実行時の流れ：メールアドレスの変更

確認のトークンは、共通のアクショントークンの仕組みが発行し検証する（[設計ガイドライン](../../../design/application/design-guidelines.md)）。
この機能が扱うのは、新しいアドレスという用途別のペイロードと、User のプライマリメールアドレスを確定する作用だけである。

1. 起票は、ステップアップ認証と新しいアドレスを検証し、用途 `email_change` のトークンを発行して保存し、確認のリンクを新しいアドレスへ送る。
2. 確定は、トークンを読み、用途、期限、未使用を確かめる。
3. `EmailChangeTokenStore.ConsumeAndApply` が、トークンの使用済み化と User の確定を一つのトランザクションで行う。確定が失敗すると、トークンは未使用のまま残る。

## データ

| データ | 内容 |
| --- | --- |
| 確認のトークン | トークンの値ではなくダイジェストで保存し、一度だけ使える |
