# IdManagement のリスク

この文書は、IdManagement の既知の欠陥、技術的負債、受容したリスクを扱う。
脅威と統制は[脅威モデル](../../../design/security/threat-model.md)が扱う。
現在の挙動を維持するか是正するかが決まっていない点は、要件には現在の挙動を書き、決定を work item で扱う。

| リスク | 影響 | 現在の扱い |
| --- | --- | --- |
| User の完全削除は、冪等でない手順の直後に Tombstone の保存が失敗すると、再実行でその手順をもう一度行う | User の使用量が実際の件数より一つ少なくなるか、`UserDeleted` が二度記録される | 使用量を手で直す。[ユーザーの設計](../user/design.md#信頼性)を参照 |
| 管理 API の操作の監査の記録は、Aggregate の保存の後に別に追記する | 追記の失敗と、保存と追記の間のプロセスの停止で、変更が残り監査の記録だけが欠ける | 配信点が失敗を「照合が必要」としてログに残す。[イベントと監査の記録](audit-events.md)を参照 |
| User、Group、Agent の更新は後勝ちである | 同じ対象を同時に更新すると、先の更新の項目が黙って失われる | [データ](data.md#排他と一意性)を参照 |
