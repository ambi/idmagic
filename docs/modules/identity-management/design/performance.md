# IdManagement の性能

この文書は、[IdManagement の品質要件](../quality.md)を満たす方式と、その確かめ方を扱う。

| 品質要件 | 方式 | 確かめ方 |
| --- | --- | --- |
| CSV の往復の規模 | 計画では、ページ単位のリポジトリの読み取りから上限付きの識別子の索引を作り、CSV の行ごとにリポジトリを検索しない | 10,000 件とすべての組み込み列を持つフィクスチャーで、エクスポートと再インポートが全行 `unchanged` になることを確かめる |
| CSV の一つの成果物の上限 | 解析器が、バイト数、行数、項目の大きさの上限を読み進めながら強制する | 規則 REQ-IDMANAGEMENT-037 の例を引くテスト |
| CSV の処理のメモリ使用量 | 解析と直列化は `io.Reader` と `io.Writer` に対して動き、CSV の全体を文字列、二次元のレコードの配列、ジョブの JSON の中の base64 として持たない。適用は、行ごとのトランザクションを保ったまま上限付きのまとまりで進める | 成果物ストアのアダプターの契約テスト |

## 実効ポリシーを超えるエクスポート

実効的な転送ポリシーを超えるエクスポートは、成功した成果物を作らずに失敗する。
上限を超えた成果物は再インポートできないので、成功として渡すと往復の性質を壊すからである。
