# 管理 API の認可の設計

この文書は、[管理 API の認可](README.md)の規則を保証する仕組みを扱う。

この機能の設計のうち、ほかの文書が扱う内容は次のとおりである。

- データ設計：この機能は永続状態を持たない
- セキュリティ設計：判定そのものがこの機能の仕様であり、システム全体の規則は[認可設計](../../../design/security/authorization.md)に従う

## アーキテクチャ

| 経路 | 判定する場所 | 判定の材料 |
| --- | --- | --- |
| 管理者のセッション | 各管理ハンドラーの冒頭で、管理者を認可する共通の処理を呼ぶ | 認証済みの User、所属テナント、有効な状態、Group 由来を合わせた実効ロール |
| API アクセストークン | 管理 API の接頭辞 `/api/admin/v1/` の要求に共通する判定 | ルートに対応する契約の操作が宣言した `x-api-token-scopes` と、トークンのスコープ |

API アクセストークンの判定は、TypeSpec から生成した実行時の契約（操作ごとの要求スコープ）を読む。
操作ごとの割り当てを文書やコードに写さないので、管理 API を足した人がスコープの宣言を書き忘れると、その操作は宣言するまで API アクセストークンで呼べない。
