# ジョブの管理

## 概要

この文書は、運用者がジョブの状態を確かめ、終端に達していないジョブを取り消す仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | テナント管理の経路での一覧、参照、取り消しと、システムの経路でのテナントを横断した一覧、参照、取り消し |
| 行為者 | テナント管理者、System 管理者（制御面主体） |
| 扱わないもの | 再試行、再実行、強制の完了は提供しない |

## モデル

管理 API は、状態、試行の回数、`error` を返し、`params`、`result`、`dedup_key` を返さない。
どれも投入したモジュールが意味を決める不透明な値であり、Jobs はその中身を検証しない。
中身を保証できない値を管理画面へ流すと、個人情報が混ざっていないことを Jobs が主張できないまま公開することになる。
`error` は返す。失敗の理由が分からなければ、失敗の一覧に意味がないためである。

- **判断**：参照と取り消しに限る理由は、[管理 API を参照と取り消しに限る](../design/decisions.md#管理-api-を参照と取り消しに限る)。

## 操作

### 管理者によるジョブの一覧と参照

#### REQ-JOBS-012 管理者は自テナントのジョブだけを一覧・参照できる

- 管理者がジョブを一覧したとき、Jobs は、要求先のテナントのジョブだけを、`status`、`kind`、`lane` の絞り込みに一致するものに限って新しい順に `limit`（デフォルト 50 件、最大 200 件）件まで返し、続きのページのカーソルを返す。
- 管理者がジョブの ID を指定して取得したとき、Jobs は、要求先のテナントのジョブだけを返す。
- テナント管理の経路では、Jobs は、要求者が制御面主体であっても、要求先のテナントの外のジョブを返さない。
- 別のテナントか存在しないジョブの ID を指定された場合、Jobs は、404 と `job_not_found` で拒否する。
- 未知の `status`、`kind`、`lane`、負の数か整数でない `limit`、別のテナントか別の絞り込みで発行したカーソルを受けた場合、Jobs は、400 と `invalid_request` で拒否する。
- 要求先のテナントの `admin` のロールを持たない利用者が一覧、取得、取り消しを要求した場合、Jobs は、403 と `access_denied` で拒否し、どのテナントのジョブも返さない。
- **例**：EX-JOBS-012-01、EX-JOBS-012-02、EX-JOBS-012-03、EX-JOBS-012-04

#### REQ-JOBS-014 管理 API はハンドラーの入出力を返さない

- 管理者がジョブを一覧または取得したとき、Jobs は、種類、レーン、状態、試行の回数と上限、失敗の理由、進捗、リースの所有者と期限、`run_at`、作成と更新の時刻を返し、`params`、`result`、`dedup_key` を返さない。
- **例**：EX-JOBS-014-01

### 管理者によるジョブの取り消し

#### REQ-JOBS-013 管理者は終端に達していないジョブを取り消せる

- 管理者が `queued` または `running` のジョブを取り消したとき、Jobs は、ジョブを `canceled` にし、200 とジョブを返し、`JobCanceled` を発行し、以後 `running` にしない。
- `running` のジョブを取り消した後、ハンドラーが次に報告するとき、Jobs は、リースを失ったハンドラーを中断させる。
- `succeeded`、`failed`、`canceled` のジョブの取り消しを要求された場合、Jobs は、409 と `job_not_cancelable` で拒否し、状態を変えない。
- テナント管理の経路で別のテナントのジョブの取り消しを要求された場合、Jobs は、要求者が制御面主体であっても 404 と `job_not_found` で拒否し、ジョブを変えない。
- **例**：EX-JOBS-013-01、EX-JOBS-013-02、EX-JOBS-013-03、EX-JOBS-013-04、EX-JOBS-013-05

### 制御面主体によるシステム経路の操作

#### REQ-JOBS-015 制御面主体はシステム経路で全テナントのジョブを一覧・参照・取り消せる

- 制御面主体がシステムの経路でジョブを一覧、取得、取り消したとき、Jobs は、テナント管理の経路と同じ規則で、すべてのテナントのジョブを扱い、`admin` のロールを併せ持つかどうかで結果を変えない。
- `system_admin` を持たないか、制御面テナントに所属しないか、制御面テナント以外の経路でシステムの経路を要求された場合、Jobs は、403 と `access_denied` で拒否し、どのテナントのジョブも返さない。
- 取り消しがブラウザーからの要求であることを証明できない場合、Jobs は、403 と `csrf_failed` または `invalid_origin` で拒否し、ジョブを変えない。
- **例**：EX-JOBS-015-01、EX-JOBS-015-02、EX-JOBS-015-03、EX-JOBS-015-04

## セキュリティ上の考慮

テナント管理の経路の参照と取り消しは、要求先のテナントに閉じる。
テナントを横断した一覧、参照、取り消しは、テナント管理の経路のパラメーターではなく、制御面主体の専用のシステムの経路に置く。
テナント管理の経路に横断を求める入力を残さないのは、その入力が一つ書き漏らされるだけで、テナントの境界の穴になるからである。
運用者は失敗したジョブを一覧で見つけた直後に止めたいので、横断の一覧と取り消しを同じシステムの経路にそろえる。
