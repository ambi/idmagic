# Audit

## 責務と境界

複数のモジュールが発行するセキュリティの監査イベントを、横断して読むための Read Model にまとめる。
監査イベントの検索とエクスポートを行う管理 API、検索属性の定義、個人識別情報の扱いもここで定める。
`DomainEvent` として蓄積した記録を、管理者向けの `AdminAuditEventResponse` として公開する。

| 扱わないもの | 担当 |
| --- | --- |
| イベントの発行 | 事実を発生させる各モジュール |
| 監査の記録の保持期間と一括削除 | [データのライフサイクル](../../design/data/lifecycle.md)と、`idmagic-batch` の保持期間の掃引 |
| ドメインイベントを監査の記録へ写す配信点 | 起動処理（`backend/cmd/internal/bootstrap`） |

## 主な流れ

| 流れ | 契機 | 実行する場所 | 詳細 |
| --- | --- | --- | --- |
| 記録の追記 | 各モジュールのユースケースの `Emit` | 呼び出したプロセスの配信点が、2 秒の期限で同期的に追記する。失敗はログに残し、操作の結果を変えない | [Audit のリスク](risks.md) |
| 検索とエクスポート | `/api/admin/v1/audit-events/...` と `/api/admin/v1/system/audit-events/...` への要求 | `api` が、経路から範囲を決めてから Repository を読む | [監査イベントの検索](features/event-search.md) |
| 保持期間の一括削除 | `idmagic-batch retention-sweep` | バッチのプロセスが、種類ごとの基準時刻より前の記録を消す | [データのライフサイクル](../../design/data/lifecycle.md) |

## 設計の要点

| 方針 | 理由 |
| --- | --- |
| 発行は各モジュールに任せ、このモジュールは読み取りのモデルだけを持つ | 記録する事実を設計できるのは、その事実を発生させる各モジュールである |
| 範囲を経路で固定する | 経路を見ただけで認可の範囲が分かる。詳細は[判断](decisions.md#問い合わせの範囲を入力ではなく経路で決める) |
| 検索の文法を閉じた登録簿に限る | 検索が意図しないカラムや比較へ広がらない。詳細は[判断](decisions.md#検索の文法を登録簿の閉じた集合に限る) |
| username の解決には ID と存在の有無だけを返す照会を使う | HTTP の組み立て地点が User の保存型を Audit の関数型へ変換する。検索範囲と未解決時の空の結果は Audit が決める |
| 委譲モードの選択肢には仕様バインディングを使う | ワイヤ語彙は `backend/shared/spec` で共有し、OAuth2 の導出規則へ依存しない |
