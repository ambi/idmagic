# Audit のアーキテクチャ

この文書は、Audit の文脈、解決戦略、構成要素、実行時の流れを扱う。
システム全体の構成は[論理アーキテクチャ](../../../design/architecture/logical.md)と[ランタイムアーキテクチャ](../../../design/architecture/runtime.md)に従う。

## 文脈と範囲

このモジュールがほかのモジュールと結ぶ契約は、仕様の[公開する契約](../README.md#公開する契約)が定める。
このモジュールは、ほかのモジュールのコードに依存しない。
記録は、起動処理の配信点がドメインイベントから作って追記する。

| 相手 | 向き | 実現方式 |
| --- | --- | --- |
| すべてのドメインイベントを発行するモジュール | 配信点が、発行されたイベントをこのモジュールの記録へ写す | 起動処理の `NewEmitFunc` が、イベントの配信の後に `AuditEventRepository.Append` を呼ぶ。`api` と `worker` のどちらのプロセスも同じ配信点を通る |
| `IdManagement` | ユーザー名による検索が、ユーザー名を `user_id` へ解決する | 管理 API のハンドラーが、相手の User の Repository を読む |
| `Authentication` | 保持期間の掃引が、種類ごとの基準時刻を組み立てる | 相手の保持期間の方針が、このモジュールの一括削除を呼ぶ |

## 解決戦略

| 方針 | 理由 |
| --- | --- |
| 発行は各モジュールに任せ、このモジュールは読み取りのモデルだけを持つ | 記録する事実を設計できるのは、その事実を発生させる各モジュールである |
| 範囲を経路で固定する | 経路を見ただけで認可の範囲が分かる。詳細は[判断](decisions.md#問い合わせの範囲を入力ではなく経路で決める) |
| 検索の文法を閉じた登録簿に限る | 検索が意図しないカラムや比較へ広がらない。詳細は[判断](decisions.md#検索の文法を登録簿の閉じた集合に限る) |

## 構成要素

コードは機能スライスを持たず、一つの層の構成である。
すべての要件は[監査イベントの検索](../event-search/README.md)に属する。

| 層 | 責務 |
| --- | --- |
| `ports` | `AuditEventRepository`、検索属性の登録簿と演算子、`TenantSaltStore` |
| `usecases` | フィルターの解析、ペイロードからの検索属性の取り出し |
| `handlers_http` | テナント管理の経路とシステムの経路の検索、取得、エクスポート、検索の選択肢。範囲の固定とカーソルの指紋 |
| `db_postgres`、`db_memory` | `ports` の PostgreSQL の実装と、テストとローカルの構成で使うメモリの実装 |
| `testing_contract` | 二つの実装が同じ契約を満たすことを確かめる共通のテスト |

## 実行時の流れ

| 流れ | 契機 | 実行する場所 | 詳細 |
| --- | --- | --- | --- |
| 記録の追記 | 各モジュールのユースケースの `Emit` | 呼び出したプロセスの配信点が、2 秒の期限で同期的に追記する。失敗はログに残し、操作の結果を変えない | [Audit のリスク](risks.md) |
| 検索とエクスポート | `/api/admin/v1/audit-events/...` と `/api/admin/v1/system/audit-events/...` への要求 | `api` が、経路から範囲を決めてから Repository を読む | [監査イベントの検索](../event-search/README.md) |
| 保持期間の一括削除 | `idmagic-batch retention-sweep` | バッチのプロセスが、種類ごとの基準時刻より前の記録を消す | [データのライフサイクル](../../../design/data/lifecycle.md) |
