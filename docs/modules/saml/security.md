# Saml のセキュリティ

この文書は、Saml の発行の経路に共通するセキュリティの仕組みを扱う。
各エンドポイントの境界は、各機能仕様のセキュリティ上の考慮の節が扱う。

## テナントとプロファイルの単位の署名

すべての要求で、発行の直前に、テナントとプロファイルに対応する署名器を取得する。
署名の提供元は、そのスコープで有効な `XmlFederationSigning` の資格情報を選ぶ。
署名の提供元、秘密鍵を扱う署名器、X.509 証明書のいずれかを使えない場合は、発行せずに失敗させる。
要求ごとに署名器を取得することで、プロセスの中で共有した証明書が、テナントやプロファイルの境界を越えて使われることを防ぐ。

## XML の処理

XML の構文解析、正規化、署名は自作せず、XML 署名のために選んだ検証済みのライブラリに委ねる。
XML の実体参照は展開しない。
