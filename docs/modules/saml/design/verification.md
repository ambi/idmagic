# Saml の検証

この文書は、Saml の要件と統制のうち、例のテストのほかに確かめているものを扱う。
システム全体の検証の方式は[検証設計](../../../design/verification/README.md)に従う。

## パースの境界のファズテスト

SP から届く要求の復号と解析は、Go のネイティブのファジングの対象である。

| 対象 | オラクル |
| --- | --- |
| `DecodeRedirect`、`DecodePost` | 展開した後の大きさが宣言した上限を超えたら、必ず拒否する。HTTP-Redirect のバインディングは DEFLATE を展開するので、圧縮爆弾がそのまま上限の根拠になる |
| `ParseAuthnRequest`、`ParseLogoutRequest` | 拒否したときに、部分的に埋まった値を返さない。呼び出し側がエラーを取りこぼしても、未検証の Issuer や ACS の URL をつかめないようにする |
| `ValidateRequestSignature` | こちらが生成していない署名を、必ず拒否する |

## 実体参照の回帰テスト

実体参照を展開しないことは、ファジングの表明ではなく、表で駆動する回帰テストで押さえる。
展開したかどうかは入力ごとに変わる性質ではないので、外部の実体、外部の DTD、内部の実体、billion laughs を並べた表のほうが読め、探索の当たり外れに依らない。
