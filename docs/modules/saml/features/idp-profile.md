# IdP プロファイルとメタデータ

## 概要

この文書は、SAML の IdP プロファイルの管理と、プロファイルごとのメタデータと署名証明書の公開の仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | IdP プロファイルの作成、変更、削除。プロファイルごとのメタデータと署名証明書の公開 |
| 行為者 | テナント管理者（プロファイルの管理）、SP（メタデータと証明書の取得） |
| 扱わないもの | プロファイルの署名の鍵のローテーションは `SigningKeys` が扱う |

## モデル

各 SP は、テナントの中の IdP プロファイル一つだけに関連付ける。
`default` のプロファイルは短い `/saml/*` の経路を、追加のプロファイルは `/saml/idp/{profile_id}/*` の経路とプロファイルに固有の entityID を使う。
`shared` のプロファイルは複数の SP で共有でき、`dedicated` のプロファイルを割り当てられる SP は一つまでである。

プロファイルの管理 API は、サーバーが生成した正式な entityID、メタデータ、SSO、SLO、証明書の取得の各 URL、証明書のフィンガープリント、関連付けた SP の数を返す。
デフォルトのプロファイルの変更、`dedicated` のプロファイルへの複数の SP の割り当て、使用中のプロファイルの削除は、Repository が最終的に拒否する。

各プロファイルのメタデータは、有効な証明書に加え、同じ鍵のスコープの有効期限内の検証用の証明書をすべて公開する。
SP は、ローテーションの直前に発行されたメッセージも検証できる。

## 操作

### SP による署名証明書の取得

#### REQ-SAML-001 SP は署名証明書を取得できる

- SP がプロファイルの署名証明書の URL を取得したとき、Saml は、そのプロファイルで現在有効な `XmlFederationSigning` の証明書を PEM で返す。
- SP が署名証明書を取得したとき、Saml は、同じ時点のそのプロファイルのメタデータが公開する有効な証明書と同じ証明書を返す。
- 署名の資格情報を解決できない場合、Saml は、500 で失敗し、証明書を返さない。
- **例**：EX-SAML-001-01、EX-SAML-001-02

### SP によるメタデータの取得

#### REQ-SAML-003 専用プロファイルは固有のメタデータを公開する

- SP がプロファイルのメタデータを取得したとき、Saml は、そのプロファイルに固有の entityID、SSO と SLO の URL と、有効な証明書と同じ鍵のスコープの有効期限内の検証用の証明書をすべて公開する。
- SP が `default` のプロファイルのメタデータを `/saml/metadata` で取得したとき、Saml は、追加のプロファイルとは異なる entityID と署名の資格情報を公開する。
- 存在しないか別のテナントのプロファイルの ID を指定された場合、Saml は、404 で拒否し、メタデータも証明書も返さない。
- 署名の資格情報を解決できない場合、Saml は、500 で失敗し、メタデータを返さない。
- **例**：EX-SAML-003-01、EX-SAML-003-02

### 管理者による IdP プロファイルの管理

#### REQ-SAML-004 管理者は SAML IdP プロファイルを共有用または専用として管理できる

- 管理者が IdP プロファイルを作成したとき、Saml は、`shared` または `dedicated` のプロファイルを作り、201 と、サーバーが生成した entityID、メタデータ、SSO、SLO、証明書の取得の URL、証明書のフィンガープリント、関連付けた SP の数を返す。
- 管理者が IdP プロファイルを一覧したとき、Saml は、テナントのすべてのプロファイルを同じ項目とともに 200 で返す。
- 管理者が追加のプロファイルの名前またはモードを変更したとき、Saml は、名前を前後の空白を除いて保存し、200 と更新後のプロファイルを返す。
- 管理者が未使用の追加のプロファイルを削除したとき、Saml は、プロファイルを消して 204 を返す。
- `default` のプロファイルの変更か削除、または SP が関連付けたプロファイルの削除を要求された場合、Saml は、409 と `profile_in_use` で拒否し、プロファイルを変えない。
- 二つ目の SP を `dedicated` のプロファイルに関連付ける要求、または不正な名前かモードのプロファイルを指定された場合、Saml は、400 と `invalid_request` で拒否し、プロファイルと SP を変えない。
- 存在しないプロファイルの変更を要求された場合、Saml は、404 と `not_found` で拒否する。
- **例**：EX-SAML-004-01、EX-SAML-004-02、EX-SAML-004-03

## セキュリティ上の考慮

IdP プロファイルの登録、参照、削除は、`AdminFederationTrustsManage` の権限（AuthZEN の action `admin:federation_trusts_manage`）を要し、`admin` ロールを持つ、有効かつ認証済みのユーザーが、所属テナントに対して行える。

IdP のメタデータと証明書の取得は、認証を要さない公開の Discovery である。
公開するのは、entityID、エンドポイント、署名証明書に限る。
