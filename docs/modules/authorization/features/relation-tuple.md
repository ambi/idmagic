# 関係タプル

## 概要

この文書は、関係タプルを一括で書き込み、オブジェクトの削除でその関係タプルを取り除く仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 登録済みのモデルに適合する関係タプルの一括の追加と削除、オブジェクトの両側の関係タプルの削除 |
| 行為者 | テナント管理者 |
| 扱わないもの | 関係タプルを使う判定は[関係の判定](check.md)が扱う |

## モデル

主体は `type:id`、`type:id#relation`（subject set）、`type:*`（ワイルドカード）の三つの形を取る。
ワイルドカードは、`direct` の規則がその型を許した場合にだけ受理する。
関係タプルはテナントの中で一意な組であり、同じ組の再書き込みは冪等である。
`direct` の規則が宣言していない形の関係タプルは、書き込みで拒否する。

## 操作

### 管理者による関係タプルの書き込み

#### REQ-AUTHORIZATION-002 関係タプルの書き込みは登録済みモデルに適合するものだけを一括で適用する

- 管理者が追加と削除の差分を書き込んだとき、AccessControl は、差分を一つのトランザクションで適用し、書き込み後の整合トークンを返す。
- 1 件以上の組を追加する差分を書き込んだとき、AccessControl は、件数と整合トークンを載せた `RelationTupleWritten` を発行する。
- 1 件以上の組を削除する差分を書き込んだとき、AccessControl は、件数と整合トークンを載せた `RelationTupleDeleted` を発行する。
- 既に存在する組の追加を受けたとき、AccessControl は、その組を重複させずに成功を返す。
- 管理者が関係タプルを書き込むか一覧したとき、AccessControl は、要求の本文の識別子によらず、呼び出し元のテナントで解決した `tenant_id` のタプルだけを読み書きする。
- 登録した認可モデルが宣言していない型か関係、`direct` の規則が許していない主体の形かワイルドカード、追加と削除の両方に現れる組を含む差分を受けた場合、AccessControl は、422 と `relation_tuple_invalid` で拒否し、1 件も適用しない。
- テナントに認可モデルを登録していない間、組み込み型以外の関係タプルの書き込みを要求されたとき、AccessControl は、404 と `authorization_model_not_found` で拒否する。
- 組み込み型 `idmagic_mcp_operation` の差分だけを書き込まれたとき、AccessControl は、`invoke` か `invoke_any_target` と、個別の `user` または `agent` への直接付与を検証し、テナントのモデル発行を要求せずに適用する。
- **例**：EX-AUTHORIZATION-002-01、EX-AUTHORIZATION-002-02、EX-AUTHORIZATION-002-03、EX-AUTHORIZATION-002-04、EX-AUTHORIZATION-002-05

### 管理者によるオブジェクトの削除

#### REQ-AUTHORIZATION-008 オブジェクトの削除はその両側の関係タプルを取り除く

- 管理者がオブジェクトを削除の対象として書き込んだとき、AccessControl は、そのオブジェクトをリソースまたは主体として参照するタプルをすべて消し、整合トークンを進め、`RelationTupleDeleted` を発行する。
- 削除の対象に型か識別子のないオブジェクトを指定された場合、AccessControl は、422 と `relation_tuple_invalid` で拒否し、1 件も適用しない。
- **例**：EX-AUTHORIZATION-008-01

#### REQ-AUTHORIZATION-012 管理コンソールは関係タプルの一覧の打ち切りを隠さない

- 管理者が管理コンソールで関係タプルを一覧するとき、AccessControl は、1000 件までを示す。
- 管理コンソールの一覧が 1000 件に達した場合、AccessControl は、条件に合うタプルがほかにも存在し得ることを示す。

### 管理コンソールでの Agent の直接付与

#### REQ-AUTHORIZATION-014 管理コンソールは対象と Agent の選択から直接のアクセス権を管理する

- 管理者が管理コンソールで Agent のアクセス権を追加するとき、AccessControl は、有効な MCP リソースサーバーの登録済み規則と公開済みモデルから、`direct` が `agent` を許す権限だけを選択肢として示す。
- 管理者が対象 ID、権限、有効な Agent を選んで追加を確定したとき、AccessControl は、REQ-AUTHORIZATION-002 の書き込みで対応する一件の関係タプルを追加し、追加した対象と Agent を示す。
- 管理者が追加を確定しようとしたとき、AccessControl は、同じ対象型と関係を使うほかの接続先にも付与が適用されることと、付与の保存だけではスコープや承認条件を含む実行許可を保証しないことを示す。
- 管理者が Agent の直接付与を一覧するとき、AccessControl は、対象、権限、Agent を示し、一件の取消でその組だけを削除する。
- 一覧が取得上限に達した場合、AccessControl は、ほかの付与が存在し得ることを示す。
- 対象の外部カタログを取得していない場合、AccessControl は、対象 ID の取得元と入力の必要性を説明し、表示中の既存付与の対象を候補として示す。
- 追加または取消が失敗した場合、AccessControl は、失敗を表示し、未保存の入力を保持する。

### 管理コンソールでの接続先と操作の割当

#### REQ-AUTHORIZATION-017 管理コンソールは接続先と操作の選択から利用割当を管理する

- 管理者が Agent の利用する接続先を編集するとき、AccessControl は、有効な接続先と登録したツールの表示名を選択肢に示し、モデル、型、関係、タプル、対象 ID の入力を要求しない。
- 管理者が保存を確定したとき、AccessControl は、選択した Agent の操作割当の追加と削除を REQ-AUTHORIZATION-002 の一つの差分として反映する。
- 管理者が利用割当を表示するとき、AccessControl は、対象制限と承認の有無、トークンの上限が別に適用されることを示す。
- 管理者が未保存の差分を編集している間、AccessControl は、追加と取消の対象を表示する。
- 保存が失敗した場合、AccessControl は、入力を保持し、失敗を表示する。
- 一覧の上限に達した場合、AccessControl は、打ち切りを表示し、不完全な一覧から取消の差分を保存しない。
- 対象ごとの権限を持つ操作を選んだとき、AccessControl は、「すべての対象」と「指定した対象だけ」のどちらかを明示して選ばせ、どちらも選ばないうちは対象を許可しない。
- 管理者が「すべての対象」を保存したとき、AccessControl は、操作の割当 `<登録 ID>/<操作の識別子>#invoke` と、同じ操作の `invoke_any_target` を組み込みの型 `idmagic_mcp_operation` へ書き、利用者のモデルを要求しない。
- 管理者が「指定した対象だけ」を保存したとき、AccessControl は、操作の割当と、対象ごとの `<登録 ID>/<操作の識別子>/<対象 ID>#invoke` を組み込みの型へ書き、利用者のモデルを要求しない。
- 対象 ID が `:` か `#` を含む場合、AccessControl は、その対象を保存せず、理由を表示する。
- **判断**：対象の範囲を割当と同じ組み込みの型で表す。利用者のモデルへ型と関係を足すと、開発者のモデルの発行と競合し、日常の画面に型と関係の名前が戻るためである。

## セキュリティ上の考慮

関係タプルの読み書きは、常に呼び出し元のテナントで解決した `tenant_id` に閉じる。
要求の本文が別のテナントの識別子を含んでいても、それが書き込みの対象のテナントを変えることはない。
