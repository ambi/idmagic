# 運用

## 概要

この文書は、運用者が SLO を検証し、プロセスの状態を観測するための仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 運用のマニフェストによる SLO の評価、生存、受付可否、起動完了のプローブ、永続化のクエリの期限 |
| 行為者 | Operator |
| 扱わないもの | SLO の値は[品質要件](../../../requirements/quality.md)が、監視の設計は[オブザーバビリティ設計](../../../design/observability/README.md)が扱う |

## 操作

### 運用者による運用の資産の適用

#### REQ-SYSTEM-001 Operator は分離された運用資産で SLO を検証する

- 運用者が運用の資産を適用したとき、System は、API の生存、受付可否、起動完了のプローブをそれぞれ `/livez`、`/readyz`、`/startupz` に、指標を `/metrics` に公開し、Prometheus に OAuth2 と OIDC の可用性、レイテンシー、5xx でない比率を評価させる。
- Prometheus Operator のない環境では、System は、`ServiceMonitor` を適用の対象から外し、標準の Prometheus のスクレイプの設定で `/metrics` を収集させる。
- **例**：EX-SYSTEM-001-01、EX-SYSTEM-001-02、EX-SYSTEM-001-03

### 運用者によるプローブの呼び出し

#### REQ-SYSTEM-002 オーケストレーション用プローブはプロセスのライフサイクルと依存先の状態を区別する

- 運用者がプローブを呼び出したとき、System は、認証を求めず、状態だけを返し、設定値と依存先の詳細を返さない。
- プロセスが動いている間、生存確認を呼び出されたとき、System は、初期化中とグレースフルドレイン中も含めて `200 healthy` を返す。
- 設定した永続化の依存先へ到達できない場合、System は、受付可否の確認に `503 unavailable` を返し、新しいトラフィックを受けさせない。
- 初期化が終わり、依存先へ到達できる間、プローブを呼び出されたとき、System は、すべてに `200 healthy` を返す。
- **例**：EX-SYSTEM-002-01、EX-SYSTEM-002-02、EX-SYSTEM-002-03

### System による永続化のクエリ

#### REQ-SYSTEM-012 PostgreSQL クエリの期限は結果の読み取り完了まで維持される

- PostgreSQL へのクエリが `Row` または `Rows` を返したとき、System は、結果の読み取りが終わるまでクエリの期限を保ち、読み取りの後に接続を解放する。
- 結果の読み取り中にクエリのタイムアウトの期限に達した場合、System は、読み取りを `deadline exceeded` で中断する。
- 単一のレコードを返すクエリに一致するレコードがない場合、System は、`Scan` に `no rows` を返す。
- **例**：EX-SYSTEM-012-01、EX-SYSTEM-012-02、EX-SYSTEM-012-03

## セキュリティ上の考慮

生存確認、受付可否、起動完了の各プローブは認証を要さないが、返すのは状態だけで、設定値や依存先の詳細は含めない。
`/metrics` も認証しないので、公開先は折り返しのアドレス、管理用のネットワーク、認証付きのプロキシの背後に限る。
