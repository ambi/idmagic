# System の設計

この文書は、System の設計を設計領域ごとに索引する。
このモジュールが外へ約束することは、仕様の [System](../README.md) と各機能仕様が定める。
一つの機能だけの仕組みは、その機能の機能仕様の「実現方式」の節に置く。
記載のない領域には[共通設計](../../../design/README.md#共通設計の適用範囲)を適用する。

| 設計領域 | 区分 | 参照先 | 内容 |
| --- | --- | --- | --- |
| アーキテクチャ設計 | 固有設計 | [担当文書](architecture.md#文脈と範囲) | 文脈と範囲、解決戦略、構成要素、実行時の流れ |
| アプリケーション設計 | 委譲 | [API の境界](../api-boundary/README.md#概要) | API と UI の方式はシステムのアプリケーション設計が扱い、このモジュールは経路の分け方をAPI の境界で定める |
| データ設計 | 対象外 | — | このモジュールは永続状態を保存しない |
| インフラストラクチャ設計 | 委譲 | [配置の設計](../../../design/architecture/deployment.md#共通トポロジー) | システムのインフラストラクチャ設計と配置の設計が扱う |
| セキュリティ設計 | 委譲 | [ホステッド UI とポータルの設計](../hosted-ui/README.md#セキュリティ)、[認可設計](../../../design/security/authorization.md#主体の種類) | 認可トランザクションとポータルのトークンはホステッド UI とポータルの設計が、システム全体の認可は認可設計が扱う |
| 信頼性設計 | 委譲 | [運用](../operations/README.md#概要) | プローブは運用が、システム全体の可用性は信頼性設計が扱う |
| 性能設計 | 委譲 | [アドミッションコントロールの設計](../admission-control/README.md#アーキテクチャ)、[キャパシティ設計](../../../design/performance/capacity.md#仮定値と実測値) | 過負荷のときの受け付けの制御はアドミッションコントロールの設計が、キャパシティの計画はキャパシティ設計が扱う |
