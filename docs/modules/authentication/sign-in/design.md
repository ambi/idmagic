# ログインの設計

この文書は、[ログイン](README.md)の要件を保証する仕組みを扱う。

## データ

カウンターは PostgreSQL の共有のテーブル `login_throttle_counters` に保存し、すべてのレプリカで共有する。
カウンターは平文ではなく、識別子の SHA-256 のハッシュを鍵とするので、平文の利用者名や IP は保持しない。
テーブルは `LOGGED` である。切り替えのときに失うことが、多層防御の後退にあたるからである。
カウンターが頻繁に受ける同じ行への `UPDATE`（HOT の更新）のために、`fillfactor = 80` で余地を残す。

## オブザーバビリティ

締め出しのたびに `LoginThrottled` を発行し、そこには平文ではなく、認証のイベントの集計と同じ、テナントのソルトを効かせた `keyHash` を載せる。
アカウントまたは IP が制限値に達した後は、失敗ごとの `AuthenticationFailed` を発行せず、集計の側へ回す（[認証のイベントの記録](../design/authentication-events.md)）。
