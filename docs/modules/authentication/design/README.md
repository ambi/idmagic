# Authentication の設計

この文書は、Authentication の設計を設計領域ごとに索引する。
このモジュールが外へ約束することは、仕様の [Authentication](../README.md) と各機能仕様が定める。
一つの機能だけの仕組みは、その機能の `design.md` に置く。
記載のない領域には[共通設計](../../../design/README.md#共通設計の適用範囲)を適用する。
このモジュールが担当する SLO とキャパシティ要件は、[品質要件の割り当て](../../../design/architecture/logical.md#品質要件の割り当て)から担当機能、設計、検証へ参照する。

| 設計領域 | 区分 | 参照先 | 内容 |
| --- | --- | --- | --- |
| アーキテクチャ設計 | 固有設計 | [担当文書](architecture.md#文脈と範囲) | 文脈と範囲、解決戦略、構成要素、実行時の流れ |
| アプリケーション設計 | 委譲 | [アカウントポータル](../account-portal/README.md#概要) | API と UI はシステムのアプリケーション設計に従い、セルフサービス API の境界はアカウントポータルが扱う |
| データ設計 | 委譲 | [認証のイベントの記録](authentication-events.md#データ) | 各 Aggregate の保存は各機能の設計が、認証のイベントの保存は認証のイベントの記録が扱う |
| 信頼性設計 | 委譲 | [認証状態の障害](architecture.md#解決戦略) | 共有の一時的な状態のストアに到達できないときは失敗させる。各機能の扱いは各機能の設計が扱う |
| オブザーバビリティ設計 | 委譲 | [認証のイベントの記録](authentication-events.md#アーキテクチャ) | 認証のイベントは認証のイベントの記録が扱い、それ以外はシステムのオブザーバビリティ設計に従う |
