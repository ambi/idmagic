# Authentication

## 責務と境界

エンドユーザーの資格情報の検証、MFA、ログインセッション、ステップアップ認証、パスワードの変更とリセット、アカウントの復旧、ログインの時点のフェデレーション、認証のイベントを扱う。
このモジュールが扱うのは、プリンシパルが本人であることをどう確かめ、確かめた結果をどうセッションとして保つかである。
認証結果は、Application のポリシー評価へ認証事実を供給し、ACR と AMR の解釈をこのモジュールに閉じる。

| 扱わないもの | 担当 |
| --- | --- |
| `User`、`Group`、`Agent` のライフサイクル | `IdManagement` |
| 下流向けの SAML の IdP と WS-Federation の発行 | `SAML`、`WS-Federation` |
| 外部からの継続的なアイデンティティの取り込み | `Sourcing` |
| OAuth の認可とトークンの発行 | `OAuth2` |
| 可逆なシークレットのエンベロープ暗号化 | `DataKeys` |

## 主な流れ

| 流れ | 契機 | 実行する場所 | 詳細 |
| --- | --- | --- | --- |
| ログイン | ブラウザーの `/api/auth/*` への要求 | `api` が、スロットル、資格情報、第二要素の順に確かめ、セッションを作る | [ログイン](features/sign-in.md) |
| セキュリティ通知 | 配信点を通るドメインイベント | 発行したプロセスが、配信点から切り離して送る | [セキュリティ通知の設計](features/security-notification.md#実現方式) |
| 保持期間の掃除 | 毎時、または `idmagic-batch retention-sweep` | バッチのプロセス | [認証のイベントの記録](observability.md#認証のイベントの記録) |

## 設計の要点

| 方針 | 理由 |
| --- | --- |
| 確かめた認証の要素と認証の時刻を境界にする | 認証の完了の前の要求を、ロールでは扱えない |
| 機微な自己操作にステップアップ認証を求める | 詳細は[判断](decisions.md#機微な自己操作に-csrf-の防御に加えてステップアップ認証を求める) |
| 共有の一時的な状態は、到達できないとき失敗させる | 抑制のない試行を通さない |
| セレモニーと暗号処理を自作しない | WebAuthn は `go-webauthn/webauthn`、パスワードのハッシュは Argon2id に委ねる |
| パスワードのデフォルト値をテナント設定と共有する | 既存の定数名は `backend/tenancy/domain` の定数を参照する。設定 API の表示と認証時の判定を同じ値から導く |

| ログインとセッション | [ログイン](features/sign-in.md) | パスワードによるログイン、ログインの流量の制限、無効なユーザーの拒否、ブラウザーの初期化 |
| ログインとセッション | [ログインセッション](features/session.md) | セッションの保存、一覧、失効、サインアウト |

| 認証の要素 | [パスワード](features/password.md) | パスワードのポリシー、変更、有効期限、リセット |

| 認証の要素 | [WebAuthn](features/webauthn.md) | WebAuthn による第二要素とステップアップ認証 |
| 認証の要素 | [復旧コード](features/recovery.md) | 復旧コードによる第二要素 |
| 認証の要素 | [信頼済みデバイス](features/trusted-device.md) | 記憶したブラウザーによる第二要素の省略 |
| 本人の操作 | [アカウントポータル](features/account-portal.md) | 本人の範囲に閉じたセルフサービス API と、機微な操作のステップアップ認証 |
| 本人の操作 | [セキュリティ通知](features/security-notification.md) | アカウントのセキュリティの上の変化の通知 |
| 本人の操作 | [サインイン履歴](features/sign-in-activity.md) | 本人によるサインイン履歴の参照 |

ログイン、アカウントポータル、サインイン履歴は機能スライスを持たず、モジュールのルートの `usecases`、`handlers_http`、`deps_http` が実装する。ルートの層は、ブラウザー向けの認証 API、セルフサービス API、管理 API を組み立てる。
