# WsFederation のセキュリティ

この文書は、WsFederation の発行の経路に共通するセキュリティの仕組みを扱う。
各エンドポイントの境界は、各機能仕様のセキュリティ上の考慮の節が扱う。

## テナント単位の署名

受動的な発行でも能動的な発行でも、発行のたびに、要求元のテナントの有効な `XmlFederationSigning` の資格情報を `SigningKeys` から取得する。
プロセスの起動時に保持した鍵では署名しない。
これにより、WS-Fed と SAML は XML 署名の資格情報のライフサイクルを共有しながら、OAuth2 と JWT の鍵から分離できる。

## 認可の境界

プロトコルのエンドポイントは管理者の認可を通らず、それぞれ別の境界を持つ。

| 経路 | 主体を決めるもの | 宛先の検証 |
| --- | --- | --- |
| メタデータと MEX | なし（公開の Discovery） | 該当なし |
| パッシブサインイン | ブラウザーのログインセッション | `wtrealm`、`wreply`、対象のユーザーの Application への割り当て |
| 能動的な STS | UsernameToken | `AppliesTo` が登録した RP に解決できること |

いずれの経路でも、未登録の宛先にトークンを発行することはない。
