# アクセスの見直し

## 概要

管理者が所属、割り当て、Agent の継続利用を定期的に確認する計画を設定し、確認担当者が維持または失効を判断する。
計画と各回の記録は IdGovernance が持ち、所属と Agent の状態は IdManagement、割り当ては Application が変更する。

## モデル

一つの見直し計画は、一種類の対象と対象 ID の集合を持つ。
各回は開始時点の所属または割り当ての行、Agent、確認担当者を固定する。
Application の対象は User または Group への割り当ての行であり、別の Group による間接のアクセスを同時には外さない。
計画の無効化は次回の開始だけを止める。
開始済みの見直しの期限と適用は変えない。

## 状態遷移

### AccessReviewLifecycle

本人であること、対象の存在と判断の値の検証は、すべての状態で状態による判定より先に行う。
別の確認担当者は 403、不明な項目または判断は 400 で拒否する。
worker の一回の実行が期限処理と処置の適用の両方を行う場合もある。

## 操作

### 管理者による見直し計画の作成と更新

#### REQ-IDGOVERNANCE-020 見直し計画は有効な対象と確認担当者を保存し、一回または日数の周期で実施する

- 管理者が見直し計画を作成したとき、IdGovernance は、前後の空白を除いた名前、対象種別、重複のない 1〜50 件の対象 ID、確認担当者、代替担当者、未回答時の処置、開始時刻、実施期間と周期を保存し、201 と計画を返し、`AccessReviewChanged` を `plan_created` として発行する。
- 管理者が現在のリビジョンを指定して計画を更新したとき、IdGovernance は、以後の回に使う設定を置き換え、リビジョンを一つ進め、200 と計画を返し、`AccessReviewChanged` を `plan_updated` として発行する。
- 開始済みの計画の周期を 0 以外に変更したとき、IdGovernance は、直近の回の開始時刻に新しい周期を加えた時刻を次回の予定にする。
- 開始済みの計画の周期を 0 に変更したとき、IdGovernance は、次回の予定を外す。
- 設定を変えずに計画を無効化したとき、IdGovernance は、対象または確認担当者が消失または無効であっても次回以降の開始を止める。
- 実施期間または周期を指定されたとき、IdGovernance は、実施期間を 1〜90 日、周期を 0（繰り返さない）または実施期間以上の 1〜365 日に限る。
- 名前が空か 200 文字を超える、対象の重複、未知の種別または処置、不正な日数を指定された場合、IdGovernance は、400 と `invalid_request` で拒否し、計画を保存しない。
- 設定を変えない無効化を除き、同じテナントに存在しない対象、動的または上流管理の Group、同じテナントで有効でない代替担当者、Agent 以外で有効でない確認担当者を指定された場合、IdGovernance は、400 と `invalid_request` で拒否し、計画を保存しない。
- 古いリビジョンの更新を要求された場合、IdGovernance は、409 と `access_review_conflict` で拒否し、計画を変えない。

### worker による各回の開始

#### REQ-IDGOVERNANCE-021 各回は開始時点の対象と確認担当者を固定し、所有者不在時は指定した代替担当者を使う

- 有効な計画の開始時刻に達したとき、IdGovernance は、同じテナントの現在の対象から各回の項目を作り、開始と期限の時刻、計画の名前、未回答時の処置を固定し、`AccessReviewChanged` を `review_started` として発行する。
- Agent の所有者が同じテナントの有効な User である間、Agent を対象とする回を開始したとき、IdGovernance は、その所有者を確認担当者にする。
- Agent の所有者が同じテナントに存在しないか有効でない場合、IdGovernance は、指定した有効な代替担当者を確認担当者にする。
- Agent 以外の回で指定した確認担当者が開始時点で有効でない場合、IdGovernance は、指定した有効な代替担当者を使う。
- 回の開始後に所有者または計画の設定が変わったとき、IdGovernance は、開始した回の項目と確認担当者を変えず、次回の開始時に現在の値を使う。
- 対象の読み取りの失敗、対象の消失、動的または上流管理への変更、代替担当者の無効化、1,000 項目の上限の超過が起きた場合、IdGovernance は、その回を開始せず、管理者に開始の失敗を表示し、後の実行で再試行する。
- 開始が予定より遅れたとき、IdGovernance は、実際の開始時刻から実施期間を数え、過去の回をまとめて作らない。
- 同じ計画の開始が同時に要求されたとき、IdGovernance は、一回だけを作り、次回の開始時刻を同じ確定境界で更新する。

### 確認担当者による回答

#### REQ-IDGOVERNANCE-022 確認担当者本人の期限内の判断だけを確定する

- 割り当てられた確認担当者本人が期限の時刻より前に維持または失効を回答したとき、IdGovernance は、項目の判断、判断者と判断時刻を保存し、200 と結果を返し、`AccessReviewChanged` を `decision_recorded` として発行する。
- 同じ確認担当者が確定済みと同じ判断を再送したとき、IdGovernance は、判断を変えずに成功し、判断のイベントを重複して発行しない。
- 期限の時刻以降の回答または異なる判断への変更を要求された場合、IdGovernance は、409 と `access_review_conflict` で拒否し、判断を変えない。
- 他人の項目への回答を要求された場合、IdGovernance は、403 と `access_denied` で拒否し、判断もアクセスも変えない。
- 未知の判断を指定された場合、IdGovernance は、400 と `invalid_request` で拒否する。

### worker による期限後の適用

#### REQ-IDGOVERNANCE-023 期限後は判断と未回答時の処置を所有者の公開操作で適用する

- 期限の時刻に達したとき、IdGovernance は、未回答の項目に計画で固定した維持または失効の処置を確定し、回答の受け付けを終え、項目ごとの処置を適用する。
- 維持を適用するとき、IdGovernance は、所属、割り当て、Agent を変更せず、すでに失われたアクセスを付与し直さない。
- 失効を適用するとき、IdGovernance は、Group の対象の所属を解除する、Application の対象の割り当てだけを解除する、Agent を無効化する、のいずれかを状態の所有者の公開操作で行い、その監査、通知、失効の作用を保つ。
- 対象のアクセスがすでにない場合、IdGovernance は、再付与せずに適用済みとして記録する。
- 適用に失敗した場合、IdGovernance は、項目に `apply_failed` を記録し、管理者へ表示し、後の worker の実行で未完了の項目だけを再試行する。
- すべての項目の適用を終えたとき、IdGovernance は、回を完了として記録し、`AccessReviewChanged` を `review_completed` として発行する。

### worker による確認の通知

#### REQ-IDGOVERNANCE-024 通知の失敗は記録して再試行し、期限後の適用を止めない

- 回の開始時と実施期間の中間に達したとき、IdGovernance は、未回答の確認担当者へ、見直しの名前、期限、未回答時の処置を含む `access_review_request` のメール通知を試みる。
- 通知に失敗した場合、IdGovernance は、その失敗を回に記録し、期限前の worker の実行で再試行する。
- 通知が失敗したまま期限に達したとき、IdGovernance は、通知の失敗を結果に残して期限後の適用を進める。

### 管理者と確認担当者による結果の参照

#### REQ-IDGOVERNANCE-025 結果の参照と更新はテナントと割り当てた本人の境界を保つ

- 管理者が計画または結果を参照したとき、IdGovernance は、同じテナントの計画と各回の対象、確認担当者、判断、未回答かどうか、適用結果、開始と通知と適用の失敗を返す。
- 確認担当者が自分の項目を参照したとき、IdGovernance は、同じテナントで本人に割り当てた項目だけを返す。
- 管理者でない主体が計画の作成、更新、管理用の一覧または結果の取得を要求した場合、IdGovernance は、403 と `access_denied` で拒否し、計画も判断もアクセスも変えない。
- 別テナントまたは存在しない計画、回、項目を要求された場合、IdGovernance は、400 と `invalid_request` で拒否し、別テナントの情報を返さない。

### 管理画面と本人の回答画面

#### REQ-IDGOVERNANCE-026 画面は見直しの対象、期限、処置と適用結果を区別して示す

- 管理者が見直しの画面を開いたとき、IdGovernance は、「見直し計画」と「確認担当者」を使い、対象、担当者と代替担当者、実施期間、周期、未回答時の処置を指定する専用の作成画面と、結果を確認する画面を示す。
- 確認担当者が本人の画面を開いたとき、IdGovernance は、対象の表示名、見直しの期限、未回答時の処置、維持と失効の操作を示し、回答が適用されるのは期限後であることを説明する。
- 失効または未回答時の失効を選ぶ操作を確定するとき、IdGovernance は、対象と影響、後から判断を変更できないことを確認するダイアログを示す。
- 読み取りまたは操作に失敗したとき、IdGovernance は、成功として表示せず、持続するエラー表示で再実行の手段を示す。
- Application の割り当てを表示するとき、IdGovernance は、対象の割り当てを外しても別の Group を介するアクセスが残り得ることを説明する。

## セキュリティ上の考慮

管理 API は管理者に限り、本人の回答 API は割り当てた確認担当者を毎回照合する。
代替担当者は計画に明示し、作成者へ暗黙に権限を与えない。
動的な所属と上流の所属を解除する規則は持たない。

## 実現方式

計画の次回時刻と新しい回の捕捉を一つのトランザクションで確定する。
回の回答、期限処理、作用の占有と結果の保存は、短い更新として回単位で直列化する。
通知と状態の所有者への適用はトランザクションの外で行い、各宛先または各項目の結果を保存する。
処理中の占有は期限を持ち、作用と結果の保存の間で停止した場合は、期限後に冪等な再実行で回収する。
通知は保存との間の停止で重複して届く場合があり、メールの厳密な一回配送は保証しない。
失効済みの権限を自動で戻す補償は行わない。
