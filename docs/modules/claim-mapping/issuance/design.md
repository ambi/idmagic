# クレームの発行の設計

この文書は、[クレームの発行](README.md)の要件を保証する仕組みを扱う。

## アーキテクチャ

`NameID` と `IssuedClaim` の集合の組み立ては、WS-Fed、WS-Trust、SAML、OIDC の各発行側が共有する一つの経路を通る。
各発行側は独自にクレームを組み立てない。
処理系は、ポリシーと解決済みの属性の対応表を受け取り、`IssuedClaim` の集合を返す。

| 段 | 内容 |
| --- | --- |
| 下限の検査 | `NameID` のソースと、各規則のソースの属性が公開できるか、各規則のクレーム型が固定の集合に含まれないかを確かめる |
| 規則の適用 | 規則ごとに、ユーザー属性、固定値、`NameID` のいずれかから値を得る。値のない任意の規則は出力しない |
| 必須の検証 | 値のない必須の規則があれば、それまでに得た値を捨てて発行を拒否する |

同じ下限の検査を、アプリケーションの設定を保存する時点でも行う。
管理者は、実行時の発行の失敗ではなく、保存の拒否として誤りを知る。
ただし、保存の後にテナントが属性を `Private` へ変えた場合は、発行時の検査が拒否する。

## 信頼性

発行の拒否は、呼び出し元のプロトコルのエラーとして返る。
拒否が続く場合は、信頼先のポリシーが参照する属性の定義と可視性を確かめ、規則またはテナントの属性定義を直す。
