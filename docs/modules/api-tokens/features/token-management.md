# API アクセストークンの発行と失効

## 概要

この文書は、テナント管理者が API アクセストークンを構成し、発行し、一覧し、失効させる仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 管理画面での接続先とスコープの意味の提示、発行、ライフサイクルのメタデータの一覧、失効 |
| 行為者 | テナント管理者 |
| 扱わないもの | 提示されたトークンの検証は[API アクセストークンの認証と認可](authentication.md)が扱う |

## 操作

### 管理画面での API アクセストークンの構成

#### REQ-APITOKENS-001 管理者は接続先とスコープの意味を確認して API アクセストークンを構成できる

- 管理者が API アクセストークンの管理画面を開いたとき、ApiTokens は、管理 API、SCIM 2.0 API、発行者本人のアカウント API の Base URL と用途を表示する。
- 管理者が発行のフォームを開いたとき、ApiTokens は、スコープを API の種類とリソースごとにまとめ、正式なスコープの値と、`read` と `write` の権限の意味を表示する。
- 管理者が発行のフォームを開いたとき、ApiTokens は、ログイン中の発行者本人をトークンの主体として表示し、操作対象のテナントと区別する。
- 折りたたんだままのスコープの集まりがある間、管理者が発行を要求したとき、ApiTokens は、発行を受け付ける。
- 管理者が発行のフォームを開いたとき、ApiTokens は、そのリソースに存在しない権限を選択肢として表示しない。
- 参照のスコープがなく変更のスコープだけを持つリソースでは、管理者が発行のフォームを開いたとき、ApiTokens は、変更の列に変更のスコープを置き、参照の列を空ける。
- **例**：EX-APITOKENS-001-01、EX-APITOKENS-001-02、EX-APITOKENS-001-03、EX-APITOKENS-001-04

### 管理者による API アクセストークンの発行、一覧、失効

#### REQ-APITOKENS-003 管理者は API アクセストークンを発行・失効できる

- 管理者がスコープの集合と有効日数を指定して API アクセストークンを発行したとき、ApiTokens は、`sub` を発行者本人、`client_id` をレルムに組み込みの公開クライアント、audience をテナントの発行者識別子、有効期限を発行時刻に有効日数を加えた時刻とする RFC 9068 の JWT を作り、201 で JWT とメタデータを返す。
- 発行で `dpop_jkt` を指定されたとき、ApiTokens は、トークンをその鍵の DPoP の証明に束縛する。
- 管理者が API アクセストークンを発行したとき、ApiTokens は、JWT を発行の応答で一度だけ返し、保存しない。
- 管理者がトークンを一覧したとき、ApiTokens は、テナントの発行済みのトークンのメタデータ（`jti`、発行者、説明、スコープ、audience、DPoP の束縛、発行時刻、有効期限、失効時刻）を、JWT を含めずに返す。
- 管理者がトークンを失効させたとき、ApiTokens は、失効時刻を記録して 204 を返し、以後そのトークンを認証しない。
- 存在しない ID のトークンの失効を要求された場合、ApiTokens は、204 を返し、どのトークンも変えない。
- `expiry_days` が 0 以下、スコープの集合が空、または定義されていないスコープを指定された場合、ApiTokens は、400 と `invalid_request` で拒否し、トークンを発行しない。
- `admin` または `system_admin` のロールを持たない利用者が発行、一覧、失効を要求した場合、ApiTokens は、403 と `access_denied` で拒否し、トークンを変えない。
- **例**：EX-APITOKENS-003-01、EX-APITOKENS-003-02、EX-APITOKENS-003-03、EX-APITOKENS-003-04

### 本人による API アクセストークンの発行、一覧、失効

#### REQ-APITOKENS-005 個人用トークンの管理は本人と所属テナントに限定される

- **上位の要件**：[REQ-AUTHENTICATION-039](../../authentication/features/account-portal.md#本人によるステップアップ認証)
- 有効なユーザーがポータルの対話セッションで個人用トークンを発行したとき、ApiTokens は、`sub` を本人に固定し、指定した account スコープと 1 日から 365 日の有効期間で JWT を発行する。
- 個人用トークンを発行したとき、ApiTokens は、JWT を応答で一度だけ返し、JWT を保存しない。
- 発行前の本人再認証の有効期間を満たさない場合、ApiTokens は、REQ-AUTHENTICATION-039 の応答で拒否し、トークンを発行しない。
- 有効なユーザーがポータルの対話セッションでトークンを一覧したとき、ApiTokens は、所属テナントで本人が発行した記録だけを、JWT を含めず返す。
- 有効なユーザーがポータルの対話セッションで本人のトークンを失効させたとき、ApiTokens は、失効時刻を記録し、204 を返す。
- 他人、別テナントまたは存在しないトークンの失効を要求された場合、ApiTokens は、204 を返し、記録を変えない。
- account 以外のスコープ、空のスコープ集合、または 1 日から 365 日の範囲外の有効期間を要求された場合、ApiTokens は、400 と `invalid_request` を返し、トークンを発行しない。
- API アクセストークンまたは通常の account スコープの OAuth トークンで個人用トークンの管理を要求された場合、ApiTokens は、403 と `insufficient_scope` を返し、記録を変えない。
- 未認証、認証保留、無効化済み、または別テナントのユーザーが個人用トークンの管理を要求した場合、ApiTokens は、401 を返し、記録を変えない。
- CSRF または Origin の検証に失敗した発行または失効を要求された場合、ApiTokens は、403 を返し、記録を変えない。
- **例**：EX-APITOKENS-005-01

## セキュリティ上の考慮

管理経路の API アクセストークンの発行、一覧、失効は、`admin` または `system_admin` のロールを持つ、有効かつ認証済みのユーザーだけが行える。
発行できるトークンは所属テナントのものに限り、`sub` は発行した本人に固定する。

本人の管理経路はロールを求めず、account スコープの発行と本人名義の記録の管理に限定する。
管理経路と本人の経路の発行、一覧、失効は、対話のセッションに限る操作である。
理由は、[トークンの発行と失効を対話のセッションに限る](../decisions.md#トークンの発行と失効を対話のセッションに限る)。
