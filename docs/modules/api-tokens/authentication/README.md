# API アクセストークンの認証と認可

## 概要

この文書は、提示された API アクセストークンを認証し、管理 API の操作を粒度スコープで認可する仕様である。

| 項目 | 内容 |
| --- | --- |
| 責務 | 署名、発行者、audience、有効期限の検証と、管理のレコードの照合。発行者のロールとトークンのスコープの両方による認可 |
| 行為者 | API アクセストークンを提示する呼び出し元、管理 API のクライアント |
| 扱わないもの | ブラウザーのポータルが提示する通常の OAuth アクセストークンとログインセッションの認可は、ポータルの境界のスコープとロールで判定し、粒度スコープを求めない |

## モデル

提示された RFC 9068 の JWT は、署名、発行者、audience、有効期限を満たしたうえで、さらに `jti` に対応する管理のレコードを毎回照合する。
レコードが失効している、期限切れである、存在しない、スコープの集合が空である場合、ApiTokens は、署名が有効でも認証を通さない。

- **判断**：二段で検証する理由は、[署名と管理のレコードの二段でトークンを検証する](../design/decisions.md#署名と管理のレコードの二段でトークンを検証する)。

トークンを提示した呼び出しは、発行者本人として認証される。
認可には、発行者が対象の操作に必要なロールを今も持つことと、トークンのスコープの集合が対象の API を許可することの両方が要る。

- **判断**：両方を求める理由は、[認可に発行者の現在のロールとトークンのスコープの両方を求める](../design/decisions.md#認可に発行者の現在のロールとトークンのスコープの両方を求める)。

## 操作

### 呼び出し元による API アクセストークンの提示

#### REQ-APITOKENS-002 API アクセストークンは有効なスコープを持つトークンだけを認証する

- 呼び出し元が API アクセストークンを提示したとき、ApiTokens は、`jti` に対応する管理のレコードのテナント、発行者、組み込みの `client_id`、スコープの集合を持つ主体として認証する。
- JWT の形式、署名、発行者、audience、`exp` のいずれかが不正な場合、ApiTokens は、401 と `invalid_token` で拒否する。
- `jti` に対応するレコードがない、失効している、有効期限を過ぎている、スコープの集合が空である場合、ApiTokens は、署名が有効でも 401 と `invalid_token` で拒否する。
- JWT の `sub`、`client_id`、スコープ、audience が管理のレコードと一致しない場合、ApiTokens は、401 と `invalid_token` で拒否する。
- DPoP に束縛したトークンを、束縛した鍵の DPoP の証明なしで提示された場合、ApiTokens は、401 と `invalid_token` で拒否する。
- **例**：EX-APITOKENS-002-01、EX-APITOKENS-002-02、EX-APITOKENS-002-03

### 管理 API のクライアントによる操作の要求

#### REQ-APITOKENS-004 管理 API は API アクセストークンの粒度スコープでフェイルクローズに認可する

- トークンのスコープの集合が操作に対応づけられたスコープのどれかを含み、発行者が操作に必要なロールを持つ間、その API アクセストークンで管理 API の操作を要求されたとき、ApiTokens は、操作の実行を許可する。
- トークンのスコープの集合が、操作に対応づけられたスコープをどれも含まない場合、ApiTokens は、403 と `insufficient_scope` で拒否し、`WWW-Authenticate` の `scope` に必要なスコープを示し、状態を変えない。
- どのスコープも対応づけられていない操作と、対話のセッションに限る操作を要求された場合、ApiTokens は、403 と `insufficient_scope` で拒否し、状態を変えない。
- 発行者が操作に必要なロールを失っている場合、ApiTokens は、スコープを満たしていても 403 と `access_denied` で拒否し、状態を変えない。
- ブラウザーのポータルが提示する通常の OAuth アクセストークン、またはログインセッションで管理 API の操作を要求されたとき、ApiTokens は、粒度スコープを求めず、ポータルの境界のスコープとロールで認可する。
- **例**：EX-APITOKENS-004-01、EX-APITOKENS-004-02、EX-APITOKENS-004-03、EX-APITOKENS-004-04、EX-APITOKENS-004-05

## セキュリティ上の考慮

スコープの集合が空のトークンは、どの API も呼び出せない。
どのスコープも対応づけられていない操作と、対話のセッションに限る操作は、どのトークンでも `insufficient_scope` で拒否する。
