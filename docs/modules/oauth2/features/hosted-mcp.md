# マネージド型 MCP Gateway

## 概要

この機能は、IdMagic の `api` プロセス内で公開された MCP サーバーの要求を評価し、上流の資格情報を注入して転送する構成を扱う。
IdMagic 自体の運用場所は問わず、IdMagic を自社で設置する場合は Gateway もその環境で動く。
利用者が Gateway を別途配置せずに使う構成を「マネージド型」、別途配置して運用する構成を「セルフホスト型」と呼ぶ。
用語の定義は[共通用語集](../../glossary.md#mcp-gateway-の提供形態)に置く。
別途配置する Gateway は [McpGateway](../../mcp-gateway/features/runtime.md) が扱う。
設定は資源登録の一部であり、規則と割当とトークンの検証を複製しない。

## 操作

### 登録と設定の参照

#### REQ-OAUTH2-091 管理者は Gateway の配置方法を選び、マネージド型の公開 URL と上流の設定を得る

- 管理者がマネージド型の接続先を登録したとき、OAuth2 は、テナントの正規 issuer に `/mcp/{resource_server_id}` を継いだ URL を `resource` として保存し、応答に含める。
- 管理者がセルフホスト型の接続先を登録したとき、OAuth2 は、従来どおり指定した `resource` を保存し、マネージド型の上流を作らない。
- 管理者が上流を指定したとき、OAuth2 は、HTTPS の絶対 URL と認証の方式を保存する。
- 管理者が `token_vault` の上流を指定したとき、OAuth2 は、コネクタ ID を保存する。
- 認証の方式が `token_exchange` と `token_vault` のどちらでもないか、上流 URL に利用者情報、クエリ、フラグメント、非公開の IP リテラル、曖昧なパスがある場合、OAuth2 は、400 と `invalid_resource_server` で拒否する。
- マネージド型で評価用のクライアントがないか、`token_exchange` の上流が同じテナントの有効な資源登録でない場合、OAuth2 は、400 と `invalid_resource_server` で拒否する。
- `token_exchange` の評価用クライアントが Token Exchange の grant を宣言していない場合、OAuth2 は、400 と `invalid_resource_server` で登録を拒否する。
- 運用場所かマネージド型の公開 URL を更新で変えようとした場合、OAuth2 は、400 と `invalid_resource_server` で拒否する。
- 管理者がマネージド型の設定を読んだとき、OAuth2 は、上流の設定と下流の公開 JWK を返し、秘密鍵と上流のトークンを返さない。
- 鍵の提供元を利用できない場合、OAuth2 は、マネージド型の登録、更新と個別設定の参照を 503 と `temporarily_unavailable` で拒否する。
- 管理画面で接続先を登録するとき、OAuth2 は、「マネージド型」と「セルフホスト型」を選択肢として示し、選んだ配置方法に必要な入力だけを表示する。
- マネージド型を登録したとき、OAuth2 は、配置用の設定とシークレットの代わりに、Agent が接続する公開 URL と迂回を防ぐ条件を管理画面へ示す。
- **判断**：公開 URL は Agent の設定へ配られる。運用場所を変えるときは登録を作り直し、古い URL の意味を黙って変えない。

### 要求の執行とメタデータ

#### REQ-OAUTH2-092 マネージド型は毎回の評価と外向きの防御を通った要求だけを転送する

- マネージド型の公開 URL への要求を受けたとき、OAuth2 は、同じテナントの現在の有効な登録だけを解決し、別テナント、非マネージド型、無効化済み、存在しない登録を 404 で拒否する。
- マネージド型のメタデータを要求されたとき、OAuth2 は、評価と転送をせず、公開 URL を `resource`、正規 issuer を `authorization_servers` に持つ JSON を返す。
- MCP の要求を受けたとき、OAuth2 は、[REQ-MCPGATEWAY-002](../../mcp-gateway/features/runtime.md#req-mcpgateway-002-解釈できない要求は評価せず上流へ送らない) と同じ 2026-07-28 版の構文を検査し、POST 以外、クエリ、許可していない Origin、圧縮した本文を転送しない。
- MCP の本文が 1 MiB を超える場合、OAuth2 は、413 で拒否する。
- プロセス全体の同時転送が 64 本に達している場合、OAuth2 は、新たな要求を 503 で拒否する。
- テナントの同時転送が 8 本に達している場合、OAuth2 は、そのテナントの新たな要求を 429 で拒否する。
- 接続先への要求が 60 秒に 60 回を超える場合、OAuth2 は、429 で拒否し、上流へ送らない。
- 操作を解決したとき、OAuth2 は、登録の評価用クライアントを使い、提示トークン、送信者の証明、現在の操作割当、条件、上限、承認の使用を既存の資源アクセスの評価で一回だけ確かめる。
- 条件の入力を作るとき、OAuth2 は、`params.arguments` の JSON オブジェクトを `attributes` として渡す。
- `params.arguments` が省略されている場合、OAuth2 は、空の JSON オブジェクトを `attributes` として渡す。
- 条件を持つ操作で属性が 16 KiB を超える場合、OAuth2 は、条件を評価不能として 403 で拒否する。
- 評価が不許可か、評価と署名と流量制限のどれかを実行できない場合、OAuth2 は、上流へ送らず、無効なトークンを 401、権限不足を 403、評価不能を 503 で返す。
- `token_exchange` の要求を許可したとき、OAuth2 は、単回使用の交換許可で登録した上流宛の DPoP トークンを得て、登録専用の鍵の証明を付ける。
- 内部からトークンを交換するとき、OAuth2 は、公開 token エンドポイントと同じ grant 宣言、Agent の発行条件、ガードレールと交換ポリシーを適用する。
- `token_vault` の要求を許可したとき、OAuth2 は、検証済みの本人と Agent と認可詳細を TokenVault へ渡す。
- TokenVault が [REQ-TOKENVAULT-016](../../token-vault/features/execution.md#req-tokenvault-016-マネージド型-mcp-の代理転送でも本人の接続と規則を守る) を満たして転送したとき、OAuth2 は、その応答を開く。
- 上流へ接続するとき、OAuth2 は、登録した HTTPS の宛先だけを使い、DNS の全アドレスを接続時に検査し、非公開アドレス、環境プロキシ、リダイレクトによる別の宛先への転送を拒否する。
- 上流へ送るとき、OAuth2 は、検査した本文を変えず、MCP のメタデータ、Accept、Content-Type だけを送り直し、受信した資格情報、Cookie、Host、転送用ヘッダーを渡さない。
- 上流の応答を返すとき、OAuth2 は、JSON か SSE の本文を逐次返し、Set-Cookie と認証のヘッダーを返さない。
- 上流が 200 以外か JSON と SSE 以外の応答を返した場合、OAuth2 は、502 で拒否し、リダイレクトを追わない。
- 転送が 120 秒か応答の本文が 16 MiB に達したとき、OAuth2 は、転送を中断する。
- 呼び出し元が切断したとき、OAuth2 は、上流の要求を取り消す。
- 転送を開始した後に失敗した場合、OAuth2 は、承認を未使用に戻さず、上流へ自動で再送しない。
- 評価が承認の使用権を再提示として返した場合、OAuth2 は、403 で拒否し、上流へ再度送らない。
- ログとエラーを出力するとき、OAuth2 は、上流の資格情報、提示された資格情報、要求と応答の本文を含めない。
- **判断**：同時転送数はプロセス内の資源の予算である。要求の回数は既存の共有流量制限で数える。登録と割当の変更は次の要求から適用し、開始済みの業務処理を巻き戻す保証を持たない。

## セキュリティ上の考慮

`token_exchange` の上流は、管理画面が示す専用公開鍵の JKT に束縛したトークンだけを受け付ける。
公開 URL のトークンと上流宛のトークンを区別するだけでは、Agent が直接得た上流宛のトークンによる迂回を防げない。
独自 OAuth の上流は、IdMagic が保管する資格情報以外で直接呼べないようにする。
トークンを本文へ反射する上流は保護の対象にしない。
閉域の上流と資格情報を MCP サーバーの近くに置く要件には、別途配置する Gateway を使う。
