# DataKeys のリスク

この文書は、DataKeys の既知の欠陥、技術的負債、受容したリスクを扱う。
脅威は[脅威モデル](../../../design/security/threat-model.md)に置く。

| リスク | 現状 | 影響 |
| --- | --- | --- |
| ローテーション、無効化、破棄を起動する経路がない | 三つのユースケースは実装されているが、管理 API も、定期実行のジョブも、運用のコマンドもそれらを呼ばない | テナントの DEK は、最初の暗号化で作られた後に入れ替わらない。鍵素材が危殆化しても、そのバージョンを止める手段がない。[秘密情報の設計](../../../design/security/secrets.md)のローテーションの行と同じ欠陥である |
| アンラップした DEK の破棄がほかのプロセスへ伝わらない | DEK の保持は各プロセスのメモリにあり、期限を持たない。ライフサイクルの操作は、操作したプロセスの保持だけを破棄する | 経路ができたとき、ほかの `api` と `worker` のプロセスは、再起動するまで退役したバージョンで暗号化し、無効化したバージョンで復号し続ける |
