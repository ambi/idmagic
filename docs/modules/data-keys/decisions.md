# DataKeys の重要な設計判断

この文書は、DataKeys の設計判断のうち、代替案を比べたものと、見直す条件が要るものを扱う。
一つの要件やモデルだけを正当化する判断は、機能仕様のその要件またはモデルの判断の欄に置く。

## DEK のライフサイクルの操作をテナント管理者に公開しない

### 背景

DEK のローテーション、無効化、破棄は、テナントのすべての暗号化した項目の読み取りに影響する。
誤った無効化や破棄は、そのテナントのシークレットを読めなくする。
一方で、鍵は定期的に入れ替え、危殆化したときは止められなければならない。

### 決定

定期のローテーションは `idmagic-batch data-key-lifecycle` が行う。
緊急のローテーションと無効化は、制御面主体の対話セッションだけが呼べる管理 API とする。
破棄は HTTP に公開しない。

### 検討した代替案

| 案 | 利点 | 欠点 | 採らない理由 |
| --- | --- | --- | --- |
| テナントの管理 API としてライフサイクルの操作を公開する | テナント管理者が自分で鍵を入れ替えられる | テナント管理者が、自身のテナントのシークレットを読めなくする操作を直接起動できる | 誤操作の被害が、テナントのすべての暗号化した項目に及ぶ |
| 緊急の操作を運用者の CLI だけにする | HTTP の入口が増えない | 実行環境への到達が前提になり、監査に操作者が残らない | 危殆化への対応で、誰が止めたかを追跡できない |

### 結果と再検討の条件

テナント管理者がライフサイクルの操作を直接起動する経路はない。
破棄を起動する経路も、現状はない（[DataKeys のリスク](risks.md)）。
顧客が管理する鍵を製品の機能として提供する場合に見直す。

## 破棄の前の確認を項目を持つモジュールの FieldMigrator に委ねる

### 背景

鍵素材を消せるのは、そのバージョンで暗号化した値が 1 件も残っていないことを確かめた後だけである。
暗号化した項目は、複数のモジュールのテーブルに散らばっている。

### 決定

破棄の前の確認と再暗号化は、項目を持つ各モジュールが `FieldMigrator` として実装し、起動処理が登録する。
このモジュールは、登録したすべての `FieldMigrator` の未移行の件数が 0 のときだけ破棄する。

### 検討した代替案

| 案 | 利点 | 欠点 | 採らない理由 |
| --- | --- | --- | --- |
| このモジュールが、暗号化した項目を持つテーブルを直接調べる | 登録の手順が要らない | このモジュールが利用側のスキーマを知ることになる | 項目を持つモジュールが増えるたびに、このモジュールを変えることになる |

### 結果と再検討の条件

このモジュールは、利用側のスキーマを知らないまま安全に破棄できる。
その代わり、暗号化した項目を新しく持つモジュールは、`FieldMigrator` を実装して登録しなければならない。登録を忘れた項目は、破棄の確認から漏れる。
暗号化した項目の所在を、スキーマの宣言から機械的に列挙できるようになった場合に見直す。

## バージョンの状態を暗号化と復号のたびに保存先から読む

### 背景

アンラップした DEK は、マスターキーのプロバイダーの呼び出しを減らすためにプロセスの中に保持する。
ライフサイクルの操作は、`api` と `batch` のどれか一つのプロセスで動く。
ほかのプロセスが保持だけで判断すると、無効化したバージョンで復号を続け、退役したバージョンで暗号化を続ける。

### 決定

保持するのは、バージョンごとに変わらない鍵素材だけにする。
有効なバージョンとバージョンの状態は、暗号化と復号のたびに保存先から読む。
読めない場合は、保持した DEK を使わずに失敗する。

### 検討した代替案

| 案 | 利点 | 欠点 | 採らない理由 |
| --- | --- | --- | --- |
| 保持に短い期限を設ける | 呼び出しごとの読み取りが要らない | 期限の間は無効化が効かない。期限ごとにアンラップが増える | 危殆化への対応で、即時のロックアウトを約束できない |
| ライフサイクルの操作をプロセスの間へ通知する | 呼び出しごとの読み取りが要らない | 通知の基盤と常時接続が要る | 通知を取りこぼしたプロセスが復号を続け、失敗の向きがフェイルオープンになる |

### 結果と再検討の条件

ライフサイクルの操作は、確定の直後からすべてのプロセスに効き、再起動を要らなくする。
その代わり、暗号化と復号のたびに索引で 1 行を読む。
再暗号化のジョブでは、1 行あたり 2 回の読み取りが増える。
暗号化した項目の読み取りが要求の経路で支配的な負荷になった場合に見直す。
