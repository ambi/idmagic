# DataKeys のリスク

この文書は、DataKeys の既知の欠陥、技術的負債、受容したリスクを扱う。
脅威は[脅威モデル](../../design/security/threat-model.md)に置く。

| リスク | 現状 | 影響 |
| --- | --- | --- |
| 破棄を起動する経路がない | `DestroyTenantDataKey` は実装されているが、管理 API も、定期実行のジョブも、運用のコマンドもそれを呼ばない | 退役したバージョンの `wrapped_dek` は残り続ける。暗号学的消去が要るときに実行する手段がない |
| アンラップした DEK の破棄がほかのプロセスへ伝わらない | DEK の保持は各プロセスのメモリにあり、期限を持たない。ライフサイクルの操作は、操作したプロセスの保持だけを破棄する。定期のローテーションは `batch` のプロセスで動くので、`api` と `worker` には常に伝わらない | ほかのプロセスは、再起動するまで退役したバージョンで暗号化し、無効化したバージョンで復号し続ける。無効化の後に旧バージョンで暗号化された値は読めなくなる。緊急時は[手順書](../../runbooks/backup-restore-dr.md#テナントの-dek-の緊急の入れ替え)のとおり再起動する |
| 無効化したバージョンの行が再暗号化を止める | `FieldMigrator` は、復号に失敗した行で一括処理全体を止める | 無効化の後、そのテナントの再暗号化のジョブは失敗を繰り返し、`data-key-lifecycle` が毎日投入し直す。未移行の件数が 0 にならないので、破棄も拒否される |
