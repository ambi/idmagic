# DataKeys のリスク

この文書は、DataKeys の既知の欠陥、技術的負債、受容したリスクを扱う。
脅威は[脅威モデル](../../design/security/threat-model.md)に置く。

| リスク | 現状 | 影響 |
| --- | --- | --- |
| 破棄を起動する経路がない | データ暗号鍵の破棄のユースケースは実装されているが、管理 API も、定期実行のジョブも、運用のコマンドもそれを呼ばない | 退役したバージョンの `wrapped_dek` は残り続ける。暗号学的消去が要るときに実行する手段がない |
| 無効化または破棄したバージョンの鍵素材がメモリに残る | ほかのプロセスは、そのバージョンの復号を次に要求されたときに保持を捨てる。要求がなければ、再起動まで残る | 製品はその鍵素材を使わない。プロセスのメモリを読める攻撃者には取得できるので、メモリの露出が疑われるときは[手順書](../../runbooks/backup-restore-dr.md#テナントの-dek-の緊急の入れ替え)のとおり再起動する |
| 確定と同時に進む暗号化が旧バージョンを使う | 状態を読んだ後にローテーションが確定すると、その暗号化は旧バージョンで保存する | その行は未移行の件数に数えるので再暗号化が回収する。無効化の直前に重なると、その行は読めなくなる。手順書は再暗号化の完了を待ってから無効化する |
| 無効化したバージョンの行が破棄を妨げる | 再暗号化はその行を残してほかの行を移すが、未移行の件数には残す | 値の再入力や行の削除で参照をなくすまで、破棄は拒否される。定期実行は未移行の行を再確認するジョブを投入する |
