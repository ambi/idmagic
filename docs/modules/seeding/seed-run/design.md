# seed の計画と適用の設計

この文書は、[seed の計画と適用](README.md)の要件を保証する仕組みを扱う。

## アーキテクチャ

マニフェストは、バージョンを持ち厳密に解釈する YAML である。
`manifests_yaml` のアダプターがドメインの型へ変換してから計画器へ渡し、ドメインとユースケースは、パーサー、ファイルシステム、環境変数の API を直接参照しない。

| 制限 | 内容 |
| --- | --- |
| `include` | マニフェストのルートの配下のローカルな相対パスだけを読み込む。深さは 16 までとし、ファイルの総数とファイルの大きさにも上限を設ける |
| 文法から除外するもの | YAML のマージキー、テンプレートの展開、リモートの URL、環境変数の展開 |
| シークレット | `SeedSecretReference` で参照し、値をマニフェストに書かない。`file` の提供元はシークレットのルートの配下だけを読み、大きさに上限を設ける |

適用は、次の順に進む。

1. 計画を作り、`conflict` があれば止める。
2. 同じ環境、プロファイル、テナントの組で、プロセスの中の排他を取る。
3. 計画を作り直し、`conflict` がなければ適用する。
4. もう一度計画を作り、`create`、`update`、`conflict` が残っていれば、収束しなかったものとして失敗する。

## 信頼性

適用は、モジュールをまたぐ一つのトランザクションではなく、依存順に並べた冪等な操作の列で行う。
`performance` のプロファイルは、デフォルトで 250 件、最大 1,000 件のバッチで進む。
専用の進捗テーブルは設けない。

部分的に失敗した場合は、同じ要求を再実行する。
論理キーと ID が決定的なので、完了した論理キーは `noop` と計画され、未完了の分だけが適用される。

手動の変更でドリフトが生じた場合は `SeedConflictError` で止まり、手動の変更を上書きしない。
マニフェストを手動の値に合わせるか、手動の変更を戻してから再実行する。
