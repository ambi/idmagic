# Seeding

## 責務と境界

環境ごとの初期データを、望ましい状態として宣言し、計画し、適用する。
マニフェストの文法、環境ごとに許すプロファイルとシークレットの提供元、プレビューと適用の計画器、シークレットを伏せた計画の表現がここに属する。

| 扱わないもの | 担当 |
| --- | --- |
| Tenant、User、Group、Application の記録と永続化 | それぞれの記録の正を持つモジュール |
| 実行の権限 | プロセスを起動できる実行環境。このモジュールは HTTP の接点を持たない |

このモジュールは記録の正を持つモジュールの保存の経路を呼ぶだけで、SQL フィクスチャでレコードを直接書き込む経路は設けない。

## 主な流れ

| 流れ | 契機 | 実行する場所 | 詳細 |
| --- | --- | --- | --- |
| プレビュー | 運用者が `idmagic-seed` を `dry_run` で起動する | コマンドのプロセスが計画だけを作り、書き込まない | [seed の計画と適用の設計](features/seed-run.md#実現方式) |
| 適用 | 運用者が `idmagic-seed` を `apply` で起動する | コマンドのプロセスが計画、適用、収束の確認を行う | [seed の計画と適用の設計](features/seed-run.md#実現方式) |

## 設計の要点

| 方針 | 理由 |
| --- | --- |
| 権限ではなく、実行環境と環境ポリシーで書き込みを制限する | テナントをまたぐ書き込みができる唯一の経路を、管理 API に載せない。詳細は[判断](decisions.md#seed-の計画と適用に-http-のエンドポイントを設けない) |
| プレビューと適用で一つの計画器を共有する | プレビューだけが通り、適用で落ちる差を作らない |
| 論理キーと ID を決定的に導き、進捗を保存しない | 再実行だけで部分的な失敗から収束する。詳細は[判断](decisions.md#進捗テーブルを使わず決定的な論理キーで冪等にする) |

## 機能一覧

| 機能 | 内容 |
| --- | --- |
| [seed の計画と適用](features/seed-run.md) | マニフェストの選択と検証、環境ポリシー、冪等な適用、ドリフトの検出 |

コマンドの引数と設定から要求を組み立てるのは `backend/cmd/idmagic-seed` である。
`backend/cmd/internal/bootstrap` はシークレットの提供元、ハッシュ器と各所有者の保存契約を結び、Seeding の計画器へ渡す。
リソースの生成、差分判定、適用順と再計画は Seeding が担当し、bootstrap はそれらの判断を持たない。
ファーストパーティークライアントの生成と比較は、時刻を引数として受ける `domain` の計算である。
所有者の Repository 契約を直接呼ぶ現在の制約は、[リスク](risks.md)で扱う。
