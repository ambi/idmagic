# Seeding

## 責務と境界

環境ごとの初期データを、望ましい状態として宣言し、計画し、適用する。
マニフェストの文法、環境ごとに許すプロファイルとシークレットの提供元、プレビューと適用の計画器、シークレットを伏せた計画の表現がここに属する。

| 扱わないもの | 担当 |
| --- | --- |
| Tenant、User、Group、Application の記録と永続化 | それぞれの記録の正を持つモジュール |
| 実行の権限 | プロセスを起動できる実行環境。このモジュールは HTTP の接点を持たない |

このモジュールは記録の正を持つモジュールの保存の経路を呼ぶだけで、SQL フィクスチャでレコードを直接書き込む経路は設けない。

## モデル

このモジュールは Aggregate を定義しない。
`SeedManifest` と `SeedPlan` は 1 回の実行の中でしか生きない値であり、投入した業務データの記録の正は各モジュールに残る。

- **判断**：状態を保存しない理由は、[Aggregate を定義せず投入の結果を保存しない](design/decisions.md#aggregate-を定義せず投入の結果を保存しない)。

| 値 | 内容 |
| --- | --- |
| `SeedRequest` | 環境、プロファイル、`dry_run` か `apply` か、マニフェストのパス、ファーストパーティーのリダイレクト URI、生成器の seed、件数、バッチの大きさ |
| `SeedManifest` | seed のリソースと決定的な生成器を宣言する、バージョン付きの YAML |
| `SeedSecretReference` | マニフェストがシークレットの値の代わりに持つ、提供元、ロケーター、バージョンの組 |
| `SeedPlan` | 現在の状態とマニフェストを比べて作る、論理キーごとの `create`、`update`、`noop`、`conflict` の操作の列。シークレットを含まない |

論理キーと ID は、プロファイルと生成器の seed から決定的に導く。
同じ要求を再実行すると、同じ論理キーを同じ ID で計画する。

## 公開する契約

要求、マニフェスト、計画、エラーの形は TypeSpec の `Seeding` のタグのモデルが定める。
このモジュールは HTTP の操作を持たない。

| 契約 | 相手 | 向き | 内容 |
| --- | --- | --- | --- |
| `idmagic-seed` のコマンド | 運用者と自動化主体 | このモジュールが提供する | 環境、プロファイル、モードを指定して計画または適用を実行する |
| `Contributor` | 起動処理が実装し、記録の正を持つモジュールの保存の経路を呼ぶ | このモジュールが定める | 計画と適用を、リソースの種類ごとに行う |
