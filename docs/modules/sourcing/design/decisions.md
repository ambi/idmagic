# Sourcing の重要な設計判断

この文書は、Sourcing の設計判断のうち、代替案を比べたものと、見直す条件が要るものを扱う。
一つの要件やモデルだけを正当化する判断は、機能仕様のその要件またはモデルの判断の欄に置く。

## SCIM の User の削除を論理削除へ統合する

### 背景

外部の IdP の同期は、設定の誤りや誤動作で、大量の User の削除を送ることがある。
完全な削除は、個人識別情報を回復できない形で失う。

### 決定

SCIM の `DELETE /Users/{id}` は即座の完全な削除にせず、プラットフォームのほかの部分と同じ論理削除（`PendingDeletion`、30 日の猶予、その後に匿名化を伴う完全な削除）を行う。

### 検討した代替案

| 案 | 利点 | 欠点 | 採らない理由 |
| --- | --- | --- | --- |
| SCIM の削除を即座の完全な削除にする | 外部の IdP の状態と、すぐにそろう | 誤った同期が、回復できない個人識別情報の喪失を引き起こす | 外部の誤りを、猶予の間に取り戻せない |

### 結果と再検討の条件

SCIM の削除は既存の論理削除の方針に統合され、それを迂回しない。
その代わり、削除した User は猶予の間、内部に残る。SCIM の照会からは消える。
外部の IdP が、猶予のない完全な削除を契約として求めるようになった場合に見直す。
