# 検証設計

システム要求を満たしたと判断する証拠の種類、実行境界、合否条件への入口を持つ。
テストコード、CI の実行結果、作業項目の RED と変更耐性の証拠はそれぞれの正本に残し、この文書へ結果を複製しない。

| 対象 | 主な証拠 |
| --- | --- |
| TypeSpec と規範文書 | `mise run verify-spec`、互換性検査、ID と参照の検査 |
| Context 内の機能 | 要求 ID を名指す単体試験と統合試験 |
| 公開経路と構成 | E2E 試験、契約と実装の差分検査、構成資材の検査 |
| 性能と容量 | 固定した運用プロファイルによる負荷試験 |
| 可用性と復旧 | 障害注入、フェイルオーバー訓練、復元訓練 |
| セキュリティ | 拒否が防いだ作用を確かめる試験、脅威と制御の追跡、依存監査 |

[システム受入れ設計](system-acceptance.md) がシステム境界での受入設計を持ち、開発中の証拠契約は[仕様先行開発ワークフロー](../development/specification-first-workflow.md)が持つ。
