# セキュリティ検証設計

[脅威モデル](../design/security/threat-model.md)が識別した脅威に応える制御が実際に働いていることを、どの証拠で判断するかを定める。
脅威の一覧、各行の状態、受容した残留リスクは脅威モデルに記録し、この文書へ写さない。

扱うのはリポジトリ内で作れる証拠である。
外部のセキュリティレビューと侵入試験は、ここで設計する証拠には含めない。
また、証拠が示すのは識別済みの脅威に応える制御が働いていることであって、識別していない脅威については何も述べない。

## 脅威の状態ごとに求める証拠

| 状態 | 求める証拠 | 実行 |
| --- | --- | --- |
| `covered` | `Controls` 列が指す規範 ID を名指すテスト | `mise run test-go-race`、`mise run test-ui-e2e` |
| `planned` | 応える規範が無いか規範化されていないため、テストではなく、その欠落を担う作業項目の存在 | `mise run spec-where THREAT-NNN` |
| `accepted` | 受容の理由と再検討の条件が[脅威モデル](../design/security/threat-model.md#受容した残留リスク)に書かれていること | `mise run check-links` が見出しの実在を確かめる |
| `retired` | 追加の証拠を要さない | 実行しない |

`planned` の行にテストを要求しない理由は、テストが不足しているからではなく、テストが照合すべき規範がまだ無いからである。
規範が書かれた時点でその行は `covered` へ移り、上の行の証拠を要求される。

## 制御の種類ごとの検証手段

| 制御の種類 | 検証手段 | 実行 | 合否条件 | 実行環境 |
| --- | --- | --- | --- | --- |
| 認証、認可、テナント境界で許可しない操作 | 受け入れテスト | `mise run test-go-race` | エラーを返すだけでなく、状態の変更、トークンの発行、外部への通知のいずれも残らない | リポジトリ内 |
| 許可しないと宣言した制御の被覆 | 静的検査 | `mise run check-security-controls`、`mise run report-security-test-gaps` | 許可しないと宣言する制御にテストがあり、拒めない guard が無い | リポジトリ内 |
| 信頼境界での値の解析、分割、正規化、比較 | プロパティテスト、ファジング | `mise run test-go-fuzz-all` | 仕様から導いた不変条件、往復、受け付けなかったあとに何も変わらないことが破れない | リポジトリ内 |
| レスポンスヘッダー、Cookie 属性、同一オリジンの前提 | E2E | `mise run test-ui-e2e` | ブラウザーが実際に受け取る値が規範のとおりである | リポジトリ内 |
| 鍵素材の秘匿と失効 | 単体、アダプター統合 | `mise run test-go-race` | 鍵素材が API、ログ、設定リファレンスへ出ず、失効後の暗号文を復号できない | リポジトリ内 |
| 依存の既知脆弱性 | 依存監査 | `mise run audit-dependencies`、`mise run audit-go-reachability`、`mise run check-vulnerability-suppressions` | 未処理の既知脆弱性と、理由または期限を欠く抑制が無い | リポジトリ内 |
| リポジトリへ混入したシークレット | 走査 | `mise run lint-repo`、`mise run audit-secrets-history` | 作業ツリーと Git 履歴のどちらにも検出が無い | リポジトリ内 |
| 危険な実装パターン | 静的解析 | CI の CodeQL | 新たな警告が無い | リポジトリ内 |
| 取り込んだ依存物と配布する成果物の来歴 | 供給鎖の検証 | 定めていない | 来歴を確かめられ、差し替えを識別できる | 手段が未定 |

## 許可しない操作の確認

確認対象は[システム受入れ設計](system-acceptance.md#許可しないリクエストの確認対象)が定める。
制御の検証では、そこで挙げたものを脅威の側から名指す。

返した状態コードとエラー本文だけを表明したテストは、エラーを返しながら操作は実行してしまう誤実装を通す。
テストは、その操作が成功していれば残ったはずのものを名指して、残っていないことを表明する。
名指す先は、読み戻せる状態、発行したトークンやセッション、外部境界へ出た要求のいずれかである。
どの水準で表明するかは[テスト方針](../development/testing.md)が定め、どの制御が許可しないと宣言しているかは `mise run report-security-test-gaps` が示す。

## 見直しのタイミング

この文書は、[脅威モデル](../design/security/threat-model.md#見直す条件)の見直し条件が満たされたときに併せて見直す。
脅威が増えても検証手段の型が変わらない場合が多いので、行の追加ではなく、既存のどの手段にも当てはまらない制御が現れたかで判断する。
