AI エージェントに、社内文書を安全に任せる

社内文書アシスタントが、改修していない MCP サーバーの文書を扱います。コードも MCP サーバーも変えず、管理画面の設定だけで「誰が・何を・いつまで」を統制します。

実在のもの：IdMagic、MCP ゲートウェイ、MCP サーバー、暗号署名。台本のもの：エージェントの判断（LLM は使わず、依頼を決め打ちで実行します）。

1. これまで：共有キーのエージェントは何でもできる

同じ MCP サーバーへ、共有の API キーだけで直接つなぎます。キーを持つものは全員同じ権限で、誰の操作かも区別できません。

2. 設定：管理画面だけで統制する

進め方

このページと IdMagic の管理画面を、別のタブで行き来します。各手順で「この画面を開く」を押し、表の入力欄に値をコピーして保存し、このページへ戻って「次へ」を押します。シェルもコードの変更も不要です。ログインは alice / demo-password-1234 です。

3. これから：同じ依頼を、もう一度

エージェントへの依頼

権限をその場で変える

トークンを取り直さなくても、判定は要求ごとに行われます。

給与テーブルも読めるようにするには、関係タプルを 1 件追加して、左の「給与テーブルを読む」をもう一度押します。削除すれば、また拒否に戻ります。

関係タプルを追加する画面を開く

4. 緊急時：画面の 1 操作で止める

暴走したエージェントを止める

エージェントの詳細で「無効化」を選んでから実行します。手元の有効期限内のトークンも、新しい発行も止まります。「緊急停止」は取り消せないので最後に試します。

重要な操作は人が承認する

再度有効にして、種別を「監督下」へ変えてから依頼します。エージェントは自分だけではトークンを得られず、所有者の承認を待ちます。

alice の承認画面を開く

5. 何が使われているか

場面技術と仕様解決すること
エージェントの IDAgent プリンシパル、所有者、区分人にも共有アカウントにも寄せず、責任者のいる ID として管理する
認証private_key_jwt (RFC 7523)、Client Credentials (RFC 6749)漏えいし得る共有シークレットをなくし、鍵は手元から出さない
宛先の限定Resource Indicators (RFC 8707)、Protected Resource Metadata (RFC 9728)文書サーバー宛のトークンを他のサーバーで使わせない
実行前の認可MCP 2026-07-28、MCP ゲートウェイ、ReBACMCP サーバーを改修せず、文書ごと、呼び出しごとに判定する
人の承認OpenID Connect CIBAその場にいない責任者に帯域外で判断してもらう
停止と記録発行済みトークンの即時失効、監査イベント有効期限を待たずに止め、後から追跡する

設定の履歴は IdMagic の「監査イベント」、棚卸しは「エージェント」→「棚卸し」で確認できます。
