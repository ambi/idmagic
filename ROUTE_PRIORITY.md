# Route Priority Reference

Generated by `mise run generate-route-reference` from the assembled router and the
priority classification the admission middleware applies. Do not edit by hand:
`mise run check-route-reference` fails when this file and the classification differ.

When the API process saturates it refuses requests from the lowest priority class
upward, with 503, `Retry-After`, and a `urn:idmagic:error:service_overloaded`
Problem Details. The refusal happens after routing and before any handler, so a
refused request changes no state. Thresholds, defaults, and the operational
reasoning live in `docs/deployment.md`; the degradation order they implement is
normative in `docs/capacity.md`.

A route reachable both unprefixed and under `/realms/{tenant_id}/…` appears once:
both forms carry the same class.

## Classes

| Class | Degradation stage | Concurrency limit | Behaviour when saturated |
| --- | --- | --- | --- |
| `management_bulk` | 3 | `ADMISSION_MANAGEMENT_BULK_MAX_CONCURRENT_REQUESTS` | Refused first. Aggregation, export, import, and full resync. |
| `management` | 4 | `ADMISSION_MANAGEMENT_MAX_CONCURRENT_REQUESTS` | Refused once the bulk limit no longer relieves the saturation. Everything an existing session's authentication and token processing does not need. |
| `interactive_auth` | 5 | `ADMISSION_MAX_CONCURRENT_REQUESTS` | Refused last, and only at the process-wide limit. |
| `infrastructure` | — | — | Never refused. Refusing a readiness probe takes every saturated replica out of load balancing at once. |
