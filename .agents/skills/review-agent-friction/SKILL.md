# 妨げの記録の振り返り

規則と判断の基準は[作業中の妨げの記録](../../../docs/development/agent-guidance.md#作業中の妨げの記録)が定める。
この skill はその手順を実行する。

1. `mise run report-agent-friction` を実行する。
   利用者が範囲を指定したら、その `git log` の範囲を引数に渡す。
2. 2 件以上の対象と、現在のツリーにない対象を一つずつ扱う。
   記録された「起きたこと」を読み、対象の現在の内容を読む。
   記録の後に対象が変わっていれば、`git log --format='%h %s' <最も古い記録のコミット>..HEAD -- <パス>` で変更を読み、すでに直っているかを確かめる。
   形式に合わない値は、書き手が意図した対象を推測せず、そのまま利用者に示す。
3. [記録から変更を決める手順](../../../docs/development/agent-guidance.md#記録から変更を決める手順)の表から、対象ごとの扱いと直し方の案を決める。
4. 対象、記録の件数、原因、扱い、直し方の案を表にして利用者に示し、採る、何もしない、後で扱うのどれにするかを聞く。
   利用者が決めるまで起票しない。
5. 採った案を `new-work-item` で起票する。
   関係する未完了の項目があれば、新しく起票せずにその項目を更新する。
6. 採った対象と何もしないと決めた対象について、起票と同じコミットに `Agent-Friction-Reviewed:` トレーラーを一件ずつ書く。
   後で扱うと決めた対象には書かない。
   起票がなければ、`git commit --allow-empty` でトレーラーだけのコミットを作る。
7. もう一度 `mise run report-agent-friction` を実行し、判断した対象が 2 件以上の区分から消えたことを確かめる。

最終報告には、判断した対象と扱い、起票した作業項目、後で扱うことにした対象を示す。
明示された場合だけ push する。
