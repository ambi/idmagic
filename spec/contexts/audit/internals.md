# Audit Internals

## Search attribute registry

検索文法は `AuditSearchRegistry` が宣言する属性、演算子、変換方法の閉じた集合に限り、任意の SQL や JSONPath は受け付けない。個人識別情報にあたる属性には、レジストリで定めた変換 (ハッシュ化や丸め) を適用してから照合するため、検索用インデックスに平文は残らない。平文を保持できるのは `audit_events.payload` だけであり、対象を失敗イベントに限ったうえで保持期間を短くする。

## Multi-valued search attributes

検索属性の副表は 1 つのイベントの 1 つの属性に対して複数の値を持てる。委譲チェーンの参加者 (`delegation.actor`) はこの多値の属性であり、チェーンに現れる主体をそれぞれ 1 行として書く。絞り込みは属性の行に対する存在判定なので、いずれかの値が一致すればそのイベントが返る。単値の属性は行が 1 つしかないだけで、同じ判定がそのまま適用される。

副表はイベントのペイロードから再生成できる派生データである。検索軸を後から追加しても、既に記録済みのイベントへ遡って行を書き足すことはしない。追記のみの監査記録に対する書き戻しになり、記録が変わらないという主張と両立しないためである。軸を持たないイベントはその軸のどの値にも一致せず、絞り込みの結果に現れない。
